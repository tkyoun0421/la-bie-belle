# P6. 예상 급여와 리허설

## 목표

예정 스케줄과 개인 시급으로 날짜별·월별 예상 급여를 제공하고 리허설 자기기록을 포함한다.

## 진입 조건

- P3 완료.
- 알림 기반과 공통 앱 셸을 재사용하기 위해 P4 완료를 권장한다.

## 작업

### P6-T01. 급여 계산 도메인 모듈

- 분 단위 순수 함수로 기본·초과 시간을 계산한다.
- 최초 540분은 1배, 초과분은 1.5배를 적용한다.
- 전 시간을 유급으로 계산한다.
- 원 단위 최종 반올림 정책을 고정한다.
- 잘못된 종료<시작 입력을 거부한다.

인수 조건:

- 9:00, 9:30, 10:00 경계와 분 단위 property 테스트가 통과한다.

### P6-T02. 일반 근무 예상 급여 조회

- assignment 시급 스냅샷과 예정 출퇴근으로 금액을 계산한다.
- 결근 assignment는 0원으로 표시한다.
- 날짜별 상세와 월별 합계를 제공한다.
- 실제 출퇴근 원본은 공식에 사용하지 않는다.

인수 조건:

- 확정 후 개인 시급을 변경해도 과거 assignment 예상치가 바뀌지 않는다.
- 복수 포지션은 한 사람의 하루 근무를 중복 계산하지 않는다.

### P6-T03. 근무자·관리자 급여 화면과 권한

- 근무자는 본인 시급, 날짜별 금액, 월 합계만 본다.
- 관리자는 근무자별 날짜·월 예상치를 조회한다.
- 모든 문구를 `예상 급여` 또는 `급여 참고`로 표시한다.
- 지급·공제·세금·정산 UI를 만들지 않는다.

인수 조건:

- 일반 근무자가 다른 사람의 시급과 금액을 조회할 수 없다.

### P6-T04. 리허설 CRUD

- 근무자가 날짜, 시작, 종료를 직접 생성한다.
- 생성 시 개인 시급을 스냅샷한다.
- 본인이 수정·삭제한다.
- 관리자와 본인만 조회한다.
- 모집, 포지션, 출퇴근, 승인과 연결하지 않는다.

인수 조건:

- 다른 근무자는 리허설의 존재도 볼 수 없다.
- 일반 근무와 시각적으로 구분되고 공식 출퇴근으로 오해되지 않는다.

### P6-T05. 월 합계와 회귀 테스트

- 일반 근무와 리허설을 구분 표시하면서 월 합계에 함께 반영한다.
- 결근, 취소, 월 경계, 시급 스냅샷을 테스트한다.
- 근무자와 관리자 모바일 E2E를 작성한다.

인수 조건:

- 같은 데이터를 조회할 때 상세 합과 월 합계가 일치한다.
- 정산 기능으로 오인할 필드가 API와 UI에 없다.

## 종료 조건

- 근무자와 관리자가 수기 계산 없이 월 예상 금액을 확인한다.
- 리허설 기록은 단순하고 일반 출퇴근과 분리되어 있다.

## 제외

- 실제 지급과 명세서.
- 리허설 승인과 인증.

# 5-deploy — 배포

## 역할

아직 백지다. 저장소에 배포 설정이 없고 플랫폼도 정하지 않았다. 첫 출시 준비 task가 채운다 — `backlog.md`의 `first-release`. 첫 운영 전에 서야 하는 최소는 적용·확인·되돌리기 순서와 환경별 설정 위치다.

다룰 것: 플랫폼 선택(ADR로 정한다), 원격 Supabase 전환, 환경 변수 관리, 릴리스 절차.

## 문서 지도

| 문서 | 답하는 질문 |
| --- | --- |
| [`environments.md`](environments.md) | 환경마다 무엇이 뜨고 설정은 어디 있고 무엇에 의존하나 |
| [`procedure.md`](procedure.md) | 무엇을 어떤 순서로 올리고 실패하면 어떻게 되돌리나 |
| `releases/` | 이번 출시에 무엇이 담겼고 실행 결과가 어땠나. 첫 기록이 생길 때 만든다 |

## 입력과 산출물

작성법 하나는 「용도·작성 시점 / 필요한 입력 / 복사용 틀 / 절별 질문 / 검토 기준」 순서다. 모든 문서에 공통인 규칙은 [문서 지도](../README.md#참조와-작성-규칙)가 소유한다.

### environments·procedure

**용도·작성 시점:** 첫 출시 준비에서 실제 환경을 확인해 작성하고 환경·절차가 바뀔 때 갱신한다. 플랫폼이 미정인 동안 아래 틀로 플랫폼·설정값·운영 명령을 임의로 확정하지 않는다.

**복사용 틀:**

```markdown
# 배포 환경

## 환경별 구성
| 환경 | 용도 | 앱·DB·외부 서비스 | 관리 위치·담당 역할 |
| --- | --- | --- | --- |

## 설정
| 설정 이름 | 필요한 환경 | 설정 위치 | 읽히는 시점 | 누락 확인 방법 |
| --- | --- | --- | --- | --- |

## 데이터와 외부 의존성
<환경 분리·초기 데이터·서비스 제약·확인 근거와 날짜>

## 미정
<출시 전에 정할 항목과 준비 작업>
```

설정에는 이름과 보관 위치를 적고 실제 시크릿 값은 쓰지 않는다. 빌드 시점과 실행 시점을 구별한다. 구독 플랜·외부 제약은 실제 환경을 조사할 때 확인한 날짜와 근거를 남긴다.

```markdown
# 배포·확인·되돌리기 절차

## 진입 조건
<릴리스 범위·검증 근거·환경 준비·실행 담당>

## 실행 순서
| 단계 | 전제 | 명령·행동 | 정상 확인 | 실패 시 중단·복구 |
| --- | --- | --- | --- | --- |
| <빌드·데이터 전환·배포·배포 후 확인의 각 단계> | <조건> | <확인된 방법> | <관찰 결과> | <행동> |

## 되돌리기
<판단 조건 / 앱·데이터별 복구 방법 / 복구 불가능한 구간 / 복구 후 확인>

## 기록과 운영 인계
<release에 남길 결과 / monitoring·response 참조>
```

**절별 질문:** 정상 배포 순서를 먼저 쓰고 각 단계가 실패했다고 가정해 중단·복구 경로를 채운다. 데이터 변경을 앱 버전 되돌리기로 복구할 수 있는지 따로 확인한다. 확인하지 않은 복구 가능성을 단정하지 않는다. 명령 설명은 procedure, 실제로 실행한 사실은 release에 둔다.

**검토 기준:** 다음 단계로 넘어갈 조건과 멈출 조건이 있는가. 앱·데이터·설정의 적용 순서를 재현할 수 있는가. 배포 전 환경값 주입처럼 실행 결과에 영향을 주는 전제를 빠뜨리지 않았는가.

### release

**용도·작성 시점:** 구체적인 출시 대상을 구성할 때 만들고 실제 실행마다 결과를 덧붙인다. task 슬러그 대신 릴리스 식별자를 파일명으로 쓰며, 아직 실행하지 않은 항목은 `미실행`으로 구별한다.

**복사용 틀:**

```markdown
# <release> — 출시 기록

## 포함 작업·Git 기준점
<포함 task와 산출물 링크 / 배포할 커밋·빌드 산출물 / 마이그레이션>

## 사전 검증 근거
<CI 실행 결과·필요한 evidence / 적용한 procedure의 버전·절 / 남은 제한>

## 배포 기록
| 시각·실행자 | 환경·적용 대상 | 실행한 단계 | 결과·근거 |
| --- | --- | --- | --- |

## 배포 후 확인
<procedure가 요구하는 확인 항목별 실제 관찰 결과>

## 되돌리기 이력·후속 작업
<되돌린 대상·시각·이유·복구 확인, 또는 실행하지 않았음 / 후속 작업 링크>
```

**절별 질문:** 릴리스에 묶인 작업의 완료 조건이나 상태를 다시 적지 않는다. 검증한 커밋과 배포할 대상이 다르면 차이를 확인하고 필요한 검증을 연결한다. 배포 명령 성공과 사용자 동작 확인을 각각 기록한다.

## 다음 단계로 넘기는 조건

배포는 운영에서 확인할 릴리스·복구 정보를 넘긴다. 남은 제한은 그것이 막는 범위와 처리 방법을 적어 넘긴다.

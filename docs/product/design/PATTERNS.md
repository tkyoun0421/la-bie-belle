## 앱 셸과 내비게이션

근무자 하단 탭은 `홈 · 일정 · 알림 · 전체` 네 개다. 아이콘과 텍스트를 항상 표시하고 선택 탭만 action 색을 사용한다. 읽지 않은 알림은 숫자 대신 작은 점으로 알린다.

- 일반 근무자에게 관리자 메뉴나 비활성 진입점의 흔적을 노출하지 않는다.
- 관리자는 같은 근무자 경험을 사용하고 `전체`에 관리자 전용 구획을 추가한다.
- 관리자 홈 상단과 전체 메뉴에서 관리자 대시보드로 진입할 수 있다.
- 관리자 대시보드와 1차 목록에서는 하단 탭을 유지한다.
- 팀원 상세, 배정 편집, 설정 폼처럼 깊은 작업에서는 하단 탭을 숨기고 상단 뒤로가기와 하단 고정 저장 버튼을 사용한다.

## 화면 우선순위

한 화면에는 가장 중요한 제목, 설명, 행동 하나가 먼저 보여야 한다.

- 홈은 고정 위젯 모음이 아니라 현재 가장 중요한 행동을 상황에 따라 바꾼다.
- 목록은 카드 묶음보다 행과 구분선을 우선한다.
- 요약은 첫 화면에서 판단할 수 있을 정도만 제공하고 민감하거나 상세한 값은 다음 단계에서 보여준다.
- 빈 상태는 이유와 다음 행동을 함께 제공한다. 장식 일러스트는 필수가 아니다.

## 선택과 저장

- 반복 선택은 화면 안에서 임시 상태로 모은 뒤 명시적인 저장 버튼으로 한 번에 전송한다.
- 저장 버튼에는 결과가 드러나는 동사를 쓴다. 예: `신청하기`, `배정 저장하기`.
- 서버 저장 전에는 “완료”처럼 보이지 않게 선택 상태와 저장 상태를 구분한다.
- 중복 탭을 막고 진행 상태를 표시하되 버튼 폭과 레이아웃을 바꾸지 않는다.

## Undo

되돌릴 수 있는 작업은 확인창 없이 실행하고 스낵바에서 Undo를 제공한다.

- 여러 항목을 batch로 저장했다면 Undo는 마지막 변경 묶음 전체를 복원한다.
- 스낵바는 결과 문구, 변경 개수, `되돌리기` 행동을 제공한다.
- API는 최초 저장 1회, Undo 복원 1회를 원칙으로 한다.
- 취소가 포함된 batch도 별도 확인창을 띄우지 않는다.
- Undo가 만료되면 같은 정상 흐름으로 다시 신청할 수 있어야 한다.

## 오버레이 선택

| 상황 | 패턴 |
| --- | --- |
| 포지션·근무자·날짜 선택 | 바텀시트 |
| 짧은 상세나 보조 행동 | 바텀시트 |
| 단순 성공 | 스낵바 또는 인라인 |
| 되돌릴 수 있는 삭제·취소 | 즉시 실행 + Undo |
| 영향이 크거나 비가역적인 행동 | 대화상자 |
| 입력이 많거나 독립적인 업무 | 전체 화면 |

- 대화상자 제목은 행동이 아니라 결과를 말한다. 예: `인원이 부족한 채로 확정할까요?`
- 스케줄 확정은 구조·자격 오류가 없고 인원이 충분하면 즉시 처리한다.
- 필요 인원 미달일 때만 확인 대화상자를 보여주고 관리자는 계속할 수 있다.
- 성별 불충족, 비활성 계정 등 구조·자격 오류는 대화상자로 우회하지 않고 차단한다.

## 폼과 검증

- 입력은 옅은 회색 채움형이며 라벨을 placeholder로 대체하지 않는다.
- 포커스는 action ring, 오류는 danger 테두리와 해결 가능한 설명으로 표시한다.
- 사용자가 입력하는 동안 형식 도움을 주되 제출 전에 모든 오류를 한꺼번에 숨기지 않는다.
- 서버 오류는 입력값을 보존하고 재시도 가능 여부와 관리자 문의 경로를 알려준다.
- 긴 폼의 주요 제출 버튼은 safe-area를 고려해 하단에 고정할 수 있다.

## 문구

- 근무자 화면은 짧고 친근한 대화체를 사용한다.
- 관리자 제목과 버튼은 짧은 업무형 문구, 설명과 경고는 친근하고 명확한 대화체를 사용한다.
- 위험·비가역 행동은 `삭제`, `복구 불가`, `기존 배정 유지`처럼 실제 결과를 직접 말한다.
- API, mutation, projection, vault 같은 기술·도메인 용어를 사용자에게 노출하지 않는다.
- 성공 문구는 완료된 사실을 말하고 과도하게 축하하지 않는다.

## 로딩, 오류, 오프라인

- 처음 읽는 화면은 콘텐츠 구조를 유지하는 skeleton을 사용한다.
- 작은 갱신은 기존 내용을 유지하고 해당 영역에만 진행 상태를 표시한다.
- 앱 셸, 아이콘, 글꼴과 모든 사용자에게 같은 public 리소스만 오프라인에서 제공한다.
- 일정, 배정표, 개인정보, 시급과 작성 중인 private 폼은 브라우저 저장소나 Service Worker에 영속하지 않는다.
- 오프라인이면 상단에 `인터넷 연결이 끊겼어요` 배너를 고정하고 모든 변경 행동을 비활성화한다.
- 신청, 배정, 확정, 출퇴근을 포함한 변경 요청을 오프라인 queue에 쌓지 않는다.
- 연결이 복구되면 private 데이터는 서버 정본에서 다시 조회한다.
- 현재 화면 메모리에 이미 표시된 private 내용은 새로고침 전까지만 남을 수 있으며 오프라인 정본으로 취급하지 않는다.

## 권한과 개인정보

- 권한 없는 기능은 비활성으로 남기지 않고 내비게이션과 화면에서 제거한다.
- 직접 URL 접근 시 일반 오류가 아니라 안전한 상위 화면으로 돌아갈 경로를 제공한다.
- 다른 근무자의 개인정보는 목록·배정표에 섞지 않는다.
- 관리자 목록에서도 휴대폰, 생년월일, 성별, 시급은 상세 화면에서만 표시한다.
- UI의 숨김은 보안 경계가 아니다. 같은 권한을 서버 command와 데이터베이스 정책에서 다시 검사한다.
- 관리자 전용 위험 행동은 대상, 결과, 실행 주체를 확인하고 감사 가능한 형태로 설계한다.

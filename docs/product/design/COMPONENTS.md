# Components

[디자인 시스템](../DESIGN.md) · [Foundations](FOUNDATIONS.md) · [Patterns](PATTERNS.md)

컴포넌트는 업무 의미를 대신 결정하지 않는다. 권한, 유효성, 서버 상태는 사용하는 화면과 command가 제공하고 컴포넌트는 그 상태를 일관되게 표현한다.

## Button

| 종류 | 높이 | radius | 사용 |
| --- | ---: | ---: | --- |
| Primary | 56px | 16px | 화면의 대표 행동 하나 |
| Secondary | 48px | 14px | 보조 행동 |
| Tertiary | 최소 44px | 없음 | 낮은 우선순위 텍스트 행동 |
| Destructive | 48~56px | 14~16px | 삭제·거절 등 위험 행동 |
| Icon | 44×44px 이상 | 원형 | 눈 표시, 닫기, 전화 등 |

- Primary는 action 배경과 흰 텍스트를 사용한다.
- Secondary는 neutral 배경과 ink 텍스트를 사용한다.
- Destructive는 danger를 사용하되 주요 버튼과 경쟁하지 않게 위험 화면에서만 노출한다.
- disabled는 대비가 유지되는 중립색을 쓰고 이유를 인접 설명이나 접근 가능한 이름으로 알린다.
- loading은 라벨 의미를 유지하고 작은 진행 표시를 추가한다. 중복 제출을 막되 완료 결과는 서버 응답 후 표시한다.
- 한 화면의 같은 계층에 Primary를 여러 개 두지 않는다.

## Input과 선택 필드

- 기본 높이 52px 이상, radius 14px, neutral 배경을 사용한다.
- 라벨은 입력 위에 유지하고 도움말·오류는 아래에 둔다.
- 휴대폰, 날짜, 시간, 금액은 적절한 모바일 키보드와 입력 형식을 제공한다.
- 선택 필드는 바텀시트를 열며 현재 값과 펼침 상태를 전달한다.
- 검색 필드는 목록 상단에 두고 입력 즉시 로컬 결과를 좁힌다.
- 비활성 필드는 값과 비활성 이유를 함께 읽을 수 있어야 한다.

## Bottom sheet

- 상단 모서리는 20px, 배경은 white, 배경 dim은 콘텐츠가 식별될 정도로 유지한다.
- 제목, 필요한 설명, 선택 목록, 행동 순서로 구성한다.
- 선택 목록의 각 행은 최소 52px이며 선택 상태를 체크 아이콘과 action 색으로 함께 표시한다.
- 내용이 길면 시트 본문만 스크롤하고 제목과 주요 행동은 유지한다.
- 닫아도 위험하지 않은 경우 swipe와 바깥 영역 닫기를 허용한다. 입력 손실이 크면 먼저 결과를 설명한다.

## Dialog

- 비가역 행동, 미달 확정처럼 영향이 큰 예외에만 쓴다.
- 제목은 결과, 본문은 영향과 대상, 버튼은 구체적인 동사로 쓴다.
- 기본 포커스가 위험 행동에 놓이지 않게 한다.
- 구조·자격 오류는 확인 버튼으로 강행할 수 있는 dialog가 아니라 차단 오류로 표시한다.
- 완전 삭제 dialog는 일반 확인형과 분리해 대상 이름 입력이 일치해야 최종 버튼을 활성화한다.

## Snackbar

- 저장 완료처럼 짧은 피드백은 화면 하단 내비게이션과 safe-area 위에 표시한다.
- 한 줄 결과와 선택적 행동 하나를 제공한다.
- Undo가 있으면 사용자가 읽고 실행할 충분한 시간을 주고 스크린 리더에 알린다.
- 여러 메시지가 겹치면 최신 중요 결과를 우선하며 성공 메시지를 무한히 쌓지 않는다.

## Badge와 chip

- pill 형태를 허용하는 대표 요소다.
- badge는 상태를 읽기 전용으로 표시하고 chip은 필터나 선택을 수행한다.
- 짧은 명사 또는 상태를 사용한다: `신청`, `마감`, `확정`, `교육`, `승인 대기`.
- danger는 오류·위험에만 사용한다. `취소됨`, `비활성` 같은 업무 상태는 neutral을 기본으로 한다.
- 작은 색 점만 단독으로 사용하지 않는다. 알림의 읽지 않음 점은 목록 제목의 굵기 차이와 함께 사용한다.

## Calendar

### 구조

- 일요일 시작 7열 달력이다.
- 주말 숫자에 관습적인 빨강·파랑을 적용하지 않는다.
- 날짜 셀은 최소 44px 높이를 확보하고 날짜 숫자, 상태 라벨, 선택 상태를 담는다.
- 오늘은 얇은 action outline, 선택은 action 배경 또는 강한 tint와 체크로 구분한다.

### 상태

| 상태 | 표현 | 행동 |
| --- | --- | --- |
| 모집 없음 | disabled 표면·텍스트 | 선택·상세 불가 |
| 모집 중, 미신청 | 기본 + `신청 가능` 접근 이름 | 선택 가능 |
| 로컬 신청 선택 | action tint + 체크 | 다시 탭해 취소 |
| 신청 완료 | `신청` badge | 마감 전 취소 가능 |
| 모집 마감 | `마감` neutral badge | 상세 조회 |
| 확정 | `확정` action badge | 상세 조회 |

- 모집이 전혀 없는 날만 disabled 처리한다.
- 마감·확정 날짜는 흐리게 막지 않고 상세를 열 수 있어야 한다.
- 여러 날짜의 로컬 변경 수와 저장 전 상태를 하단 행동 영역에서 요약한다.

## Schedule row

- 날짜와 요일, 예정 출퇴근, 내 포지션, 상태 순으로 보여준다.
- 본인과 직접 관련된 변경이 있으면 action accent와 짧은 설명을 추가한다.
- 다른 근무자의 개인정보나 출결은 넣지 않는다.
- 목록 전체를 카드로 만들지 않고 행 사이 구분선을 사용한다.
- 탭 영역 전체가 상세로 이동하며 접근 가능한 이름에는 날짜와 상태를 포함한다.

## Assignment roster

- 전체 배정표는 포지션별 구획 또는 조밀한 행 목록으로 표현한다.
- 본인 행은 옅은 action 배경과 `나` 라벨로 강조한다.
- 다른 근무자는 이름과 포지션만 보여준다.
- 정식 담당자는 action, 교육생은 neutral `교육` badge를 사용한다.
- 복수 포지션은 이름을 중복해 오해시키기보다 한 사람 행 안에 모든 포지션을 표시할 수 있다.

## Staffing summary

기본 문구는 `필요 N · 배정 M · 교육 K`다.

- 부족하면 `정식 담당자 N명 부족`을 함께 표시한다.
- 교육생 수는 배정 수에 합산하지 않는다.
- 모바일은 요약 행을 먼저 보여주고 탭하면 담당자를 펼친다.
- 태블릿 이상은 담당자 목록을 기본으로 펼칠 수 있다.
- 충분함은 success, 부족은 warning을 사용하되 숫자와 문구를 반드시 병기한다.

## Worker picker

관리자 배정에서 다음 그룹 순서를 유지한다.

1. 신청했고 자격을 충족한 근무자
2. 신청하지 않았지만 자격을 충족한 근무자
3. 교육생으로만 추가 가능한 근무자
4. 선택할 수 없는 근무자

- 이미 다른 포지션에 배정된 사람은 현재 포지션을 표시한다.
- 선택할 수 없는 사람도 검색 결과에서 숨기지 않고 비활성 상태와 이유를 보여준다.
- 성별 불충족과 비활성 계정은 강행할 수 없다.
- 미신청 자격 충족자는 확인 후 정식 배정할 수 있다.
- 가능 포지션이 없지만 성별을 충족하면 교육생으로 추가할 수 있다.

## Notification row

- 제목, 짧은 내용, 상대 시각을 표시한다.
- 읽지 않음은 작은 action 점과 강한 제목을 함께 사용한다.
- 탭하면 관련 화면으로 이동하고 읽음 처리한다.
- 목록은 `오늘`, `이번 주`, `이전`으로 그룹화한다.
- 유형 필터, 삭제, 보관은 MVP에서 제공하지 않는다.

## Connectivity banner

- 화면 상단에서 `인터넷 연결이 끊겼어요`와 읽기 전용 상태를 알린다.
- 연결 복구 시 `최신 내용을 불러왔어요` 같은 짧은 인라인 또는 스낵바 피드백 후 사라진다.
- banner가 하단 행동과 겹치지 않으며 오프라인 동안 모든 변경 버튼은 이유와 함께 비활성화된다.

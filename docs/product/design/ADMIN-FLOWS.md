# Admin flows

[디자인 시스템](../DESIGN.md) · [Patterns](PATTERNS.md) · [Components](COMPONENTS.md)

관리자는 근무자 기능을 그대로 사용한다. 관리자 경험은 별도 앱이 아니라 권한이 확인된 사용자에게만 추가되는 운영 계층이다.

## 진입과 대시보드

- 홈 상단과 `전체`의 관리자 전용 구획에서 `관리자 대시보드`로 진입한다.
- 일반 근무자에게는 구획, 아이콘, 빈자리 모두 노출하지 않는다.
- 대시보드는 통계나 장식 차트보다 지금 처리할 일을 다음 순서로 보여준다.

1. 오늘 근무와 출결 요약
2. 가입·취소·교대 요청
3. 마감 예정·인원 미달·확정 대기 스케줄
4. 모집·배정·팀원 관리 빠른 작업
5. 최근 변경 요약

- 처리할 일이 없으면 정상 상태임을 짧게 알리고 다음 운영 작업으로 연결한다.
- 관리자 제목·버튼은 `가입 승인`, `배정 편집`처럼 짧게 쓰고 경고 설명은 친근하고 명확하게 쓴다.

## 팀원 관리

사용자-facing 명칭은 `팀원 관리`, 코드와 Domain에서는 `worker`를 유지한다.

### 목록

- 승인 대기를 상단에 먼저 보여준다.
- 전체 목록은 카드보다 조밀한 행을 사용한다.
- 각 행은 이름, 계정 상태, 대표 가능 포지션을 보여준다.
- 이름 검색과 상태 필터를 제공한다.
- 관리자 본인도 팀원 목록에 포함한다.
- 휴대폰, 생년월일, 성별, 시급은 목록에 표시하지 않는다.
- 휴면·자동 탈퇴 운영 필터에서는 마지막 인정 활동 시각, 휴면·자동 탈퇴 예정일과 전환을 막는 활성 신청·배정 여부를 확인할 수 있다.

### 상세

- 기본 정보, 연락처, 상태, 시급, 가능 포지션, 관련 관리 행동을 구획으로 나눈다.
- 전화번호 옆 `전화하기`는 기기 전화 앱으로 연결한다.
- 서비스는 통화 여부나 통화 기록을 수집하지 않는다.
- 승인, 휴면·재활성화, 시급·가능 포지션 변경은 결과와 영향을 명확히 보여주고 감사 기록 대상임을 전제로 한다.
- 관리자는 사유 입력 없이 휴면·재활성화를 처리한다. 활성 신청이나 진행 중·미래 배정이 있으면 휴면을 차단하고 해당 항목으로 이동할 수 있게 한다.

## 모집

- 월 달력에서 여러 근무일을 선택해 한 번에 모집을 연다.
- 이미 활성 모집이 있는 날짜와 지난 날짜는 달력에서 선택할 수 없다(2026-08-07 설계 결정 — 최종 거부는 DB가 담당).
- 신청 마감일을 공통으로 설정하고 batch 생성 전 선택 날짜 수를 요약한다.
- 모집 오픈 시점에 예식, 출퇴근, 필요 인원 상세 입력을 강요하지 않는다.
- 마감 연장과 재오픈은 현재 상태와 새 마감 시점을 확인하고 저장한다.
- 취소된 스케줄을 완전 삭제처럼 표현하지 않고 보존되는 상태로 표시한다.

## 예식과 시간

1. 예식 개수와 첫 예식 시작 시간을 입력한다.
2. 생성되는 예식 시간 목록과 추천 출퇴근 시간을 즉시 미리 본다.
3. 개별 예식 시작 시각과 추천 출퇴근을 필요한 경우 수정한다.
4. 구조 오류를 해결한 뒤 저장한다.

- 추천값과 직접 수정값을 시각적으로 구분하되 직접 수정이 예외나 오류처럼 보이지 않게 한다.
- 시간 변경이 확정 근무자에게 영향을 주면 변경 대상과 알림 발생을 저장 전에 알려준다.

## 배정

흐름은 `포지션 선택 → 근무자 선택`으로 통일한다.

### 근무자 선택

- 신청자를 먼저, 미신청 자격 충족자를 다음에 보여준다.
- 이미 다른 포지션에 배정된 근무자도 현재 포지션을 표시하고 선택할 수 있다.
- 자격 없는 근무자를 숨기지 않고 비활성 상태와 이유를 보여준다.
- 검색을 제공한다.

### 관리자 예외 규칙

| 조건 | 결과 |
| --- | --- |
| 신청하지 않았지만 자격 충족 | 확인 후 정식 배정 가능 |
| 가능 포지션 없음, 성별 충족 | 교육생으로 추가 가능 |
| 성별 불충족 | 배정 불가 |
| 비활성 계정 | 배정 불가 |
| 정식 인원 미달 | 경고 후 확정 가능 |

- 확인 대화상자로 성별·활성 상태 오류를 억지로 통과시킬 수 없다.
- 교육생은 담당자와 포지션에 연결하며 neutral `교육`으로 표시한다.
- 포지션마다 `필요 N · 배정 M · 교육 K`와 부족 인원을 함께 보여준다.
- 한 근무자가 여러 포지션을 겸하면 포지션별 숫자의 합이 실제로 오는 사람 수보다 많아진다. 두 값이 다를 때만 필요 인원 표 위에 `오는 사람 N명 · 포지션 합계 M`을 한 줄로 보여주고, 겸직이 없어 두 값이 같은 날은 줄을 띄우지 않는다. 겸할 수 있는 포지션 개수에는 상한이 없다.
- 탈퇴자의 진행 중·미래 확정 배정은 `변경 필요`로 표시하고 정식 배정 인원에서 제외한다. 대체 근무자를 지정하면 같은 배정의 근무자를 바꾸고 표시를 해제한다.
- 모바일은 요약을 우선하고 태블릿 이상은 담당자 목록을 기본으로 펼친다.

## 확정과 확정 후 변경

1. 예식, 예정 시간, 필요 인원, 배정의 구조 오류를 먼저 해결한다.
2. 성별·가능 포지션 자격 오류를 해결한다.
3. 정식 인원 미달이 없으면 `스케줄 확정`을 즉시 처리한다.
4. 미달이면 `인원이 부족한 채로 확정할까요?` 대화상자에서 부족 포지션을 보여주고 계속할 수 있다.
5. 성공 후 확정 revision과 알림 발송 결과를 간결하게 알린다.

- 확정 후 시간·예식·배정을 바꿀 때 영향받는 근무자와 변경 내용을 보여준다.
- 저장 후 이전·이후 값, 변경 관리자, 시각이 감사됨을 전제로 한다.
- 단순 확인 팝업을 매번 띄우지 않고 실제 예외와 위험에만 사용한다.

## 변경 요청

- 대시보드에서 취소·특정 교대·공개 교대 요청을 한 목록으로 처리한다.
- 상세에서 기존 배정, 요청 유형, 선택 사유, 교대 후보 자격을 확인한다.
- 특정 교대 상대가 응답하지 않았어도 관리자는 승인할 수 있음을 상태 문구로 명확히 한다.
- 승인 command는 현재 자격을 다시 검사하며 실패하면 해결 이유를 보여준다.
- 전체 공개 교대는 자격 있는 참여자를 보여주고 관리자가 최종 교대자를 선택한다.
- 당일 포지션 교환은 관리자 편집에서 두 근무자의 포지션을 직접 바꾸고 감사·알림을 남긴다.

## 출결

- 대시보드에서 오늘 미인증, 지각, 퇴근 누락을 우선순위로 보여준다.
- 당일 팀장은 해당 날짜의 현장 확인과 결근 처리만 할 수 있고 본인 출결 판정은 관리자에게 남긴다.
- 관리자는 필요한 날짜의 출결과 확인 사건을 조회한다.
- 결근 처리는 배정을 삭제하거나 출퇴근 원본을 수정하는 행동처럼 표현하지 않는다.
- 출퇴근 원본에는 수정·삭제 행동을 제공하지 않는다.

## 예상 급여 조회

- 팀원과 월을 선택해 날짜별·월별 예상 금액을 조회한다.
- `예정된 근무 시간으로 계산한 참고 금액이며 실제 지급 금액과 다를 수 있어요`를 유지한다.
- 일반 근무와 리허설 금액을 분리하고 합계를 함께 보여준다.
- 지급 완료나 정산 상태를 입력하는 기능은 제공하지 않는다.

## 설정

- 장소 좌표·GPS 반경, 기본 시급, 포지션 기본 인원·성별 조건, 출근 추천 규칙을 업무별 화면으로 나눈다.
- 저장 전 변경 전후와 영향 범위를 보여준다.
- QR 비밀, 서버 키 등 운영 비밀은 UI에 노출하지 않는다.
- 슈퍼 관리자만 관리자 임명·해제를 볼 수 있다.

## 계정 완전 삭제

완전 삭제는 근무자가 앱 밖에서 관리자에게 직접 요청했을 때만 관리자가 실행한다. 앱 안에 근무자용 요청 접수나 처리 상태를 만들지 않는다.

1. 팀원 상세의 위험 구획에서 `계정 완전 삭제`를 선택한다.
2. 즉시 파기되는 복구 정보, 익명화되는 과거 기록, 복구 불가 결과를 설명한다.
3. 대상 근무자의 이름을 직접 입력한다.
4. 입력값이 정확히 일치해야 destructive 최종 버튼이 활성화된다.
5. 서버가 관리자 권한과 대상을 다시 확인하고 완전 삭제를 실행한다.
6. 실행 관리자, 대상, 시각을 수정 불가능한 감사 기록에 남긴다.

- 일반 근무자와 권한 없는 관리자는 화면과 command 모두 접근할 수 없다.
- 이름이 일치하지 않으면 실행할 수 없다.
- 이 작업에는 Undo나 취소 완료 문구를 제공하지 않는다.
- 성공 후 복구할 수 있다고 암시하지 않고 완료 사실과 감사 식별 정보를 관리자에게 보여준다.

## 반응형

- 모바일은 대시보드 요약과 단계별 전체 화면 편집을 사용한다.
- 태블릿 이상에서는 팀원 목록, 배정 요약과 상세를 나란히 확장할 수 있다.
- 넓은 화면에서도 정보 밀도를 위한 행 구조를 유지하고 마케팅형 대형 카드 그리드를 만들지 않는다.
- 깊은 편집 화면은 기기 크기와 무관하게 상단 뒤로가기와 명확한 저장 행동을 유지한다.

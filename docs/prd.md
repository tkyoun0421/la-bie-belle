# PRD — 라비에벨 근무자 앱

2026-08-25 인터뷰로 정했다.

## 무엇을 만드나

라비에벨 웨딩홀 근무자를 위한 PWA다. 관리자가 월 근무표를 짜서 확정하면 근무자 폰에 뜨고, 근무자는 현장에서 출근을 찍고, 그 기록에서 앱이 급여를 계산한다.

## 대상 사용자

**관리자.** 여러 명이고 본인도 근무표에 들어간다. 지금 카톡과 메모장으로 한 달치 근무표를 짜고, 바뀔 때마다 다시 공지하고, 급여를 따로 계산해 전달한다.

**근무자.** 30명 안팎이다. 내 근무가 언제인지 알려고 카톡을 거슬러 올라가고, 이번 달에 얼마 받는지는 정산 때까지 모른다.

## 지금의 문제

근무표가 카톡에 있어 흩어진다. 확정본과 변경본이 섞이고, 누가 무엇을 봤는지 남지 않는다. 교대는 개인 대화로 정해져 관리자가 마지막에야 안다. 급여는 관리자가 손으로 계산하고 근무자는 검산할 근거가 없다.

## 핵심 기능

### 근무표

홀은 하나다. 관리자가 월 단위로 짜고 확정한다.

하루의 자리는 아홉 포지션 열한 명이 기본이다.

| 포지션 | 인원 |
| --- | --- |
| 팀장 | 1 |
| 스캔 | 1 |
| 메인 | 1 |
| 드레스 | 1 |
| 축가 | 1 |
| 매니저 | 2 |
| 안내 | 2 |
| 드레스실 | 1 |
| 대기실 | 1 |

이 구성은 기본값이고 날마다 손본다. 한가한 날은 매니저를 하나로 줄이고 바쁜 날은 안내를 셋으로 늘린다.

교육생은 포지션에 덧붙는다. 안내 두 자리가 정규로 차 있어도 그 옆에 교육으로 한 명이 더 붙는다. 정규 자리를 먹지 않고, 무엇을 배우는 중인지가 기록에 남는다.

근무 시간은 날짜마다 하나다. 그날 나온 사람은 포지션과 상관없이 같은 시각에 출근하고 같은 시각에 퇴근한다. 관리자는 날짜별로 시간을 한 번만 정한다.

확정 전에는 관리자가 마음대로 고친다. 확정을 누르면 근무자에게 알림이 나가고 그때부터 근무표는 공개된 약속이 된다.

### 교대

확정 뒤에 바뀌는 길은 둘이다.

근무자가 다른 근무자에게 교대를 요청하고, 받는 쪽이 수락하면 관리자가 승인한다. 셋이 다 거쳐야 근무표가 바뀐다. 누가 언제 무엇에 동의했는지가 남는다.

관리자는 이 절차 없이 강제로 바꾼다. 급한 날을 위한 길이다.

### 출근 인증

근무자가 현장에서 출근을 찍는다. 홀 근처에서 눌리는 방식과 현장 QR을 찍는 방식 둘 다 쓴다. 실내에서 위치가 안 잡히면 QR로 간다.

출근 인증은 급여를 직접 만들지 않는다. 관리자가 지각이나 결근을 조정할 때 근거로 본다.

### 급여

앱이 계산한다. 시급은 사람마다 다르고 관리자가 정한다.

계산의 근거는 확정된 배정이다. 지각·결근·연장처럼 배정과 어긋난 날은 관리자가 그 건만 조정하고, 조정 이력이 남는다.

가산은 둘이다.

- **연장** — 하루 9시간을 넘긴 시간에 1.5배
- **공휴일** — 요일과 상관없이 그날 전 시간에 1.5배

가산은 하루에 하나만 붙는다. 둘 다 걸리면 큰 쪽을 쓴다. 시급 12,000원인 사람이 공휴일에 10시간 일하면 전 시간에 공휴일 가산이 붙어 180,000원이고, 연장은 따로 더하지 않는다. 같은 사람이 평일에 10시간 일하면 9시간은 기본, 1시간은 연장으로 126,000원이다.

공휴일은 공공 API에서 받아 우리 쪽에 저장한다. 외부가 멈춰도 이미 받아둔 해의 급여는 흔들리지 않아야 한다.

지급은 주 1회다. 근무자는 주·월·연 단위로 자기 급여를 본다.

### 휴무 희망

근무자가 다음 달 근무표가 나오기 전에 쉬고 싶은 날을 넣는다. 관리자는 카톡을 뒤지는 대신 목록으로 본다.

희망은 희망이다. 관리자가 반영할 의무는 없다.

### 알림

푸시로 나가는 것 넷이다.

- 근무표가 확정되거나 변경됐을 때
- 근무 전날 저녁
- 출근 직전
- 관리자 공지

관리자 공지는 근무표와 무관한 전달이다. 대시보드 맨 위의 안 본 알림이 이걸 담는다.

### 계정

구글 OAuth로 가입한다. 가입만으로는 아무것도 안 보인다. 관리자가 승인해야 근무표가 열린다.

근무표와 급여가 외부로 새지 않게 막는 유일한 문이다.

### 관리자 통계

월별 인건비 합계, 포지션별 근무 시간, 사람별 출근 횟수를 본다. 급여 계산이 이미 있으니 집계를 얹는다.

## 화면

앱을 열면 스플래시가 뜨고 데이터가 준비되면 대시보드로 넘어간다.

대시보드는 위에서부터 안 본 알림, 출근 인증, 이번 주 근무, 내 급여 순이다. 근무자가 앱을 여는 이유가 대부분 이 넷 안에 있다.

관리자는 같은 앱에서 관리자 화면으로 넘어간다. 본인도 근무자라서 두 모드를 오간다.

## 비범위

1차에서 하지 않는다.

**예식 정보 관리.** 신랑신부 이름, 홀 예약, 식순은 다루지 않는다. 앱은 누가 언제 나오는지까지만 본다.

**앱 안 채팅.** 교대 요청과 알림은 있지만 자유 대화는 없다. 그건 카톡에 남긴다.

## 아직 안 정한 것

- 디자인 방향 — 레퍼런스를 보고 사람이 정한다
- 영속과 인증의 기술 선택 — ADR로 따로 정한다
- 관리자 권한을 더 쪼갤지 — 지금은 관리자 전원이 같은 권한이다
- 퇴사자와 지난 근무표를 어떻게 남길지

# 라비에벨 제품 디자인 시스템

- 상태: MVP 구현 기준
- 기준일: 2026-07-23
- 제품명: 설치명·브라우저 제목 `라비에벨 근무`, 화면 내 이름 `라비에벨`
- 관련 문서: [PRD](PRD.md), [Domain](DOMAIN.md), [Architecture](ARCHITECTURE.md)

## 책임

이 문서는 라비에벨 모바일 PWA의 시각 언어와 상호작용 원칙을 정하는 공식 진입점이다. 제품 동작은 PRD, 공통 언어와 업무 경계는 Domain, 기술 경계는 Architecture와 ADR이 우선한다. 디자인 문서는 그 규칙을 사용자가 이해하고 안전하게 실행할 수 있는 화면으로 번역한다.

실제 CSS·Tailwind 토큰은 구현 시 이 문서에서 파생한다. 별도 토큰 JSON을 두어 기준을 중복하지 않는다.

## 제품 인상

라비에벨은 젊은 아르바이트생이 근무 신청과 확인을 쉽고 가볍게 느끼는 서비스다. 정보는 또렷하고 반응은 부드러우며, 사용자가 다음 행동을 고민하지 않게 한다.

- 정보와 행동의 우선순위를 여백과 타이포그래피로 표현한다.
- 선택과 완료에는 짧고 부드러운 반응을 제공한다.
- 카드, 색상, 팝업을 남용하지 않는다.
- 게임화, 캐릭터, 과장된 축하 효과를 사용하지 않는다.
- 웨딩홀을 연상시키는 꽃·리본·반지·장식 사진을 디자인 문법으로 삼지 않는다.
- 관리 기능은 권한이 있는 사용자에게만 보이며, 권한 검사는 서버와 데이터베이스에서도 강제한다.

## 핵심 원칙

1. **지금 할 일부터**: 홈과 관리자 대시보드는 통계보다 현재 필요한 행동을 먼저 보여준다.
2. **한 번에 편하게**: 여러 날짜 신청처럼 반복 행동은 로컬에서 모아 한 번에 저장한다.
3. **되돌릴 수 있게**: 가역 작업은 즉시 실행하고 마지막 변경 묶음 전체 Undo를 제공한다.
4. **위험은 분명하게**: 비가역 작업만 확인 대화상자를 사용하고 결과를 직접 설명한다.
5. **정보는 필요한 만큼만**: 다른 근무자의 개인정보와 관리자 기능의 흔적을 노출하지 않는다.
6. **움직임은 의미 있게**: 모션은 상태 변화와 진행을 설명하되 작업 완료를 늦추지 않는다.
7. **접근성은 기본값**: WCAG 2.2 AA, 키보드, 스크린 리더, 글자 확대, reduced motion을 기본 조건으로 둔다.

## 화면 범위와 반응형

- 근무자 경험은 모바일 우선으로 설계한다.
- 관리자 목록과 배정 화면만 태블릿 이상에서 넓게 확장한다.
- 별도 데스크톱 전용 제품은 만들지 않는다.
- MVP는 라이트 모드만 제공한다.
- 앱 아이콘은 `#0052ff` 배경과 흰색 `L` 모노그램 방향을 따른다. 실제 자산, safe-area 검증, 단색 알림 아이콘은 구현 전 별도 제작한다.

## 제품 규칙 추적

| 제품 규칙 | 디자인 적용 |
| --- | --- |
| `PRD:INV-ATT-01` | 출퇴근 원본 수정·삭제 UI를 만들지 않고 현장 확인을 별도 사실로 표현한다. |
| `PRD:INV-STAFF-01` | 인원 미달은 경고 대화상자로 알리되 관리자 확정을 허용한다. |
| `PRD:INV-STAFF-02` | 교육생을 별도 표시하고 필요 인원 충족 수에서 제외한다. |
| `PRD:INV-STAFF-03` | 복수 포지션을 모두 배정표와 충족도에 반영한다. |
| `PRD:INV-PAY-01` | `예상`을 지속적으로 표시하고 실제 지급액과 다를 수 있음을 안내한다. |
| `PRD:INV-REH-01` | 리허설을 자기기록이며 공식 출퇴근이 아닌 참고 기록으로 안내한다. |
| `PRD:AC-12` | 관리자 전용 메뉴를 숨기고 모든 권한 오류에 안전한 대체 경로를 제공한다. |

## 변경 규칙

- 원시 브랜드 색상을 바꾸거나 새 글꼴·아이콘 세트를 도입할 때는 이 문서를 먼저 수정한다.
- 새로운 공통 패턴은 특정 화면에서 두 번 이상 재사용되거나 안전성 규칙을 공유할 때만 추가한다.
- 제품 동작이 바뀌는 디자인 변경은 PRD → Domain → ADR → Architecture → Phase 순서로 먼저 정합화한다.
- 문서와 구현이 다르면 구현을 기준으로 문서를 소급 변경하지 않고 의도와 제품 규칙을 다시 확인한다.

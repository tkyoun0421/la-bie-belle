# 라비에벨 근무 관리 PRD

- 상태: 딥인터뷰 재검토 기준안
- 기준일: 2026-07-24
- 대상: 단일 근무 장소, 단일 예식홀
- 클라이언트: 모바일 PWA

이 문서는 기존 설계를 보존한 인터뷰 출발점이다. 관련 task가 사용자 승인과 함께 `planned`로 인계되기 전에는 신규 구현을 자동 시작하지 않는다.

## 제품 불변 규칙

아래 ID는 task와 테스트가 추적하는 안정적인 제품 spec ID입니다.

- **INV-ATT-01**: 출퇴근 원본 시각은 서버에서 생성하며 누구도 수정하거나 삭제할 수 없다.
- **INV-STAFF-01**: 필요 인원 미달은 경고하지만 스케줄 확정을 막지 않는다.
- **INV-STAFF-02**: 교육생은 포지션 필요 인원에 포함하지 않는다.
- **INV-STAFF-03**: 한 근무자의 복수 포지션은 각 포지션 필요 인원을 모두 충족한다.
- **INV-PAY-01**: 예상 급여는 예정 출퇴근 시간을 기준으로 하며 실제 급여 정산 기능이 아니다.
- **INV-REH-01**: 리허설은 근무자 자기기록이며 공식 출퇴근 인증으로 취급하지 않는다.

## 1. 제품 목표

라비에벨 웨딩홀의 월별 근무 모집, 신청, 포지션 배정, 변경 요청, 출퇴근 확인, 예상 급여 확인을 하나의 모바일 서비스에서 처리한다.

### 성공 기준

다음 달 스케줄 모집부터 기존 단체 채팅과 수기 배정표를 완전히 대체한다.

### 초기 운영 규모

- 관리자 약 3명
- 월 근무 스케줄 약 8개
- 하나의 근무 장소와 하나의 홀

## 2. 사용자와 권한

### 근무자

- Google OAuth로 가입한다.
- 이름, 휴대폰 번호, 성별, 생년월일을 입력한다.
- 관리자 승인 후 서비스를 사용한다.
- 가능한 근무일을 신청한다.
- 확정된 전체 배정표와 본인 예상 급여를 확인한다.
- 확정 후 취소 또는 교대를 요청한다.
- 본인 출퇴근을 인증한다.
- 본인 리허설 근무를 기록한다.

### 관리자

- 근무자 기능을 함께 사용할 수 있다.
- 가입을 승인하거나 거절한다.
- 근무자 개인정보, 시급, 가능 포지션을 관리한다.
- 모집, 예식 정보, 필요 인원, 배정, 확정을 관리한다.
- 신청하지 않은 근무자도 직접 배정할 수 있다.
- 취소·교대 요청과 당일 출결을 관리한다.
- 전체 근무자의 예상 급여를 조회한다.
- 앱 밖에서 직접 접수한 요청에 한해 근무자 계정을 완전 삭제한다.

### 슈퍼 관리자

- 관리자 권한을 모두 가진다.
- 일반 관리자를 임명하거나 해제한다.
- 최초 계정은 배포 환경변수에 등록된 Google 이메일로 부여한다.

### 당일 팀장

- 시스템 관리자가 아니라 해당 날짜에 `팀장` 포지션으로 배정된 근무자다.
- 다른 근무자의 출근, 지각, 미출근, 결근 상태를 확인한다.
- 미출근자를 결근 처리할 수 있다.
- 자신의 출결 판정은 변경할 수 없으며 관리자가 확인한다.

## 3. 계정 생명주기

계정 상태는 `승인 대기`, `활성`, `승인 거절`, `휴면`, `탈퇴`를 사용한다.

- 누구나 Google OAuth로 가입할 수 있다.
- 승인 대기 사용자는 프로필 작성과 승인 상태 확인만 할 수 있다.
- 활성 사용자만 신청과 배정이 가능하다.
- 관리자도 근무자로 신청·배정될 수 있다.
- 가능 포지션과 개인 시급은 관리자만 수정한다.

### 휴면과 자동 계정 정리

- **ACCT-DORMANT-01**: 활성 계정은 마지막 인정 활동 시각부터 한국 시간 달력 기준 3개월이 지나면 휴면 대상이 된다.
- 인정 활동은 서버에 정상 저장된 출근 신청과 본인·관리자의 재활성화다. 정상 신청은 나중에 취소되어도 인정하지만 실패·중복 요청은 인정하지 않는다.
- 출근 신청 이력이 없으면 최초 활성 승인 시각을 기준으로 한다.
- 대상 월에 같은 날짜가 없으면 그달의 마지막 날을 기한으로 사용한다.
- 활성 신청 또는 진행 중·미래 활성 배정이 있으면 자동·관리자 수동 휴면을 모두 차단한다. 완료·취소된 과거 배정은 차단 사유가 아니다.
- 휴면 사용자는 로그인해 상태와 자동 탈퇴 예정일을 확인하고 본인이 즉시 재활성화할 수 있다. 관리자도 휴면과 재활성화를 처리할 수 있다.
- 본인 또는 관리자가 재활성화하면 그 시각을 새 인정 활동 시각으로 사용해 3개월 휴면 기한과 1년 자동 탈퇴 기한을 모두 다시 계산한다.
- 관리자의 수동 휴면은 인정 활동 시각과 자동 탈퇴 예정일을 바꾸지 않는다.
- 상태 변경 사유는 받지 않으며 변경 전후 상태, 행위자, 시각만 감사 기록에 남긴다.
- 관리자는 현재 상태, 마지막 인정 활동 시각, 휴면·자동 탈퇴 예정일, 전환을 막는 활성 신청·배정 여부를 확인할 수 있다.

### 장기 비활동과 미승인 계정 삭제

- **ACCT-CLEANUP-01**: 활성 또는 휴면 계정은 마지막 인정 활동 시각부터 한국 시간 달력 기준 1년이 지나면 자동 탈퇴 대상이 된다.
- 활성 신청 또는 진행 중·미래 활성 배정이 있으면 자동 탈퇴를 보류하고 차단 사유가 사라진 뒤 다시 평가한다.
- 자동 탈퇴 전 앱 내 알림이나 푸시는 보내지 않는다. 휴면 상태 화면에는 자동 탈퇴 예정일을 표시한다.
- 자동 탈퇴의 개인정보 삭제, 3년 분리 보관과 과거 이력 보존은 일반 탈퇴와 동일하다.
- 한 번도 활성 승인되지 않은 승인 대기 계정은 가입 시각, 승인 거절 계정은 거절 시각부터 3개월 후 휴면·복구 vault 없이 완전히 삭제한다. 로그인과 상태 확인은 기한을 연장하지 않으며 승인 감사 기록만 익명화해 남긴다.
- 자동 상태 처리는 한국 시간 기준 매일 새벽 멱등하게 실행한다. 정책 최초 적용 시 기존 계정의 기준 시각은 기존 기준 시각과 정책 적용일 중 더 늦은 값으로 정해 최소 3개월의 유예를 보장한다.
- 상태 전환, 신청, 승인과 삭제가 동시에 발생하면 계정을 잠근 트랜잭션에서 먼저 완료된 작업만 유효하게 한다.
- 탈퇴 후 Google 연결 해제나 푸시 구독 삭제가 실패해도 계정을 다시 활성화하지 않는다. 실패한 외부 정리를 멱등 재시도하고 장기 실패는 관리자에게 운영 오류로 표시한다.

### 탈퇴와 복구

- 탈퇴에 관리자 승인은 필요하지 않다.
- 즉시 삭제: Google 연결, 이메일, 휴대폰 번호, 푸시 구독 정보.
- 3년간 분리 보관: 이름, 생년월일, 성별, 개인 시급, 내부 근무자 ID.
- 과거 스케줄, 배정, 출퇴근 기록은 유지한다.
- 재가입 시 이름·생년월일·성별로 복구 후보를 찾고 관리자가 기존 이력과 새 계정을 연결한다.
- 3년 후 복구용 개인정보를 파기하고 과거 기록을 완전히 익명화한다.
- 근무자는 앱에서 일반 탈퇴만 직접 실행할 수 있다.
- 복구할 수 없는 완전 삭제는 앱 안에서 접수하지 않으며, 근무자가 관리자에게 직접 요청한다.
- 관리자만 관리 화면에서 완전 삭제를 실행할 수 있다.
- 완전 삭제 전 복구 불가 결과를 안내하고 대상 근무자의 이름을 다시 입력해 확인한다.
- 완전 삭제 시 복구 정보를 즉시 파기하고 과거 기록을 익명화하며, 실행 관리자·대상·시각을 감사 기록에 남긴다.

### 탈퇴의 신청·배정 연쇄 처리

- **ACCT-DEPART-01**: 자진 탈퇴는 활성 신청·배정 또는 진행 중 근무가 있어도 즉시 완료된다.
- 활성 신청은 `계정 탈퇴` 사유로 자동 취소하고 이력을 보존한다.
- 탈퇴자가 당사자인 대기 중 취소·교대 요청은 `계정 탈퇴로 무효화`하고 관리자와 교대 상대에게 알린다.
- 확정 스케줄 자체는 유지한다. 탈퇴자의 진행 중·미래 배정에는 `변경 필요`를 표시하고 필요 인원 계산에서 즉시 제외한다.
- 관리자가 대체 근무자를 지정하면 같은 배정의 근무자를 교체하고 `변경 필요`를 해제한다. 별도 `탈퇴로 대체됨` 상태를 만들지 않고 이전·이후 근무자, 처리 관리자와 시각을 감사 기록에 남긴다.
- 진행 중 근무에서 이미 생성된 출퇴근 원본은 그대로 보존한다. 탈퇴 후 체크아웃 예외 처리는 출퇴근 정책에서 별도로 정한다.

## 4. 포지션

| 포지션 | 기본 필요 인원 | 기본 성별 조건 |
| --- | ---: | --- |
| 팀장 | 1 | 제한 없음 |
| 스캔 | 1 | 제한 없음 |
| 메인 | 1 | 제한 없음 |
| 드레스 | 1 | 여성 |
| 축가 | 1 | 제한 없음 |
| 매니저 | 2 | 제한 없음 |
| 안내 | 2 | 남성 |
| 드레스실 | 1 | 여성 |
| 신부 대기실 | 1 | 여성 |

- 관리자는 포지션별 기본 필요 인원과 성별 조건을 수정할 수 있다.
- 개인별 가능 포지션과 성별 조건을 모두 통과해야 정식 담당자로 배정할 수 있다.
- 안내, 매니저, 축가는 기본 포지션이며 승인된 근무자에게 자동으로 가능 상태가 적용된다. 성별 조건은 그대로 적용한다.
- `매니저` 포지션과 시스템 `관리자` 권한은 별개다.

### 복수 포지션

- 한 근무자는 하루 동안 여러 포지션을 동시에 맡을 수 있다.
- 시간대별 포지션 변경은 지원하지 않는다.
- 한 사람이 맡은 각 포지션은 해당 포지션의 필요 인원 1명을 모두 충족한다.

### 교육생

- 교육 중 여부를 근무자 프로필 상태로 미리 만들지 않는다.
- 관리자는 정식 가능 포지션이 아닌 근무자도 특정 배정의 교육생으로 추가할 수 있다.
- 교육생은 개인별 가능 포지션이 없어도 되지만 해당 포지션의 성별 조건은 통과해야 한다.
- 교육생은 담당자와 포지션에 연결한다.
- 한 담당자당 기본 교육생은 1명이지만 여러 명을 허용한다.
- 교육생은 필요 인원에 포함하지 않는다.
- 교육생의 예상 급여는 개인 시급으로 계산한다.

## 5. 일반 근무 스케줄

### 상태

`모집 중 → 모집 마감 → 확정 준비 → 확정`

- 관리자는 마감일을 연장하거나 모집을 재오픈할 수 있다.
- 관리자는 확정 후에도 스케줄과 배정을 변경할 수 있다.
- 취소된 스케줄은 별도 상태로 보존하며 삭제하지 않는다.

### 모집 생성

- 관리자는 여러 근무일을 선택해 한 번에 모집을 연다.
- 모집 생성 시 필요한 값은 근무일과 신청 마감일이다.
- 예식, 출퇴근, 필요 인원 상세는 모집 오픈 시점에 필요하지 않다.
- 마감은 지정 날짜의 23:59:59 Asia/Seoul에 자동 처리한다.

### 신청

- 근무자는 달력에서 여러 날짜를 선택해 한 번에 신청한다.
- 신청 마감 전에는 자유롭게 신청하거나 취소한다.
- 신청 마감 후에는 직접 변경할 수 없고 관리자에게 요청한다.
- 신청은 근무 가능 여부만 표현하며 희망 포지션을 받지 않는다.

## 6. 예식과 근무 시간

스케줄 확정 전에 관리자가 예식 정보를 생성한다.

1. 예식 개수와 첫 예식 시작 시간을 입력한다.
2. 1시간 간격으로 예식 아이템을 자동 생성한다.
3. 마지막 예식 시작 시간은 생성된 아이템에서 계산한다.
4. 각 예식 시작 시간은 `12:10`처럼 개별 수정할 수 있다.
5. 첫·마지막 예식 변경 시 예정 출퇴근 시간을 다시 추천한다.

### 시간 추천

- 출근 시간은 관리자가 관리하는 규칙표를 사용한다.
- 초기 규칙: 첫 예식 10:00이면 출근 08:20.
- 초기 규칙: 첫 예식 11:00이면 출근 09:10.
- 퇴근 기본값은 마지막 예식 시작 2시간 후다.
- 추천된 출근·퇴근 시간은 관리자가 직접 수정할 수 있다.

## 7. 필요 인원과 배정

- 포지션 기본값을 스케줄에 복사하고 날짜별로 수정한다.
- 신청자를 우선 표시하되 신청하지 않은 근무자도 관리자가 배정할 수 있다.
- 성별 또는 가능 포지션 조건을 통과하지 못하면 정식 담당자로 선택할 수 없다.
- 이미 다른 포지션에 배정된 근무자도 복수 포지션으로 추가할 수 있다.
- `필요 N / 배정 M / 교육 K`를 포지션별로 표시한다.
- 필요 인원 미달은 명확히 경고하고 나중에 조회할 수 있게 한다.
- 미달 상태에서도 관리자가 확정할 수 있다.
- 확정 후 모든 배정 근무자는 전체 근무자의 이름과 포지션을 볼 수 있다.
- 일반 근무자는 다른 사람의 개인정보, 시급, 출퇴근 상태를 볼 수 없다.

## 8. 확정 후 변경

### 관리자 변경

- 관리자는 출퇴근 시간, 예식, 필요 인원, 배정을 변경할 수 있다.
- 영향받는 근무자에게 앱 내 알림과 푸시를 보낸다.
- 변경자, 변경 시각, 변경 전후 값을 감사 기록에 남긴다.

### 근무 취소 요청

- 근무자는 확정 후 취소를 요청할 수 있다.
- 사유 입력은 선택이다.
- 관리자가 승인하기 전까지 기존 배정과 책임이 유지된다.

### 특정 근무자 교대

- 기존 근무자가 교대 상대를 지정해 관리자에게 요청한다.
- 상대 근무자에게 알림을 보내고 읽음 여부를 기록한다.
- 상대가 응답하지 않아도 관리자가 승인할 수 있다.
- 상대는 기존 근무자의 모든 정식 포지션을 수행할 수 있어야 한다.
- 승인 전까지 기존 배정이 유지된다.

### 전체 공개 교대

- 관리자가 교대 요청을 전체 근무자에게 공개할 수 있다.
- 조건을 만족하는 근무자가 참여 의사를 표시한다.
- 관리자가 최종 교대자를 선택하고 승인한다.

### 당일 근무자 간 포지션 교환

- 근무자가 관리자에게 별도로 문의한다.
- 관리자가 이미 배정된 두 근무자의 포지션을 직접 교환한다.
- 일반 근무자용 포지션 변경 요청 기능은 만들지 않는다.

## 9. 알림

앱 내 알림함과 PWA 웹 푸시를 사용한다. 문자와 카카오톡은 제외한다.

알림 대상 사건:

- 새 모집 오픈
- 스케줄 확정
- 확정 스케줄의 시간 또는 배정 변경
- 취소·교대 요청, 공개, 승인, 거절
- 탈퇴로 인한 취소·교대 요청 무효화와 배정 변경 필요
- 교대 상대 알림의 읽음 상태
- 예정 출근 시각까지 미인증
- 예정 퇴근 시각까지 미인증

출근 전과 자동 탈퇴 전 사전 알림은 보내지 않는다. 출퇴근 누락 알림은 해당 날짜에 배정된 관련 근무자와 당일 팀장에게만 보낸다.

## 10. 출퇴근과 출결

### 인증 가능 시간

- 출근: 예정 출근 2시간 전부터.
- 퇴근: 예정 퇴근 1시간 전부터.
- 뒤늦은 과거 날짜 직접 등록은 허용하지 않는다.

### GPS 우선 인증

- 단일 장소의 GPS 좌표와 반경을 관리자가 설정한다.
- 기본 반경은 100m다.
- 위치 정확도 오차가 100m 이하이고 반경 안이면 성공한다.
- 실패 사유에는 권한 거부, 낮은 정확도, 반경 밖이 포함된다.

### QR 대체 인증

- GPS가 실패하면 현장 QR로 인증할 수 있다.
- QR은 매주 수요일 Asia/Seoul 기준으로 갱신한다.
- 만료된 QR은 사용할 수 없다.

### 불변 출퇴근 기록

- 출퇴근 원본 시각은 클라이언트가 아니라 서버가 생성한다.
- 원본에는 인증 방식, 위치·정확도 또는 QR 식별 정보를 함께 저장한다.
- 생성된 원본은 누구도 수정하거나 삭제할 수 없다.
- 팀장의 현장 확인은 원본 수정이 아니라 별도 확인 이벤트로 추가한다.

### 지각과 결근

- 예정 출근 시각을 1분이라도 넘긴 인증은 지각이다.
- 예정 출근까지 미인증이면 근무자와 당일 팀장에게 알린다.
- 이후 인증하면 지각 출근으로 기록한다.
- 팀장은 미출근자를 결근 처리할 수 있다.
- 결근은 배정을 삭제하지 않고 처리자와 시각을 보존한다.
- 당일 팀장의 본인 출결은 관리자만 확인한다.
- 예정 퇴근까지 미인증이면 근무자와 팀장에게 알린다.

## 11. 예상 급여

예상 급여는 실제 급여 정산이나 지급 기록이 아니다.

- 개인별 시급은 관리자가 입력하고 근무자는 본인 시급만 본다.
- 신규 근무자는 시스템 기본 시급을 적용하고 관리자가 변경할 수 있다.
- 예정 출퇴근 시간을 기준으로 계산한다.
- 출근부터 퇴근까지 전부 유급이다.
- 최초 9시간은 개인 시급을 적용한다.
- 9시간 초과분은 개인 시급의 1.5배를 적용한다.
- 분 단위로 비례 계산한다. 30분은 0.5시간이다.
- 결근 처리된 근무의 표시 금액은 0원이다.
- 근무자는 날짜별 금액과 월별 합계를 본다.
- 관리자는 전체 근무자의 날짜별 금액과 월별 합계를 본다.
- 확정 시점의 시급을 배정에 스냅샷하여 이후 개인 시급 변경이 과거 예상치를 바꾸지 않게 한다.

## 12. 리허설

리허설은 일반 스케줄이 아니라 근무자 자기기록형 급여 참고 데이터다.

- 근무자가 날짜, 시작 시각, 종료 시각을 직접 생성한다.
- 본인이 수정하거나 삭제할 수 있다.
- 모집, 신청, 확정, 포지션, 필요 인원, GPS·QR 인증이 없다.
- 본인과 관리자만 조회한다.
- 개인 시급과 일반 근무의 9시간 초과 규칙으로 예상 금액을 계산한다.
- 생성 시점의 시급을 스냅샷한다.
- 공식 출퇴근 또는 실제 급여 정산 자료로 표현하지 않는다.

## 13. 개인정보와 공개 범위

- 관리자는 승인된 업무 목적 범위에서 개인정보를 조회한다.
- 일반 근무자는 확정 배정표에서 다른 근무자의 이름과 포지션만 본다.
- 교대 후보 화면에서는 이름과 교대 가능 여부만 본다.
- 휴대폰 번호, 생년월일, 성별, 가능 포지션 전체, 시급, 출퇴근 상태는 일반 근무자에게 공개하지 않는다.
- 위치정보 원본은 출퇴근 검증과 감사 목적으로만 사용한다.

## 14. MVP 제외 범위

- 자동 배정과 추천
- 사고 이력
- 실제 급여 정산, 지급 완료, 급여명세서
- 문자·카카오톡 알림
- 다중 장소·다중 홀
- 시간대별 포지션 변경
- 데스크톱 전용 UI
- 현재 디자인 시스템을 벗어나는 브랜드 리디자인

MVP 화면은 [제품 디자인 시스템](DESIGN.md)을 구현 기준으로 사용한다. 실제 앱 아이콘·브랜드 자산 제작은 별도 작업이다.

## 15. 제품 인수 조건

MVP는 다음 조건을 모두 만족해야 한다. `AC-*`는 task와 E2E 검증이 참조하는 안정적인 제품 spec ID다.

1. **AC-01**: 관리자가 한 달치 근무일을 일괄 오픈할 수 있다.
2. **AC-02**: 근무자가 여러 날짜를 한 번에 신청·취소할 수 있다.
3. **AC-03**: 관리자가 예식과 시간을 생성하고 포지션별로 배정·확정할 수 있다.
4. **AC-04**: 조건 불충족 배정을 막고 미달 확정은 경고 후 허용한다.
5. **AC-05**: 확정 근무자가 전체 배정표와 자신의 예상 급여를 확인한다.
6. **AC-06**: 취소·교대 요청과 관리자 승인이 앱에서 완료된다.
7. **AC-07**: GPS 실패 시 QR로 출퇴근할 수 있고 원본 시각은 변경할 수 없다.
8. **AC-08**: 팀장이 지각·미출근·결근을 확인할 수 있다.
9. **AC-09**: 근무자와 관리자가 월별 예상 급여를 조회한다.
10. **AC-10**: 리허설 기록이 일반 스케줄과 분리되어 계산에 포함된다.
11. **AC-11**: 핵심 사건에 앱 내 알림과 PWA 푸시가 전달된다.
12. **AC-12**: 승인 대기·근무자·관리자·팀장 간 권한 우회가 차단된다.
13. **AC-13**: 휴면·자동 계정 정리와 탈퇴 연쇄 처리가 `ACCT-DORMANT-01`, `ACCT-CLEANUP-01`, `ACCT-DEPART-01`의 시간·배정·개인정보·동시성 규칙을 보존한다.

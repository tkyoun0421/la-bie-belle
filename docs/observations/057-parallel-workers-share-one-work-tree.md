# 「전체 녹색」을 리턴 조건으로 주면 남의 미완성이 그 조건에 든다

AC-12의 열 둘(`scheduleWorker`·`scheduleAdmin`)을 worker 둘에게 같이 맡겼다. 소유 경로를 갈라 줬고 실제로 둘이 같은 파일을 고친 적은 없다. 그런데 **검증이 겹쳤다** — 먼저 끝난 쪽이 리턴 조건대로 `pnpm typecheck`와 `pnpm test`를 저장소 전체에 돌렸고 그 결과가 이렇게 나왔다.

```
pnpm test -- --selectProjects logic   309 passed, 1 failed
pnpm typecheck                        error TS 12건
```

실패도 오류도 전부 아직 돌고 있는 쪽의 미완성 테스트 파일 하나에서 났다. worker가 그것을 「다른 에이전트의 미완성 파일이다」로 바르게 판정해 리턴에 적었고 자기 경로는 초록이었다.

## 판정이 맞았어도 비용은 들었다

세 자리에 든다. worker가 남의 실패를 읽고 가리는 데 도구 호출이 들고, 리턴을 받는 쪽이 「그 열두 건이 정말 남의 것인가」를 다시 재야 하고, 무엇보다 **worker가 그 실패를 제 것으로 읽으면 남의 미완성 파일을 고치러 들어간다.** 소유 경로 밖을 안 고치라고 적어 뒀어도 「검증이 빨개서 고쳤다」는 길은 그 금지와 부딪히지 않는 것처럼 보인다.

## 작업 트리를 떼는 길이 막혀 있다

| 길 | 되나 | 값 |
| --- | --- | --- |
| worker마다 worktree | 브랜치가 열 수만큼 갈리고 [관찰 056](056-spec-gate-ties-parallel-columns-to-one-branch.md)의 게이트가 막는다 | plan을 열로 쪼개야 풀린다 |
| 리턴 조건을 경로로 좁힌다 | 된다 | 열 전부가 돈 뒤 전체를 보는 눈이 어디에도 안 선다 |
| 순차로 돈다 | 된다 | 병렬로 버는 시간을 버린다 |

지금은 둘째를 쓰면서 전체 검증을 총괄이 맡았다 — worker가 돌아올 때마다 `git diff --name-status`로 손댄 것을 보고, 열이 다 들어온 뒤 한 번 전체를 돌린다.

## 기계가 대신할 수 있나

**아니다.** 「내 경로는 초록이고 전체의 빨강은 내 경로 밖에서만 났다」는 조건은 적을 수 있지만 그것을 재는 것이 사람의 눈이다. 테스트 실패 경로를 소유 경로와 대보는 손을 세울 수는 있는데, 그러면 「남의 열이 깨진 채로도 내 리턴은 초록」이 규칙이 되어 어느 worker도 저장소 전체를 안 본다.

같은 자리가 다시 오는 조건은 **worker 둘 이상을 한 작업 트리에서 동시에 돌리는 것**이다. 세 번째면 `implementer` 정의문의 리턴 게이트에 「전체 검증은 경로 필터와 함께 읽는다」를 박을 값이 선다.

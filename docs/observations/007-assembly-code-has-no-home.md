# 조립 코드가 갈 곳이 없어 훅 사각으로 도피했다

## 일

login-screens 회차에서 라우트 셋이 공유하는 조립 로직(세션 읽기 + 승인 시각 읽기 + 목적지 판정)이 정착지를 못 찾았다. entities와 shared를 같이 불러야 하는데 shared에 두면 FSD 계층 규칙이 막고, features나 screens의 `.ts`로 두면 짝 테스트 없이는 `tdd-guard-unit.py`가 막는다. implementer는 훅이 안 보는 `src/app/auth-gate.ts`에 뒀고, 그 파일은 직접 테스트 짝 없이 e2e가 배선을 밟는 것으로만 검증된다. pr-diff 감사도 이 파일을 "계획에 없던 테스트 공백"으로 짚었다.

## 고침

FSD에서 여러 계층을 내려다보며 묶는 조립의 자리를 정한다 — `src/app`을 조립 계층으로 인정하고 그 안 `.ts`도 훅 감시(짝 테스트 요구)에 넣든, features에 조립 슬라이스를 두게 하든. 결정이 ADR-001의 계층 서술에 얹혀야 하니 총괄 몫이다.

## 원칙

규칙이 어떤 코드의 정착지를 정의하지 않으면 그 코드는 감시가 없는 곳으로 흘러간다.

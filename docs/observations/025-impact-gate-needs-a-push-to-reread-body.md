# 본문을 읽는 게이트가 본문 수정으로는 안 돈다

## 일

「영향 확인」 게이트는 PR 본문을 입력으로 받는다. 그런데 `ci.yml`의 `pull_request:`가 타입을 안 적어 기본 셋(`opened`·`synchronize`·`reopened`)으로 돌았다 — **본문 수정은 그 셋에 없다.** 게이트가 빨개져서 본문을 고쳐도 검사가 다시 안 돌고, 통과시키려면 내용과 무관한 커밋을 하나 밀어야 했다.

세 번째다. `payroll-data`의 구현자가 한 번(PR #442에서 본문을 고친 뒤 커밋이 같이 있어 넘어갔다), 이 PR에서 두 번 — 한 번은 게이트가 옛 본문을 읽었고, 한 번은 고친 본문이 안 읽혔다.

같은 자리에서 두 번째 함정도 드러났다. 게이트는 **맨 처음 나오는 「영향 확인」 절 하나만** 본다(`tests/lint/sources-impact.ts`의 `impactSection`). 묶음 둘을 한 PR에 담아 절이 둘이 되면 뒤엣것을 안 읽고, 본문에 문서 이름이 눈에 보이는데도 「안 든다」고 막는다.

## 고침

`pull_request:`에 타입 넷을 적었다 — 기본 셋에 `edited`를 더한다. 본문만 고쳐도 게이트가 다시 돈다. 문서만 바뀐 PR은 무거운 단계(DB·번들·타입 재생성)를 이미 건너뛰니 다시 도는 값이 싸다.

둘째는 안 고쳤다. 절이 둘이면 합치는 것이 맞고, 그것은 쓰는 사람 몫이다.

## 원칙

입력을 어디서 읽는지가 트리거를 정한다. 본문을 읽는 검사는 본문이 바뀔 때 돌아야 하고, 그 줄이 없으면 사람이 검사를 속이는 방법(빈 커밋)을 먼저 배운다.

# 관찰 로그

정의문·훅·CLAUDE.md 규칙이 삐걱인 자리를 남기는 곳이다. 증축 규칙("같은 스폰 프롬프트 세 번째면 정의문 추출")의 카운터가 여기다. 갈래를 만든 근거는 ADR-006.

## 파일

관찰 1건 = 파일 1개. 이름은 `NNN-슬러그.md`이고, 번호는 이 디렉터리와 `archive/`를 합쳐 가장 큰 번호 더하기 1이다.

```markdown
---
status: open        # open | actioned | declined
target: implementer # 정의문·스킬·훅·CLAUDE.md 절 이름. 새 구조 제안이면 "제안: <이름>"
date: 2026-09-06
resolved:           # 닫은 날짜. open인 동안 비워 둔다
---

**일**: 무슨 마찰이었나. 몇 주 뒤 대화 없이 읽어도 알게 쓴다.
**고침**: 어느 정의문 어느 절을 어떻게 바꾸자는 것인지.
**원칙**: 일반화한 한 줄. 다른 정의문에도 적용되는지 본다.
```

세 줄은 이렇게 채운다.

| 항목 | 구체적으로 쓰는 방법 |
| --- | --- |
| 일 | 계기 → 기대한 동작 → 실제 마찰 → 근거 위치 순으로 쓴다. 개인 평가나 추정 원인은 분리한다 |
| 고침 | 정의문·훅의 어느 책임을 어떻게 고칠지 적는다. 대안 검토가 필요하면 proposal로 연결한다 |
| 원칙 | 다음에도 같은 종류의 문제인지 판정할 수 있는 문장으로 쓴다. 일회성 우회로를 전역 규칙으로 만들지 않는다 |

관찰을 기록하는 것과 해결안을 채택하는 것을 구별한다.

## 언제 쓰나

마찰을 본 그 턴에 총괄이 쓴다. 나중으로 미루지 않는다 — 쓰기가 곧 강제 장치고, 머릿속 "나중에 적어야지"는 세션이 끝나면 사라진다.

신호는 다섯이다.

- 같은 스폰 프롬프트가 반복된다. 두 번째부터 기록한다 — 세 번째 판정의 근거가 이 파일들이다.
- subagent가 정의문의 규칙을 어겼다. 규칙을 더 크게 쓰는 게 아니라 구조로 막을 자리를 적는다.
- 생산 리턴이 정해진 형식(완료 / 미완 / 명령과 결과 / 이슈)을 벗어났다.
- 경계 위반이 리뷰를 지나 main에 들어갔다.
- 사용자 교정이 정의문의 빈 자리를 드러냈다.

기록하지 않는 것: 일회성 교정, 이 저장소를 벗어나면 무의미한 우회로, 사용자 취향. 마지막은 총괄 메모리 몫이다 — 메모리는 총괄이 어떻게 일하는지, 관찰은 저장소의 정의문·훅이 어떠한지로 가른다.

test writer 셋(unit·integration·e2e)은 가족이다. 하나를 겨눈 관찰은 셋 다 검토하고 판정을 본문에 한 줄 남긴다.

## 상태와 마감

status는 open으로 시작한다. 관찰을 반영한 PR이 그 관찰의 status를 actioned로 바꾸고 resolved에 날짜를 적는다 — 반영과 기록을 다른 PR로 가르면 기록 쪽이 샌다. 반영하지 않기로 했으면 declined로 바꾸고 이유를 본문에 한 줄 더한다.

커밋은 둘 중 먼저 오는 쪽이다. task 브랜치에서 일하는 중이면 그 PR에 편승하고, 아니면 session-recorder의 마감 PR에 실린다. 마감 때 session-recorder는 open 관찰을 세어 같은 target 3건이면 리턴에 증축 후보와 관찰 번호를 보고하고, `backlog.md`의 `candidate`에 `증축 후보: <target> (관찰 NNN·NNN·NNN)` 행이 없을 때만 한 줄 더한다 — 다음 마감에 또 세어도 중복 등록되지 않는다. handoff.md에는 안 올린다 — 다음 작업을 실제로 막을 때만 총괄이 「재개 맥락」에 적는다. resolved 날짜가 지난 파일은 archive/로 옮긴다. 판정은 총괄이 한다.

## 주의

`git clean -fd`는 아직 커밋 안 된 관찰을 지운다. 저장소는 PUBLIC이다 — 세션 맥락을 적되 시크릿과 로컬 경로는 안 된다.

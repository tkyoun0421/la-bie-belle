# 여섯 파일짜리 탐색가에게 백 파일을 줬다

## 일

AC-06의 재료를 모으려고 `explorer` 둘을 띄웠다. 하나는 `model/` 폴더의 `.ts` 41개를, 하나는 `shared/lib/` 29개와 `screens/*/model/` 80개를 받았다. 둘 다 **도구 호출 한도에 걸려 표를 덜 채운 채 돌아왔다** — 하나는 「6회 중 4회 사용, 남은 2회로는 전체 완성 불가능」을 적었고, 하나는 import 수를 세는 grep을 못 돌렸다고 적었다.

정의문이 그 한도를 이미 적고 있다.

> 도구 호출 4회짜리라 대상이 대여섯 파일을 넘으면 스폰하는 쪽이 갈라서 여럿 띄운다

**스폰한 쪽이 그 줄을 안 지켰다.** 100개를 둘로 갈라 「절반씩」 주면 된다고 읽은 것이고, 갈라야 하는 단위는 절반이 아니라 대여섯이다.

## 재면서 알게 된 것

갈라서 스무 개를 띄우는 것이 답이 아니었다. 묻던 것 다섯 중 넷이 기계가 세는 것이다.

| 물은 것 | 성격 |
| --- | --- |
| export 이름과 갈래 | 정규식 |
| 반환 꼴(`boolean`·유니온·`string`) | 정규식 |
| 사이드 이펙트(`new Date`·`Math.random`·`fetch`) | 정규식 |
| 이 파일을 import하는 자리 수 | `grep -rl` |
| **성격 판정(`policy`냐 `utils`냐)** | **사람** |

스크립트 하나(`ac06-survey.py`)가 앞의 넷을 444줄로 뽑았고, 그것을 읽고 다섯째를 판정하는 데는 탐색가가 필요 없었다. **탐색가가 값을 내는 자리는 「무엇이 어디 있나」고, 「전수를 재서 표로 내라」는 스크립트 자리다.**

판정이 애매한 자리를 양쪽 근거로 돌려준 것은 리턴에서 쓸 만했다 — `attendanceStatus.ts`의 「시간 창이 언제 열리는가」가 판정이냐 계산이냐, `computeWorkTotals`가 policy를 쓰는 utils냐 같은 것들이다. 그것은 파일 대여섯을 깊게 읽는 일이고 정의문이 말하는 크기와 맞는다.

## 남는 위험

**한도가 리턴에만 적혀 있고 입구에서 안 막힌다.** 스폰 프롬프트가 파일 백 개를 가리켜도 그 자리에서는 아무것도 안 말하고, 한도를 다 쓴 뒤 「못 했다」로 돌아온다. 그때는 토큰이 이미 나갔다.

정의문에 「전수를 재는 일은 스크립트로」를 적는 길이 있다. 다만 **같은 실수가 아직 한 번이라** 증축 규칙의 기준(같은 스폰 프롬프트 세 번째)에는 못 미친다 — 세어 두고 두 번 더 나면 정의문을 고친다.

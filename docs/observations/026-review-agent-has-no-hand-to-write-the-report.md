# 리뷰 에이전트에게 리포트를 쓸 손이 없다

## 일

관찰 022가 「막힌 도구를 만나면 코멘트 없이 끝난다」를 잡아 읽기 전용 셸 손 열을 더하고 「어떤 경우에도 코멘트 하나는 남긴다」를 프롬프트에 적었다(#439). 고친 직후 한 번은 들었다 — #438의 리뷰가 42초·코멘트 0에서 6분 46초·코멘트 1로 바뀌었다.

그 뒤로 다시 났다.

| PR | 턴 | 시간 | 막힌 도구 호출 | 코멘트 |
| --- | --- | --- | --- | --- |
| [#448](https://github.com/tkyoun0421/la-bie-belle/pull/448) | 6 | 34초 | 2 | 없음 |

`allowedTools`에 **`Write`가 없다.** 리포트는 한국어 수십 줄이고 표가 든다. 그것을 `gh pr comment --body "..."`의 셸 인자에 직접 싣는 길은 따옴표와 줄바꿈에서 깨지기 쉬워서, 자연스러운 손은 파일에 쓰고 `--body-file`로 넘기는 쪽이다. 그 손이 막히면 남은 길이 좁고, 프롬프트는 「코멘트 하나는 남긴다」만 말할 뿐 **막혔을 때 어느 길로 남기라는 말이 없다.**

막힌 도구 이름은 실행 로그에 안 실려 확정하지 못했다 — `permission_denials_count`만 센다. 위는 로그가 주는 수(6턴·2건)와 `allowedTools`에 `Write`가 없다는 사실에서 세운 판정이다.

## 고침

`pr-review.yml`을 두 자리 고쳤다.

- `allowedTools`에 `Write`를 더한다. 잡의 권한이 `contents: read`고 push하는 단계가 없어 저장소로 나가는 길은 안 열린다.
- 프롬프트가 길을 지정한다 — 리포트를 `/tmp/review.md`에 쓰고 `--body-file`로 넘긴다. 그리고 한 길이 막히면 다른 길로 남기라고 적는다: 파일로 못 쓰면 `--body`에 짧게, 그것도 막히면 무엇이 막혔는지만이라도.

가드(코멘트 수를 세어 0이면 빨갛게)는 그대로 둔다. 이번에도 그 가드가 잡았다.

## 원칙

「무슨 일이 있어도 결과물을 남겨라」는 남길 **손**이 있을 때만 지켜진다. 도구 목록을 줄일 때는 그 목록으로 산출물을 실제로 만들 수 있는지를 한 번 밟아 봐야 한다 — 읽는 손만 주고 쓰는 손을 안 주면 「빠짐없이 보고 아무것도 못 남기는」 자리가 선다.

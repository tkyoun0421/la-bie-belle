# Worker flows

[디자인 시스템](../DESIGN.md) · [Patterns](PATTERNS.md) · [Components](COMPONENTS.md)

## 로그인과 가입

### 로그인

- 공개 마케팅 소개 없이 Google 로그인에 집중한 한 화면을 사용한다.
- 짧은 제품명, 서비스 용도 한 문장, `Google로 계속하기`를 중심에 둔다.
- 개인정보 처리와 문의 경로는 낮은 계층으로 제공한다.

### 가입

- 이름, 휴대폰 번호, 생년월일, 성별을 한 화면에서 입력한다.
- 성별에는 포지션 배정 조건 확인에 사용된다는 설명을 제공한다.
- 하단 고정 `가입 신청하기`로 제출한다.
- 제출 후 승인 대기 화면에서 현재 상태와 관리자 문의 경로만 명확히 보여준다.
- 승인 거절·정지 상태는 가능한 행동과 문의 방법을 직접 설명한다.

## 앱 셸과 홈

하단 탭은 `홈 · 일정 · 알림 · 전체`다. 홈의 메인 영역은 다음 우선순위에서 현재 가장 중요한 항목 하나를 선택한다.

1. 오늘 가능한 출근·퇴근
2. 마감 임박 근무 신청
3. 확정 스케줄 변경 확인
4. 다음 근무
5. 아직 할 일이 없는 빈 상태

- 이름을 반복하는 인사보다 날짜, 상태, 다음 행동을 우선한다.
- 예상 급여 금액은 홈에 표시하지 않는다.
- 당일 팀장에게만 `근무자 출결 확인하기` 진입점을 상황형으로 보여준다.
- 팀장의 과거 출결 관리 메뉴는 제공하지 않는다.

## 근무 신청

1. `일정`에서 일요일 시작 월 달력을 연다.
2. 모집 중인 여러 날짜를 탭해 로컬 선택을 바꾼다.
3. 하단 영역에서 변경 개수를 확인하고 `신청하기`를 누른다.
4. 서버는 batch 요청 한 번으로 신청·취소를 저장한다.
5. `근무 가능일을 변경했어요` 스낵바와 `방금 변경한 N개 날짜 되돌리기`를 보여준다.
6. Undo는 마지막 batch 전체를 복원 요청 한 번으로 되돌린다.

- 모집이 없는 날만 disabled다.
- 마감·확정 날짜는 상세를 조회할 수 있다.
- 마감 전 신청 취소에 별도 확인창을 사용하지 않는다.
- 저장 실패 시 로컬 선택을 보존하고 재시도 가능 여부를 알린다.

## 확정 스케줄

상세는 다음 순서를 지킨다.

1. 날짜와 예정 출퇴근
2. 내 배정
3. 전체 배정표
4. 예식 시간
5. `근무 변경 요청`

- 전체 배정표는 기본으로 펼쳐 놓는다.
- 본인 행은 action tint와 `나`, 다른 사람은 이름과 포지션만 보여준다.
- 전화번호, 성별, 시급, 출결은 노출하지 않는다.
- 변경된 시간·배정이 있으면 무엇이 바뀌었는지 먼저 설명한다.

## 근무 변경 요청

취소와 교대를 별도 메뉴로 나누지 않고 `근무 변경 요청` 하나로 묶는다.

1. 바텀시트에서 `근무 취소` 또는 `특정 근무자와 교대` 유형을 선택한다.
2. 교대는 조건을 충족하는 후보를 선택하고, 선택 사유를 입력할 수 있다.
3. 제출 전 `관리자가 승인하기 전까지 기존 배정과 책임이 유지돼요`를 보여준다.
4. 제출 후 현재 요청 상태와 관리자 처리 결과를 상세에서 확인한다.

- 상대방의 읽음이나 응답은 관리자 승인 전제조건처럼 표현하지 않는다.
- 당일 근무자 간 포지션 교환 기능은 만들지 않고 관리자에게 직접 문의하도록 안내한다.

## 출퇴근

홈에는 현재 가능한 행동 하나만 크게 표시한다.

### GPS 성공

1. 사용자가 `출근 인증하기` 또는 `퇴근 인증하기`를 누른다.
2. 영역이 `현재 위치를 확인하고 있어요`로 바뀐다.
3. 위치 핀 주위에 잔잔한 원 애니메이션을 표시한다. reduced motion에서는 정적 진행 표시를 쓴다.
4. 성공하면 좌표·거리·정확도를 숨기고 `현장 위치가 확인됐어요`를 보여준다.
5. 서버 기록이 완료되면 서버 시각과 짧은 체크 모션을 표시한다.

### GPS 실패

- `위치 권한이 꺼져 있어요`, `위치 정확도가 낮아요`, `근무지 범위 밖이에요`처럼 해결 가능한 이유를 보여준다.
- 권한 설정 재시도와 `QR로 인증하기`를 제공한다.
- 위치 확인 성공처럼 보이기 전에 서버 기록 성공을 확인한다.

출퇴근 원본 수정·삭제 UI를 만들지 않는다. 팀장이나 관리자의 현장 확인은 원본을 고친다는 표현이 아니라 별도의 확인으로 설명한다.

## 예상 급여와 리허설

예상 급여는 `전체 → 예상 급여`에서만 금액을 보여준다. 홈과 전체 메뉴 항목에는 금액 미리보기를 두지 않는다.

### 예상 급여 화면

- 진입 시 이번 달 예상 합계를 바로 보여준다.
- 눈 아이콘으로 금액을 숨길 수 있고 이 선택은 기기 로컬에 유지한다.
- `예정된 근무 시간으로 계산한 금액이에요. 실제 지급 금액과 다를 수 있어요.`를 합계 근처에 표시한다.
- `급여`, `정산 완료`, `지급 예정`처럼 실제 정산으로 오해할 표현을 쓰지 않는다.
- 한 화면에서 전체 예상 합계, 일반 근무 예상 금액, 리허설 예상 금액, 날짜별 내역을 보여준다.

### 리허설

- 같은 화면에서 `리허설 기록 추가`와 이번 달 기록 목록을 제공한다.
- 날짜, 시작 시각, 종료 시각은 한 흐름에서 입력한다.
- 기록을 탭하면 바텀시트에서 수정·삭제한다.
- `직접 작성한 참고 기록이며 공식 출퇴근 기록이 아니에요`를 기록 영역에 표시한다.
- 삭제는 본인이 다시 기록할 수 있는 가역 행동으로 처리하고 가능한 경우 Undo를 제공한다.

## 알림과 푸시 권한

- 푸시 권한은 첫 앱 진입 때 요청하지 않는다.
- 첫 근무 신청 저장 성공 후 알림의 가치를 설명하는 사전 안내를 보여준다.
- 사용자가 `알림 받기`를 선택한 다음에만 브라우저 권한을 요청한다.
- iPhone에서 홈 화면 설치가 필요하면 권한 요청 전에 설치 방법을 안내한다.
- 거절하거나 지원하지 않는 환경에서도 앱 내 알림함은 정상 동작한다.

알림함은 최신순 단일 목록이며 `오늘`, `이번 주`, `이전`으로 나눈다. 유형 필터 없이 `모두 읽음`만 제공하고 항목을 탭하면 관련 화면으로 이동하며 읽음 처리한다.

## 전체 메뉴와 탈퇴

- 프로필, 예상 급여, 알림 설정, 문의, 일반 탈퇴를 정보 계층에 맞춰 배치한다.
- 일반 탈퇴는 관리자 승인 없이 사용자가 직접 완료한다.
- 탈퇴 전 즉시 삭제되는 정보와 3년 분리 보관되는 복구 정보를 구분해 설명한다.
- 앱 안에 완전 삭제 신청 폼이나 처리 상태를 만들지 않는다.
- `복구할 수 없는 완전 삭제를 원하면 관리자에게 직접 문의해주세요.`와 문의 경로를 제공한다.

## 오프라인

- 이전에 본 일정과 배정표만 읽기 전용으로 볼 수 있다.
- 신청, 변경 요청, 리허설 수정, 출퇴근을 포함한 모든 변경 행동을 차단한다.
- 출퇴근은 나중 전송되는 것처럼 보이거나 queue에 저장되어서는 안 된다.
- 연결 복구 시 최신 서버 상태로 자동 갱신하고 작성 중이던 폼 값은 사용자가 검토한 뒤 제출한다.

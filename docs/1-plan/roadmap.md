# 로드맵

큰 순서가 산다. 어떤 기능 묶음이 어떤 차례로 어떤 릴리스가 되는가다. task 하나의 순서는 `../backlog.md`의 `ready` 행 순서가 담고, 여기는 묶음 단위만 담는다.

시나리오([`scenarios.md`](scenarios.md))의 장면 번호를 출시 판정의 참조가 가져다 쓴다.

## 릴리스 목록

| 릴리스 | 담는 묶음 | 미루는 묶음과 이유 | 출시 판정의 참조 |
| ------ | --------- | ------------------ | ---------------- |
| 1차 | 계정(가입·승인), 근무표(신청 생성·근무 신청·확정·강제 변경·근무 요청·근무 취소·보기), 출근 인증(위치·QR·지각·사유 승인), 급여 예상, 통계(근무·근태), 알림(교대와 공지를 뺀 전부) | 교대 — 요청 흐름이 복잡하고 수기로 버틸 수 있다. 관리자 공지 — 없어도 첫 실사용이 선다 | 장면 1·2·3·4·6이 e2e로 통과하고, 아이폰과 안드로이드 실기기에서 푸시와 위치 인증이 확인된다 |
| 2차 | 교대 전 흐름과 교대 알림, 관리자 공지 | — | 장면 5가 e2e로 통과한다 |

## 순서의 이유

1차는 화면 디자인을 전부 끝낸 뒤에 구현한다. 계획과 설계가 꼼꼼히 선 다음에 코드를 만들고, 그리다 만나는 미정은 착수 전 인터뷰로 정한다.

그리는 순서는 관리자 근무표 제작·확정부터다. 제일 크고 복잡한 화면을 먼저 뚫으면 근무표 구조가 거기서 확정되고, 근무자의 근무표 보기가 그 구조를 따라온다. 나머지 화면의 순서는 그리면서 정한다.

통계는 시급 설정을 안 기다린다. 관리자 통계가 세는 것이 시간과 출결이라 시급이 없어도 화면에 채울 숫자가 난다.

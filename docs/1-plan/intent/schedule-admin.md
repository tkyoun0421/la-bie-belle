# 관리자 근무표 제작·확정

2026-09-07 태관 인터뷰의 산출물이다. 사슬의 첫 고리로, `2-design/spec/schedule-admin.md`의 입력이 된다(ADR-005). 도메인 규칙은 [domain/schedule.md](../../2-design/domain/schedule.md)가 정본이고, 인터뷰에서 새로 정한 도메인 항목은 이미 그리로 올라갔다 — 여기는 화면 결정만 담는다.

## 왜 만들고 무엇을 원하나

시나리오 장면 2가 이 화면의 이야기다. 관리자 윤서준이 모인 휴무 희망을 보며 다음 달 근무표를 짜고 확정 버튼을 누른다. 1차 릴리스 판정 기준에 들어 있고, 그리는 순서 결정([roadmap.md](../roadmap.md)「순서 규칙」)에서 첫 번째로 뽑혔다 — 제일 크고 복잡한 화면을 먼저 뚫으면 근무표 구조가 확정되고 근무자의 근무표 보기가 따라온다.

주 타깃은 아이폰 사파리 PWA, 세로 화면이다.

## 화면 결정

### 뼈대

- 편집 뼈대는 **월 달력 + 날 상세**다. 달력 칸에는 채움 상태만 작게 보이고, 열린 날을 누르면 그날의 자리 목록으로 들어간다
- 앱은 예식 날을 모른다. 관리자가 달 근무표를 만드는 것이 선행이고, 만든 직후 달력은 전부 닫힌 날이다. 관리자가 예약 장부를 보고 예식 있는 날을 연다
- **관리자 홈 뼈대도 이번에 그린다.** 근무표 관리로 들어가는 진입과 근무 시간 기본값 설정이 여기 산다. 다른 자리(가입 대기 등)는 자리만 잡고 「제안」으로 표시한다

### 날 열기와 닫기

- 열기는 **다중 선택 후 「n일 열기」 버튼**이다. 장부를 보며 여러 날을 고르고 한 번에 연다
- 확정 전 닫기는 배정이 있어도 된다 — 「배정 n건이 사라집니다」 경고를 확인받고 배정까지 지운다

### 자리 구조

- **포지션 단위 잠금이 기본이다.** 잠금은 구조 변경(자리 삭제·겸임 합침)만 막고, 사람 넣기·빼기는 잠금과 무관하다
- 잠금을 푼 포지션에서 — 자리를 아래로 끌어 버리면 삭제, 다른 포지션 자리에 겹치면 겸임 자리, 포지션 줄의 +로 자리 추가
- **겸임은 자리 합침으로만 만든다.** 픽커에서 이미 배정된 사람은 못 고르고 「겸임은 자리를 합쳐 만드세요」 안내가 뜬다
- 교육 배정은 포지션 줄의 「교육 붙이기」로 덧붙인다. 구조 변경이 아니라 잠금과 무관하다

### 사람 채우기

- 픽커 기본은 **배정 가능한 사람만**이다. 「전체 보기」를 펼치면 전원이 나오고 사람마다 상태 메시지(휴무 희망·자격 없음·배정됨)가 붙는다
- 제한 포지션에 교육 이력 없는 사람을 넣으려 하면 도메인 규칙대로 앱이 알리고, 이번만 넣을지 자격까지 줄지 고른다

### 휴무 희망

셋에서 보인다 — 달력 칸의 희망자 수, 날 상세의 그날 희망자 목록, 별도 모아보기 화면.

### 근무 시간

날을 열면 기본값이 깔리고 날 상세에서 고친다. 기본값을 바꾸는 자리는 관리자 홈이다.

### 확정과 확정 뒤

- **휴무 희망 마감일 전에는 확정 불가.** 급하면 마감일을 당긴다. 마감일은 자유 수정(오늘 이전 불가)이고 바뀌면 전원 알림
- 확정 뒤 날 열기 허용, 빈 자리는 배정 추가 규칙으로 채움 — 도메인 미정이 이 인터뷰에서 해소됐다
- **강제 변경도 1차에 넣는다.** 통지는 빠진 사람과 들어온 사람 둘만 — [domain/notification.md](../../2-design/domain/notification.md)의 「근무표 변경」 행 그대로다

# ADR-001 — FSD 레이아웃과 TDD 강제

2026-08-25에 정했다.

## 결정

코드는 Feature-Sliced Design으로 배치하고, 테스트를 먼저 쓰는 규율은 문서가 아니라 훅이 막는다.

## 레이어

`src/` 아래 다섯이다.

- `app/` — Next.js 라우팅 전용이다. 얇게 유지하고 화면 조립을 두지 않는다. 전역 provider와 스타일도 여기 산다.
- `screens/` — 화면 조립. FSD의 pages 레이어인데 Next가 그 이름을 예약어처럼 쓰므로 screens로 부른다. 슬라이스 이름은 라우트 이름과 같게 짓는다.
- `features/` — use-case.
- `entities/` — 도메인 모델과 규칙.
- `shared/` — 어느 기능에도 매이지 않은 것. `shared/ui`에 shadcn 생성물이, `shared/lib`에 공용 유틸이 산다.

widgets 레이어는 두지 않는다. 화면 조립 덩이가 실제로 반복되면 그때 넣는다.

## 세그먼트

슬라이스 안은 성격대로 나눈다. `types`, `components`, `hooks`, `actions`, `dals`, `models` 같은 이름을 쓰고, 목록은 열어둔다. 새 성격이 필요하면 그 자리에서 만든다.

처음부터 폴더로 나누지 않는다. 슬라이스 안에 파일을 바로 두다가 같은 성격이 셋째로 생기면 그때 세그먼트 폴더로 묶는다.

## 화면과 로직

`.tsx`는 더미 UI다. 받은 것을 그리기만 한다. 계산, 상태 규칙, 통신은 전부 `.ts`로 뺀다.

집행은 `house/dumb-ui` lint 규칙이 한다(`eslint-rules/dumb-ui.mjs`, `src/**/*.tsx`에 걸린다). `.tsx` 안의 `@supabase/*` import와 `fetch()` 호출과 TanStack Query 훅 직접 호출을 잡는다.

## 테스트 자리

- 단위 테스트는 대상 파일과 같은 레벨의 `__tests__/<이름>.test.ts`에 둔다.
- e2e는 루트 `tests/e2e/<이름>.spec.ts`에 둔다. 이름은 라우트 이름이고, 루트 화면은 `home`이다.

## 훅이 막는 것

`.claude/hooks/`의 두 훅이 Write와 Edit 앞에서 판정한다.

- **단위** — `src/` 아래 `.ts`가 실행 코드(함수·클래스·화살표 함수)를 내보내는데 같은 레벨 `__tests__`에 짝 테스트가 없으면 막는다. `src/app/`과 `src/shared/ui/`, 타입 선언 파일, 테스트 파일 자체는 보지 않는다.
- **e2e** — `src/app/`의 `page.tsx`·`layout.tsx`·`route.ts`와 `src/screens/<슬라이스>/` 아래 파일에 짝 spec이 없으면 막는다.

훅은 세그먼트 이름을 모른다. 확장자와 파일 내용으로만 판정하므로 세그먼트가 늘어도 훅을 고칠 일이 없다.

## 함께 정한 것

**탈출구를 두지 않는다.** 막히면 테스트를 먼저 쓴다. 훅 자체가 틀렸을 때만 훅 파일을 고쳐 푼다.

**Bash로 쓰는 것은 보지 않는다.** 명령줄 문자열을 정규식으로 읽는 판정은 정확하지 않아, 멀쩡한 명령을 막을 위험이 구멍을 메우는 값보다 크다. 이 구멍은 `implementer` 정의문의 절차와 `pr-diff` 감사자의 "테스트 없는 구현" 점검이 뒤에서 받는다. 실제로 이 길로 테스트 없는 코드가 main에 들어오면 그때 막는다.

**새 파일과 기존 파일 수정을 똑같이 막는다.** 테스트 없는 파일을 고치려면 테스트부터 쓴다.

## 남는 위험

훅은 Write와 Edit만 본다. 그 밖의 경로로 파일을 쓰면 통과한다.

라우트 이름을 짝짓기에 쓰므로, 서로 다른 라우트가 마지막 디렉터리 이름을 공유하면 spec 하나를 함께 가리킨다. 그런 라우트가 생기면 이름을 다르게 짓는다.

`house/dumb-ui`는 `.tsx`가 직접 쓰는 것만 본다. `@/shared/lib/`를 한 겹 거치면 통과한다. `src/app/page.tsx`가 지금 그 상태다 — `getCurrentUser`를 불러 Supabase에 붙는데 lint는 아무 말도 안 한다.

규칙의 버그가 아니라 type-aware lint를 안 켜기로 한 결정의 대가다. 어떤 `.ts` 함수가 통신하는지 알려면 타입 정보가 필요한데, 그건 lint 속도를 이유로 이미 접었다(`docs/plan.md`의 lint task 「범위 밖」). 그러니 `.tsx`와 통신 사이의 경계는 lint가 아니라 리뷰가 지킨다.

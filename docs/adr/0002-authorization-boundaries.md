# ADR-0002: RLS와 서버 트랜잭션으로 권한 강제

- 상태: Accepted
- 날짜: 2026-07-23

## Context

근무자, 당일 팀장, 관리자, 슈퍼 관리자는 같은 데이터에 서로 다른 권한을 가진다. 이름, 생년월일, 휴대폰, 성별, 시급, 위치정보를 다루므로 화면의 조건부 렌더링만으로 권한을 보장할 수 없다.

## Decision

- 모든 노출 테이블에 RLS를 활성화하고 기본 거부 정책을 사용한다.
- 단순 본인 CRUD는 사용자 JWT와 RLS로 처리한다.
- 확정, 교대 승인, 계정 복구, 역할 변경처럼 여러 행을 변경하는 작업은 서버 전용 트랜잭션 또는 security definer 함수로 처리한다.
- service role 키는 서버에서만 사용한다.
- `user_roles`와 계정 승인 상태를 모든 권한 판단의 기준으로 사용한다.
- `팀장` 권한은 전역 역할이 아니라 해당 날짜의 확정 assignment에서 파생한다.
- 권한 매트릭스를 SQL 통합 테스트로 고정한다.

## Consequences

- 클라이언트 우회 요청도 데이터베이스에서 차단된다.
- RLS 정책과 서버 함수 테스트가 구현의 필수 부분이 된다.
- 복잡한 관리자 작업은 직접 테이블 mutation보다 명시적 command API를 사용한다.
- 관리자도 근무자이므로 역할을 상호 배타적인 enum 하나로 표현하지 않는다.

# 못 찍은 근무자가 사유를 내고 관리자가 판정한다

## 요구

출근 인증을 못 찍으면 결근이다. [ATT-010](../modules/attendance/README.md#att-010)이 사유를 내고 관리자가 승인하는 길을 열어뒀는데 그 화면이 없다.

**문 셋이 남의 task에 있다** — 근무자가 들어오는 문은 대시보드의 못 찍음 블록, 관리자가 판정하는 자리는 `/admin/approvals`, 결과가 보이는 자리는 근무자 날 시트의 인증 상태 열이다. 이 task가 그 셋을 잇는다.

## 설계 참조

- **사유는 근무가 끝나고 48시간까지다** — [ATT-011](../modules/attendance/README.md#att-011). 날짜 경계가 아니라 근무가 끝난 시각에서 센다 — 늦게 끝난 사람과 일찍 끝난 사람이 같은 여유를 받는다
- **보낸 사유는 못 고친다** — [ATT-012](../modules/attendance/README.md#att-012). 고쳐 쓸 일이 있으면 거절을 기다리거나 관리자에게 말한다
- **판정에 시한이 없다** — [ATT-015](../modules/attendance/README.md#att-015). 마감이 지나 결근이 된 뒤에도 승인된다
- **관리자는 사유 글 전문을 읽는다** — [ATT-018](../modules/attendance/README.md#att-018)
- **화면의 모양과 문안** — [excuse.md](../modules/attendance/screens/excuse.md)가 정본이고 상태 아홉이 그 표에 있다

## 완료 조건

### AC-01

- 전제: 인증을 못 찍은 날이 있는 근무자
- 행동: 대시보드의 「사유 넣기」로 시트를 연다
- 관찰 결과: 바텀시트가 서고 왼쪽이 「닫기」, 오른쪽이 보내기다. **덮개를 눌러도 안 닫힌다** — 쓰던 글이 날아가는 것을 막는다. 닫는 길은 「닫기」 하나다. 칸에 커서가 가면 **시트째 올라앉는다** — 가려지는 쪽만 밀면 칸과 버튼 중 하나가 화면 밖으로 나간다
- 검증 층: e2e — 덮개를 눌러도 안 닫히는 것은 규칙이고 쉽게 깨진다
- 근거: [excuse.md 「화면 상태와 흐름」](../modules/attendance/screens/excuse.md#화면-상태와-흐름)

### AC-02

- 전제: 사유 시트
- 행동: 글을 친다
- 관찰 결과: **다섯 자 미만이면 보내기가 잠기고** 칸 아래 도움말이 왜인지 말한다 — **테두리를 안 물들인다**. 글자 수는 **서른 자가 남았을 때 나타난다**. 200자에서 더 안 들어가고 숫자 색이 바뀌는데 **이미 쓴 글을 안 지운다**. 길이를 **사람이 보는 글자로 센다** — 이모지 하나가 2로 세어지면 상한이 사람이 세는 것과 어긋난다. 화면이 먼저 막고 함수가 마지막 문이다
- 검증 층: unit — 길이 세기와 경계 둘(다섯 자·서른 자 남음·200자)이 순수 계산이다
- 근거: [excuse.md](../modules/attendance/screens/excuse.md), [attendance-data AC-04](../../3-build/plans/attendance-data.md#ac-04)

### AC-03

- 전제: 다섯 자 이상 적었다
- 행동: 보낸다
- 관찰 결과: 오른쪽 버튼에서 링이 돌고 **닫기도 같이 잠긴다** — 중간에 닫으면 갔는지 알 길이 없다. 성공하면 같은 시트에서 결과가 나고 **1.65초 뒤 저절로 닫힌다**. 실패하면 **안 닫히고 쓴 글이 칸에 그대로 있다**. **실패에 링이 없다** — 밖으로 번지는 것은 좋은 소식의 모양이다. **색만으로 실패를 안 알린다** — 모양과 움직임과 문장 셋이 같이 말한다. 도는 시간이 끝나면 반드시 성공 아니면 실패가 온다 — 링이 돌다 사라지는 끝이 없다
- 검증 층: e2e
- 근거: [excuse.md 「화면 상태와 흐름」](../modules/attendance/screens/excuse.md#화면-상태와-흐름)

### AC-04

- 전제: 이미 사유를 낸 날
- 행동: 「사유 넣기」를 다시 누른다
- 관찰 결과: **읽기 전용 칸**과 「확인 중」 배지가 뜨고 버튼이 닫기 하나다. 언제 보냈는지가 날짜 줄에 선다. **보낸 사유는 못 고친다**
- 검증 층: e2e
- 근거: [ATT-012](../modules/attendance/README.md#att-012)

### AC-05

- 전제: 관리자가 사유를 반려했다
- 행동: 근무자가 앱을 연다
- 관찰 결과: **시트가 아니라 대시보드 블록**이다. 관리자가 남긴 이유가 그대로 인용돼 보이고 「사유 다시 쓰기」가 선다. **그 버튼이 빈 시트를 연다** — 앞 글을 채워주지 않는다. 거절된 글을 고쳐 내는 것이 아니라 새로 내는 것이다. 관리자 이유가 비어 있을 수 없다 — 거절에 이유가 필수다
- 검증 층: e2e
- 근거: [excuse.md](../modules/attendance/screens/excuse.md), [attendance-data AC-04](../../3-build/plans/attendance-data.md#ac-04)

### AC-06

- 전제: 관리자. `/admin/approvals`에 사유가 있다
- 행동: 줄을 눌러 판정한다
- 관찰 결과: 누가·어느 날 근무·언제 냈는지와 **글 전문**이 보인다. 승인과 반려 둘이고 **반려는 이유를 받는다** — 안 쓰면 못 보낸다. 판정하면 **목록에 머물고** 그 줄이 자리에서 결과로 바뀐다. **관리자에게 사유가 왔다는 알림이 없다** — 승인할 일 줄의 건수가 대신한다
- 검증 층: e2e
- 근거: [ATT-018](../modules/attendance/README.md#att-018), [approvals.md](../system/screens/approvals.md)

### AC-07

- 전제: 근무자의 날 시트
- 행동: 인증 창이 열린 뒤의 명단을 본다
- 관찰 결과: 사람 줄마다 상태가 붙고 현황 줄이 선다 — [schedule-worker](schedule-worker.md)가 비워 둔 자리를 이 task가 채운다. 상태 여섯은 저장된 값이 아니라 **읽을 때마다 계산된다**. 현황 줄은 0인 항목을 뺀다. 통신 지연 표시도 같은 함수에서 온다
- 검증 층: unit — 여섯 상태의 갈림과 현황 줄의 셈이 계산이고 `attendance-data`가 낸 순수 함수를 쓴다
- 근거: [attendance-data AC-06](../../3-build/plans/attendance-data.md#ac-06)

### AC-08

- 전제: 근무가 끝나고 48시간이 지났다
- 행동: 사유를 내려 한다
- 관찰 결과: `window_closed`다. **인증 창이 그날 18:00에 닫히는 것과 별개로 센다.** 다만 **관리자 판정에는 시한이 없어** 마감이 지나 결근이 된 날도 목록에 남아 승인된다. 급여가 예상치라 이 마감이 돈을 자르지 않는다 — 48시간을 넘겨 못 넣은 날이 있어도 실제 지급은 관리자가 따로 맞춘다
- 검증 층: integration — 마감의 기준 시각이 함수 안에 있다
- 근거: [ATT-011](../modules/attendance/README.md#att-011), [ATT-015](../modules/attendance/README.md#att-015)

## 상태 격자

| 자리 | 무엇이 뜨나 | AC |
| --- | --- | --- |
| 빈 상태 | 시트를 열자마자는 빈 칸과 잠긴 보내기다. 사유가 하나도 없으면 `/admin/approvals`의 그 구획이 빈다 — 근무 취소 요청과 한 목록이라 둘 다 없을 때만 목록 자체가 빈 상태다 | AC-01, AC-06 |
| 로딩 | 보내는 동안 오른쪽 버튼에서 링이 돌고 **닫기도 잠긴다**. 판정 목록은 [runtime.md 「로딩」](../system/runtime.md#로딩)의 기본값을 상속한다. **시트가 덮고 있는 동안 대시보드가 안 움직인다** — 다 내려간 뒤에 버튼과 블록이 바뀐다 | AC-03 |
| 실패 | 시트가 **안 닫히고 쓴 글이 그대로 있다**. 링이 아니라 다른 모양이 서고 색·모양·문장 셋이 같이 말한다. `window_closed`는 마감이 지난 것이라 다시 눌러도 같다 — 그 사실을 말한다 | AC-03, AC-08 |
| 권한 없음 | 사유는 그날 배정된 본인만 낸다. 판정은 관리자만이고 근무자가 부르면 `not_allowed`. 관리자는 사유 글 전문을 읽지만 근무자는 남의 사유를 못 본다 | AC-06 |
| 경계 | 다섯 자 미만은 잠김, **서른 자 남았을 때** 글자 수가 나타남, **200자**에서 멈춤. 길이는 **사람이 보는 글자**로 센다. 사유 마감은 **근무 끝에서 48시간**이고 인증 창이 18:00에 닫히는 것과 별개다. **판정에는 시한이 없다** | AC-02, AC-08 |
| 재진입 | 이미 낸 날을 다시 열면 **읽기 전용**이다. 반려된 뒤의 「사유 다시 쓰기」는 **빈 시트**를 연다 — 앞 글을 안 채운다. 키보드가 올라왔다 내려가도 시트 위치가 제자리로 돌아온다 | AC-04, AC-05 |
| 동시 변경 | 관리자 둘이 같은 사유를 판정하면 늦은 쪽이 이미 판정된 것을 보고 목록을 다시 읽는다. 근무자가 시트를 연 사이 관리자가 그날 배정을 빼면 보내기가 거절된다 — 사유가 배정에 붙는다 | AC-06 |
| 성공 직후 | 시트에서 결과가 나고 **1.65초 뒤 저절로 닫힌다**. 대시보드는 시트가 다 내려간 뒤에 버튼과 블록이 바뀐다. 판정하면 그 줄이 자리에서 결과로 바뀌고 목록을 안 떠난다. 결과가 근무자에게 알림으로 가는데 그 발송은 알림 영역이다 | AC-03, AC-06 |

## 범위 밖

- 대시보드의 못 찍음 블록과 「사유 넣기」 버튼 자리 — `dashboard`가 세우고 이 task가 그 문을 시트에 연결한다
- 날 시트의 명단과 버튼 둘 — [schedule-worker](schedule-worker.md). 이 task는 그 줄에 상태를 채운다
- 판정 목록의 근무 취소 줄 — [schedule-requests](schedule-requests.md)
- 판정 결과 알림이 실제로 나가는 것 — `notification-emit`. 이 task는 판정이 알림 대상이라는 것만 넘긴다
- 출근 인증 자체 — [attendance-checkin](attendance-checkin.md)
- 상태 여섯을 내는 순수 함수 — `attendance-data`가 이미 냈다

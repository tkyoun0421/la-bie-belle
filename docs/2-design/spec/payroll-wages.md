# 관리자가 기본 시급과 사람별 시급을 정한다

## 요구

급여 계산은 [payroll-data](../../3-build/plans/payroll-data.md)가 세웠는데 시급을 넣을 자리가 없다. 기본 시급도 사람별 시급도 화면 없이는 DB에 직접 써야 한다.

이 화면 하나가 둘을 다 든다 — 기본 시급 줄과 사람 목록이다.

## 설계 참조

- **시급은 덮어쓰지 않고 쌓인다** — [PAY-011](../modules/payroll/README.md#pay-011). 같은 날 다시 저장하면 그날 줄을 덮어써서 되돌릴 수 있다
- **퇴사한 사람은 목록에 없다** — [PAY-020](../modules/payroll/README.md#pay-020)
- **화면의 모양과 문안** — [wages.md](../modules/payroll/screens/wages.md)가 정본이다

## 완료 조건

### AC-01

- 전제: 관리자
- 행동: `/admin/wages`를 연다
- 관찰 결과: 기본 시급 줄이 맨 위에 서고 **아래에 몇 명이 이 값을 쓰는지 한 줄이 붙는다**. 그 아래 사람 목록이 이름 가나다순이다 — **개별로 정한 사람을 위로 안 올리고, 기본을 쓰는 사람을 따로 표시하지도 않는다**. 이름 뒤에 「님」이 없다. 퇴사한 사람은 목록에 없다
- 검증 층: e2e
- 근거: [PAY-020](../modules/payroll/README.md#pay-020), [wages.md 「시급 짜임」](../modules/payroll/screens/wages.md#시급-짜임)

### AC-02

- 전제: 기본 시급 줄
- 행동: 값을 고쳐 저장한다
- 관찰 결과: **몇 명이 같이 바뀌는지를 저장 전에 말한다.** 치는 동안 세 자리마다 쉼표가 따라 들어가고 「원」이 숫자에 붙어 오른쪽에 선다. **확인을 안 묻는다** — 여러 사람이 움직이지만 같은 날 다시 저장하면 되돌릴 수 있어서다. 저장하면 토스트가 뜨고 그 값을 쓰는 사람들의 줄이 같이 바뀐다
- 검증 층: e2e
- 근거: [PAY-011](../modules/payroll/README.md#pay-011), [writing.md 「숫자와 단위」](../design-system/writing.md#숫자와-단위)

### AC-03

- 전제: 사람 줄
- 행동: 시급을 고쳐 저장한다
- 관찰 결과: **열 때 지금 시급이 채워져 있다** — 기본을 쓰는 사람도 그 값이 채워져 있고, 고쳐 저장하면 그때부터 개별이 된다. 적용 안내가 언제부터 걸리는지를 말한다
- 검증 층: e2e
- 근거: [design.md 「시급과 조정」](../modules/payroll/design.md#시급과-조정)

### AC-04

- 전제: 개별 시급을 쓰는 사람의 시트
- 행동: 기본으로 되돌린다
- 관찰 결과: **확인을 한 번 묻고 바뀔 값을 그 자리에서 말한다** — 지금 값이 기본보다 높으면 누르는 순간 내려간다. **기본을 쓰는 사람에게는 되돌리기 줄이 아예 없다** — 이미 붙어 있다
- 검증 층: e2e
- 근거: [design.md 「시급과 조정」](../modules/payroll/design.md#시급과-조정)

### AC-05

- 전제: 두 시트 중 아무거나
- 행동: 규칙 밖의 값을 넣는다
- 관찰 결과: **상한이 100,000원이다** — 넘으면 더 안 들어가고 칸 아래에 문구가 선다. **하한은 0 초과 하나다** — 최저임금을 안 본다. 해마다 바뀌는 값을 앱이 들면 안 고쳤을 때 틀린 경고가 서고, 틀린 경고는 없는 경고보다 나쁘다. 값이 지금과 같거나 빈 칸이거나 0이면 저장이 안 눌린다
- 검증 층: unit — 값의 꼴과 저장 가능 여부를 보는 순수 함수고 두 시트가 같은 조각을 쓴다
- 근거: [wages.md 「시급 문안」](../modules/payroll/screens/wages.md#시급-문안)

### AC-06

- 전제: 시급을 여러 번 바꾼 사람
- 행동: 사람 시트를 연다
- 관찰 결과: 이력이 최근 위로 **세 줄까지** 보이고 넘치면 「더 보기」가 붙는다. **줄이 하나뿐이면 이력을 안 그린다.** 이력 줄은 안 눌린다 — 그 시점으로 되돌리는 길이 없다
- 검증 층: e2e
- 근거: [wages.md 「시급 짜임」](../modules/payroll/screens/wages.md#시급-짜임)

### AC-07

- 전제: 근무자
- 행동: `/admin/wages`에 직접 닿는다. 또는 함수를 직접 부른다
- 관찰 결과: 화면이 안 뜨고 `/`로 간다. 쓰기 함수 셋은 `not_allowed`로 거절한다. 남의 시급은 한 행도 안 온다
- 검증 층: integration — RLS와 함수 거절이 DB에 있다
- 근거: [navigation.md 「경로」](../system/navigation.md#경로)

## 상태 격자

| 자리 | 무엇이 뜨나 | AC |
| --- | --- | --- |
| 빈 상태 | 승인된 사람이 하나도 없으면 목록 자리가 빈 상태고 **기본 시급 줄은 그때도 선다**. 기본을 쓰는 사람이 0명이면 그 아래 줄의 문구가 바뀐다 — 「0명이 이 값을 써요」가 아니다. 이력이 한 줄뿐이면 이력 자체를 안 그린다 | AC-01, AC-02, AC-06 |
| 로딩 | 첫 진입에 스켈레톤, 캐시가 있으면 표시 없음 — [runtime.md 「로딩」](../system/runtime.md#로딩)의 기본값을 상속한다. 사람 시트의 이력은 **목록이 이미 받은 데이터에서 갈라 쓴다** — 시트를 열 때 질의를 새로 안 던져 로딩이 없다 | AC-01, AC-06 |
| 실패 | **저장이 실패하면 시트가 안 닫히고 넣은 값이 칸에 그대로 있다.** 문구 두 줄이 서는데 사람이 먼저 걱정하는 것이 방금 넣은 값이라 그것을 먼저 말한다 | AC-02, AC-03 |
| 권한 없음 | 근무자가 경로에 닿으면 `/`로 간다. 쓰기 함수 셋이 `not_allowed`고 남의 시급은 한 행도 안 온다 | AC-07 |
| 경계 | 상한 **100,000원**, 하한은 **0 초과 하나**다. 최저임금을 안 본다 — 틀린 경고가 없는 경고보다 나쁘다. 지금 값과 같거나 빈 칸이거나 0이면 저장이 안 눌린다. 퇴사한 사람은 목록에 없다 | AC-01, AC-05 |
| 재진입 | 시트를 다시 열면 지금 시급이 채워져 있다. 기본을 쓰는 사람도 기본값이 채워진 채 열린다 — 빈 칸이 아니다 | AC-03 |
| 동시 변경 | 관리자 둘이 같은 날 같은 사람의 시급을 고치면 **늦은 쪽이 그날 줄을 덮어쓴다**([PAY-011](../modules/payroll/README.md#pay-011)). 이력에 그날 줄이 하나만 남고 마지막 값이 산다. 기본 시급도 같다 | AC-02, AC-03 |
| 성공 직후 | 시트가 닫히고 토스트가 뜨며 목록의 값이 바뀐다. 기본 시급을 바꾸면 그 값을 쓰는 사람들의 줄이 같이 움직인다. 되돌리기는 그 사람 줄이 기본값으로 내려간다 | AC-02, AC-03, AC-04 |

## 범위 밖

- 금액을 실제로 계산하는 것 — `payroll-data`가 이미 냈다. 이 화면은 시급을 넣는 자리까지다
- 근무자가 자기 급여를 보는 자리 — [payroll-view](payroll-view.md)
- 결근·연장 조정 — [payroll-adjust](payroll-adjust.md)
- 공휴일 받아오기 — `payroll-holidays`
- 퇴사한 사람의 지난 시급 — 목록에 없지만 이력은 남는다. 지난 급여가 흔들리면 안 된다

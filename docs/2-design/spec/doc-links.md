# 마크다운 문서를 읽는 모듈을 세우고 깨진 링크를 잡는다

문서가 테스트 입력인 저장소인데 마크다운 제목을 읽는 정규식이 저장소 안팎 다섯 곳에 각자 있었다. 그중 둘은 저장소 밖 임시 스크립트로 두 세션에서 따로 짜인 링크 검사였고, 슬러그 규칙이 서로 달랐으며 둘 다 중복 제목의 번호 앵커(`#색-1`)를 못 세어 가짜 지적을 냈다. 순회는 대상이 검사마다 달라 겹치지 않는다 — 겹치는 것은 마크다운 구조 하나라 seam을 거기에만 세운다.

## 완료 조건

- `tests/lint/markdown.ts`가 마크다운 원문 문자열 하나를 받아 구조를 돌려준다 — 제목(급·글·앵커 슬러그·줄), 링크(코드블록과 인라인 코드 밖의 것만, 줄 포함), 백틱 코드스팬, 그리고 어느 제목 아래 줄들을 그 제목부터 다음 같은 급 제목 전까지 잘라 주는 것. **파일시스템을 모른다.** 파일을 찾고 읽는 일은 호출자 몫이다.
- 앵커 슬러그는 GitHub 규칙이다 — 소문자로, 백틱과 별표를 벗기고, 공백은 `-`로, 한글·영숫자·`-`·`_` 밖의 글자는 지운다. 같은 제목이 되풀이되면 둘째부터 `-1`·`-2`가 붙는다.
- 짝 테스트 `tests/lint/markdown.test.ts`가 문자열을 넣어 구조를 확인한다. 픽스처 파일 없이 인라인 문자열로 충분해야 한다 — 이 모듈의 인터페이스가 곧 테스트 표면이다.
- `tests/lint/doc-links.ts`가 `docs/` 아래 `.md` 전부(`docs/log/` 제외)를 읽어, 상대 링크 중 **가리키는 파일이 없는 것**과 **`#앵커`가 그 파일의 제목에 없는 것**을 `pnpm test`에서 잡는다. `http(s):`와 `mailto:`는 안 본다. 코드블록과 인라인 코드 안의 링크도 안 본다 — 그 자리는 예시라서다. 예외 목록은 두지 않는다.
- `tests/lint/doc-map.ts`가 절 찾기와 코드스팬 뽑기를 `markdown.ts`에 넘긴다. 남는 것은 `docs/` 접두사 필터와 존재 확인뿐이다. 기존 `doc-map.test.ts`가 고치지 않은 채 그대로 통과한다.
- 순회는 `readdirSync({ recursive: true })`다. `globSync`는 Node 22에서 experimental이라 실행마다 경고를 찍는다.
- 지금 저장소의 문서에서 이 검사가 잡는 것이 0건이다. 검사를 켜는 커밋과 문서를 고치는 커밋이 갈리지 않는다 — 켜는 순간 초록이어야 한다.

## 범위 밖

- `scripts/tokens-md.mts`의 절 나누기를 이 모듈 위로 옮기는 것. 지금 아프지 않은 자리고, `generate-globals-css.mts`에 복제된 `SUBSECTION` 정규식과 묶어 따로 간다.
- `legacy-doc-paths.ts`·`sian-html.ts`의 순회를 공용으로 빼는 것. 넷의 대상 집합이 다 달라 하나로 묶으면 옵션이 인터페이스를 넓힐 뿐이다. 순회가 아파지면 그때 본다.
- `docs/log/`의 링크. 회차 기록은 당시 경로를 그대로 두는 원칙이 문자열 검사와 같이 걸린다.

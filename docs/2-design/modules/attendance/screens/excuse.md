# 사유 시트

## 목적과 진입

인증 창이 닫힌 뒤 「사유 넣기」를 누르면 올라오는 바텀시트다. 쓰는 것부터 결과까지 이 시트 안에서 끝난다.

값은 [tokens.md](../../../design-system/tokens.md)에만 있고 여기는 토큰 이름으로만 말한다.

버튼이 서는 자리는 [dashboard.md](../../../system/screens/dashboard.md)의 못 찍음 블록이고, 시트가 닫힌 뒤의 대시보드가 결과를 이어받는다.

[components.md](../../../design-system/components.md#dialog와-바텀시트)의 Dialog와 바텀시트를 그대로 쓴다. 왼쪽이 「닫기」이고 오른쪽이 primary인 것도 그 문서가 정한 대로다.

움직이는 모습은 옆의 `excuse.sian.html`을 브라우저로 열어 본다. 구현할 때 이 문서와 그 파일과 [tokens.md](../../../design-system/tokens.md) 셋을 같이 연다. 시안과 이 문서가 어긋나면 이 문서가 이긴다.

경로와 역할 조건은 [navigation.md](../../../system/navigation.md#경로)가 든다.

## 화면 상태와 흐름

못 찍은 근무자가 대시보드의 「사유 넣기」 시트에서 낸다(`submit_excuse`) → 관리자 `/admin/approvals` → 판정(`decide_excuse`)은 목록에 머문다 → 근무자에게 결과 알림 → `/schedule?date=` 그날 명단의 자기 상태.

관리자에게 사유가 왔다는 알림은 없다 — 승인할 일 줄의 건수가 대신한다.

| 상태 | 진입 조건·계기 | 보이는 내용 | 가능한 행동 | 다음 상태·목적지 |
| --- | --- | --- | --- | --- |
| 열자마자 | 대시보드의 「사유 넣기」 | 손잡이, 제목, 날짜 줄, 라벨 줄, 빈 칸에 자리표시, 버튼 둘. 보내기 잠김 | 쓴다, 닫기 | 다섯 자를 넘기면 보내기가 눌린다. 닫기 → [dashboard.md](../../../system/screens/dashboard.md) |
| 다섯 자 미만 | 칸에 다섯 자가 안 찼다 | 보내기 잠긴 채 칸 아래에 도움말 | 더 쓴다, 닫기 | 다섯 자를 넘기면 보내기가 눌린다 |
| 서른 자 남음 | 상한까지 서른 자가 남았다 | 라벨 줄 오른쪽에 글자 수가 나타난다 | 더 쓴다, 보내기, 닫기 | 200자 |
| 200자 | 상한에 닿았다 | 숫자가 `critical` 색이 되고 더 안 들어간다 | 보내기, 닫기 | 보내는 중 |
| 보내는 중 | 「보내기」를 누른다 | 오른쪽 버튼에서 링이 돌고 닫기도 같이 잠긴다 | — | 보냄 또는 못 보냄 |
| 보냄 | 제출이 기록됐다 | 원과 체크, 결과 제목과 아래 줄 | — | 1.65초 뒤 저절로 닫히고 [dashboard.md](../../../system/screens/dashboard.md) |
| 못 보냄 | 제출이 실패했다 | 원이 흔들리고 ✕. 쓴 글은 시트에 그대로 | 다시 보내기, 닫기 | 보내는 중 또는 [dashboard.md](../../../system/screens/dashboard.md) |
| 이미 보낸 뒤 다시 열기 | 이미 낸 날의 「사유 넣기」 | 읽기 전용 칸과 「확인 중」 배지. 버튼은 닫기 하나 | 닫기 | [dashboard.md](../../../system/screens/dashboard.md) |
| 반려된 뒤 | 관리자가 반려한다 | 시트가 아니라 다음에 앱을 열었을 때 대시보드 블록으로 | 사유 다시 쓰기 | 열자마자 |
| 키보드가 올라옴 | 칸에 커서가 간다 | 시트가 키보드 위에 올라앉는다 | — | — |

각 자리의 문구는 [사유 시트 문안](#사유-시트-문안)이 소유한다.

## 짜임과 토큰

### 사유 시트 짜임

| 자리 | 무엇 |
| --- | --- |
| 뒤 덮개 | 대시보드를 덮는다 |
| 손잡이 | 시트 맨 위 가운데 |
| 제목 | 왜 못 찍었는지 알려주세요 |
| 날짜 줄 | 어느 날 어느 근무의 사유인지 |
| 입력 | 라벨 줄 · 칸 · 필요할 때만 나오는 도움말 |
| 버튼 두 개 | 왼쪽 닫기, 오른쪽 보내기 |

**결과가 같은 시트 안에서 난다.** 시트가 사라졌다 다른 것이 뜨는 것이 아니라 시트의 내용만 결과로 바뀐다. 손잡이와 시트의 네 모서리가 그 자리에 그대로 있어서, 방금 누른 것에 대한 답이라는 것이 자리로 읽힌다.

**성공은 저절로 닫히고 실패는 안 닫힌다.** 성공은 1.65초 뒤 시트가 내려간다. 사람이 할 일이 남아 있지 않고, 닫힌 뒤의 대시보드에 결과가 두 자리(블록 아래 줄과 버튼)에 남아 있어서 놓칠 일이 없다. 실패는 다시 보낼지 닫을지를 사람이 정해야 해서 안 닫는다.

**덮개를 눌러도 안 닫힌다.** 쓰던 글이 있는데 바깥을 잘못 누르면 날아간다. 닫는 길은 「닫기」 하나다.

**반려된 뒤에는 다시 쓴다.** [attendance/README.md](../README.md#att-013)가 「거절되면 다시 넣는다」로 닫았다 — 마감(근무 뒤 48시간)이 이미 횟수를 막고 있어 따로 상한을 안 둔다. 보낸 사유를 고치는 길은 없다. 관리자가 이미 읽었을 수 있어서 판단의 근거가 뒤에서 바뀌면 안 되고, 그래서 「이미 보낸 뒤 다시 열기」가 읽기 전용이다.

**다섯 자가 최소다.** 「네」나 「아파서」로는 관리자가 판단할 것이 없다. 최소를 두면 사람이 한 문장은 쓴다.

**200자가 상한이다.** [modules/](../../)에 길이 규칙이 없어서 여기서 정했다. 사유는 관리자가 여러 건을 훑는 글이고 한두 문장이면 충분하다. 상한에 닿아도 이미 쓴 글을 지우지 않는다 — 더 안 들어갈 뿐이다.

**글자 수가 보이는 시점과 자리는 [components.md의 Input](../../../design-system/components.md#input)이 정본이다.** 상한까지 서른 자가 남았을 때 라벨 줄 오른쪽에 나타난다.

**보내는 동안 닫기까지 잠근다.** 중간에 닫으면 갔는지 안 갔는지 알 길이 없다. 대신 도는 시간이 끝나면 반드시 다음 화면이 온다 — 체크 아니면 ✕다. [motion.md](../../../design-system/foundation/motion.md#축하할-순간)가 「돌기만 하다 사라지면 끝난 것인지 실패한 것인지 모른다」고 한 자리다.

**키보드가 올라오면 시트째 올린다.** 가려지는 쪽만 밀면 입력 칸과 버튼 중 하나가 화면 밖으로 나간다. 둘 다 보여야 쓰고 바로 보낼 수 있다.

#### 사유 시트 색

| 자리 | 토큰 |
| --- | --- |
| 뒤 덮개 | 라이트는 `bg.neutral-solid`, 다크는 팔레트의 `neutral-00`. 투명도 42% |
| 시트 면 | `bg.neutral` |
| 제목 | `fg.neutral` |
| 날짜 줄 | `fg.neutral-subtle` |
| 라벨 | `fg.neutral-muted` |
| 입력 칸 면 | `bg.neutral-weak` |
| 입력 칸 테두리 | `stroke.neutral` |
| 입력 칸 테두리 — 쓰는 중 | `stroke.brand-solid` |
| 자리표시 글자 | `fg.neutral-subtle` |
| 입력 글자 | `fg.neutral` |
| 글자 수 | `fg.neutral-subtle` |
| 글자 수 — 상한 | `fg.critical` |
| 도움말 | `fg.neutral-muted` |
| 성공 원 | `bg.neutral` 면에 `bg.brand-solid` 테두리 2px |
| 성공 체크 | `fg.brand` |
| 번지는 링 | `bg.brand-solid` |
| 실패 원 | `bg.critical-weak` 면에 `bg.critical-solid` 테두리 2px |
| 실패 ✕ | `fg.critical` |
| 읽기 전용 칸 | `bg.neutral-weak`에 테두리 없음. 글자는 `fg.neutral-muted` |
| 「확인 중」 배지 | `bg.neutral-weak` 면에 `fg.neutral-muted` |
| 반려 블록 | `bg.critical-weak`. 아이콘은 `fg.critical` |

**성공은 브랜드 색이고 실패는 `critical`이다.** [color.md](../../../design-system/foundation/color.md)가 `critical`을 「오류와 되돌릴 수 없는 파괴. 결근, 삭제」로 정했다. 보내기 실패는 되돌릴 수 없는 것이 아니지만 사람이 알아야 할 나쁜 소식이고, 이 팔레트에서 나쁜 소식을 말하는 색은 그것뿐이다.

**오류 테두리를 안 쓴다.** [components.md](../../../design-system/components.md#input)의 Input이 오류 테두리를 `bg.critical-solid`로 정했다. 이 시트에서는 다섯 자 미만이어도 테두리를 안 물들인다. 덜 쓴 것은 틀린 것이 아니라 아직 안 쓴 것이고, 쓰는 도중에 붉어지면 재촉으로 읽힌다.

**색만으로 실패를 안 알린다.** 같은 문서가 「색약인 사람에게는 테두리 색 변화가 안 보인다」고 했다. 실패는 색 말고도 셋으로 말한다 — ✕ 모양, 흔들리는 움직임, 「사유를 보내지 못했어요」라는 문장이다.

**덮개가 다크에서 뒤집히면 안 된다.** `bg.neutral-solid`는 [tokens.md](../../../design-system/tokens.md)의 적응형 팔레트를 따라 다크에서 밝은 회색이 된다. 그대로 쓰면 화면을 흰 막이 덮는다. 덮개만 팔레트를 안 따르고 어두운 쪽에 고정한다. 아래 「규칙과 부딪힌 자리」에 적었다.

#### 사유 시트 글자

| 자리 | 유틸 |
| --- | --- |

## 문안

### 사유 시트 문안

| 자리 | 문장 |
| --- | --- |
| 제목 | 왜 못 찍었는지 알려주세요 |
| 날짜 줄 | 9월 12일(토) · 10:00–19:00 근무 |
| 라벨 | 무슨 일이 있었나요 |
| 자리표시 | 가게에 있었지만 위치가 안 잡혔어요 |
| 도움말 — 다섯 자 미만 | 조금 더 자세히 써주세요 · 다섯 자 이상 |
| 도움말 — 상한 | 여기까지만 쓸 수 있어요 |
| 왼쪽 버튼 | 닫기 |
| 오른쪽 버튼 | 보내기 |
| 오른쪽 버튼 — 보내는 중 | 보내는 중 |
| 성공 제목 | 사유를 보냈어요 |
| 성공 아래 줄 | 관리자가 확인하면 알려드릴게요 |
| 실패 제목 | 사유를 보내지 못했어요 |
| 실패 아래 줄 | 쓴 내용은 그대로 있어요 · 다시 보내볼게요 |
| 실패 오른쪽 버튼 | 다시 보내기 |
| 이미 보낸 뒤 제목 | 보낸 사유예요 |
| 이미 보낸 뒤 날짜 줄 | 9월 12일(토) · 18:52에 보냈어요 |
| 이미 보낸 뒤 라벨 | 보낸 내용 |
| 상태 배지 | 확인 중 |
| 반려 블록 제목 | 사유가 받아들여지지 않았어요 |
| 반려 블록 아래 줄 | 관리자가 「위치 기록이 없어요」라고 남겼어요 |
| 반려 버튼 | 사유 다시 쓰기 |

**실패 문구가 사람을 안 탓한다.** 「쓴 내용은 그대로 있어요」를 먼저 말한다. 보내기가 실패했을 때 사람이 가장 먼저 걱정하는 것은 방금 쓴 글이 날아갔는지다. 무엇이 잘못됐는지는 그다음이고, 그것도 사람이 한 일이 아니다.

**「취소」가 아니라 「닫기」다.** [writing.md](../../../design-system/writing.md#다이얼로그-왼쪽-버튼은-닫기다)가 정한 대로다.

**제목이 질문이다.** 「사유 입력」이 아니라 「왜 못 찍었는지 알려주세요」다. 칸 하나를 채우는 일이라 무엇을 쓰는 칸인지 제목이 말해주면 라벨을 두 번 읽지 않아도 된다.

**「사유」를 화면에 안 쓴다.** 제목과 라벨은 「왜 못 찍었는지」와 「무슨 일이 있었나요」다. [writing.md](../../../design-system/writing.md#도메인-용어를-그대로-쓴다)의 용어 표에 「사유」가 없어서 정본 표기가 아니고, 그 말 자체가 서류의 말이다. 다만 대시보드의 버튼은 「사유 넣기」다 — 거기서는 무엇을 하러 가는지를 짧게 말해야 하고 「왜 못 찍었는지 쓰기」는 버튼에 길다.

## 모션

### 사유 시트 모션

| 무엇 | 어떻게 | 길이 |
| --- | --- | --- |
| 시트 열기 | 아래에서 올라온다. 덮개가 같은 시간에 밝아진다 | `--duration-slow` |
| 보내는 중 | 오른쪽 버튼 안에서 링이 돈다 | 응답이 올 때까지 |
| 성공 | 링 둘이 밖으로 번지고, 흰 원이 튀어오르고, 체크가 왼쪽부터 그어진다 | 800ms |
| 실패 | 원이 좌우로 흔들리고 ✕가 두 획으로 차례로 그어진다 | 620ms |
| 시트 닫기 | 아래로 내려간다 | `--duration-slow` |

바텀시트가 `--duration-slow`인 것은 [motion.md](../../../design-system/foundation/motion.md)가 정한 값이다.

**사유 제출은 축하가 아니다.** [motion.md](../../../design-system/foundation/motion.md#축하할-순간)가 확실한 축하로 둘을 꼽았고 — 출근 인증 완료와 가입 프로필을 보낸 순간 — 사유는 거기 없다. 보낸 것은 결과 확인이다.

그래서 같은 어휘를 쓰되 크기를 줄였다. 인증은 일곱 겹이 1050ms 동안 터지고, 여기는 링 둘과 원 하나와 획 하나가 800ms다. 섬광도 방사도 없다. **어휘가 같아야 「끝났다」로 읽히고 크기가 달라야 무엇이 더 큰 일인지 안다.**

**실패는 안 터진다.** 링이 없다. 밖으로 번지는 것은 좋은 소식의 모양이라 실패에 붙이면 뜻이 어긋난다. 실패는 제자리에서 흔들리고 멈춘다.

**✕도 그어진다.** 두 획이 180ms와 400ms에 차례로 간다. 성공의 체크와 같은 어휘라 「같은 자리에서 다른 답이 나왔다」로 읽힌다. 다 그려진 ✕가 나타나면 결과가 먼저 와 있던 것처럼 보인다.

**결과에서 뒤 화면이 안 움직인다.** 시트가 덮고 있는 동안 대시보드는 아무것도 안 바꾼다. 시트가 다 내려간 뒤 220ms에 버튼과 블록이 바뀐다.

**움직임 줄이기.** 켠 사람에게는 시트가 미끄러지지 않고 그 자리에 나타난다. 링과 흔들림이 빠지고 체크와 ✕는 그어지지 않고 다 그려진 채로 나타난다. 커서 깜빡임도 멈춘다.

## 예외와 미정

### 안 담은 것

**관리자가 판정하는 화면.** 사유가 도착한 뒤의 목록과 판정은 [approvals.md](../../../system/screens/approvals.md)에 있다.

대시보드가 안 담은 것은 [dashboard.md](../../../system/screens/dashboard.md#안-담은-것)에 있다.

### 규칙과 부딪힌 자리

몰라서 어긴 것과 알고 정한 것은 다르다. 뒤에 오는 사람이 이 자리를 버그로 고치지 않게 남긴다. 나머지 자리는 [dashboard.md](../../../system/screens/dashboard.md#규칙과-부딪힌-자리)에 있다.

**알림 블록의 「성공」을 안 쓴다.** [components.md](../../../design-system/components.md#알림-블록)의 알림 블록은 안내·성공·경고·오류 넷이다. 사유를 보낸 결과에 성공 블록을 쓰지 않고 시트 안에서 끝냈다. 성공 블록이 필요 없다는 뜻은 아니고, 이 자리에서는 결과가 이미 시트에서 났다.

**덮개 색을 가리키는 토큰이 없었다 — 닫혔다.** [components.md](../../../design-system/components.md#dialog와-바텀시트)가 뒤 덮개를 「`bg.neutral-solid`에 투명도」로 정했는데 그 토큰이 적응형 팔레트를 따라 다크에서 밝은 회색이 되어, 덮개가 화면을 흰 막으로 덮었다. `bg.scrim`이 [tokens.md](../../../design-system/tokens.md#bg)에 서면서 닫혔다 — 라이트 `neutral-1000`, 다크 `neutral-00`에 투명도 42%가 값 안에 들어 있다. 이 토큰을 받으려고 「팔레트 칸이 `—`인 행」 규칙도 같이 섰다.

**Input의 오류 테두리를 안 쓴다 — 닫혔다.** 사유 칸은 다섯 자 미만이어도 테두리를 안 물들이고 아래 도움말로만 알린다. [components.md](../../../design-system/components.md#input)에 「아직 쓰는 중인 것에는 오류 테두리를 안 쓴다」가 조항으로 섰다 — 오류 테두리는 사람이 보낸 뒤에 거절당한 자리 몫이다.

**「사유」가 도메인 용어 표에 없다 — 닫혔다.** [writing.md](../../../design-system/writing.md#도메인-용어를-그대로-쓴다)에 「사유」가 쓰는 말로 섰고(안 쓰는 말은 「소명」·「이의 신청」), 「사람에게 물을 때만 풀어 쓴다」가 같이 박혔다. 이 화면이 버튼에 「사유 넣기」를 쓰고 시트 제목은 「왜 못 찍었는지 알려주세요」로 푸는 것이 그 조항 그대로다.

### 아직 안 정한 것

임의로 채우지 않는다. 사람이 정하고 나서 이 절에서 뺀다. 「제안」으로 그린 것은 결정되면 본문에서 표시를 뗀다.

비어 있다.

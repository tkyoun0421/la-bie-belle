# 여백과 모양

규칙과 근거를 담는다. 눈금과 반지름과 그림자 값은 [tokens.md](../tokens.md#4-스페이싱)에만 있다.

## 스페이싱

눈금은 열셋이다. Tailwind의 `--spacing` 기본값을 그대로 쓰므로 유틸 숫자가 곧 눈금 자리다. 눈금과 유틸 숫자의 대응표는 [tokens.md](../tokens.md#4-스페이싱)에 있다.

### 주 리듬

여백을 고를 때 `2`에서 시작해 `4`, `6`, `8`로 간다. 이 넷이 화면 대부분을 덮는다.

| 유틸 | 쓰는 자리 |
| --- | --- |
| `gap-2` | 붙어 있는 것들 사이. 아이콘과 라벨, 배지와 배지 |
| `p-4` | 카드 안쪽 여백, 목록 한 줄의 위아래 |
| `gap-6` | 카드와 카드 사이 |
| `mt-8` | 섹션과 섹션 사이 |

### 가장 작은 두 눈금은 미세 조정에만

`0.5`와 `1.5`는 눈금에 있지만 레이아웃에 쓰지 않는다. 아이콘이 글자 기준선에서 조금 뜰 때, 배지 안쪽이 `1`로는 답답하고 `2`로는 헐렁할 때 쓴다.

레이아웃에 이 둘이 섞이면 눈금이 사실상 절반 단위로 촘촘해진다. 그러면 어떤 값을 골라도 되니까 아무도 고민하지 않고, 화면마다 여백이 조금씩 달라진다. 눈금을 두는 이유가 고민을 줄이는 것인데 그게 사라진다.

### 누를 수 있는 것은 44px 이상이다

손가락이 닿는 면이 가로세로 44px보다 작으면 안 된다. 아이폰 사파리가 주 타깃이라 애플 HIG의 44pt를 기준으로 삼았다.

**보이는 크기와 닿는 크기는 다르다.** 아이콘 버튼을 44px로 그리라는 뜻이 아니다 — 모양은 필요한 만큼만 그리고 그 밖으로 투명한 여백을 둘러 닿는 면을 44px로 채운다. 대시보드 알림 줄의 ✕가 그 자리다. 32px 아이콘이 눈에 맞는데 그것을 44px로 키우면 지우는 버튼이 화면에서 제일 세진다.

이 규칙은 닿는 면에만 걸린다. 안 눌리는 것에는 최소 크기가 없다.

**가로로 여럿이 서는 자리는 가로 폭이 이 값을 못 지킬 수 있다.** 달력 칸이 일곱, 세그먼트가 둘씩 서는 화면에서 375px을 나누면 44px이 안 나온다. 그때는 세로를 44px 이상으로 두고 가로는 줄 수 있는 만큼 준다 — 사람이 세로로 훑으며 누르는 자리라 위아래 여유가 잘못 누르는 것을 더 막는다. 이 예외를 쓴 자리는 그 화면 문서에 적는다.

### 눈금 밖 숫자

Tailwind는 `p-7`도 만들어준다. 만들어준다고 쓰지 않는다.

`p-7`이 필요해 보이면 대개 안쪽 요소의 크기가 어긋난 것이다. 여백으로 메우기 전에 그쪽을 본다.

### 이 눈금은 우리가 정했다

타이포그래피는 TDS의 스케일을 그대로 가져왔지만 스페이싱은 그렇지 않다. TDS가 스페이싱 눈금을 공개하지 않았다. 기준 단위와 열세 단계는 우리가 정했다.

바꿀 여지가 타이포그래피보다 크다는 뜻이다. 실제 화면을 그리다 눈금이 안 맞는 자리가 반복해서 나오면 그때 고친다.

## 라운딩

| 유틸 | 쓰는 자리 |
| --- | --- |
| `rounded-none` | 화면 폭에 붙는 면 |
| `rounded-xs` | 아직 배정 없음 |
| `rounded-sm` | 배지, 달력 칸 |
| `rounded-md` | 입력 |
| `rounded-lg` | 버튼, 세그먼트, 토스트, 작은 카드, 다이얼로그 |
| `rounded-xl` | 카드 |
| `rounded-full` | 원과 트랙 |

이름은 Tailwind 기본 이름을 쓰고 값만 갈아끼웠다. 타이포그래피와 같은 이유다. shadcn 컴포넌트가 `rounded-md`와 `rounded-xl`을 그대로 뱉는데, 값이 우리 것이면 설치하는 순간 스케일 안으로 들어온다.

`rounded-xs`는 아직 쓸 자리를 안 정했다. 어울리는 자리가 나오면 이 표에 적는다. 자리를 미리 지어내지 않는다.

### 누를 수 있는 것은 lg다

버튼도 세그먼트도 토스트도 `rounded-lg`(14px)다. 입력(12px)보다 크고 카드(20px)보다 작아서, 모서리만 보고도 「면 → 누를 것 → 적을 것」이 갈린다. 카드와 같은 값을 주면 누를 수 있는 것과 그냥 면이 섞이는데, 두 단계를 사이에 두면 그 일이 안 일어난다.

알약(`rounded-full`)을 버린 것은 곡률이 높이의 절반이라 48px 버튼이 좌우 반원이 되기 때문이다. 버튼 하나만 보면 시원한데, 한 화면에 버튼과 배지와 세그먼트와 토스트가 같이 서면 화면 전체가 둥글게 뭉개진다. 고정값이라 높이를 바꿔도 모서리가 안 따라오는 것은 값을 잃은 쪽이지만, 버튼 높이가 36·40·48 셋뿐이라 셋 다 14px에서 같은 얼굴이 된다.

배지는 한 단계 아래인 `rounded-sm`(8px)이다. 높이가 24px이라 14px을 주면 곡률이 높이의 절반을 넘어 다시 알약이 된다.

`rounded-full`은 원을 그리는 자리에만 남는다 — 사진과 이니셜 원, 안 읽음 점, 시트 손잡이, 하루 띠의 트랙과 채움, 스위치, 그리고 글자 없이 아이콘만 든 정사각형 버튼. 가로세로가 같거나 높이가 몇 픽셀인 조각이라 고정값을 주면 모양이 깨진다.

높이 32px 이하인 작은 버튼도 `rounded-sm`(8px)으로 내린다. 그 높이에서 14px은 곡률이 절반에 가까워 결국 알약으로 보인다.

### 안쪽 라운딩

카드 안에 카드를 넣을 때 안쪽을 바깥쪽과 같은 값으로 두면 모서리가 어긋나 보인다. 한 단계 내린다. `rounded-xl` 안에는 `rounded-lg`가 들어간다.

## 그림자와 면 나누기

라이트에서는 그림자로 면을 띄우고, 다크에서는 선으로 면을 나눈다.

`shadow-card`는 다크에서 `none`이 되고, `stroke.surface`는 라이트에서 투명이고 다크에서만 색을 갖는다. 카드에는 둘을 항상 같이 건다.

```
bg-bg-neutral rounded-xl shadow-card border border-stroke-surface
```

라이트에서는 테두리가 투명이라 그림자만 보이고, 다크에서는 그림자가 없어 테두리만 보인다. 클래스 목록은 양쪽에서 같다. `dark:` 조건을 화면 코드에 뿌리지 않으려고 이렇게 짰다.

### 다크에서 그림자를 버리는 이유

그림자는 배경보다 어두운 색을 깔아 면이 떠 보이게 하는 방식이다. 배경이 이미 거의 검정인 다크에서는 더 어두워질 자리가 거의 없다. 그림자를 그려도 안 보이고, 보이게 하려고 진하게 만들면 검은 얼룩이 된다.

다크에서 면을 나누는 방법은 선이다. `stroke.surface`가 가리키는 단계는 다크 배경보다 한 칸 밝아서 가는 선으로도 경계가 읽힌다.

### 그림자 값의 구성

두 겹이다. 위 겹은 면이 배경에 닿는 자리를 잡고, 아래 겹은 넓고 흐리게 퍼져 떠 있는 느낌을 만든다. 아래 겹의 spread가 음수라서 그림자가 요소보다 좁게 잘리고 옆으로 새지 않는다.

색은 순수 검정이 아니라 `neutral-1000`에 가까운 브라운 계열이다. 순수 검정으로 그리면 브라운 화면에서 그림자만 차갑게 뜬다.

그림자는 셋이다. 카드와 바텀시트와 팝오버가 떠 있는 면의 전부고, 각각 `shadow-card`·`shadow-sheet`·`shadow-pop`이다. 단계라기보다 방향의 차이다 — 카드는 화면에 앉아 아래로 짧게, 팝오버와 Dialog는 화면 위에 떠 아래로 길게, 시트는 아래에서 올라와 위로 진다. 셋이 한 화면에 겹쳐 쌓이는 일이 없어서 그림자로 높이를 셈할 일은 없다. 값은 [tokens.md](../tokens.md#5-라운딩과-그림자)에 있다.

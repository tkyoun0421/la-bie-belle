# 가입 대기

관리자가 가입 신청을 받거나 물리는 화면이다. 값은 [tokens.md](../tokens.md)에만 있고 여기는 토큰 이름으로만 말한다.

들어오는 문은 하나다. 관리자 홈의 「가입 대기 · 2명」 줄이고([schedule-admin.md](schedule-admin.md#관리자-홈)) 그 줄이 이 화면을 연다. 새 신청이 들어와도 푸시는 안 간다 — 그 줄의 숫자가 유일한 신호다([domain/notification.md](../../domain/notification.md#알림이-안-나가는-자리)).

보내는 쪽 화면은 [login.md](login.md#프로필-작성)에 있다.

움직이는 모습은 옆의 `members-pending.sian.html`을 브라우저로 열어 본다. 시안과 이 문서가 어긋나면 이 문서가 이긴다.

## 목록

### 짜임

세로로 쌓는다.

1. 앱바 — 뒤로, 제목, 오른쪽 더보기
2. 줄 여럿
3. 빈 상태 — 기다리는 사람이 없을 때 2 대신 선다

**하단 버튼이 없다.** 이 화면의 동작은 줄마다 따로 있고 화면 전체를 끝내는 동작이 없다. [components.md](../components.md#bottomcta)가 「화면의 끝이 아닌 버튼은 여기 오지 않는다」고 정한 자리다.

**여럿을 한 번에 처리하지 않는다.** 체크박스를 두고 「3명 승인」을 만들지 않았다. 사람마다 받을지 말지가 갈리는 판단이고, 한 번에 넘기게 만들면 얼굴을 안 보고 넘기게 된다. 근무 요청 픽커가 여럿을 고르는 것은 같은 물음을 여러 명에게 던지는 것이라 성격이 다르다([schedule-admin.md](schedule-admin.md#사람-픽커)).

### 줄 하나

[components.md](../components.md#listrow)의 ListRow다. 왼쪽에 사진, 가운데에 이름과 보조 정보, 오른쪽에 화살표다.

| 자리 | 담는 것 |
| --- | --- |
| 사진 | 프로필 사진. 원 |
| 이름 | 프로필의 이름 |
| 보조 정보 | 보낸 지 얼마나 됐는지 |
| 오른쪽 | 화살표 |

**줄에는 승인 버튼이 없다.** 누르면 시트가 올라오고 거기서 정한다. 줄에서 바로 승인하면 성별과 생년월일과 연락처를 못 보고 누르게 되는데, 그 셋이 관리자가 사람을 알아보는 재료다([domain/account.md](../../domain/account.md#성별과-생년월일을-쓰는-곳)).

**보조 정보가 기다린 시간이다(제안).** 성별과 나이를 여기 붙일 수도 있었는데 안 붙였다. 목록에서 정할 것이 없으니 목록이 말할 것은 「누가」와 「얼마나 오래」뿐이다. 나머지는 시트가 말한다.

**오래 기다린 사람이 위다(제안).** 새로 온 사람을 위에 두면 오래 기다린 사람이 아래로 밀려 계속 안 처리된다.

### 빈 상태

기다리는 사람이 없으면 목록 자리에 한 줄이 선다. 그림을 그리지 않는다.

관리자 홈의 줄이 「가입 대기 · 0명」이어도 눌린다. 눌러 보고 비었다는 것을 확인하는 것이 안 눌리는 줄을 보고 왜 안 눌리나 하는 것보다 낫다.

### 색

| 자리 | 토큰 |
| --- | --- |
| 화면 바탕 | `bg.neutral` |
| 앱바 제목 | `fg.neutral` |
| 앱바 아이콘 | `fg.neutral` |
| 줄 | [components.md](../components.md#listrow)의 ListRow |
| 사진 테두리 | `stroke.neutral` |
| 빈 상태 글자 | `fg.neutral-subtle` |

**이 화면에 브랜드 색이 없다.** 목록에는 누를 수 있는 브랜드 면이 하나도 안 선다. 브랜드는 시트의 「승인」 하나에만 나간다([color.md](../foundation/color.md#브랜드-색을-아끼는-이유)).

### 글자

| --- | --- |
| 앱바 제목 | `text-lg font-semibold` |
| 줄 이름 | `text-base font-medium` |
| 줄 보조 정보 | `text-sm` |
| 빈 상태 | `text-sm` |

### 여백과 모양

| 자리 | 유틸 |
| --- | --- |
| 화면 좌우 여백 | `px-6` |
| 줄 | `py-4` |
| 사진 | `size-10` `rounded-full` |
| 사진과 글자 사이 | `gap-3` |

구분선은 사진 왼쪽 끝이 아니라 이름 왼쪽 끝부터 긋는다([components.md](../components.md#listrow)).

### 문안

| 자리 | 문장 |
| --- | --- |
| 앱바 제목 | 가입 대기 |
| 줄 보조 정보 — 오늘 | 오늘 보냈어요 |
| 줄 보조 정보 — 어제 | 어제 보냈어요 |
| 줄 보조 정보 — 그 전 | 3일 전에 보냈어요 |
| 빈 상태 | 기다리는 사람이 없어요 |

날짜를 안 쓰고 며칠 전인지로 적는다. 관리자가 여기서 보는 것은 언제 왔는지가 아니라 얼마나 기다렸는지다.

### 모션

**등장 모션이 없다.** [motion.md](../foundation/motion.md#자주-일어나는-것은-움직이지-않는다)대로다. 관리자가 필요할 때 드나드는 화면이다.

**줄이 사라질 때.** 승인이나 거절이나 차단이 끝나면 그 줄이 **오른쪽으로** 밀리며 사라지고 아래 줄이 올라온다. `--duration-base`다. 처리가 끝난 줄이라 목록 밖으로 나가는 쪽이 오른쪽이다 — 왼쪽은 뒤로 가는 방향이라 다른 뜻으로 읽힌다.

## 상세 시트

줄을 누르면 아래에서 올라온다. [components.md](../components.md#dialog와-바텀시트)의 바텀시트다.

### 짜임

1. 오른쪽 위 더보기
2. 사진
3. 이름
4. 값 넷 — 성별, 생년월일, 연락처, 이메일
5. 보낸 시각
6. 버튼 둘 — 「거절」과 「승인」

**이메일이 여기 있다.** 프로필의 다섯에는 없지만 구글 계정이 주는 것이고, 같은 이름 둘을 가르는 마지막 자리다.

**생년월일 옆에 나이를 같이 적는다.** 「1992년 3월 4일(34세)」다. 관리자가 실제로 쓰는 것은 나이인데 저장하는 것은 생년월일이라, 화면이 그 셈을 대신한다.

**「차단」은 버튼으로 안 선다.** 오른쪽 위 더보기 안에 있다. 관리자가 매일 하는 것은 승인이고 차단은 몇 달에 한 번이다. 계정을 계속 막는 동작을 승인 옆에 두면 잘못 누른다.

### 값이 빈 자리

**사진이 없을 수 있다.** 구글이 사진을 안 주는 계정이 있다. 그때는 회색 원에 이름 첫 글자가 선다. 목록 줄에서도 같다.

나머지 넷은 안 빈다. 프로필을 다 채워야 이 목록에 뜬다([domain/account.md](../../domain/account.md#가입이-끝나는-때)).

### 색

| 자리 | 토큰 |
| --- | --- |
| 시트 면 | `bg.neutral` |

| 값 라벨 | `fg.neutral-muted` |
| 값 | `fg.neutral` |

| 사진 없을 때 원 | `bg.neutral-weak` 면에 `fg.neutral-muted` |

**여기서는 「승인」이다.** [writing.md](../writing.md)의 「사람이 누르는 버튼은 예외다」는 상대에게 할 말을 버튼에 쓰는 조항인데, 이 버튼은 상대에게 하는 말이 아니라 관리자가 내리는 판정이다. 근무 요청 시트의 「근무할게요」와 갈리는 자리다.

### 모션

**시트.** 아래에서 올라오고 `--duration-slow`다.

**승인을 누르면.** 시트가 바로 닫히고 토스트가 뜬다. 확인을 한 번 더 묻지 않는다 — 관리자가 이 화면에서 가장 많이 하는 일이고, 잘못 승인한 사람은 직원 관리 화면에서 되돌린다.

**거절과 차단을 누르면.** 시트 안이 확인 모습으로 바뀐다. 아래 「확인」 절에 있다.

## 거절과 차단 확인

시트가 새로 뜨지 않고 지금 시트의 안쪽이 바뀐다. 사진과 이름은 그 자리에 남고 값 넷 자리에 물음이 선다.

**시트를 새로 쌓지 않는 이유.** 시트 위에 시트를 얹으면 덮개가 두 겹이 되고, 뒤로 가는 길이 두 단이 된다. 물어보는 대상은 같은 사람이라 화면이 바뀔 이유가 없다.

| 자리 | 거절 | 차단 |
| --- | --- | --- |
| 제목 | 윤태관 님을 안 받을까요 | 윤태관 님을 차단할까요 |
| 아래 줄 | 다시 보내면 목록에 또 떠요 | 이 구글 계정으로는 다시 못 들어와요 |
| 왼쪽 버튼 | 닫기 | 닫기 |
| 오른쪽 버튼 | 거절 (secondary) | 차단 (destructive) |

**차단만 destructive다.** 계정을 계속 막는 것이고 푸는 데 관리자 손이 또 든다.

**「닫기」다.** 「취소」가 아니다([writing.md](../writing.md#다이얼로그-왼쪽-버튼은-닫기다)).

닫기를 누르면 상세 시트로 돌아간다. 시트가 통째로 닫히지 않는다.

**보낸 시각도 같이 빠진다.** 값 넷과 함께 사라진다. 남는 것은 사진과 이름뿐이다 — 이 자리가 묻는 것은 「이 사람이 맞나」와 「정말 할 건가」 둘이고, 언제 보냈는지는 그 둘 중 어느 쪽도 아니다.

**더보기 아이콘은 감춘다.** 물음이 선 동안 다른 길을 열어두지 않는다. 닫기로 상세로 돌아가면 다시 뜬다.

| 자리 | 유틸 | 토큰 |
| --- | --- | --- |
| 확인 제목 | `text-base font-medium` | `fg.neutral` |
| 확인 아래 줄 | `text-sm` | `fg.neutral-muted` |

시트 안쪽이 바뀌는 데 `--duration-base`가 든다. 사진과 이름은 안 움직이고 그 아래만 바뀐다.

## 끝난 뒤

셋 다 토스트로 알린다. [components.md](../components.md#토스트)의 성공 종류다.

| 무엇 | 토스트 |
| --- | --- |
| 승인 | 윤태관 님을 승인했어요 |
| 거절 | 윤태관 님을 안 받았어요 |
| 차단 | 윤태관 님을 차단했어요 |

토스트에 「되돌리기」를 안 붙인다. [components.md](../components.md#토스트)가 「사라지는 것에 액션을 걸면 놓친 사람이 그 액션을 다시 찾을 길이 없다」고 정했다.

줄은 목록에서 사라진다. 승인된 사람은 직원이 되고, 거절된 사람은 다시 보낼 때까지 없고, 차단된 사람은 「차단한 사람」으로 옮겨간다.

**둘이 같은 사람을 동시에 열었으면(제안).** 먼저 누른 쪽이 이긴다. 늦게 누른 쪽은 시트가 닫히고 「이미 처리된 사람이에요」가 안내 토스트로 뜨며 목록이 새로 그려진다. 근무 요청의 늦은 수락과 같은 결이다([schedule-worker.md](schedule-worker.md)).

## 차단한 사람

목록 화면 앱바의 더보기 안에 「차단한 사람」이 있다. 누르면 같은 모양의 목록이 열린다.

| 자리 | 담는 것 |
| --- | --- |
| 앱바 제목 | 차단한 사람 |
| 줄 | 사진, 이름, 차단한 지 얼마나 됐는지 |
| 줄 오른쪽 | 「차단 풀기」 |
| 빈 상태 | 차단한 사람이 없어요 |

**여기는 줄에서 바로 누른다.** 상세 시트가 없다. 여기서 하는 판단은 「이 사람 맞나」 하나고 그건 사진과 이름이 답한다.

「차단 풀기」를 누르면 확인 시트가 올라온다. 풀면 그 계정이 다시 로그인할 수 있고, 프로필을 다시 보내면 가입 대기 목록에 뜬다.

| 자리 | 문장 |
| --- | --- |
| 줄 보조 정보 — 오늘 | 오늘 차단했어요 |
| 줄 보조 정보 — 어제 | 어제 차단했어요 |
| 줄 보조 정보 — 그 전 | 2주 전에 차단했어요 |
| 확인 제목 | 윤태관 님의 차단을 풀까요 |
| 확인 아래 줄 | 다시 로그인할 수 있게 돼요 |
| 확인 버튼 | 닫기 · 차단 풀기 |
| 토스트 | 윤태관 님의 차단을 풀었어요 |

목록과 같은 결이다 — 날짜를 안 쓰고 얼마나 됐는지로 적는다.

**확인 시트에 사진과 이름을 안 세운다.** 물음과 버튼 둘이다. 줄에서 사진과 이름을 보고 누른 직후라 같은 것을 한 번 더 세울 이유가 없다. 상세 시트에서 오는 거절·차단 확인과 갈리는 자리인데, 거기는 시트가 이미 서 있어서 사진과 이름이 **남는** 것이고 여기는 새로 **세우는** 것이다.

**「차단 풀기」는 destructive가 아니다.** 문을 여는 동작이다. 줄 오른쪽의 것은 secondary 알약이고 확인 시트 오른쪽의 것은 primary다 — 줄에서는 여럿이 나란히 서니 어느 하나가 튀면 안 되고, 시트에서는 그 화면이 묻는 것에 답하는 버튼이라 primary가 하나 선다.

## 안 담은 것

**이름을 고치는 자리.** 오타를 관리자가 고친다고 [domain/account.md](../../domain/account.md#이름)가 정했는데 그 자리는 직원 관리 화면이다. 이 화면은 아직 직원이 아닌 사람만 다룬다.

**직원 목록.** 승인된 사람을 보고 관리자로 올리거나 퇴사 처리하는 화면은 따로다.

**거절 사유.** 관리자가 사유를 안 적는다. 적게 하면 그 사유를 어디에 보여줄지가 따라오는데, 거절은 알림도 안 나가는 자리다.

**여럿 한 번에 처리.** 위 「짜임」에 이유가 있다.

**승인 되돌리기.** 잘못 승인한 사람을 여기서 못 되돌린다. 승인되는 순간 이 목록에서 나간다.

---

## 규칙과 부딪힌 자리

**시트 안에 버튼이 둘이다.** [components.md](../components.md#button)는 「한 화면에 primary는 하나다」이고 그건 지켰다 — 「승인」만 primary고 「거절」은 secondary다. 나란히 선 것이 걸리는 자리인데, 이 시트가 묻는 것이 「받을까 말까」 하나라서 답 둘이 같은 높이에 서는 것이 맞다고 봤다. 되돌릴 수 없는 쪽(차단)은 여기 없다.

**목록 줄에 상태 배지가 없다.** 대기 중인 사람만 뜨는 목록이라 배지로 나눌 상태가 없다. 「차단한 사람」을 같은 목록에 섞고 배지로 갈랐다면 배지가 필요했을 텐데, 그러면 매일 보는 목록에 몇 달에 한 번 볼 것이 섞인다.

## 아직 안 정한 것

임의로 채우지 않는다. 사람이 정하고 나서 이 절에서 뺀다.

**더보기를 눌렀을 때 뜨는 것의 모양.** 이 화면에 더보기가 둘이다 — 앱바의 것(「차단한 사람」)과 상세 시트의 것(「차단하기」). 그런데 열렸을 때의 면과 모서리와 그림자와 어느 쪽으로 붙는지가 [components.md](../components.md)에 없다. 이 화면 혼자 정할 것이 아니라 공용 컴포넌트로 올릴 자리고, 같은 모양이 다른 화면에서 한 번 더 나오면 그때 올린다.

**대기가 아주 많을 때.** 수십 명이 한꺼번에 들어오면 목록이 길어진다. 스크롤로 끝낼지 나눠 담을지 안 정했다. 웨딩홀 규모에서 실제로 그럴 일이 있는지부터 본다.

**찾기.** 이름으로 찾는 칸이 없다. 위와 같은 자리에서 같이 본다.

**차단한 사람이 아주 오래됐을 때.** 몇 년 지난 차단이 목록에 계속 쌓인다. 지우는 규칙이 없다.

**「기다리는 사람이 없어요」 아래에 무엇을 둘지.** 지금은 한 줄로 끝난다. 관리자가 여기까지 왔는데 할 일이 없을 때 어디로 보낼지 안 정했다.

# 런타임

돌아갈 때의 규칙이 산다. 언제 다시 읽나, 무엇을 먼저 그리나, 어긋나면 누가 이기나다.

[`data-model/`](../data-model/)이 무엇을 저장하는지를 말하고 [`api/`](../api/)가 어떻게 주고받는지를 말한다면, 여기는 그 위에서 시간과 순서를 다룬다.

## 여기 담는 것

이 파일이 도메인을 가로지르는 넷을 들고, 도메인마다의 경쟁 조건은 `<도메인>.md`로 나간다.

### 캐시 네 계층

이 앱은 Next.js 16 + TanStack Query + Supabase + PWA라 캐시가 앉는 자리가 넷이다. 계층마다 다른 결정이 필요하다.

| 계층 | 정할 것 |
| --- | --- |
| Service Worker | 오프라인에서 무엇이 열리나. 홀은 실내라 통신이 흔들린다 |
| TanStack Query | `staleTime`, 쿼리 키, 무엇이 무엇을 무효화하나 |
| Next.js 서버 | 어느 화면이 RSC고 어느 것이 클라이언트인가. `revalidate` 값 |
| Supabase | 실시간 구독을 쓰나. 쓰면 어느 테이블에 |

### 시각의 출처

인증 창(근무 시작 1시간 전~18시), 지각 판정(10분), 사유 마감(48시간), 근무 요청 만료(48시간), 대시보드 카운트다운이 전부 시각에 걸린다.

**기기 시계를 믿으면 안 된다.** 바꾸면 전부 흔들리고, 출근 인증은 되돌릴 길이 없다. 서버 시각을 언제 받아 어떻게 맞추는지가 여기 산다.

### 경쟁 조건

같은 것을 둘이 동시에 건드리는 자리다. 도메인마다 다르니 `<도메인>.md`로 나가되, **무엇이 이기는지의 기본값**은 여기 적는다.

### 로딩과 낙관적 업데이트

빈 상태와 실패와 잠금은 [`../../design-system/pages/`](../../design-system/pages/)가 이미 다 그렸다. 여기는 **정상인데 아직 안 온 상태**다.

- 첫 로딩이 스켈레톤인가 스피너인가. [`tokens.md`](../../design-system/tokens.md)에 스피너 회전만 값으로 있고 언제 쓰는지가 없다
- 낙관적 업데이트를 어디에 쓰나. 근무 신청 체크는 즉시 칠하는 게 맞고, 근무 요청 수락은 선착순이라 절대 아니다
- 화면 사이 전환. 페이지 문서가 「등장 모션이 없다」로 적은 것은 조각 이야기고 화면 전환은 안 정해졌다

## 지금 보이는 아픈 자리

채울 때 여기서 출발한다. 전부 [`../../domain/`](../../domain/)과 페이지 문서에서 이미 드러난 것들이다.

- **근무 요청 선착순.** 셋에게 같은 자리를 물었고 둘이 동시에 누른다. 화면은 「토스트로 알린 뒤 시트를 닫고 달력을 새로 그린다」까지 정했는데 서버가 어떻게 한 명만 통과시키는지가 비어 있다
- **관리자 동시 편집.** 둘이 같은 근무표를 고친다. 마지막이 이기나, 막나, 서로 보이나
- **급여가 매번 다시 계산된다.** 확정해 잠그는 행위가 없다고 [`payroll.md`](../../domain/payroll.md)가 정했다. 그 계산이 DB 뷰인지 서버인지 화면인지, 통계의 인건비는 서른 명 곱하기 한 달치다
- **하루 띠가 매초 움직인다.** 진행률과 남은 시간은 서버에 다시 묻는 게 아니라 화면 안에서 도는 값이다. 무엇이 폴링이고 무엇이 로컬 계산인지 갈라야 한다
- **오프라인 인증.** 홀 실내에서 통신이 끊기면 출근 인증이 안 찍힌다. 큐에 넣고 나중에 보내면 시각이 어긋나고, 안 넣으면 사유를 써야 한다

## 아직 백지다

[`data-model/`](../data-model/)과 [`api/`](../api/)가 먼저다. 그 둘을 채우면서 튀어나오는 것을 여기 모은다.

**인터뷰가 몇 라운드 붙는다.** 오프라인을 어디까지 여나, 실시간을 쓰나, 동시 편집을 막나가 사람이 정할 자리다.

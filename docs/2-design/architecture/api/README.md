# API

서버와 주고받는 경계가 산다. 경로, 입출력, 권한이다.

## 여기 담는 것

이 파일이 도메인을 가로지르는 것을 들고, 도메인마다의 경계는 `<도메인>.md`로 나간다.

- **Supabase를 화면이 직접 부르는 자리와 서버 라우트를 두는 자리의 기준.** 대부분은 RLS가 이미 막으니 직접 부르면 되는데, 여러 행을 한 번에 바꾸거나 순서가 중요한 자리는 서버가 받아야 한다
- 오류의 모양 — 무엇이 실패로 돌아오고 화면이 그것을 어떻게 가르나
- 권한 — RLS가 막는 것과 라우트가 막는 것의 경계
- 서버 시각을 어디서 받나

## 서버가 받아야 하는 자리

[`../../domain/`](../../domain/)을 읽으면 지금도 몇이 보인다. 채울 때 여기서 출발한다.

- **근무 요청 수락** — 여럿이 동시에 누르고 선착순이다. 한 명만 통과해야 한다
- **가입 승인** — 관리자만인데 컬럼 권한이 역할 단위라 RLS만으로 안 된다. `authenticated`에 `approved_at`을 열면 관리자든 아니든 다 열린다
- **기본 시급 변경** — 여러 사람의 이력에 같은 날 줄이 한꺼번에 선다
- **근무표 확정** — 되돌릴 수 없고 알림이 전원에게 나간다
- **퇴사 처리** — 앞으로 배정된 근무가 있으면 막아야 하는데, 그 판정이 화면에 있으면 우회된다

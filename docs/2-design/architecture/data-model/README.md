# 데이터 모델

테이블과 관계가 산다. 실제 스키마의 정본은 `supabase/migrations/`고 여기는 그 지도와 근거를 담는다.

지금 선 테이블은 `profiles` 하나다. 세션 기반을 깔 때 만든 것이고 나머지는 아직 없다.

## 여기 담는 것

이 파일이 도메인을 가로지르는 것을 들고, 도메인마다의 테이블은 `<도메인>.md`로 나간다. 파일 이름은 [`../../domain/`](../../domain/)의 것을 그대로 쓴다.

- 전체 테이블 목록과 한 줄 역할
- 관계 지도 — 무엇이 무엇에 딸리나
- RLS 기본값 — 안 적은 테이블이 무엇으로 잠기나
- 남의 것을 못 보는 자리 — 시급과 급여 금액은 본인 행과 관리자만이다([domain/payroll.md](../../domain/payroll.md#시급을-누가-보나)). 화면에서 안 그리는 것으로는 직접 질의하는 길이 안 닫힌다
- 컬럼 이름 규칙과 도메인 용어의 대응
- 시각 컬럼의 규칙 — 무엇을 저장하고 어느 시간대로 읽나

## 채우는 조건

**테이블이 둘 이상 얽히기 시작하면 그린다.** 하나짜리 스키마에 지도를 그리면 마이그레이션 파일을 한 번 더 베껴 쓰는 것이 된다.

다음 회차가 그 조건이 차는 자리다 — 근무표만 해도 날·자리·배정·교육 배정·겸임 자리로 다섯이 얽힌다.

## 아직 백지다

채울 때 [`../../domain/`](../../domain/) 여섯에서 뽑는다. 갈래가 대략 이렇다.

| 파일 | 담을 것 |
| --- | --- |

# 알림

푸시로 나가는 것 열하나다. 대부분 근무자에게 가고, 빈 자리 재촉과 근무 취소 요청과 근무 요청 수락은 관리자에게 간다.

## 용어

**가입 승인** — 정의는 [account.md](account.md)에 있다. 승인 시각이 채워지는 그 순간에 알림이 나간다.

**관리자 공지** — 근무표와 무관한 전달. 대시보드 맨 위의 안 본 알림이 이걸 담는다.

**미리 알림** — 근무 전날 저녁에 나가는 것. 주말 근무는 금요일에 묶어서 보낸다.

## 열하나

- 가입 승인
- 스케줄 신청 접수가 열렸을 때 — 근무표를 만드는 순간 나가고 마감일을 함께 알린다
- 근무표가 확정되거나 변경됐을 때
- 스케줄 신청 마감일이 바뀌었을 때
- 미리 알림
- 출근 직전
- 관리자 공지
- 교대의 각 단계 — 수락은 관리자에게도 간다([swap.md](swap.md)의 표)
- 근무 취소의 각 단계 — 요청은 관리자에게, 결과는 요청한 근무자에게 간다. 정의는 [schedule.md](schedule.md)
- 근무 요청의 각 단계 — 요청 도착은 받은 근무자에게, 수락은 관리자에게 간다. 거절·만료는 건건이 안 가고, 자리의 요청이 모두 거절·만료로 끝나면 그때 관리자에게 한 번 간다 — 빈 자리가 안 채워진 채 방치되는 것을 막는 최소한이다. 늦은 수락의 실패는 푸시가 아니라 수락을 누른 순간 화면이 알린다. 정의는 [schedule.md](schedule.md)의 「근무 요청」
- 확정 뒤 빈 자리 재촉 — 관리자에게 간다

가입 승인만 승인 전 사람에게 간다. 근무자에게 가는 나머지는 승인된 사람의 근무를 다루는 것이라 승인 전에는 보낼 내용 자체가 없다.

## 언제 나가나

미리 알림은 근무 전날 저녁 9시다. 화요일 근무면 월요일 저녁 9시에 간다.

토요일과 일요일 근무는 금요일 저녁 9시에 묶어서 한 번 보낸다. 예식장은 주말에 몰려서 이틀치를 따로 보내면 금요일 밤과 토요일 밤에 연달아 울린다.

출근 직전 알림은 근무 시작 10분 전이다. 인증 버튼은 한 시간 전부터 열려 있으니([attendance.md](attendance.md)) 이 알림은 마지막으로 챙기는 몫이다.

스케줄 신청 접수 열림은 관리자가 근무표를 만드는 즉시 나간다. 마감일 변경도 바꾸는 즉시다([schedule.md](schedule.md)) — 신청을 낼 기회가 줄어들 수 있는 변경이라 모르면 안 된다.

근무 요청 도착은 관리자가 보내는 즉시, 수락 알림은 수락으로 배정이 확정되는 즉시 나간다. 전부 소진 알림은 그 자리의 마지막 요청이 거절·만료되는 즉시다.

빈 자리 재촉은 예식 3일 전, 그날 빈 자리가 남아 있을 때 나간다. 시점은 저녁 9시로 제안돼 있다 — 아래 「아직 안 정한 것」.

## 누구에게 나가나

| 알림 | 받는 사람 |
| --- | --- |
| 가입 승인 | 승인을 받은 그 사람 |
| 근무표 확정 | 그달에 배정된 사람 |
| 근무표 변경 | 빠진 사람과 들어온 사람. 근무 요청을 수락해 들어온 본인은 뺀다 — 자기 행동이라 이미 안다 |
| 스케줄 신청 접수 열림 | 승인된 사람 전원 |
| 스케줄 신청 마감일 변경 | 승인된 사람 전원 |
| 근무 요청 도착 | 요청을 받은 근무자 |
| 근무 요청 수락 | 관리자 |
| 근무 요청 전부 소진 | 관리자 |
| 미리 알림 | 그 근무에 배정된 사람 |
| 출근 직전 | 그 근무에 배정된 사람 |
| 관리자 공지 | 승인된 사람 전원 |
| 근무 취소 요청 | 관리자 |
| 근무 취소 결과 | 요청한 근무자 |
| 확정 뒤 빈 자리 재촉 | 관리자 |

확정 뒤 교육 배정을 붙이는 것도 근무표 변경이다 — 교육으로 붙은 사람이 들어온 사람으로 알림을 받는다([schedule.md](schedule.md)의 「확정 뒤에 바꾸는 길」, 2026-09-07).

교대의 단계별 대상은 [swap.md](swap.md)에 있다.

## 켜는 자리

승인 대기 화면에서 받는다. 로그인은 됐는데 볼 것이 없는 유일한 시간이라 방해가 가장 덜한 자리다.

저절로 안 묻는다. 켜기를 권하는 자리를 화면에 두고, 사람이 누를 때 브라우저가 묻는다. 앱을 열자마자 권한 요청으로 덮는 것은 [writing.md](../design-system/writing.md)가 막는다.

안 켜도 넘어간다. 앱을 열면 승인됐는지 바로 보이니 알림은 앱을 안 열어도 알게 해주는 몫이지 없으면 못 아는 것이 아니다. 켜야만 다음으로 가는 문은 만들지 않는다.

아이폰은 홈 화면 추가가 먼저다. 같은 자리에서 그것도 안내한다. 아래 「아이폰」 절이 그 이유다.

여기서 안 켠 사람은 나중에 설정에서 켠다. 끄는 것과 같은 자리다.

## 끄는 길

근무자가 전부 끌 수 있다. 종류별로 나누지 않고 통째로 끈다.

끄면 근무표가 바뀐 것도 모른 채 안 나오는 일이 생긴다. 그래도 안 받겠다는 선택을 앱이 막지 않는다.

## 읽음

대시보드 맨 위의 안 본 알림은 항목을 눌러야 사라진다. 목록을 훑고 지나가는 것으로는 안 사라진다. 중요한 것을 스치고 지나칠 수 없게 하려는 것이다.

지난 알림은 안 지운다. 언제 무슨 알림이 나갔는지가 다 남는다.

## 아이폰

PWA 푸시는 홈 화면에 추가해야만 온다. 안 하면 알림이 하나도 안 간다.

추가하는 법은 승인 대기 화면에서 안내한다. 그래도 안 한 사람은 관리자 화면에 목록으로 뜬다. 중요한 알림을 놓칠 사람을 관리자가 미리 알고 따로 연락한다.

## 푸시가 안 갔을 때

기기가 꺼져 있었거나 권한을 거부했으면 푸시는 그냥 못 받는다. 대신 앱을 열면 대시보드 맨 위에 안 본 알림이 쌓여 있다. 홈 화면 추가를 안 한 아이폰 사용자도 앱만 열면 다 본다.

## 아직 안 정한 것

인터뷰로 채운다. 채운 항목은 이 절에서 빼고 위로 올린다.

- **거절되면 알림이 가나.** 가입 승인이 알림으로 나가니 거절도 대칭으로 나갈 법하다. 그런데 거절은 이번만이고 같은 사람이 다시 가입할 수 있어서([account.md](account.md)), 안 받았다는 통보가 최종 판정처럼 읽히면 다시 올 사람을 돌려세운다. 안 보내면 승인 대기 화면에 계속 남는다
- **끈 사람에게 근무표 변경이 걸리면.** 알림을 끈 사람의 배정이 강제 변경으로 바뀌면 관리자가 그 사실을 아나. 따로 연락할 근거가 필요한 자리다
- **금요일 저녁에 확정되면.** 금요일 저녁 9시 미리 알림 직전이나 직후에 근무표가 확정되면 알림 둘이 겹친다. 묶는지 따로 보내는지
- **빈 자리 재촉의 시점.** 예식 3일 전 저녁 9시로 제안했다 — 미리 알림과 같은 시각이라 알림 리듬이 하나로 묶인다
- **근무 취소 알림의 모양과 시점.** 요청 즉시 관리자에게 가는지, 승인·거절 결과 문구를 어떻게 쓰는지

「근무 요청의 거절·만료 알림」(전부 소진 시 관리자에게 한 번)과 「수락자의 변경 알림 중복」(수락자는 뺀다)은 인터뷰로 닫혀 「열하나」와 「누구에게 나가나」로 올라갔다.

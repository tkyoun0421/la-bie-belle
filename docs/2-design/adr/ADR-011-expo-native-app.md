# ADR-011 — Expo로 네이티브 앱을 만든다

2026-09-20에 정했다. [ADR-007](ADR-007-web-pwa-over-native.md)의 「웹 PWA로 간다」를 대체한다.

## 배경과 제약

ADR-007이 웹 PWA를 고르며 다시 열 조건 셋을 적어뒀다 — 홈 화면 추가를 안 해서 알림을 놓치는 일이 반복될 때, 홀이 여럿이 되거나 쓰는 사람이 수백 명대로 늘 때, 웹이 못 하는 것을 도메인이 요구할 때다. **셋 중 무엇도 관찰되지 않았다.** 이 결정은 그 조건을 채워서가 아니라 선택으로 뒤집은 것이다.

그 사실을 적어두는 이유는, 안 적으면 다음에 같은 자리에 섰을 때 「조건을 적어둔들 지키지 않는다」가 되기 때문이다. 조건은 여전히 유효한 판단 기준이고 이번에는 그것과 별개로 방향을 바꿨다.

바꿀 수 있는 시점이라는 조건은 붙는다. 화면 구현이 로그인과 승인 대기 둘뿐이라 `src` 전체가 2,831줄이다. 버릴 코드가 가장 적은 자리다.

## 대안과 선택

| 대안 | 얻는 것 | 치르는 것 |
| --- | --- | --- |
| 웹 PWA를 유지 | 주소 하나로 배포. 연회비·심사·설치가 없다 | ADR-007이 감수한 값 넷이 계속 남는다 |
| 웹 화면을 네이티브로 감싼다 | 스토어에 올라가고 푸시가 열린다 | 주소창 제약만 없어지고 웹뷰의 한계는 그대로다 |
| **Expo로 네이티브 앱** | 푸시·권한·레이아웃·테스트 제약이 한 번에 없어진다 | 연회비, 심사, 설치 유도, 빌드 둘 |

**Expo를 골랐다.** ADR-007이 감수하기로 한 값 넷을 네이티브가 전부 없앤다 — 아이폰 푸시가 홈 화면 추가에 걸리던 것, 권한을 거부하면 다시 못 묻던 것, 주소창과 홈 인디케이터가 레이아웃을 먹던 것, CI가 아이폰 사파리를 못 보던 것이다. 앞의 둘은 화면 문서에 이미 조항으로 그려져 있었고, 그 조항들이 사라지는 것이 설계가 가벼워진다는 뜻이다.

**웹은 같이 안 낸다.** Expo는 같은 코드로 웹을 낼 수 있고 관리자가 PC에서 근무표를 짜는 그림도 가능하다. 그래도 지금 안 여는 것은 모든 화면이 두 폭을 감당해야 하기 때문이다 — 시안도 폰과 넓은 화면 둘씩 그려야 하고, 화면 문서마다 넓은 폭에서 무엇이 어떻게 서는지를 정해야 한다. 근무표처럼 넓은 화면이 유리한 일이 실제로 폰에서 불편하다는 것이 관찰되면 그때 연다.

**받아들이는 비용 넷이다.** 애플과 구글 양쪽의 개발자 계정 연회비가 든다. 첫 등록도 고칠 때마다도 심사를 거치는데, JS와 에셋만 바뀌는 수정은 EAS Update로 심사 없이 내보낼 수 있고 네이티브가 바뀌면 다시 올려 다시 심사받는다. 주소 하나를 보내면 끝나던 것이 스토어에서 받아 설치하는 과정이 되어, 근무자 수십 명에게 그 과정을 안내하는 몫이 생긴다. 같은 코드라도 iOS와 안드로이드 각각을 빌드하고 각각 올린다.

## 적용과 결과

| 지금 | 바뀐 뒤 |
| --- | --- |
| Next.js 16 App Router | Expo + Expo Router |
| Tailwind CSS 4 + shadcn/ui | NativeWind + 직접 만든 조각 |
| Playwright | Maestro — [ADR-013](ADR-013-e2e-runner-maestro.md)이 골랐다 |
| vitest | Jest |
| 쿠키와 서버 라우트로 세션 | SecureStore와 딥링크 콜백 |
| `pnpm build` 뒤 웹 배포 | EAS Build·Submit, JS만 고칠 땐 EAS Update |

**Tailwind 표기는 살린다.** 디자인 문서가 여백과 라운딩과 글자 크기를 `py-3`·`rounded-xl`·`text-sm` 같은 유틸 이름으로 적고 있고, 그런 표기가 서른여섯 개 문서에 육백 군데 넘는다. NativeWind가 그 표기를 React Native에서 받아주므로 문서를 픽셀 값으로 내려 적지 않는다. 다만 `gap`과 그림자처럼 React Native 스타일 엔진이 원래 못 받는 속성은 조각마다 확인이 필요하다.

**`.ts`와 `.tsx`의 경계는 그대로다.** [ADR-001](ADR-001-fsd-layout-and-tdd-guard.md)이 정한 FSD 층과 「`.tsx`는 더미 UI」 규칙은 플랫폼을 안 탄다. 바뀌는 것은 `.tsx`가 무엇을 그리느냐뿐이다.

**다시 써야 하는 것은 인증 계층 하나다.** 지금 세션이 Next의 서버 라우트와 쿠키에 기대고 있어서 그 부분은 통째로 바뀐다. 나머지 `.ts` 로직은 플랫폼을 안 타서 거의 그대로 간다.

**따라 움직이는 정본은 넷이다.** ADR-001의 스택 절, [4-test](../../4-test/)의 실행 문서, [5-deploy](../../5-deploy/)의 절차, 그리고 `CLAUDE.md`의 명령어 목록이다.

## 재검토 조건

- 스토어 심사가 배포 속도를 실제로 막을 때. 급한 수정이 EAS Update 범위 밖이라 며칠씩 묶이는 일이 반복되면 그때는 구조 문제다
- 설치를 끝내 안 하는 근무자가 남아 관리자가 사람 손으로 메우는 것이 일상이 될 때. ADR-007이 웹을 고르며 걱정한 것이 알림이었는데 네이티브에서는 설치가 그 자리에 선다
- 넓은 화면이 유리한 일이 폰에서 불편하다는 것이 관찰될 때. 그때 웹 타깃을 연다

배포 파이프라인의 세부와 스토어 등록 정보는 안 정했다. [ADR-005](ADR-005-sdlc-stage-folders-and-artifact-chain.md)가 적은 대로 배포가 다가오면 정한다.

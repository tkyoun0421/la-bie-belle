# ADR-013 — e2e 러너를 Maestro로 고른다

2026-09-23에 정했다. [ADR-011](ADR-011-expo-native-app.md)이 「Maestro 또는 Detox」로 열어둔 자리를 닫는다.

## 배경과 제약

Playwright는 브라우저가 없어져 걷혔다. 그 자리가 빈 동안 `tdd-guard-e2e.py`가 `tests/e2e/`를 못 찾아 **아무것도 안 막는다** — 화면을 고치면서 e2e를 안 써도 훅이 통과시킨다. 화면 task가 스무 개 넘게 대기 중이고 그것들이 서기 전에 게이트가 다시 물어야 한다.

지켜야 하는 조건이 셋이다.

**딥링크가 업무의 중심이다.** 종이 QR이 `labiebelle://check-in?...`을 싣고, 구글 OAuth 콜백도 딥링크로 돌아온다([navigation.md](../system/navigation.md#딥링크)). 러너가 딥링크를 못 열면 확인해야 하는 여정의 시작점에 못 닿는다.

**관리 흐름을 유지한다.** ADR-011이 Expo의 관리 흐름(managed workflow)을 골랐다 — `ios/`와 `android/` 디렉터리를 저장소에 두지 않고 EAS가 빌드한다. 네이티브 디렉터리를 꺼내야 하는 도구는 그 선택을 되돌린다.

**세션을 심어 화면으로 바로 들어가야 한다.** 여정마다 구글 로그인을 실제로 통과할 수 없다. 웹 시절엔 쿠키를 심었고 지금은 SecureStore다([strategy.md](../../4-test/strategy.md#대역과-실제-의존성)).

## 대안과 선택

| | Maestro | Detox |
| --- | --- | --- |
| 테스트를 쓰는 언어 | YAML | TypeScript |
| 앱 내부 접근 | 없다 — 화면에 보이는 것만 본다 | 있다 — JS 런타임에 붙는다 |
| 네이티브 디렉터리 | 필요 없다 | `expo prebuild`로 꺼내야 한다 |
| Expo의 공식 취급 | 공식 e2e 문서가 이것을 든다 | 자기 템플릿을 지웠다 |
| 딥링크 | `openLink`가 기본 커맨드다 | Android·iOS 양쪽에 열린 버그가 있다 |
| 설치 | 별도 CLI(JVM 필요) | npm 의존성 |

**Maestro를 고른다.** 근거가 셋이다.

첫째, **Expo가 Detox를 버렸다.** Expo는 자기 Detox 템플릿을 지웠고 지금 공식 e2e 문서가 드는 것은 Maestro다. Expo의 SDK 올림에 러너가 따라오지 못하면 그 비용을 우리가 전부 진다.

둘째, **Detox는 `expo prebuild`를 요구한다.** 네이티브 디렉터리를 저장소에 꺼내면 관리 흐름의 이점 — 네이티브 설정을 `app.json` 하나로 다루고 SDK 올림을 Expo가 대신 처리하는 것 — 이 사라진다. e2e 하나 때문에 플랫폼 결정을 되돌리는 거래다.

셋째, **딥링크가 Detox에서 불안하다.** 열린 버그가 Android와 iOS 양쪽에 있다. 우리 여정의 시작점이 거기라 이 자리가 흔들리면 쓸 수 없다.

**뒤집을 수 있었던 한 가지는 닫았다.** Maestro가 앱을 죽이고 상태를 남긴 채 다시 띄울 수 있는지가 관건이었다 — 「앱을 다시 연 뒤 상태가 끊김」이 e2e로 배정되는 리스크의 절반이다. `stopApp`·`killApp`이 있고 `launchApp`에 `clearState`를 안 주면 상태를 지우지 않는 차가운 시작이다. 요구가 채워진다.

**받아들이는 비용 셋이다.**

**YAML은 타입 검사를 안 받는다.** 지금 spec 스물에 걸쳐 완료 조건 95개가 「검증 층: e2e」로 적혀 있다. 그것이 전부 YAML이 되고, 플로우 사이에 공유할 조각은 함수가 아니라 `runFlow`로 끼우는 파일이다. 오타가 실행 시점에야 드러난다.

**앱 내부를 못 본다.** 세션을 심는 일을 코드로 할 수 없다. 딥링크나 화면 조작, 아니면 테스트용 경로 중 하나로 풀어야 하고 **그 방법은 아직 안 정했다** — 첫 화면 task가 로그인 뒤 화면에 닿을 때 정한다. 지금 플로우는 세션 없는 진입만 본다.

**CLI가 pnpm 밖이다.** Maestro는 npm 의존성이 아니라 별도 CLI고 JVM을 요구한다. 버전이 `pnpm-lock.yaml`에 안 박히니 로컬과 CI가 다른 버전을 쓸 수 있다. CI 단계를 세울 때 버전을 명시로 박는다.

## 적용과 결과

플로우는 `tests/e2e/`에 산다. 이름은 훅이 화면에서 뽑는 이름과 같다 — `tdd-guard-e2e.py`가 `src/app/login.tsx`를 고칠 때 `tests/e2e/login.yaml`을 찾는다. 실행과 설정의 정본은 [execution.md의 「`pnpm e2e`」](../../4-test/execution.md#pnpm-e2e)다.

**이 결정으로 게이트가 다시 문다.** `tests/e2e/`가 서면서 `tdd-guard-e2e.py`의 「쓸 자리가 없으면 아무것도 안 막는다」 조건이 풀린다. 라우트를 고치는 다음 task는 그 화면의 플로우를 먼저 써야 한다.

**CI에는 아직 안 선다.** e2e 단계는 설치 가능한 `.apk`·`.app`을 요구하고 그 빌드는 EAS 설정과 같이 선다([execution.md의 CI 한계](../../4-test/execution.md#ci와-결과-위치)). 그때까지 플로우는 손으로 돌린다.

## 재검토 조건

- YAML로 표현할 수 없는 단언이 나올 때. 그런 자리가 쌓이면 Maestro의 JavaScript 지원으로 갈지, 그 리스크를 unit·integration으로 내릴지 판단한다
- Expo가 공식 e2e 권장을 바꿀 때
- 플로우 실행 시간이 CI에서 감당할 수 없게 늘 때. 그때는 전부 돌리는 대신 태그로 골라 돌린다

세션을 심는 방법과 CI에서 앱을 빌드하는 단계는 안 정했다. 둘 다 그것을 처음 필요로 하는 task에서 정한다.

# ADR-004 — 도메인 규칙이 사는 곳

2026-08-26에 정했다.

## 결정

`docs/domain.md` 한 파일을 `docs/domain/` 디렉터리로 연다. 그 디렉터리는 지금 `docs/2-design/domain/`에 있다(ADR-005). 안에 영역별 파일을 두고 각 파일이 그 영역의 용어와 규칙을 함께 담는다. `README.md`는 어느 파일에 무엇이 있는지와 컨텍스트 경계만 담는다.

도메인 규칙의 정본은 여기다. PRD도 spec도 규칙을 다시 쓰지 않는다.

## 왜

규칙이 갈 곳이 없었다.

`docs/1-plan/prd.md`는 왜 만드는지와 누구를 위한 것인지를 담는다. `docs/2-design/spec/<task>.md`는 task 하나가 무엇이 되면 완료인지를 담는다(ADR-002). `docs/2-design/adr/`는 되돌리기 어려운 기술 결정을 담는다. 그런데 "하루 9시간을 넘긴 시간에 1.5배가 붙는다" 같은 계산 규칙과 "교대는 요청과 수락과 승인 셋을 다 거친다" 같은 상태 전이는 셋 중 어디에도 안 맞는다.

task-spec에 넣으면 더 나빠진다. 급여 계산 규칙은 정산 화면 task 하나의 완료 조건이 아니다. 근무표 task도 통계 task도 조정 task도 같은 규칙을 본다. 어느 task 파일에 넣든 나머지가 그걸 베껴 가고, 베낀 순간 정본이 여럿이 된다.

PRD에 넣는 길도 막혔다. 엣지 케이스까지 담으면 PRD가 수백 줄 명세서가 되고, 그러면 사람도 subagent도 안 읽는다. PRD는 새로 온 사람이 십 분 만에 읽는 문서여야 한다.

**중복은 이미 났다.** `prd.md:69`의 "연장 — 하루 9시간을 넘긴 시간에 1.5배"와 `domain.md:44`의 "연장 — 하루 9시간을 넘긴 시간. 1.5배가 붙는다"가 같은 규칙을 두 번 적는다. `CLAUDE.md`는 정본이 다른 곳에 있는 내용을 옮겨 적지 말라고 하는데 규칙이 갈 곳을 안 줘서 어긋났다. 엣지 케이스를 채우기 시작하면 이 중복이 열 배가 된다.

## 갈래

```
docs/2-design/domain/
  README.md      지도와 컨텍스트 경계
  schedule.md    근무표 — 포지션·자리·배정·확정·휴무 희망
  swap.md        교대 — 요청과 수락과 승인, 강제 변경
  attendance.md  출근 인증 — 위치와 QR, 인증 시각
  payroll.md     급여 — 시급·가산·조정·정산
  account.md     계정 — 프로필·가입 승인·관리자 권한
  notification.md 알림 — 무엇이 언제 누구에게 나가나
```

새 영역이 생기면 파일을 더하고 `README.md`에 한 줄을 더한다.

## 용어와 규칙을 같은 파일에 둔다

`README.md`에 용어를 모으고 영역 파일에 규칙만 두는 길도 있었다. 안 골랐다.

같은 개념의 정의와 규칙이 떨어지면 어긋난다. "연장"의 뜻이 `README.md`에 있고 계산이 `payroll.md`에 있으면 한쪽을 고칠 때 다른 쪽이 남는다. 정본이 갈라지는 걸 막으려고 여는 디렉터리에서 스스로 가르면 앞뒤가 안 맞는다.

찾기는 `README.md`의 지도가 받는다. 어느 파일에 무엇이 있는지 한눈에 보이면 파일이 여섯이어도 헤매지 않는다.

## PRD가 남기는 것

PRD에서 규칙과 숫자를 뺀다. 남는 것은 셋이다.

- 왜 만드나와 지금의 문제
- 누구를 위한 것인가
- 무엇을 안 하나(비범위)

기능을 소개하는 문단은 남긴다. 다만 "앱이 급여를 계산한다" 선까지고, 어떻게 계산하는지는 `docs/2-design/domain/payroll.md`를 가리킨다.

## ADR-002와의 경계

ADR-002가 정한 spec은 그대로다. `docs/2-design/spec/<task>.md`는 task 하나의 완료 조건이 길어질 때 쓰고, 승격 기준도 안 바뀐다.

가르는 질문 하나다. **"task가 끝나도 이 문장이 남는가."** 남으면 도메인 규칙이라 `docs/2-design/domain/`으로 가고, task와 함께 수명이 끝나면 spec이다.

"연장 가산은 하루 9시간 초과분에 1.5배"는 급여 화면을 다 만들어도 남는다. "이 화면에서 이번 주 급여와 지난주 급여를 같이 보여준다"는 그 task의 완료 조건이다.

spec은 도메인 규칙을 인용하지 않고 링크한다. 같은 문장을 두 곳에 쓰지 않는 원칙은 여기도 같다.

## 함께 정한 것

**규칙 문서는 총괄이 쓴다.** 결정이 담기기 때문이다. ADR-002가 spec에 건 조항과 같다. subagent는 읽고 참조하지만 고치지 않는다.

**새 훅을 만들지 않는다.** 규칙이 PRD로 새는 것을 기계가 판정하기 어렵다. `pr-diff` 감사와 총괄 리뷰가 받는다. 이 길로 위반이 main에 들어오면 증축 규칙대로 그때 훅을 단다.

**빈 파일을 미리 만들지 않는다.** 영역 파일은 그 영역을 인터뷰로 확정할 때 생긴다. 지금 `domain.md`에 있는 용어만 해당 파일로 옮기고 나머지는 인터뷰가 채운다.

## 남는 위험

문서가 하나에서 일곱으로 늘어난다. 세션이 규칙을 찾을 때 여는 파일이 많아진다. `README.md`의 지도가 이걸 받는데, 지도를 안 고치고 파일만 더하면 그 순간 지도가 거짓말을 한다.

영역을 코드보다 먼저 나눈다. 틀린 자리에 그을 위험이 ADR-002의 컨텍스트 경계와 같다. 파일 경계일 뿐이라 틀리면 옮기면 된다. `src/` 아래에 영역 이름 폴더를 만들지 않는 조항은 ADR-002 그대로다.

규칙과 코드를 잇는 장치는 여전히 없다. `docs/2-design/domain/payroll.md`를 고치고 계산 코드를 안 바꿔도 아무도 안 막는다. 이건 ADR-002가 이미 적은 위험이고 여기서 더 커진다.

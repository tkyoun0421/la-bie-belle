# ADR-006 — 관찰 로그를 docs/observations/에 둔다

2026-09-06에 정했다.

## 결정

증축 규칙에는 카운터가 없었다. "같은 스폰 프롬프트 세 번째면 정의문 추출"이라고 정해 놓고도 첫 번째와 두 번째를 세는 장치가 없어, 세션이 갈리면 판정이 기억에 의존했다. 정의문·훅·규칙이 삐걱인 자리를 관찰 1건 = 파일 1개로 `docs/observations/`에 남겨 그 카운터를 만든다.

발상과 파일 포맷은 rebelytics의 task-observer 스킬에서 가져왔다(one-skill-to-rule-them-all, CC BY 4.0, Eoghan Henn). 통째로 들이지 않고 셋만 남겼다. 관찰 1건 = 파일 1개라 병렬 쓰기가 서로를 덮지 않는 것, frontmatter만 훑는 싼 스캔, 그리고 쓰기 자체가 강제 장치라는 원칙이다. 나머지는 버렸다 — staging 디렉터리와 승인 매니페스트는 단명 브랜치 → PR → 총괄 리뷰가 같은 보장을 이미 주고, id 채번 셸 기계는 쓰는 주체가 총괄 하나라 경합이 없고, 별도 주간 리뷰는 회차 마감이 그 자리다.

## 새 배치

```
docs/observations/
  README.md          포맷·신호·상태 규칙의 정본
  NNN-슬러그.md       관찰 1건
  archive/           해결된 관찰
```

포맷과 쓰기 규칙의 정본은 `docs/observations/README.md`다. 여기 옮겨 적지 않는다.

## 흐름에 닿는 자리

셋이 바뀐다.

- CLAUDE.md 문서 지도에 갈래 한 줄, 증축 규칙에 카운터 위치 한 줄이 붙는다.
- session-recorder가 마감 때 관찰을 집계한다. 같은 대상 3건이면 handoff.md 열린 결정에 증축 후보를 올리고, 해결된 파일을 archive/로 옮긴다. 판정은 여전히 총괄 몫이다.
- 관찰을 반영한 정의문 PR이 그 관찰의 status도 같이 닫는다. 반영과 기록을 갈라놓으면 뒤쪽이 샌다.

## 범위 밖

총괄 세션의 메모리는 이 갈래와 겹치지 않는다. 메모리는 총괄이 어떻게 일하는지에 대한 것이고, 관찰은 저장소의 정의문·훅에 대한 것이다. 사용자 취향은 메모리로, 정의문 빈틈은 관찰로 간다.

세션 시작 시 관찰을 강제로 읽게 하는 훅은 만들지 않는다. 관찰이 안 쌓이거나 안 읽히는 상처가 실제로 나면 그때 짓는다.

## 남는 위험

커밋 전의 관찰은 working tree에만 있다. `git clean -fd`가 지운다. 커밋이 늦어질수록 창이 길어지는데, task PR 편승과 마감 PR 포함 중 먼저 오는 쪽에 싣는 규칙으로 창을 줄일 뿐 없애지는 못한다.

저장소가 PUBLIC이라 관찰 본문의 세션 맥락도 공개된다. 회차 로그와 같은 수위라 새 위험은 아니지만, 시크릿·로컬 경로 금지는 여기도 적용된다.

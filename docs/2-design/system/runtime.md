# 런타임

돌아갈 때의 규칙이 산다. 언제 다시 읽나, 무엇을 먼저 그리나, 어긋나면 누가 이기나다.

## 캐시·수명

### 캐시 두 계층

- 적용 범위: 앱이 쥐는 캐시 전부
- 기본 계약: 계층마다의 결정은 아래 표다
- 이유:
  - **realtime을 안 쓰는 이유.** 서른 명·홀 하나라 남이 바꾸는 일이 분에 한 번도 안 된다. 선착순은 함수가 풀었고(`slot_full`) 동시 편집은 `stale`이 잡는다 — 막히지 않고 늦게 안다. 소켓 연결·재연결·배터리를 치를 값이 없다
  - **껍데기를 캐시할 자리가 없는 이유.** 화면과 서체와 아이콘이 설치할 때 기기에 들어와 있다. 웹이라면 그것을 받아 두는 계층이 따로 필요했는데 앱은 그 자리가 비어 있다 — 오프라인에 앱이 안 뜨는 일도 없다
  - **서버가 승인을 판정하지 않는 이유.** 판정할 서버가 없다([system/architecture.md](architecture.md#경계-하나)). 승인·차단·퇴사는 앱이 뜬 뒤 `['profile']`을 읽어 가른다 — [`account/design.md`](../modules/account/design.md)

| 계층 | 결정 |
| --- | --- |
| TanStack Query | 데이터의 유일한 캐시. 기기 저장소에 영속해 마지막 응답이 다음 진입에 바로 뜬다 |
| Supabase realtime | 안 쓴다 |

### TanStack Query 규칙

- 적용 범위: 데이터 캐시의 모든 키
- 기본 계약:
  - **키는 `[도메인, 범위]`다.** `['schedule', '2026-09']`, `['attendance', '2026-09-20']`, `['notifications']`, `['payroll', '2026-09']`, `['profile']`. 도메인 파일이 각자의 키를 적는다
  - **`staleTime`은 30초, `gcTime`은 7일이다.** 30초 안에 같은 화면을 오가면 안 다시 읽고, 7일 안 열면 캐시가 지워진다. 근무표는 달 단위라 지난달이 7일 뒤 지워져도 다시 읽으면 된다
  - **다시 읽는 때 셋.** 화면 진입, 앱으로 돌아올 때, 쓰기 성공 뒤 무효화. 폴링은 없다. 「앱으로 돌아올 때」는 브라우저 탭이 아니라 앱 상태가 앞으로 오는 것이고, 그 신호를 한 곳에서 받아 캐시에 알린다
  - **`networkMode`는 `'always'`다.** 기본값 `'online'`은 오프라인이면 요청을 멈춰뒀다가 복귀 때 자동으로 보낸다 — 쓰기가 사람 모르게 큐에 드는 셈이다. `'always'`면 바로 실패하고 「다시 시도」가 사람 손에 남는다
  - **영속은 `persistQueryClient`와 기기 저장소다.** `maxAge`는 `gcTime`과 같다. `buster`는 앱 버전이다 — 새 버전으로 응답 모양이 바뀌면 옛 캐시를 통째로 버린다. 앱은 고친 것이 사람마다 다른 시점에 닿으므로 이 값이 웹보다 중요하다. `['profile']`과 `['hall', 'qr']`는 영속하지 않는다(`shouldDehydrateQuery`) — 차단된 사람이 옛 프로필로 근무표를 보거나 옛 QR로 인증하는 일이 없게. 로그아웃·퇴사·차단이면 전부 지운다
  - **복원 중(`isRestoring`)에는 아무것도 안 그린다.** 스켈레톤도 아니다. 저장소에서 돌아오는 데 수십 ms라 스켈레톤을 그리면 깜빡인다. 그동안은 스플래시가 그대로 떠 있다

### 무효화 표

- 적용 범위: 쓰기 성공 뒤의 무효화
- 기본 계약: **규칙 하나.** `['schedule']`을 무효화하는 함수는 `['payroll']`도 무효화한다. 무효화 키는 행위를 소유한 영역 design이 든다
- 이유: 급여는 배정에서 계산한다

### 읽기 범위

- 적용 범위: 화면이 한 번에 읽는 키
- 기본 계약: `max_rows`가 1000이라 그 안에 드는 표는 한 질의다. 근무표 한 달, 급여 한 달, 프로필 서른. 임베딩은 살아 있는 행만 받는다 — `ended_at is null`을 건다. 통계가 여러 달을 합칠 때는 달마다 질의한다
- 이유: 이력은 화면이 안 그린다. **범위 없이 읽는 키가 문제다** — 쌓이는 표는 여럿이지만 화면이 전체를 읽는 키는 셋이다. 어느 키가 어떤 범위인지는 그 키를 소유한 영역 design에 있다

## 세션

### 기기에 남기는 자리

- 적용 범위: Supabase 세션 하나
- 기본 계약: **열쇠와 본문을 가른다.** SecureStore에 AES-256 열쇠만 두고, 그 열쇠로 암호화한 세션을 AsyncStorage에 둔다. 암호화는 `aes-js`가 하고 난수는 `react-native-get-random-values`가 낸다
- 이유: 세션 JSON이 SecureStore가 받는 크기를 넘는다 — 토큰 둘과 사용자 객체가 든다. iOS 키체인은 2048바이트보다 큰 값도 받지만 안드로이드는 그 근처에서 실패한다. 한쪽에서만 되는 저장은 저장이 아니다. 고른 둘은 순수 JavaScript와 폴리필이라 Expo Go에서도 돈다

### 클라이언트 설정

- 적용 범위: `createClient`에 넘기는 `auth`
- 기본 계약: 아래 다섯이다

| 설정 | 값 | 이유 |
| --- | --- | --- |
| `storage` | 위의 어댑터 | 열쇠와 본문이 갈린 자리 |
| `persistSession` | `true` | 다시 열 때 로그인을 안 거친다 |
| `autoRefreshToken` | `true` | 액세스 토큰 수명이 짧다 |
| `detectSessionInUrl` | `false` | 주소창이 없다 |
| `flowType` | `pkce` | 딥링크가 세션 대신 코드를 싣고 온다 |

### 자동 갱신은 앱이 앞에 있을 때만

- 적용 범위: 토큰 갱신 타이머
- 기본 계약: 앱 상태가 `active`면 `startAutoRefresh()`, 아니면 `stopAutoRefresh()`다. 신호를 받는 자리는 캐시가 「앱으로 돌아올 때」를 받는 곳과 같다([TanStack Query 규칙](#tanstack-query-규칙))
- 이유: 뒤에 있는 앱에서 갱신을 돌리면 네트워크 없는 동안 실패가 쌓인다. 앞으로 올 때 한 번 갱신하면 같은 일이 된다

## 오프라인

- 적용 범위: 통신이 끊긴 동안의 모든 읽기·쓰기와 화면
- 기본 계약:
  - **앱이 메모리에 살아 있으면 마지막 본 화면이 그대로 뜨고 「통신 없음」 띠가 붙는다.** 쓰기 버튼은 잠긴다
  - **완전히 새로 뜨는데 오프라인이면 「통신 없음」 화면이다.** 화면 자체는 기기에 있으니 흰 화면은 아니다
  - 띠는 기기가 말하는 연결 여부가 아니라 **실제 요청 실패**로 뜬다. 다시 읽기가 성공하면 띠가 진다
  - **쓰기는 큐에 넣지 않는다.**
- 이유: 홀에서 「오늘 누가 오나」를 보는 게 주 용도라 그 화면이 오프라인에서도 보여야 한다. `['profile']`을 영속하지 않아 승인·차단을 가를 수 없다. 기기가 말하는 연결 여부는 와이파이에 붙었지만 인터넷이 안 되는 상태를 못 가른다 — 홀 와이파이가 그 상태가 되기 쉽다. 언제 갈지 모르는 쓰기는 사람이 「됐다」고 믿고 가버리는 것이 문제다
- 예외: 출근 인증만 예외다 — 누른 시각과 위치를 기기에 담아두고 연결되면 보낸다. 누른 시각에서 2시간이 지나면 서버가 거절한다([ATT-029](../modules/attendance/README.md#att-029)). 세부는 [`attendance/design.md`](../modules/attendance/design.md#출근-인증)

## 시각

- 적용 범위: 화면이 그리는 모든 시각
- 기본 계약: **앱이 뜨면 `server_now()` 한 번, 그 차이를 기기 시계에 더해 쓴다.** 앱으로 돌아올 때 다시 받는다. 오프셋은 기기 저장소에 남겨 오프라인으로 뜨면 마지막 값을 쓰고, 없으면 0이다. 하루 띠·카운트다운·버튼 켜짐이 이 값이고 매초 도는 것은 로컬 계산이다. 판정은 함수의 `now()`다 — [서버 시각](#서버-시각)
- 예외: 출근 인증의 `reported_at` 하나다

### 서버 시각

- 적용 범위: 앱이 뜬 뒤 화면이 읽는 시각
- 기본 계약: **앱이 뜨면 `server_now()`를 한 번 부르고 차이를 든다.** `offset = server - Date.now()`. 화면은 `Date.now() + offset`을 쓴다. 앱이 앞으로 돌아올 때 다시 받는다 — 오래 뒤에 있다 오면 기기 시계가 그사이 바뀌었을 수 있다. 화면 시각은 보여주기용이다. 버튼이 켜지는 것, 카운트다운, 남은 시간이 여기 걸리고 판정은 함수의 `now()`다. 언제 다시 받고 오프라인이면 어쩌나는 [시각](#시각)이 정한다
- 이유: 하루 띠가 매초 도는 것은 이 값이다 — 서버를 매초 안 부른다. 기기 시계를 바꿔 버튼을 켜도 눌러보면 `window_closed`가 온다

### 시각 컬럼

- 적용 범위: 시점과 날짜를 담는 모든 열
- 기본 계약: **달력 날짜는 `date`, 시점은 `timestamptz`, 되풀이되는 벽시계 시각은 `time`이다.** `days.work_date date`(KST 달력의 그날), `days.starts_at/ends_at time`, 인증·만료·마감·승인 시각 전부 `timestamptz`. `wage_rates.effective_date`·`availabilities.work_date`는 `date`. 「오늘이 며칠인가」를 SQL에서 쓸 때는 `(now() at time zone 'Asia/Seoul')::date`다
- 이유: `now()::date`는 UTC 자정 근처에서 하루 틀린다. 근무 시각은 날마다 되풀이되는 10시·22시라 `time`이고, 날짜를 겹쳐 담으면 `work_date`와 두 벌이 선다
- 예외: `time`은 시점이 아니라 **그날과 묶어야 비교가 된다.** `(work_date + starts_at) at time zone 'Asia/Seoul'`이 그 근무가 실제로 시작하는 시점이고, 인증 창·지각·사유 마감이 전부 이 꼴로 `now()`와 비교한다. 이 결합을 빼먹으면 `time`이 시점처럼 비교돼 조용히 틀린다
- 예외: **테스트가 만드는 날짜 문자열도 KST다.** `new Date().getDate()`로 「오늘」을 만들면 기계의 시간대가 답을 정한다 — CI가 UTC라 한국 시각 자정부터 아침 아홉 시까지는 DB의 「오늘」보다 하루 뒤처진다. 그 아홉 시간 동안만 빨개지는 테스트가 서고, 낮에 돌리는 사람은 평생 못 본다. 날짜 문자열은 `tests/integration/`의 공용 헬퍼가 KST로 낸다

### 업무 상수

- 적용 범위: 인증 창(1시간 전~18시)·지각 10분·사유 48시간·요청 만료 48시간·교대 수락 12시간·연장 9시간 1.5배
- 기본 계약: **TypeScript 한 곳이 정본이다.** 상수는 `src/entities/<도메인>/model/constants.ts`에 산다. 함수가 같은 숫자를 SQL 리터럴로 들고, `tests/lint/`의 대조 테스트가 마이그레이션의 `interval` 문자열과 TS 상수를 맞춘다

## 경쟁·재시도

### 경쟁 조건 기본값

- 적용 범위: 같은 행을 둘 이상이 동시에 바꾸는 자리
- 기본 계약: **뒤에 온 쪽이 진다. 막지 않고 `stale`로 알린다.** 관리자 둘이 같은 자리를 고치면 앞이 배정 행을 닫고 새 행을 만들었으니 뒤의 함수가 닫힌 id를 받아 `stale`을 던진다. 화면은 「이 근무가 바뀌었어요」를 보이고 다시 읽는다. 잠금·편집 중 표시는 없다
- 이유: 관리자가 여럿이어도 같은 날을 동시에 고치는 일은 드물다
- 예외: 선착순(근무 요청 수락)은 함수가 한 트랜잭션에서 풀어 첫 사람만 통과한다. 화면은 `slot_full`을 받아 토스트로 말한다. 도메인마다의 경쟁은 각 파일에 있다

### 재시도

- 적용 범위: 읽기와 쓰기 전부
- 기본 계약:
  - **읽기**는 TanStack Query 기본값(3회, 지수 백오프). 실패하면 캐시가 있으면 캐시 + 띠, 없으면 실패 화면
  - **쓰기**는 재시도하지 않는다. `TransportError`면 시트를 열어둔 채 「다시 시도」 버튼이고 사람이 누른다. 예외는 출근 인증 하나
  - **재시도해도 안전한 함수는 두 번 불려도 한 번만 쓴다.** `check_in`이 `already_done`을 던지는 것이 그 규칙이다

## 로딩·낙관적 처리

### 로딩

- 적용 범위: 데이터를 기다리는 모든 화면과 버튼
- 기본 계약:
  - **화면 첫 진입에 데이터가 없으면 스켈레톤이다.** 최종 모양의 회색 덩이라 데이터가 와도 레이아웃이 안 튄다. 조각은 `components.md`에 올린다
  - **캐시가 있으면 로딩 표시가 없다.** 옛 데이터를 보이고 뒤에서 갱신한다. 값이 바뀌면 그 자리만 바뀐다
  - **보내는 중인 버튼은 글자 자리에 스피너다.** 이미 토큰이 있다
  - **앱 스플래시는 OS가 그린다.** 배경색과 아이콘을 주면 앱이 뜰 때까지 그것이 떠 있고, 캐시 복원이 끝나면 내린다

### 낙관적 업데이트

- 적용 범위: 화면이 일으키는 쓰기
- 기본 계약: **되돌릴 수 있고 남과 안 겹치는 것만 즉시 칠한다.** 근무 신청 체크, 알림 읽음, 프로필 연락처. 실패하면 되돌리고 토스트. **남과 겹치거나 되돌릴 수 없는 것은 응답을 기다린다.** 근무 요청 수락, 교대 승인, 출근 인증, 확정. 버튼이 스피너를 물고 잠긴다

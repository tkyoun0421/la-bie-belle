# 문안

화면에 나가는 한국어 규칙이다. 토스 TDS의 [Consumer UX Guide](https://developers-apps-in-toss.toss.im/design/consumer-ux-guide)를 가져와 우리 앱에 맞췄다.

## 해요체로 통일한다

앱 전체가 해요체다. 합쇼체(`~습니다`)와 섞지 않는다.

한 화면 안에서 어체가 섞이면 문장마다 말하는 사람이 바뀌는 것처럼 읽힌다. 해요체를 고른 이유는 이 앱이 근무자 서른 명이 매일 쓰는 도구라서다. 합쇼체는 격식이 필요한 공지에 어울리고 매일 보는 화면에서는 딱딱하다.

| 쓴다 | 안 쓴다 |
| --- | --- |
| 오늘 근무가 있어요 | 오늘 근무가 있습니다 |
| 인증이 끝났어요 | 인증이 완료되었습니다 |
| 아직 확정 전이에요 | 아직 확정되지 않았습니다 |

## 능동형과 긍정형을 먼저 쓴다

무엇이 일어났는지가 아니라 누가 무엇을 했는지로 쓴다. 안 되는 것보다 되는 것을 먼저 말한다.

| 쓴다 | 안 쓴다 |
| --- | --- |
| 관리자가 9월 근무표를 확정했어요 | 9월 근무표가 확정되었습니다 |
| 근무 시작 1시간 전부터 인증할 수 있어요 | 근무 시작 1시간 전에는 인증할 수 없어요 |
| 교대 요청을 보냈어요 | 교대 요청이 전송 처리되었어요 |

피동형은 행위자를 지운다. "근무표가 변경되었습니다"를 읽으면 누가 바꿨는지 모른다. 교대로 바뀐 것과 관리자가 강제 변경한 것은 근무자에게 다른 사건이라([domain/swap.md](../domain/swap.md)) 문장이 그걸 구분해야 한다.

## 다이얼로그 왼쪽 버튼은 "닫기"다

"취소"라고 쓰지 않는다.

"취소"는 두 가지로 읽힌다. 다이얼로그를 닫는다는 뜻일 수도 있고, 지금 진행 중인 작업을 취소한다는 뜻일 수도 있다. "교대 요청을 보낼까요?"라는 다이얼로그에서 "취소"를 누르면 요청이 취소되는 것인지 다이얼로그만 닫히는 것인지 알 수 없다.

"닫기"는 다이얼로그를 닫는다는 뜻만 있다.

작업 자체를 취소하는 버튼이 필요하면 무엇을 취소하는지 적는다. "교대 요청 취소"처럼 쓴다.

## 과도한 경어를 뺀다

높이는 말이 많을수록 문장이 길어지고, 길어지면 읽는 데 오래 걸린다. 매일 십 초 쓰는 화면에서는 존중보다 속도가 낫다.

| 쓴다 | 안 쓴다 |
| --- | --- |
| 삭제할까요? | 삭제하시겠어요? |
| 오늘 근무가 있어요 | 오늘 근무가 있으세요 |
| 관리자가 확인 중이에요 | 관리자가 확인하고 계세요 |
| 관리자에게 확인할게요 | 관리자께 여쭤볼게요 |

`~시겠어요?`는 지운다. 계시다는 있다로, 여쭙다는 확인하다로, `~께`는 `~에게`로 쓴다.

## 다크패턴을 쓰지 않는다

다섯을 금지한다.

**진입 시 전면 바텀시트.** 앱을 열자마자 전체를 덮는 시트를 띄우지 않는다. 근무자가 앱을 여는 이유는 오늘 근무를 보려는 것이고, 대시보드가 그 답을 들고 있다. 알림 권한 요청도 스플래시 다음에 바로 덮지 않는다.

**뒤로가기 인터럽트.** 뒤로가기를 눌렀는데 "정말 나가시겠어요?"로 붙잡지 않는다. 입력하던 것이 날아가는 자리라면 그 사실만 알리고 나가는 길을 막지 않는다.

**거절 선택지 없는 안내.** 버튼이 "확인" 하나뿐인 다이얼로그로 동의를 받지 않는다. 알림을 끄는 것도 마찬가지다. [domain/notification.md](../domain/notification.md)가 근무자는 알림을 통째로 끌 수 있다고 정해뒀고, 화면이 그 선택을 어렵게 만들지 않는다.

**예상치 못한 광고.** 이 앱에 광고는 없다. 나중에도 넣지 않는다.

**모호한 CTA 라벨.** 버튼에 "확인", "네", "계속"만 쓰지 않는다. 무엇이 일어나는지 적는다.

| 쓴다 | 안 쓴다 |
| --- | --- |
| 출근 인증하기 | 확인 |
| 교대 요청 보내기 | 네 |
| 9월 근무표 확정하기 | 계속 |

되돌릴 수 없는 동작일수록 라벨이 정확해야 한다. 출근 인증은 한 번 찍으면 되돌리는 길이 없고([domain/attendance.md](../domain/attendance.md)), 근무표 확정도 되돌릴 수 없다([domain/schedule.md](../domain/schedule.md)).

## 도메인 용어를 그대로 쓴다

화면 문구는 [docs/domain/](../domain/)의 용어를 그대로 쓴다. ADR-002가 문서와 코드와 화면이 같은 말을 쓴다고 정해뒀다.

| 쓴다 | 안 쓴다 |
| --- | --- |
| 근무표 | 스케줄, 시간표 |
| 배정 | 할당, 편성 |
| 포지션 | 역할, 파트 |
| 출근 인증 | 체크인, 출석 |
| 교대 | 스왑, 대타 |
| 강제 변경 | 관리자 변경 |
| 휴무 희망 | 휴무 신청 |
| 관리자 공지 | 공지사항 |
| 근무자 | 직원, 스태프 |

"휴무 희망"을 "휴무 신청"으로 바꾸면 뜻이 달라진다. 희망은 관리자를 구속하지 않고 신청은 승인이나 반려를 기대하게 만든다. domain 문서가 이걸 구분해뒀다.

앱 안에서 부르는 이름을 바꾸고 싶으면 화면이 아니라 domain 문서를 먼저 고친다.

## 우리 앱 문장

실제로 쓸 문장이다. 새 화면을 쓸 때 여기 어투를 따른다.

| 자리 | 문장 |
| --- | --- |
| 대시보드 오늘 근무 | 오늘 근무가 있어요 |
| 출근 인증 버튼 | 출근 인증하기 |
| 근무표 미확정 | 9월 근무표는 아직 확정 전이에요 |
| 근무표 미확정 보조 | 8월 28일에 나옵니다 |
| 인증 완료 | 출근 인증이 끝났어요 |
| 인증 창 열리기 전 | 근무 시작 1시간 전부터 누를 수 있어요 |
| 근무 없는 날 | 오늘은 근무가 없어요 |
| 급여 화면 머리 | 이번 주 예상 급여예요 |
| 교대 요청 도착 | 김민수 님이 9월 12일 근무를 바꾸고 싶어 해요 |
| 교대 만료 | 12시간이 지나 요청이 만료됐어요 |

### 확인이 필요한 두 문장

**"8월 28일에 나옵니다"** — 두 가지가 걸린다. 첫째로 어체가 합쇼체라 위의 해요체 규칙과 어긋난다. 둘째로 [domain/schedule.md](../domain/schedule.md)에 근무표 확정 마감일이 없다. 관리자가 언제 확정할지 앱이 모르는데 날짜를 약속하면 그 날짜에 안 나왔을 때 앱을 안 믿게 된다.

관리자가 예정일을 직접 알린 경우에만 쓸 수 있는 문장이다. 그런 입력을 받을지, 아니면 날짜 없이 "관리자가 확정하면 알려드릴게요"로 갈지 사람이 정한다.

## 급여는 예상치라고 밝힌다

[domain/payroll.md](../domain/payroll.md)가 정한 것이다. 앱이 계산한 급여는 예상치고 실제 지급액과 어긋날 수 있다.

금액을 자르거나 숨기지 않는다. 계산된 대로 보여주되 예상이라는 것을 같이 적는다.

| 쓴다 | 안 쓴다 |
| --- | --- |
| 이번 주 예상 급여예요 | 이번 주 급여 |
| 실제 지급액과 다를 수 있어요 | (생략) |

"약 126,000원"처럼 숫자를 뭉개지 않는다. 근무자가 검산할 근거를 주는 것이 이 화면의 목적이라 숫자는 정확해야 하고, 예상이라는 것은 문장이 말한다.

## 숫자와 단위

- 금액은 세 자리마다 쉼표를 찍고 "원"을 붙인다. `126,000원`
- 시각은 24시간제다. `10:00`, `19:00`
- 날짜는 `9월 12일`로 쓴다. 연도가 필요하면 `2026년 9월 12일`
- 요일은 괄호로 붙인다. `9월 12일(토)`
- 시간 길이는 `9시간`으로 쓴다

숫자가 세로로 쌓이는 자리에는 `tabular-nums`를 건다.

## 사람 이름

`김민수 님`처럼 이름 뒤에 띄어쓰고 "님"을 붙인다. "김민수님"으로 붙여 쓰지 않는다.

관리자 화면의 목록처럼 이름이 잔뜩 나열되는 자리에서는 "님"을 뺀다. 스무 명 목록에 "님"이 스무 번 나오면 이름을 훑기 어렵다.

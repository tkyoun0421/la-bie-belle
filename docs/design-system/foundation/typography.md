# 타이포그래피

규칙과 근거를 담는다. 크기와 행간과 굵기 값은 [tokens.md](../tokens.md#3-타이포그래피)에만 있다.

## 스케일

7단계다. 토스 TDS의 스케일을 그대로 가져왔다. 크기만이 아니라 행간까지 짝으로 정해져 있어서, 개발자가 `leading-`을 따로 고를 일이 없다.

| 유틸 | 용도 |
| --- | --- |
| `text-3xl` | 아주 큰 제목 |
| `text-2xl` | 큰 제목 |
| `text-xl` | 일반 제목 |
| `text-lg` | 작은 제목 |
| `text-base` | 일반 본문 |
| `text-sm` | 작은 본문 |
| `text-xs` | 부가 텍스트 |

이름은 Tailwind 기본 이름을 그대로 두고 값만 갈아끼웠다. `text-title-1` 같은 새 이름을 만들 수도 있었지만 그러면 shadcn이 뱉는 `text-sm`이 우리 스케일 밖에 남는다. 컴포넌트 하나 설치할 때마다 클래스를 손으로 바꿔야 하고, 안 바꾼 자리가 조용히 남는다. 이름을 빼앗는 쪽이 싸다.

`text-4xl`부터 위는 지웠다. 가장 큰 단계보다 큰 글자를 쓸 자리가 없다.

행간을 클래스로 따로 건드리지 않는다. `text-base leading-6` 같은 조합은 스케일 밖으로 나가는 것이고, 한글은 라틴 문자보다 세로로 꽉 차서 행간을 줄이면 금방 답답해진다. 토큰의 행간이 이미 그것을 감안한 값이다.

## 굵기

다섯이다.

| 유틸 | 쓰는 자리 |
| --- | --- |
| `font-light` | 아주 큰 숫자 |
| `font-normal` | 본문 |
| `font-medium` | 라벨, 버튼 |
| `font-semibold` | 제목 |
| `font-bold` | 강조 |

Tailwind가 들고 오는 `font-thin`, `font-extralight`, `font-extrabold`, `font-black`은 지웠다.

한글에서 굵기는 라틴 문자보다 티가 덜 난다. 획이 많아서 인접한 두 단계의 차이가 작다. 강조가 필요하면 굵기 한 단계보다 크기 한 단계가 잘 먹는다.

## 서체

Pretendard를 self-host한다.

고른 이유는 셋이다. 한글과 라틴 문자의 획 두께가 맞아서 "9월 12일 10:00" 같은 문자열이 한 줄에서 어긋나지 않는다. 라이선스가 SIL Open Font License라 상업적 사용과 수정과 재배포가 전부 열려 있다. 그리고 Google Fonts에 없어서 CDN으로 붙일 길이 없고, 어차피 파일을 우리가 들고 있어야 한다.

self-host는 라이선스 문제가 아니라 성능 선택이기도 하다. 외부 폰트 호스트를 거치면 첫 화면에서 연결이 한 번 더 생긴다. 매일 십 초 쓰는 앱에서 그 왕복이 화면 전체를 늦춘다.

`next/font/local`로 붙인다. 설정 코드는 [tokens.md](../tokens.md#서체-연결)에 있다. 가변 폰트 한 장으로 무게 다섯을 다 덮는다. 무게마다 파일을 따로 받으면 다섯 번 내려받아야 한다.

한글 폰트는 글자 수 때문에 라틴 폰트보다 훨씬 무겁다. 실제로 붙일 때 서브셋 버전을 쓸지 확인한다. 폰트가 늦게 와도 글자가 먼저 보이게 `display: "swap"`을 건다.

## 숫자 정렬

시각과 금액에는 `tabular-nums`를 건다.

```
<span className="tabular-nums">126,000원</span>
```

`tabular-nums`가 없으면 숫자마다 폭이 달라서 세로로 쌓인 목록에서 자릿수가 어긋난다. `1`은 좁고 `0`은 넓어서 급여 내역을 훑을 때 금액이 들쭉날쭉해 보인다. 근무 시각도 마찬가지다. `11:00`과 `10:00`이 다른 폭으로 찍힌다.

거는 자리는 이렇다.

- 근무 시각과 인증 시각
- 급여 금액과 시급
- 날짜와 근무 시간 합계

문장 안에 섞인 숫자에는 안 건다. "근무자 30명"처럼 흐르는 글에서는 오히려 어색하다.

## 크기를 하드코딩하지 않는다

`font-size`를 직접 쓰거나 대괄호 임의값으로 크기를 박지 않는다. 토큰만 쓴다.

토큰 값은 rem이다. iOS와 안드로이드의 접근성 글자 크기 설정, 그리고 브라우저의 기본 글자 크기 설정이 rem에는 걸리고 px에는 안 걸린다. px로 박으면 근무자가 시스템에서 글자를 키워도 앱만 그대로 남는다.

TDS가 이 원칙을 명시해뒀고 우리도 그대로 가져온다. 웨딩홀 근무자 서른 명 중에 글자를 키워 쓰는 사람이 반드시 있다.

스케일 밖 크기가 필요해 보이면 대개 스케일이 아니라 레이아웃이 잘못된 것이다. 그래도 필요하면 토큰을 하나 더하고 [tokens.md](../tokens.md#3-타이포그래피)에 줄을 더한다.

## 화면에서 자주 쓰는 자리

출발점이다. 화면별 디자인이 나오면 그쪽이 정본이 된다.

| 자리 | 단계 | 굵기 |
| --- | --- | --- |
| 급여 금액 | `text-3xl` | `font-light` |
| 화면 제목 | `text-xl` | `font-semibold` |
| 카드 제목 | `text-lg` | `font-semibold` |
| 본문 | `text-base` | `font-normal` |
| 목록 한 줄의 이름 | `text-base` | `font-medium` |
| 목록 한 줄의 보조 정보 | `text-sm` | `font-normal` |
| 버튼 라벨 | `text-base` | `font-medium` |
| 배지, 시각, 날짜 | `text-xs` | `font-medium` |

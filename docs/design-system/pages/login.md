# 로그인과 승인 대기

앱에 들어오는 두 화면이다. 값은 [tokens.md](../tokens.md)에만 있고 여기는 토큰 이름으로만 말한다.

화면 둘을 한 파일에 둔 것은 둘이 한 흐름이기 때문이다. 로그인하면 승인 대기가 나오고, 승인 대기에서 로그아웃하면 로그인으로 돌아온다. 짜임과 여백 틀과 등장 모션이 같아서 파일을 나누면 같은 규칙을 두 번 적게 된다.

어느 화면이 뜨는지는 [domain/account.md](../../domain/account.md)의 승인 시각이 가른다. 세션이 없으면 로그인, 세션이 있고 승인 시각이 비었으면 승인 대기다.

---

## 로그인

### 짜임

세로로 한 줄씩 쌓고 전부 가운데 정렬이다.

1. 브랜드 마크 — 둥근 사각형 안에 "라"
2. 서비스 이름
3. 한 줄 설명
4. 구글 버튼
5. 버튼 아래 안내 문구

덩이는 둘이다. 1~3이 가운데 덩이고 4~5가 아래 덩이다. 남는 세로 공간을 가운데 덩이의 위와 아래가 반씩 나눠 가져서, 가운데 덩이는 화면 한가운데에 서고 아래 덩이는 바닥에 붙는다.

카드를 쓰지 않는다. 누를 것이 하나뿐인 화면에서 테두리가 나눌 것이 없다. 다른 화면이 카드를 쓴다는 이유만으로 여기도 두면 결만 맞추고 값은 없다.

### 색

| 자리 | 토큰 |
| --- | --- |
| 화면 바탕 | `bg.neutral` |
| 브랜드 마크 면 | `bg.brand-solid` |
| 브랜드 마크 글자 | `fg.brand-contrast` |
| 서비스 이름 | `fg.neutral` |
| 한 줄 설명 | `fg.neutral-subtle` |
| 버튼 아래 안내 문구 | `fg.neutral-subtle` |

구글 버튼은 이 표에 없다. 우리 팔레트를 못 쓰는 자리라 [아래 절](#구글-버튼은-구글이-정한다)에서 따로 다룬다.

### 글자

| 자리 | 유틸 |
| --- | --- |
| 브랜드 마크 글자 | `text-lg font-bold` |
| 서비스 이름 | `text-2xl font-bold` |
| 한 줄 설명 | `text-sm` |
| 구글 버튼 라벨 | `text-sm font-medium` |
| 버튼 아래 안내 문구 | `text-xs` |

### 여백과 모양

| 자리 | 유틸 |
| --- | --- |
| 화면 좌우 여백 | `px-6` |
| 화면 아래 여백 | `pb-6`에 `env(safe-area-inset-bottom)`을 더한다 |
| 브랜드 마크 | `size-12` `rounded-lg` |
| 마크와 이름 사이 | `mb-5` |
| 이름과 설명 사이 | `mt-2` |
| 구글 버튼 | `h-12` `rounded-full` |
| 버튼과 안내 문구 사이 | `mt-4` |

버튼은 좌우 여백만 남기고 화면 폭을 채운다.

아래 여백에 `env(safe-area-inset-bottom)`을 더하는 이유는 [components.md](../components.md#bottomcta)가 BottomCTA에 적어둔 것과 같다. 이 앱은 PWA라 홈 화면에서 실행되면 아이폰 홈 인디케이터가 버튼 자리까지 올라온다.

### 문안

| 자리 | 문장 |
| --- | --- |
| 브랜드 마크 | 라 |
| 서비스 이름 | 라비에벨 |
| 한 줄 설명 | 근무표와 급여를 한곳에서 봐요 |
| 구글 버튼 | Google 계정으로 로그인 |
| 버튼 아래 안내 | 가입하면 관리자가 확인한 뒤에 근무표가 보여요 |

안내 문구는 두 줄로 끊는다. "가입하면 관리자가 확인한 뒤에"에서 줄을 바꾼다.

이 문구가 승인 대기 화면을 미리 알린다. 로그인을 누르고 나서 처음 보는 화면이 대시보드가 아니라는 것을 누르기 전에 말해두면, 승인 대기 화면이 오류로 읽히지 않는다.

### 모션

**등장.** 아래에서 살짝 올라오며 나타난다. `--duration-slower`를 쓰고 요소끼리 어긋나게 계단을 준다. 순서는 브랜드 마크, 이름, 설명, 버튼, 안내 문구다.

[motion.md](../foundation/motion.md#자주-일어나는-것은-움직이지-않는다)가 자주 일어나는 것에는 모션을 얹지 말라고 했는데 이 화면은 거기 안 든다. 로그인 화면은 앱을 여는 사람이 한 번 보고 그 뒤로는 승인될 때까지 다시 안 본다.

계단 간격은 `tokens.md`에 없는 값이다. [아직 안 정한 것](#아직-안-정한-것)에 있다.

**버튼 눌림.** `--duration-fast`로 살짝 줄어든다. 스케일은 `tokens.md`의 버튼 눌림 값을 그대로 쓴다.

**로딩이 없다.** 구글 버튼을 누르면 그 자리에서 구글로 넘어간다. 스피너를 띄워도 보여줄 틈이 없고, 돌다 사라지는 것을 보면 실패한 것인지 넘어간 것인지 알 수 없다. 눌리는 동안 줄어드는 것만 남긴다.

**움직임 줄이기.** 켠 사람에게는 이동이 빠지고 밝기만 바뀐다. 이동 계열 클래스에만 `motion-safe:`를 붙인다.

## 승인 대기

### 짜임

세로로 쌓고 전부 가운데 정렬이다.

1. 승인 대기 알약 — 뛰는 점과 글자
2. 제목
3. 도는 문구 한 줄
4. 가는 선
5. 계정 한 줄 — 구글 프로필 사진과 이메일
6. 로그아웃 버튼

여기도 덩이가 둘이다. 1~3이 가운데 덩이, 4~6이 아래 덩이고 남는 공간을 가운데 덩이의 위아래가 반씩 나눈다.

**계정은 한 줄이다.** 사진과 이메일을 가로로 나란히 두고 가운데로 모은다. **이름은 안 보인다.** [domain/account.md](../../domain/account.md#프로필이-생기는-때)가 이름은 로그인 시점에 비어 있고 본인이 나중에 채운다고 정해뒀으니, 승인 전 화면에서는 대개 빈칸이 뜬다. 사진은 실제로 온다 — 같은 문서가 구글 프로필 사진으로 관리자가 사람을 구분한다고 적어뒀다.

**버튼은 로그아웃 하나다.** "다른 계정으로 로그인"을 같이 두지 않는다. 둘 다 세션을 끊는 같은 일이고, 로그아웃하면 로그인 화면이 나오니 계정은 거기서 고른다. 버튼 이름 둘이 같은 결과로 가면 무엇이 다른지 사람이 한 번 더 생각해야 한다.

### 색

| 자리 | 토큰 |
| --- | --- |
| 화면 바탕 | `bg.neutral` |
| 알약 면 | `bg.brand-weak` |
| 알약 글자 | `fg.brand` |
| 뛰는 점 | `bg.brand-solid` |
| 제목 | `fg.neutral` |
| 도는 문구 | `fg.neutral-muted` |
| 가는 선 | `stroke.neutral` |
| 이메일 | `fg.neutral-subtle` |
| 로그아웃 버튼 | [components.md](../components.md#button)의 Button outline |

알약은 [components.md](../components.md#badge)의 Badge brand와 같은 조합이다. 새로 정한 것이 아니다.

### 글자

| 자리 | 유틸 |
| --- | --- |
| 알약 | `text-xs font-medium` |
| 제목 | `text-xl font-bold` |
| 도는 문구 | `text-sm` |
| 이메일 | `text-sm` |
| 로그아웃 라벨 | `text-sm font-medium` |

제목이 로그인 화면의 서비스 이름보다 한 단계 작다. 승인 대기는 상태를 알리는 화면이지 앱을 소개하는 화면이 아니다.

### 여백과 모양

| 자리 | 유틸 |
| --- | --- |
| 화면 좌우 여백 | `px-6` |
| 화면 아래 여백 | `pb-6`에 `env(safe-area-inset-bottom)`을 더한다 |
| 알약 | `h-8` `px-3` `rounded-full` |
| 뛰는 점 | `size-1.5` |
| 점과 알약 글자 사이 | `gap-2` |
| 알약과 제목 사이 | `mt-4` |
| 제목과 도는 문구 사이 | `mt-2` |
| 가는 선 위아래 | `my-5` |
| 프로필 사진 | `size-8` `rounded-full` |
| 사진과 이메일 사이 | `gap-3` |
| 계정 줄과 버튼 사이 | `mt-4` |
| 로그아웃 버튼 | `h-12` `rounded-full` |

점에 `1.5`를 쓴 것은 [spacing-shape.md](../foundation/spacing-shape.md#가장-작은-두-눈금은-미세-조정에만)가 열어둔 자리다. 레이아웃이 아니라 조각 하나의 크기고, `1`로는 안 보이고 `2`로는 글자만큼 커진다.

도는 문구 자리는 두 줄이 들어갈 높이로 미리 잡는다. 문구마다 길이가 달라서 자리를 안 잡으면 줄이 갈릴 때 위아래가 같이 밀린다.

### 문안

| 자리 | 문장 |
| --- | --- |
| 알약 | 승인 기다리는 중 |
| 제목 | 관리자가 확인 중이에요 |
| 도는 문구 1 | 승인되면 알림이 가요 |
| 도는 문구 2 | 이번 달 근무표를 한눈에 봐요 |
| 도는 문구 3 | 출근은 현장에서 찍어요 |
| 도는 문구 4 | 일한 시간과 급여를 같이 봐요 |
| 계정 | 로그인한 구글 계정의 이메일 주소 |
| 버튼 | 로그아웃 |

**정해진 것은 넷을 돌린다는 것과 첫 줄이 상태라는 것이다.** 문장 자체는 나중에 고칠 수 있다. 첫 줄이 지금 무슨 일이 벌어지는지 말하고 나머지 셋이 승인된 뒤에 무엇을 하는 앱인지 말한다. 이 순서를 뒤집지 않는다 — 기다리는 사람이 가장 먼저 알고 싶은 것은 앱 소개가 아니다.

넷은 라벨이 아니라 소개 문구다. 그래서 [writing.md](../writing.md#도메인-용어를-그대로-쓴다)의 용어를 글자 그대로 옮기지 않은 자리가 있다. "출근 인증"이 셋째 줄에서 "출근은 현장에서 찍어요"가 됐다. 버튼이나 화면 제목이면 용어를 그대로 써야 하지만 여기는 앱을 처음 보는 사람에게 쓰임을 말하는 자리다.

### 모션

**등장.** 로그인 화면과 같다. 순서는 알약, 제목, 도는 문구, 가는 선부터 아래 덩이 전체다.

**뛰는 점.** 알약 안의 점이 커졌다 작아지며 계속 뛴다. 주기 값은 `tokens.md`에 없다.

**문구 교체.** `--duration-slow`로 밀려 올라가며 바뀐다. 나가는 줄은 위로 빠지고 들어오는 줄은 아래에서 올라온다. 이동 거리는 등장과 같은 눈금을 쓴다. 바뀌는 주기 값은 `tokens.md`에 없다.

제목은 안 바뀐다. 갈리는 것은 아래 한 줄뿐이다.

**움직임 줄이기.** 이동이 빠지고 밝기만 바뀐다. 점은 멈춘다. **글은 그대로 다 돈다.**

회전까지 멈추지 않는 것은 [motion.md](../foundation/motion.md#접근성)가 모션 없이 뜻이 안 통하는 화면을 만들지 말라고 했기 때문이다. 도는 문구는 밀려 올라가는 것이 아니라 글자가 갈리는 것으로 뜻이 통하고, 밝기만 바뀌어도 새 줄이 왔다는 것은 읽힌다. 점도 같다. 멈춰도 옆에 "승인 기다리는 중"이라고 적혀 있어서 상태가 사라지지 않는다.

## 구글 버튼은 구글이 정한다

이 버튼만 우리 디자인 시스템 밖에 있다. 권고가 아니라 필수 요건이고, 구글 문서가 app verification에 required라고 적었다. 배포할 때 OAuth 앱 심사가 이걸 본다. 출처는 [Google Identity — Branding guidelines](https://developers.google.com/identity/branding-guidelines)다.

못 바꾸는 것들이다.

- **배경은 셋 중 하나다.** 밝게, 중간, 어둡게. 그 밖은 못 쓴다. **우리 브랜드 갈색은 규정 밖이다.** 우리는 어두운 배경을 쓴다.
- **G 로고의 색과 크기를 못 바꾼다.** 단색 버전도 못 쓰고 구식 로고도 못 쓴다.
- **로고만 두지 않는다.** 버튼 경계와 글자가 같이 있어야 한다.
- **"Google" 한 단어로 로그인 동작을 나타내지 않는다.**

바꿔도 되는 것들이다.

- **문구는 우리말로 쓴다.** 구글이 앱 언어로 번역하는 것을 허용하고 권장한다. 우리는 "Google 계정으로 로그인"을 쓴다.
- **모양은 직사각형과 알약 둘 다 허용한다.** 우리는 알약을 고른다. [components.md](../components.md#button)가 버튼을 `rounded-full`로 정했고 구글이 그것을 막지 않으니, 규정 안에서 우리 결을 지킬 수 있는 자리다.
- **크기는 조정한다.** 다만 종횡비는 유지한다.

**로고 에셋은 구글이 배포하는 `signin-assets.zip`을 받아 쓴다.** 직접 그린 SVG는 색이 조금씩 어긋나고, 어긋난 것을 눈으로는 못 잡는다. 구글이 사전 승인해 배포하는 파일을 그대로 쓰면 그 위험이 없다.

버튼의 배경과 테두리와 글자 색 셋은 구글이 못 박은 값이라 우리 팔레트 밖이다. `tokens.md`에 없고, 그래서 이 문서에도 적지 않는다. 어디에 둘지는 [아직 안 정한 것](#아직-안-정한-것)에 있다.

대비도 우리가 볼 자리가 아니다. 구글이 정한 조합이고 우리가 고칠 수 없어서 `tokens.md`의 대비 표에 줄을 더하지 않는다.

## 안 담은 것

**승인까지 걸리는 시간.** "하루 안에 처리돼요" 같은 문장을 쓰지 않는다. 관리자가 언제 확인하는지 정해둔 규칙이 `docs/domain/`에 없어서 앱이 모르는 것을 약속하게 된다. 그 시각이 지났는데 승인이 안 나면 그 뒤로는 앱이 하는 말을 안 믿는다. [writing.md](../writing.md#확인이-필요한-두-문장)가 근무표 확정 날짜를 두고 이미 같은 판정을 내렸다.

이 판단은 이 화면 하나가 아니라 앞으로 나올 화면 전부에 걸린다. **앱이 모르는 시각을 약속하지 않는다.**

**관리자에게 연락할 길.** 둘이 막는다. 첫째로 [domain/account.md](../../domain/account.md#관리자)가 관리자를 여럿으로 두고 누가 가입 승인을 맡는지 안 나눴다. 둘째로 승인 전에는 자기 프로필 바깥을 한 행도 못 받아서 앱이 관리자 목록을 이 화면에 띄울 수 없다. 연락처를 코드에 박는 길도 없다 — 저장소가 PUBLIC이다.

**카드.** 두 화면 다 안 쓴다.

**로딩 표시.** 구글 버튼 자리에 없다.

**이름.** 승인 대기 화면에 안 나온다.

**"다른 계정으로 로그인" 버튼.** 로그아웃과 같은 일이다.

이름 입력 폼과 관리자 승인 화면은 이 문서 밖이다. 다음 task다.

## 규칙을 알고 어긴 자리

몰라서 어긴 것과 알고 정한 것은 다르다. 뒤에 오는 사람이 이 자리를 버그로 고치지 않게 남긴다.

**뛰는 점.** [motion.md](../foundation/motion.md#자주-일어나는-것은-움직이지-않는다)가 "모션을 얹을 자리는 상태가 실제로 바뀌는 순간"이라고 정했는데 이 점은 아무것도 안 바뀌는 동안 계속 움직인다.

그걸 알고 넣었다. 승인 대기 화면은 사람이 할 일이 없는 화면이라 정지 화면과 구분이 안 되고, 멈춘 화면은 앱이 죽은 것처럼 읽힌다. 기다리는 중이라는 것을 글자를 더 늘리지 않고 알리는 값이 규칙을 지키는 값보다 크다고 봤다.

대신 셋으로 값을 묶었다. 움직이는 것은 점 하나뿐이고, 이 화면 밖으로 안 나가고, 움직임 줄이기를 켜면 멈춘다.

**브랜드 마크의 브랜드 색.** [color.md](../foundation/color.md#브랜드-색을-아끼는-이유)가 브랜드 색이 나가는 자리를 셋으로 못 박았다. 주요 액션 버튼, 활성 탭, 강조 문구다. 로고는 그 셋에 없다.

로그인 화면에는 브랜드 색 버튼이 아예 없다. 구글 버튼이 그 자리를 차지했고 그 색은 우리가 못 정한다. 그래서 마크에 브랜드 색을 깔아도 "여기를 누르라"는 신호와 경쟁하지 않는다. 절제 규칙이 막으려던 것이 여기서는 안 일어난다.

`color.md`의 셋에 로고를 더할지는 총괄이 정한다.

## 아직 안 정한 것

임의로 채우지 않는다. 사람이 정하고 나서 이 절에서 뺀다.

**모션 값 셋.** 도는 문구가 바뀌는 주기, 점이 뛰는 주기, 등장 계단 간격이다. `tokens.md`의 duration 넷은 전부 한 번 일어나고 끝나는 전환의 길이라 이 셋을 담지 못한다. 앞의 둘은 되풀이 주기고 셋째는 요소 사이 간격이다. 새 토큰이 필요하고 이름과 값은 사람이 정한다. 그때까지 이 문서는 셋을 이름으로만 가리킨다.

**구글 버튼 색 셋을 어디 둘지.** 배경과 테두리와 글자다. 우리 팔레트 밖이고 지금 lint가 hex 리터럴을 잡으니 화면 코드에 그냥 적을 수 없다. `tokens.md`에 구글 전용 자리를 만들지, lint를 그 자리만 뚫을지 정해야 한다.

**"승인되면 알림이 가요"의 근거.** [domain/notification.md](../../domain/notification.md#다섯)가 푸시로 나가는 것을 다섯으로 못 박았는데 가입 승인이 그 다섯에 없다. 지금 이 문장은 앱이 안 하는 일을 약속한다. 알림을 여섯으로 늘리든 문장을 고치든 둘 중 하나다.

**라이트와 다크에서 버튼 테마를 나눌지.** 지금은 양쪽 다 어두운 배경 하나다. 구글이 테마마다 다른 버튼을 쓰는 것을 막지 않으니 다크에서 밝은 버튼으로 바꿀 수도 있다. 실제 화면을 보고 정한다.

**브랜드 마크가 `color.md`의 셋에 드는지.** 위의 「규칙을 알고 어긴 자리」에 있다.

**도는 문구 넷의 문장.** 넷을 돌린다는 것과 첫 줄이 상태라는 것만 정해졌다.

# 로그인과 승인 대기

앱에 들어오는 두 화면이다. 값은 [tokens.md](../tokens.md)에만 있고 여기는 토큰 이름으로만 말한다.

화면 둘을 한 파일에 둔 것은 둘이 한 흐름이기 때문이다. 로그인하면 승인 대기가 나오고, 승인 대기에서 로그아웃하면 로그인으로 돌아온다. 짜임과 여백 틀과 등장 모션이 같아서 파일을 나누면 같은 규칙을 두 번 적게 된다.

어느 화면이 뜨는지는 [domain/account.md](../../domain/account.md)의 승인 시각이 가른다. 세션이 없으면 로그인, 세션이 있고 승인 시각이 비었으면 승인 대기다.

---

## 로그인

### 짜임

세로로 한 줄씩 쌓고 전부 가운데 정렬이다.

1. 브랜드 마크 — 둥근 사각형 안에 "라"
2. 서비스 이름
3. 한 줄 설명
4. 구글 버튼
5. 버튼 아래 안내 문구

덩이는 둘이다. 1~3이 가운데 덩이고 4~5가 아래 덩이다. 남는 세로 공간을 가운데 덩이의 위와 아래가 반씩 나눠 가져서, 가운데 덩이는 화면 한가운데에 서고 아래 덩이는 바닥에 붙는다.

카드를 쓰지 않는다. 누를 것이 하나뿐인 화면에서 테두리가 나눌 것이 없다. 다른 화면이 카드를 쓴다는 이유만으로 여기도 두면 결만 맞추고 값은 없다.

### 색

| 자리 | 토큰 |
| --- | --- |
| 화면 바탕 | `bg.neutral` |
| 브랜드 마크 면 | `bg.brand-solid` |
| 브랜드 마크 글자 | `fg.brand-contrast` |
| 서비스 이름 | `fg.neutral` |
| 한 줄 설명 | `fg.neutral-subtle` |
| 버튼 아래 안내 문구 | `fg.neutral-subtle` |

구글 버튼은 이 표에 없다. 우리 팔레트를 못 쓰는 자리라 [아래 절](#구글-버튼은-구글이-정한다)에서 따로 다룬다.

### 글자

| 자리 | 유틸 |
| --- | --- |
| 브랜드 마크 글자 | `text-lg font-bold` |
| 서비스 이름 | `text-2xl font-bold` |
| 한 줄 설명 | `text-sm` |
| 구글 버튼 라벨 | `text-sm font-medium` |
| 버튼 아래 안내 문구 | `text-xs` |

### 여백과 모양

| 자리 | 유틸 |
| --- | --- |
| 화면 좌우 여백 | `px-6` |
| 화면 아래 여백 | `pb-6`에 `env(safe-area-inset-bottom)`을 더한다 |
| 브랜드 마크 | `size-12` `rounded-lg` |
| 마크와 이름 사이 | `mb-5` |
| 이름과 설명 사이 | `mt-2` |
| 구글 버튼 | `h-12` `rounded-full` |
| 버튼과 안내 문구 사이 | `mt-4` |

버튼은 좌우 여백만 남기고 화면 폭을 채운다.

아래 여백에 `env(safe-area-inset-bottom)`을 더하는 이유는 [components.md](../components.md#bottomcta)가 BottomCTA에 적어둔 것과 같다. 이 앱은 PWA라 홈 화면에서 실행되면 아이폰 홈 인디케이터가 버튼 자리까지 올라온다.

### 문안

| 자리 | 문장 |
| --- | --- |
| 브랜드 마크 | 라 |
| 서비스 이름 | 라비에벨 |
| 한 줄 설명 | 근무표와 급여를 한곳에서 봐요 |
| 구글 버튼 | Google 계정으로 로그인 |
| 버튼 아래 안내 | 가입하면 관리자가 확인한 뒤에 근무표가 보여요 |

안내 문구는 두 줄로 끊는다. "가입하면 관리자가 확인한 뒤에"에서 줄을 바꾼다.

이 문구가 승인 대기 화면을 미리 알린다. 로그인을 누르고 나서 처음 보는 화면이 대시보드가 아니라는 것을 누르기 전에 말해두면, 승인 대기 화면이 오류로 읽히지 않는다.

### 모션

**등장.** 아래에서 살짝 올라오며 나타난다. 한 요소가 움직이는 시간은 `--duration-slower`고 요소끼리 어긋나는 간격은 `--stagger-step`이다. 순서는 브랜드 마크, 이름, 설명, 버튼, 안내 문구다.

[motion.md](../foundation/motion.md#자주-일어나는-것은-움직이지-않는다)가 자주 일어나는 것에는 모션을 얹지 말라고 했는데 이 화면은 거기 안 든다. 로그인 화면은 앱을 여는 사람이 한 번 보고 그 뒤로는 승인될 때까지 다시 안 본다.

**버튼 눌림.** `--duration-fast`로 살짝 줄어든다. 스케일은 `tokens.md`의 버튼 눌림 값을 그대로 쓴다.

**로딩이 없다.** 구글 버튼을 누르면 그 자리에서 구글로 넘어간다. 스피너를 띄워도 보여줄 틈이 없고, 돌다 사라지는 것을 보면 실패한 것인지 넘어간 것인지 알 수 없다. 눌리는 동안 줄어드는 것만 남긴다.

**움직임 줄이기.** 켠 사람에게는 이동이 빠지고 밝기만 바뀐다. 이동 계열 클래스에만 `motion-safe:`를 붙인다.

## 승인 대기

### 짜임

세로로 쌓고 전부 가운데 정렬이다.

1. 승인 대기 알약 — 뛰는 점과 글자
2. 제목
3. 도는 문구 한 줄
4. 알림 영역
5. 가는 선
6. 계정 한 줄 — 구글 프로필 사진과 이메일
7. 로그아웃 버튼

여기도 덩이가 둘이다. 1~3이 가운데 덩이, 4~7이 아래 덩이고 남는 공간을 가운데 덩이의 위아래가 반씩 나눈다.

**알림 영역이 아래 덩이의 맨 위다.** 도는 문구 아래, 가는 선 위에 온다. 화면이 짧아 자리가 모자라면 위아래로 나눠 갖던 남는 공간이 먼저 사라지고 가운데 덩이가 위로 붙는다. 도는 문구 넷은 줄이지 않는다 — 넷을 돌리는 것이 이 화면이 기다리는 시간을 쓰는 방식이라, 자리를 만들려고 그걸 깎으면 화면에 남는 것이 상태를 알리는 두 줄뿐이다.

**계정은 한 줄이다.** 사진과 이메일을 가로로 나란히 두고 가운데로 모은다. **이름은 안 보인다.** [domain/account.md](../../domain/account.md#프로필이-생기는-때)가 이름은 로그인 시점에 비어 있고 본인이 나중에 채운다고 정해뒀으니, 승인 전 화면에서는 대개 빈칸이 뜬다. 사진은 실제로 온다 — 같은 문서가 구글 프로필 사진으로 관리자가 사람을 구분한다고 적어뒀다.

**아래 덩이의 버튼은 로그아웃 하나다.** "다른 계정으로 로그인"을 같이 두지 않는다. 둘 다 세션을 끊는 같은 일이고, 로그아웃하면 로그인 화면이 나오니 계정은 거기서 고른다. 버튼 이름 둘이 같은 결과로 가면 무엇이 다른지 사람이 한 번 더 생각해야 한다.

### 알림 영역의 세 모습

[domain/notification.md](../../domain/notification.md#켜는-자리)가 알림 켜기를 받는 자리를 이 화면으로 정했다. 로그인은 됐는데 볼 것이 없는 유일한 시간이라 방해가 가장 덜하다.

한 자리가 기기 상태에 따라 셋으로 갈린다.

| 모습 | 언제 | 담는 것 |
| --- | --- | --- |
| 아직 안 켬 | 들어왔을 때의 기본 | 제목, 아래 줄, 「알림 켜기」 버튼 |
| 켠 뒤 | 권한이 실제로 허용됐을 때 | 체크 아이콘과 제목, 아래 줄 |
| 아이폰·홈 화면 전 | 「알림 켜기」가 안 먹혔을 때 | 제목, 번호 매긴 3단계 |

**저절로 안 띄운다.** 화면에 들어가자마자 권한을 묻지 않는다. 사람이 「알림 켜기」를 눌러야 브라우저가 묻는다. [writing.md](../writing.md#다크패턴을-쓰지-않는다)가 알림 권한 요청도 스플래시 다음에 바로 덮지 말라고 못 박았고, `notification.md`의 「켜는 자리」가 도메인 쪽에서 같은 말을 한다.

**아이폰을 판별하지 않는다.** 사파리인지, 홈 화면 추가를 했는지를 브라우저를 보고 알아내지 않는다. 셋째 모습은 처음부터 뜨는 것이 아니라 첫째에서 전이된 결과다. 「알림 켜기」를 눌렀는데 권한 요청이 안 먹히면 그때 바뀐다.

판별을 버린 이유는 정확도다. userAgent로 기기와 브라우저를 알아내는 것은 자주 틀리고, 틀리면 아이폰이 아닌 사람에게 홈 화면 추가를 시키거나 아이폰 사람에게 안 먹히는 버튼을 남긴다. 눌러본 결과는 안 틀린다. 켜기를 시도한 자리에서 실제로 무슨 일이 일어났는지가 답이라 추측할 것이 없다.

**셋째 모습에는 버튼이 없다.** 홈 화면 추가는 앱이 대신 해줄 수 없고 사파리의 공유 메뉴에서만 되는 일이다. 여기에 누를 것을 두면 눌러도 아무 일이 안 일어난다. 대신 3단계를 적는다.

### 색

| 자리 | 토큰 |
| --- | --- |
| 화면 바탕 | `bg.neutral` |
| 알약 면 | `bg.brand-weak` |
| 알약 글자 | `fg.brand` |
| 뛰는 점 | `bg.brand-solid` |
| 제목 | `fg.neutral` |
| 도는 문구 | `fg.neutral-muted` |
| 알림 영역 면 — 아직 안 켬 | `bg.neutral-weak` |
| 알림 영역 면 — 켠 뒤 | `bg.positive-weak` |
| 알림 영역 면 — 아이폰 | `bg.informative-weak` |
| 알림 영역 제목 | `fg.neutral` |
| 알림 영역 아래 줄과 3단계 | `fg.neutral-muted` |
| 체크 아이콘 | `fg.positive` |
| 알림 켜기 버튼 | [components.md](../components.md#button)의 Button primary |
| 가는 선 | `stroke.neutral` |
| 이메일 | `fg.neutral-subtle` |
| 로그아웃 버튼 | [components.md](../components.md#button)의 Button outline |

알약은 [components.md](../components.md#badge)의 Badge brand와 같은 조합이다. 새로 정한 것이 아니다.

알림 영역의 면 셋 중 둘은 [components.md](../components.md#알림-블록)의 알림 블록에서 왔다. 켠 뒤가 성공이고 아이폰 안내가 안내다. 아직 안 켬은 그 넷 중 어디에도 안 들어서 `bg.neutral-weak`를 깔았다 — 넷은 전부 무슨 일이 일어났다고 말하는 색인데 여기는 아직 아무 일도 안 일어난 자리다.

글자에는 색을 안 입힌다. 알림 블록의 규칙 그대로 뜻은 면과 아이콘이 나르고 제목은 읽히는 데만 집중한다. 아이콘이 있는 것은 켠 뒤 하나뿐이고 나머지 둘은 제목이 상태를 말한다.

**아래 줄이 `fg.neutral-muted`인 것은 대비 때문이다.** 시안은 한 단계 더 흐린 색을 썼는데, `fg.neutral-subtle`을 `bg.informative-weak` 위에 올리면 라이트에서 4.49로 본문 기준 아래로 떨어진다. 나머지 두 면에서도 4.5를 겨우 넘는다. 세 면에 한 토큰을 쓰려면 `fg.neutral-muted`가 셋 다 통과하는 유일한 값이다. 측정값은 [tokens.md](../tokens.md#7-대비-검증)에 넣었고 떨어진 조합도 거기 적었다.

### 글자

| 자리 | 유틸 |
| --- | --- |
| 알약 | `text-xs font-medium` |
| 제목 | `text-xl font-bold` |
| 도는 문구 | `text-sm` |
| 알림 영역 제목 | `text-sm font-semibold` |
| 알림 영역 아래 줄과 3단계 | `text-xs` |
| 알림 켜기 라벨 | `text-sm font-medium` |
| 이메일 | `text-sm` |
| 로그아웃 라벨 | `text-sm font-medium` |

제목이 로그인 화면의 서비스 이름보다 한 단계 작다. 승인 대기는 상태를 알리는 화면이지 앱을 소개하는 화면이 아니다.

알림 영역 제목은 도는 문구와 크기가 같고 굵기로만 갈린다. 화면 제목을 키로 삼으면 알림이 이 화면의 주인공처럼 읽히는데, 주인공은 여전히 기다리는 상태고 알림은 그 옆에 붙는 제안이다. 체크 아이콘 크기는 표에 없다 — [components.md](../components.md#아이콘)가 아이콘은 옆 글자 크기를 따라간다고 정했다.

### 여백과 모양

| 자리 | 유틸 |
| --- | --- |
| 화면 좌우 여백 | `px-6` |
| 화면 아래 여백 | `pb-6`에 `env(safe-area-inset-bottom)`을 더한다 |
| 알약 | `h-8` `px-3` `rounded-full` |
| 뛰는 점 | `size-1.5` |
| 점과 알약 글자 사이 | `gap-2` |
| 알약과 제목 사이 | `mt-4` |
| 제목과 도는 문구 사이 | `mt-2` |
| 알림 영역 | `rounded-lg` `p-4` |
| 체크와 알림 영역 제목 사이 | `gap-2` |
| 알림 영역 제목과 아래 줄 사이 | `mt-2` |
| 알림 영역 제목과 3단계 사이 | `mt-2` |
| 아래 줄과 알림 켜기 버튼 사이 | `mt-4` |
| 알림 켜기 버튼 | `h-10` `rounded-full` |
| 가는 선 위아래 | `my-5` |
| 프로필 사진 | `size-8` `rounded-full` |
| 사진과 이메일 사이 | `gap-3` |
| 계정 줄과 버튼 사이 | `mt-4` |
| 로그아웃 버튼 | `h-12` `rounded-full` |

점에 `1.5`를 쓴 것은 [spacing-shape.md](../foundation/spacing-shape.md#가장-작은-두-눈금은-미세-조정에만)가 열어둔 자리다. 레이아웃이 아니라 조각 하나의 크기고, `1`로는 안 보이고 `2`로는 글자만큼 커진다.

도는 문구 자리는 두 줄이 들어갈 높이로 미리 잡는다. 문구마다 길이가 달라서 자리를 안 잡으면 줄이 갈릴 때 위아래가 같이 밀린다.

알림 영역 안은 눈금 둘로만 짠다. 붙어 있는 것끼리는 `2`, 성격이 갈리는 자리에는 `4`다. [spacing-shape.md](../foundation/spacing-shape.md#주-리듬)의 주 리듬 안이고, 상자 하나에서 값을 더 늘리면 여백이 리듬이 아니라 취향이 된다.

**알림 켜기 버튼이 로그아웃보다 낮다.** 로그아웃은 화면 폭을 채우는 `h-12`고 알림 켜기는 면 안에 들어앉은 `h-10`이다. 둘이 같으면 화면 아래쪽에 같은 크기의 버튼이 둘 서서 어느 쪽이 이 화면의 끝인지 흐려진다.

### 문안

| 자리 | 문장 |
| --- | --- |
| 알약 | 승인 기다리는 중 |
| 제목 | 관리자가 확인 중이에요 |
| 도는 문구 1 | 이번 달 근무표를 한눈에 봐요 |

| 알림 아래 줄 — 아직 안 켬 | 알림을 켜두면 앱을 안 열어도 알 수 있어요 |
| 알림 버튼 | 알림 켜기 |
| 알림 제목 — 켠 뒤 | 승인되면 알려드릴게요 |
| 알림 아래 줄 — 켠 뒤 | 알림은 설정에서 언제든 끌 수 있어요 |
| 알림 제목 — 아이폰 | 홈 화면에 추가하면 알림을 받아요 |
| 3단계 1 | 아래 공유 버튼을 눌러요 |
| 3단계 2 | "홈 화면에 추가"를 골라요 |
| 3단계 3 | 홈 화면에서 다시 열어요 |
| 계정 | 로그인한 구글 계정의 이메일 주소 |
| 버튼 | 로그아웃 |

**도는 문구에서 정해진 것은 넷을 돌린다는 것이다.** 문장 자체는 나중에 고칠 수 있다.

넷 다 승인된 뒤에 이 앱으로 무엇을 하는지 말한다. 상태를 말하는 줄은 없다. 알약이 "승인 기다리는 중"이라고 적고 제목이 "관리자가 확인 중이에요"라고 적어서 상태는 이미 두 번 나왔고, 도는 줄까지 상태면 한 화면에서 같은 말을 세 번 하게 된다.

넷째 줄의 근거는 [domain/swap.md](../../domain/swap.md)다. 근무자가 다른 근무자에게 교대를 요청하는 것이 도메인에 있어서 앱이 실제로 하는 일이다.

넷은 라벨이 아니라 소개 문구다. 그래서 [writing.md](../writing.md#도메인-용어를-그대로-쓴다)의 용어를 글자 그대로 옮기지 않은 자리가 있다. "출근 인증"이 둘째 줄에서 "출근은 현장에서 찍어요"가 됐다. 버튼이나 화면 제목이면 용어를 그대로 써야 하지만 여기는 앱을 처음 보는 사람에게 쓰임을 말하는 자리다.

**켠 사람에게만 약속한다.** 첫째 모습은 묻기만 하고 둘째 모습이 되어야 "알려드릴게요"라고 적는다. 알림을 안 켠 사람에게 앱이 알려줄 길은 없으니 그 사람에게는 약속하지 않는다. 안 켜도 그냥 넘어가는 것은 [domain/notification.md](../../domain/notification.md#켜는-자리)가 정한 대로다. 켜야만 다음으로 가는 문은 없다.

**"승인되면"이 피동인데 남겼다.** [writing.md](../writing.md#능동형과-긍정형을-먼저-쓴다)가 피동형을 물리는 이유는 행위자가 지워지기 때문인데, 바로 위 제목이 "관리자가 확인 중이에요"라고 적어 행위자를 이미 말했다. "관리자가 승인하면 알려드릴까요?"로 고치면 한 화면에서 관리자를 두 번 부르고 물음만 길어진다. 규칙이 막으려던 일이 안 일어나는 자리라 문장을 그대로 뒀다.

**끄는 길을 켠 자리에서 알린다.** 둘째 모습의 아래 줄이 설정에서 끌 수 있다고 말한다. [domain/notification.md](../../domain/notification.md#끄는-길)가 근무자는 알림을 통째로 끌 수 있다고 정했고 [writing.md](../writing.md#다크패턴을-쓰지-않는다)가 화면이 그 선택을 어렵게 만들지 말라고 했다. 켠 직후가 끄는 길을 알려주기 가장 싼 자리다.

3단계의 "홈 화면에 추가"는 iOS 공유 메뉴에 실제로 뜨는 이름이라 그대로 옮겼다. 우리말로 다듬으면 메뉴에서 그 항목을 못 찾는다.

### 「승인되면 알림이 가요」를 뺐다가 되돌린 경위

도는 문구의 첫 줄은 원래 "승인되면 알림이 가요"였고 사람이 고른 문구였다. 도메인과 부딪혀서 뺐고, 도메인이 바뀌고 나서 알림 영역으로 돌아왔다.

뺀 이유는 둘이었다. [domain/notification.md](../../domain/notification.md)가 푸시로 나가는 것을 다섯으로 못 박았는데 가입 승인이 그 다섯에 없었다. 앱이 안 하는 일을 약속하는 문장이었다는 뜻이다. 같은 문서가 [PWA 푸시는 홈 화면에 추가해야만 온다](../../domain/notification.md#아이폰)고 적어둔 것도 걸렸다. 승인 대기 중인 사람은 앱을 방금 처음 열었으니 홈 화면 추가를 했을 리가 없다.

둘 다 풀렸다. 알림이 [여섯](../../domain/notification.md#여섯)이 되면서 가입 승인이 맨 앞에 들어갔고, 여섯 중 그것만 승인 전 사람에게 간다. 홈 화면 추가를 어디서 안내할지는 [켜는 자리](../../domain/notification.md#켜는-자리)가 이 화면으로 정했다.

**돌아온 문장은 그때 뺀 문장과 다르다.** 그때는 도는 문구가 누구에게나 알림이 간다고 말했고, 지금은 알림을 켠 사람에게만 알려주겠다고 적는다. 알림 종류를 늘린 것만으로는 안 풀렸다. 이 화면을 보는 사람에게 푸시가 실제로 닿는지를 화면이 알아야 했고, 그걸 알아내는 자리가 「알림 켜기」 버튼이다.

### 모션

**등장.** 로그인 화면과 같다. 순서는 알약, 제목, 도는 문구, 그리고 알림 영역부터 아래 덩이 전체다.

**뛰는 점.** 알약 안의 점이 커졌다 작아지며 계속 뛴다. 주기는 `--interval-beat`다.

**문구 교체.** `--duration-slow`로 밀려 올라가며 바뀐다. 나가는 줄은 위로 빠지고 들어오는 줄은 아래에서 올라온다. 이동 거리는 등장과 같은 눈금을 쓴다. 갈리는 주기는 `--interval-rotate`다.

제목은 안 바뀐다. 갈리는 것은 아래 한 줄뿐이다.

**알림 켜기 눌림.** 로그인 화면의 버튼과 같다. `--duration-fast`로 살짝 줄어들고 스케일은 `tokens.md`의 버튼 눌림 값을 쓴다.

**모습이 갈릴 때.** 알림 영역의 내용과 면 색이 `--duration-base`로 함께 바뀐다. 첫째에서 둘째로 갈 때는 버튼이 빠지고 체크와 새 문장이 들어오며, 첫째에서 셋째로 갈 때는 3단계가 들어온다. 내용과 색을 따로 끊으면 한 번 누른 것이 두 번 바뀐 것처럼 보인다.

체크는 밝기가 들어오면서 `zoom-in-95`로 커진다. [motion.md](../foundation/motion.md#눌림과-등장)가 등장 애니메이션은 0에서 시작하지 말라고 했고 그 유틸이 정해둔 범위 안이다.

바로 위 문구 교체보다 짧은 것은 이동이 없기 때문이다. 도는 문구는 한 줄이 위아래로 밀리지만 알림 영역은 제자리에서 갈린다. [motion.md](../foundation/motion.md#duration-넷)가 이동 거리에 비례해 길이를 고르라고 했다.

새 토큰은 안 만들었다. 한 번 일어나고 끝나는 전환이라 `--duration-` 계열에 그대로 들고, 알림 영역은 화면 안의 작은 덩이라 [motion.md](../foundation/motion.md#duration-넷)가 `--duration-base`에 적어둔 "대부분의 전환"이 이 자리다. 되풀이하는 것도 아니고 요소끼리 어긋나는 것도 아니라 `--interval-`이나 `--stagger-`를 늘릴 이유도 없다.

**움직임 줄이기.** 이동이 빠지고 밝기만 바뀐다. 점은 멈추고 체크는 크기 변화 없이 밝기로만 들어온다. 모습이 갈리는 것 자체는 남는다. **글은 그대로 다 돈다.**

회전까지 멈추지 않는 것은 [motion.md](../foundation/motion.md#접근성)가 모션 없이 뜻이 안 통하는 화면을 만들지 말라고 했기 때문이다. 도는 문구는 밀려 올라가는 것이 아니라 글자가 갈리는 것으로 뜻이 통하고, 밝기만 바뀌어도 새 줄이 왔다는 것은 읽힌다. 점도 같다. 멈춰도 옆에 "승인 기다리는 중"이라고 적혀 있어서 상태가 사라지지 않는다.

## 구글 버튼은 구글이 정한다

이 버튼만 우리 디자인 시스템 밖에 있다. 권고가 아니라 필수 요건이고, 구글 문서가 app verification에 required라고 적었다. 배포할 때 OAuth 앱 심사가 이걸 본다. 출처는 [Google Identity — Branding guidelines](https://developers.google.com/identity/branding-guidelines)다.

못 바꾸는 것들이다.

- **배경은 셋 중 하나다.** 밝게, 중간, 어둡게. 그 밖은 못 쓴다. **우리 브랜드 갈색은 규정 밖이다.** 우리는 어두운 배경을 쓴다.
- **G 로고의 색과 크기를 못 바꾼다.** 단색 버전도 못 쓰고 구식 로고도 못 쓴다.
- **로고만 두지 않는다.** 버튼 경계와 글자가 같이 있어야 한다.
- **"Google" 한 단어로 로그인 동작을 나타내지 않는다.**

바꿔도 되는 것들이다.

- **문구는 우리말로 쓴다.** 구글이 앱 언어로 번역하는 것을 허용하고 권장한다. 우리는 "Google 계정으로 로그인"을 쓴다.
- **모양은 직사각형과 알약 둘 다 허용한다.** 우리는 알약을 고른다. [components.md](../components.md#button)가 버튼을 `rounded-full`로 정했고 구글이 그것을 막지 않으니, 규정 안에서 우리 결을 지킬 수 있는 자리다.
- **크기는 조정한다.** 다만 종횡비는 유지한다.

**로고 에셋은 구글이 배포하는 `signin-assets.zip`을 받아 쓴다.** 직접 그린 SVG는 색이 조금씩 어긋나고, 어긋난 것을 눈으로는 못 잡는다. 구글이 사전 승인해 배포하는 파일을 그대로 쓰면 그 위험이 없다.

버튼의 배경과 테두리와 글자 색 셋은 우리 팔레트 밖이라 [tokens.md의 「바깥이 정한 값」](../tokens.md#9-바깥이-정한-값)에 있다. `--vendor-google-bg`와 `--vendor-google-stroke`와 `--vendor-google-fg`고 유틸은 `bg-google-bg`와 `border-google-stroke`와 `text-google-fg`다.

토큰을 거치게 만든 것은 lint에 구멍을 안 내려는 것이다. 화면 코드에 hex를 그냥 적으면 `house/no-color-literals`가 잡는데, 이 자리만 예외를 뚫으면 다른 색도 같은 구멍으로 샌다.

대비도 우리가 볼 자리가 아니다. 구글이 짝지은 조합이고 우리가 고칠 수 없어서 `tokens.md`의 대비 표에 줄을 더하지 않는다.

구글 문서는 글자를 Google Sans Medium으로 그리라고 적었는데 그 서체는 서드파티 웹에 배포되지 않아서 우리가 못 쓴다. 우리 서체로 그린다. 이 어긋남을 심사가 어떻게 보는지는 [아직 안 정한 것](#아직-안-정한-것)에 있다.

## 안 담은 것

**승인까지 걸리는 시간.** "하루 안에 처리돼요" 같은 문장을 쓰지 않는다. 관리자가 언제 확인하는지 정해둔 규칙이 `docs/domain/`에 없어서 앱이 모르는 것을 약속하게 된다. 그 시각이 지났는데 승인이 안 나면 그 뒤로는 앱이 하는 말을 안 믿는다. [writing.md](../writing.md#확인이-필요한-두-문장)가 근무표 확정 날짜를 두고 이미 같은 판정을 내렸다.

이 판단은 이 화면 하나가 아니라 앞으로 나올 화면 전부에 걸린다. **앱이 모르는 시각을 약속하지 않는다.**

**관리자에게 연락할 길.** 둘이 막는다. 첫째로 [domain/account.md](../../domain/account.md#관리자)가 관리자를 여럿으로 두고 누가 가입 승인을 맡는지 안 나눴다. 둘째로 승인 전에는 자기 프로필 바깥을 한 행도 못 받아서 앱이 관리자 목록을 이 화면에 띄울 수 없다. 연락처를 코드에 박는 길도 없다 — 저장소가 PUBLIC이다.

**카드.** 두 화면 다 안 쓴다.

**로딩 표시.** 구글 버튼 자리에 없다.

**이름.** 승인 대기 화면에 안 나온다.

**"다른 계정으로 로그인" 버튼.** 로그아웃과 같은 일이다.

**알림을 끄는 UI.** 이 화면에는 켜는 것만 있다. [domain/notification.md](../../domain/notification.md#끄는-길)가 끄는 자리를 설정으로 정했고 그 화면이 아직 없다. 여기서 안 켠 사람이 나중에 켜는 자리도 같은 설정이다.

**거절됐을 때.** 관리자가 거절하면 이 화면이 어떻게 되는지는 안 담았다. 거절에 알림을 보낼지가 [domain/notification.md](../../domain/notification.md#아직-안-정한-것)에서 아직 열려 있다.

이름 입력 폼과 관리자 승인 화면은 이 문서 밖이다. 다음 task다.

## 규칙과 부딪힌 자리

디자인 시스템의 조항과 부딪힌 자리 넷이다. 앞의 둘은 규칙을 어기거나 고쳐서 이미 처리했고, 뒤의 둘은 알림 영역이 들어오면서 새로 생겼다.

몰라서 어긴 것과 알고 정한 것은 다르다. 뒤에 오는 사람이 이 자리를 버그로 고치지 않게 남긴다.

**뛰는 점.** [motion.md](../foundation/motion.md#자주-일어나는-것은-움직이지-않는다)가 "모션을 얹을 자리는 상태가 실제로 바뀌는 순간"이라고 정했는데 이 점은 아무것도 안 바뀌는 동안 계속 움직인다.

그걸 알고 넣었다. 승인 대기 화면은 사람이 할 일이 없는 화면이라 정지 화면과 구분이 안 되고, 멈춘 화면은 앱이 죽은 것처럼 읽힌다. 기다리는 중이라는 것을 글자를 더 늘리지 않고 알리는 값이 규칙을 지키는 값보다 크다고 봤다.

대신 셋으로 값을 묶었다. 움직이는 것은 점 하나뿐이고, 이 화면 밖으로 안 나가고, 움직임 줄이기를 켜면 멈춘다.

**브랜드 마크의 브랜드 색.** 이 자리는 규칙을 고쳐서 풀었다. [color.md](../foundation/color.md#브랜드-색을-아끼는-이유)가 브랜드 색이 나가는 자리를 셋으로 못 박고 있었는데 로고가 그 셋에 없었다. 브랜드 마크를 넷째로 더했다.

근거는 경쟁 축이다. 앞의 셋은 전부 누르거나 고르는 것이라 서로 신호를 뺏지만 로고는 누르는 것이 아니다. 로고에 브랜드 색이 있다고 버튼을 못 찾게 되지는 않는다.

**로고와 브랜드 색 버튼이 같은 화면에 서면 그때 다시 본다.** 로그인 화면은 구글이 버튼 자리를 가져가서 브랜드 색 버튼이 아예 없다. 헤더에 로고를 두는 화면이 생기면 그 화면에서 판단이 다시 필요하고, 그 조건은 `color.md`에도 같이 적었다.

**승인 대기 화면에 브랜드 색이 둘.** [color.md](../foundation/color.md#브랜드-색을-아끼는-이유)가 브랜드 색이 나가는 자리를 넷으로 한정한다. 「알림 켜기」는 그중 주요 액션 버튼이라 규정 안이다. 그런데 이 화면에는 승인 대기 알약이 이미 브랜드 색을 쓰고 있어서, 버튼이 들어오면서 한 화면에 브랜드 색이 둘이 됐다.

무게는 갈린다. 알약은 `bg.brand-weak`의 옅은 면이고 버튼은 `bg.brand-solid`의 꽉 찬 면이라 나란히 놓아도 어디를 누르는지 헷갈리지 않는다. 알약은 애초에 누르는 것이 아니다. 누를 수 있는 브랜드 색은 여전히 하나뿐이라 [components.md](../components.md#button)의 "한 화면에 primary는 하나다"도 지켜진다.

그래도 실제 화면에서 다시 본다. 바로 위에 적은 "로고와 브랜드 색 버튼이 같은 화면에 서면 다시 본다"와 같은 종류의 자리고, 알약과 버튼이 세로로 가까이 서는 이 화면이 그 조건에 가장 가깝다.

**알림 블록에 중립 종류가 없다.** [components.md](../components.md#알림-블록)의 알림 블록은 안내·성공·경고·오류 넷인데 「아직 안 켬」이 그 넷 중 어디도 아니다. 아무 일도 안 일어난 자리라 뜻이 실린 색을 쓰면 안 된다. 이 화면에서는 `bg.neutral-weak`로 깔고 컴포넌트 표에 다섯째 줄을 더하지는 않았다. 이 상자는 알림 블록과 달리 버튼을 품고 세 모습으로 갈리는 것이라, 화면 하나를 근거로 공용 컴포넌트를 늘리기에는 이르다. 다른 화면에서 같은 모양이 한 번 더 필요해지면 그때 올린다.

## 아직 안 정한 것

임의로 채우지 않는다. 사람이 정하고 나서 이 절에서 뺀다.

**라이트와 다크에서 버튼 테마를 나눌지.** 지금은 양쪽 다 어두운 배경 하나다. 구글이 테마마다 다른 버튼을 쓰는 것을 막지 않으니 다크에서 밝은 버튼으로 바꿀 수도 있다. 라이트와 중립 테마의 값은 아직 `tokens.md`에 안 옮겼다. 실제 화면을 보고 정한다.

**구글 버튼의 서체.** 구글은 Google Sans Medium을 적었는데 그 서체가 서드파티 웹에 배포되지 않는다. 우리 서체로 그리는 것이 심사에 걸리는지 확인이 필요하다. 걸린다면 구글이 배포하는 버튼 이미지를 통째로 쓰는 길이 있는데 그러면 문구를 우리말로 못 쓴다.

**권한을 거부한 뒤의 모습.** 「알림 켜기」를 눌렀는데 사람이 브라우저의 물음에서 거부하면 어떤 모습이 되는지 안 정했다. 아이폰·홈 화면 전과는 다른 자리다 — 그쪽은 권한을 물을 길이 아예 없는 것이고 이쪽은 물었는데 거부당한 것이라, 홈 화면 추가를 안내하면 엉뚱한 말이 된다. 브라우저는 한 번 거부하면 다시 묻지 않으니 첫째 모습을 그대로 두면 눌러도 아무 일이 안 일어나는 버튼이 남는다.

**도는 문구 넷의 문장.** 넷을 돌린다는 것만 정해졌다.

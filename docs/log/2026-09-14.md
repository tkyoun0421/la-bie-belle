# 2026-09-14 — `architecture/` 넷이 다 선다

PR 넷(#315, #316, #317, #318)으로 `docs/2-design/architecture/`의 `data-model`·`api`·`runtime`·`flows`가 순서대로 채워진다. 앞선 문서가 뒤 문서의 전제가 되는 사슬이라 넷이 이어서 한 회차 안에 들어왔다.

## data-model — 사실은 DB에, 상태는 계산한다 (#315)

인터뷰 스물세 라운드와 `architecture-advisor` 검토 한 번을 거쳐 `data-model/README.md`가 섰다. 원칙 넷이 문서 머리에 선다 — 출근 상태·급여·자격·빈 자리는 저장하지 않고 계산한다, 쓰기는 전부 security definer Postgres 함수를 `dals`가 `rpc()`로 부른다, 이력은 닫고 새로 만든다(배정·자리·시급의 `ended_at`), 막는 것은 데이터라 시급·개인정보·QR을 표로 갈라 RLS가 행 단위로 막는다.

되돌리기 어려운 결정 둘이 여기서 났다. `profiles.id`를 `auth.users.id`에서 떼어 `user_id → auth.users on delete set null`로 잇는다 — 계정을 다시 잇고 프로필은 남기는 동작이 지금 구조로는 안 돼서다. 개인정보는 `profile_private` 표로 가른다. 조언자 검토가 뒤집은 것도 있다 — 겸임은 `merge_group` 열이 아니라 새 자리 행이고, 요청은 표 둘이 아니라 `requests(kind)` 한 표이며, 자격은 `granted`만 저장한다.

기존 `profiles` 마이그레이션과 integration 테스트는 이 결정과 어긋나지만 건드리지 않았다. 데이터 task가 갈아엎을 몫이다. pg_cron·Webhook이 Supabase Free 플랜에서 되는지는 확인하지 못해 열린 결정에 남겼다.

## api — 경계는 하나, 브라우저가 Supabase를 바로 부른다 (#316)

인터뷰 열 라운드와 조언자 검토 한 번으로 `api/`가 섰다. Next 서버는 로그인 게이트와 첫 페이지만 맡고 나머지는 브라우저가 Supabase를 직접 부른다 — 권한이 이미 RLS에 있어 서버가 중간에 설 이유가 없고, 콜드 스타트를 출근 인증이 기다릴 이유도 없다. 읽기는 PostgREST 임베딩(뷰는 `excuse_status`·`open_slots` 둘)이고 타입은 `gen types`로 뽑아 저장소에 두고 CI가 diff 0을 확인한다. 쓰기는 함수 마흔쯤을 호출자 있는 `public`과 pg_cron 전용 `internal`로 가른다. 오류는 예외 + 고정 코드 열둘을 `dals`가 `DomainError`/`TransportError`로 가른다. 서버 시각은 `server_now()` 한 번과 offset으로, 푸시는 Webhook + pg_cron 재시도인데 잡기(`claimed_at`)와 성공(`pushed_at`)을 다른 열로 나눴다 — 같은 열이면 실패한 발송이 재시도 대상에서 빠진다.

이 PR의 둘째 커밋이 `architecture/README.md`의 300줄 규칙을 버렸다. 폴더를 채우는 순간 도메인 파일 여섯(`account`·`schedule`·`swap`·`attendance`·`payroll`·`notification`)이 같이 서는 구조라 파일 길이 기준이 무의미해졌다 — `data-model/`·`api/` 둘 다 README(가로지르는 규칙) + 도메인 여섯으로 갔다. 축은 관심사 폴더·도메인 파일 그대로 유지했다.

ADR-003의 「`dals`에서만」 조항을 `from`·`rpc`·`storage`·`channel`로 좁히고 `auth.*`는 `shared/lib`으로 못박아, 09-13 handoff가 열어뒀던 결정 하나가 여기서 닫혔다. CLAUDE.md 「공개 저장소」 규칙을 따라 시안 넷의 더미 전화번호 아홉을 `010-0000-000x` 꼴로 바꿨다.

## runtime — 캐시는 넷, 판정은 서버 시각 아니면 누른 시각 (#317)

인터뷰 일곱 라운드와 조언자 검토 한 번으로 `runtime/`이 섰다. Service Worker는 껍데기만(Serwist), 데이터는 TanStack Query 하나로 IndexedDB에 영속시킨다(`buster` = 빌드 id, `networkMode: 'always'`, `staleTime` 30초·`gcTime` 7일). Next 서버의 `proxy`는 세션 쿠키만 보고 승인·차단·퇴사 판정은 클라이언트가 `['profile']`로 가른다 — 서버가 판정을 HTML에 그려버리면 껍데기 자체를 캐시할 수 없어서다. realtime은 안 쓴다.

되돌리기 어려운 결정 둘. 승인 게이트가 서버에서 클라이언트로 옮겨간다 — 지금 코드의 `readAuthGate`가 데이터 task에서 이동 대상이다. 출근 판정은 서버 시각이 아니라 누른 시각(`reported_at`)이고 `now()`보다 10분 넘게 이르면 `now()`로 깎는다 — 「인자로 시각을 받지 않는다」 원칙의 유일한 예외가 여기 섰고 `already_done` 코드가 함께 생겼다.

무효화 키를 `runtime/README.md` 한 곳에 표로 모으고 도메인 파일은 가리키기만 하게 했다 — `['schedule']`을 무효화하면 `['payroll']`도 같이 무효화한다는 규칙이 흩어지면 놓치기 쉬워서다. 이 결정을 따라 `api/README.md`·`api/account.md`·`api/attendance.md`·`data-model/attendance.md`·`data-model/account.md`·`domain/attendance.md` 여섯이 손질됐다.

## flows — 경로 열여덟, 동적 세그먼트 없음 (#318)

`architecture/` 마지막 자리다. 화면 문서 열둘의 「들어오는 문」을 조사 넷으로 모으고 조언자 검토 한 번을 거쳐 `flows/`가 섰다. 날짜는 전부 `?date=` 쿼리로 표현한다 — 근무자에게는 달력 위 시트, 관리자에게는 날 상세 화면. 동적 세그먼트가 없으니 라우트가 전부 정적 껍데기가 되고 prefetch와 Service Worker 캐시가 그 위에서 작동한다. 층은 근무자 탭 넷, 관리자 홈 → 달력(`/admin/schedule`) → 날 상세, 게이트 넷(`/login`·`/pending`·`/blocked`·`/left`)으로 갈렸다.

앱바 뒤로가 `history.back()`이 아니라 부모 경로로 명시 이동하도록 정했다 — 알림을 눌러 바로 착지해도 뒤로 갈 곳이 있어야 해서다. 시트는 history에 들어가 안드로이드 뒤로와 iOS 스와이프로 닫힌다(iOS 홈 화면 앱에서 `popstate`가 안 오면 그때 뺀다는 조건이 열린 결정에 남았다). 알림 CTA는 알림이 말한 자리까지만 간다는 원칙 아래 종류별 목적지 표가 `flows/notification.md`에 섰다.

조언자가 정본과 어긋난 자리 여러 곳을 잡았다 — 관리자 달력이 홈과 별개 화면이어야 하는데 안 그려져 있던 것, 날 상세의 뒤로가 달력으로 가야 하는 것, 퇴사한 뒤 화면(`/left`)과 그 급여 뒤로 처리, 대시보드 「이번 주 근무」가 그날 시트까지 이어져야 하는 것, 교대 수락(요청자)·교대 승인 알림 줄, 주말 묶음 미리 알림이 그 사람 첫 근무 날 기준이어야 하는 것, 남이 나를 내렸을 때 즉시가 아니라 다음 진입 시 알려야 하는 것. 전부 조언자 검토 단계에서 반영됐다.

## 남은 것

`architecture/` 넷이 다 찼지만 미정이 여럿 새로 열렸다 — 교대 승인 화면 자체가 없어 관련 알림 목적지 한 줄이 빈 채고, `?month=`의 뜻이 달 키 결정에 딸려 있고, 화면이 없는 함수 넷(`post_announcement`·`set_hall_location`·`undo_leave`·`import_holidays`)과 알림 설정·지난 알림 목록도 1차에 그릴지 미정이다. 관리자 홈 앱바의 뒤로는 `profile.md` 쪽을 택했으니 `schedule-admin.md`가 따라와야 한다. 전부 handoff의 「열린 결정」에 옮겼다.

# 2026-09-22 — 번들링이 죽어 있던 것과 세션·진입 판정을 세운다

PR 셋(#382·#383·#384)으로 `expo-scaffold`의 남은 조각 — 서체·번들 검사·세션·딥링크·진입 판정 — 을 채웠다. 그 과정에서 검사 넷이 다 초록인데 앱이 안 뜨는 구멍을 찾았고, 서체 유틸 하나가 문서와 실물에서 어긋나 있던 것과 로그인 목적지가 화면 코드에 박혀 있던 것을 잡았다.

## 번들링이 죽어 있었는데 검사 넷이 다 초록이었다

`react-native-svg@15.13.0`의 `src/utils/fetchData.ts`가 Node 내장 `buffer`를 import해서 Metro가 `expo export`를 못 돌렸다. `pnpm lint`·`typecheck`·`test`·`format:check` 어느 것도 Metro를 안 돌려서 [#380](https://github.com/tkyoun0421/la-bie-belle/pull/380)이 골격을 세운 뒤로 아무도 몰랐다. 상위가 [PR #2808](https://github.com/software-mansion/react-native-svg/pull/2808)에서 `Buffer`를 `atob()`로 바꿔 15.15.3에 실었고, Expo SDK 57이 고정한 값은 15.15.4다 — 구버전을 쓰던 것이 원인이지 폴리필이 필요한 문제가 아니었다.

`pnpm bundle`을 그 자리에 세웠다. `expo export`를 iOS·안드로이드로 한 번씩 돌리고, env 없이도 돌며(`EXPO_PUBLIC_*`가 비어도 번들은 만들어진다), CI는 문서만 바뀐 PR에서 건너뛴다. 네이티브 컴파일은 여전히 EAS 몫이고 이건 그 앞 JavaScript 번들 단계만 본다.

## 서체 유틸 400은 `font-normal`이 아니라 `font-sans`다

Wanted Sans 넷을 번들에 올리며 컴파일 실측을 다시 돌렸다. Tailwind 4에서 `--font-*`는 패밀리 네임스페이스라 `font-medium`·`font-semibold`·`font-bold`는 `fontFamily`를 내지만 `font-normal`은 `fontWeight: 400`만 걸고 패밀리를 안 바꾼다 — 그것만 쓰면 실제로는 시스템 서체가 나온다. 400 굵기를 쓰려면 `font-sans`를 써야 한다. `tokens.md`와 `typography.md` 여섯 자리를 이 실측으로 고쳤다.

서체 로딩은 맵 둘(`FONT_ASSETS`·`FONT_SOURCES`)을 나란히 뒀다. 하나는 `globals.css`의 `--font-*` 값과 글자까지 대조하는 짝 테스트용, 하나는 `useFonts`에 그대로 넘기는 것 — Metro가 자산 경로를 정적으로 읽어 서로 돌려 쓸 수 없다. 경로를 자산 모듈이 아니라 문자열로 둔 것도 이유가 있다. Jest의 에셋 트랜스포머가 어떤 `.ttf`든 `1`로 바꿔서, 불러온 값으로는 굵기 오배선(Bold 자리에 Regular)을 못 잡는다.

원본 서체 넷이 9.4MB고 서브셋을 안 거쳤다. `tokens.md`가 서브셋을 거친다고 적어둔 자리는 아직 비어 있다 — `font-subset` task로 남겼다.

## 코드 교환이 목적지를 정하고 있었다

`handle-auth-callback.ts`가 성공 시 `"/"`를 하드코딩해서 새로 들어온 사람도 `/pending` 대신 홈으로 갔다. 목적지 문자열 대신 `{ ok }` / `{ ok: false, reason }`만 알리게 좁혔고, 어디로 갈지는 `resolve-entry-destination.ts`와 `decide-entry.ts`가 딴다. `read-supabase-env.ts`가 아직 `NEXT_PUBLIC_*`를 읽던 것도 같이 잡았다 — Expo는 `EXPO_PUBLIC_*`만 번들에 인라인한다.

세션은 SecureStore 열쇠(AES-256) + AsyncStorage 암호문으로 갈랐다. 세션 JSON이 토큰 둘과 사용자 객체를 들어 2048바이트를 넘는데, iOS 키체인은 받지만 안드로이드 키체인은 그 근처에서 실패한다 — 크기로 갈리는 분기가 아니라 역할로 고정 분리라 짧은 값도 같은 길을 간다. `runtime.md`에 「세션」 절을 새로 세웠다.

딥링크는 PKCE라 코드를 싣고 돌아온다. GoTrue의 redirect glob는 `.`과 `/`를 구분자로 보고 `*`는 그 문자를 못 넘어서, Expo Go가 돌려주는 `exp://192.168.0.10:8081/--/auth/callback`처럼 호스트에 점이 있는 주소는 `**`로 등록해야 걸린다 — `supabase/config.toml`의 `additional_redirect_urls`를 그렇게 고쳤다.

### 판정 실패의 폴백이 화면 파일에 앉아 있었다

자동 리뷰가 `_layout.tsx`의 `.catch(() => "/retry" as const)`를 잡았다. 「판정이 실패하면 `/retry`」는 업무 규칙이고 정본은 `navigation.md`의 「앱을 열면」 표인데, 그 규칙이 `.tsx`에 있으면 ADR-001의 「계산·상태는 `.ts`로」를 어기고 `tdd-guard-unit.py`가 `src/app/`을 안 봐서 테스트로 강제되지도 않는다. 폴백을 `decide-entry.ts`로 옮기고 성공 경로 다섯·실패 경로 셋을 테스트로 묶었다. 게이트가 서는 경로가 넷에서 다섯(`/retry` 추가)이 됐다.

### `react-native`는 Jest에서 대역이 안 먹는다

`moduleNameMapper`가 `react-native`를 절대경로로 리매핑해서, 테스트가 직접 import할 때는 대역이 서지만 `src/`의 다른 파일이 안에서 부르면 실물이 온다. `resolve-entry-destination.ts`와 `wire-auto-refresh.ts`는 `AppState`·`Linking`을 대역하지 않고 함수 인자로 주입받게 짰다. `execution.md`의 「돌릴 때」 절에 이 함정을 적었다.

## #382와 #384가 같은 파일에서 부딪혔다

`_layout.tsx`에 서체 로딩(#382)과 진입 판정(#384)이 각자 `SplashScreen.hideAsync()`를 불렀다. 서체만 기다리면 판정 전에 스플래시가 내려가 잘못된 층이 한 프레임 비치고, 판정만 기다리면 글자가 시스템 서체로 한 번 그려진 뒤 Wanted Sans로 뛴다. 판정 결과를 `destination` 상태에 담아 두고 둘 다 끝났을 때 `router.replace(destination)` → `hideAsync()`를 한 번만 부르는 모양으로 손으로 합쳤다. `shouldDismissSplash`는 서체 상태만 보는 원래 계약을 유지했다 — 판정 완료까지 그 함수에 넣으면 기존 단언을 갈아야 해서, 두 조건을 `.tsx`에서 함께 본 뒤에 그 함수를 부르는 쪽을 택했다.

## plan의 `sources` 영향 검사가 실질적으로 죽어 있다

`decide-entry.ts`가 바꾼 정본 셋(`runtime.md`·`account/design.md`·`navigation.md`)이 `expo-scaffold` plan의 `sources`에 걸려 있어 같은 PR에서 plan을 갱신하다 드러났다. `findImpacted`(`tests/lint/sources-impact.ts:40`)가 `status: approved`인 문서만 영향으로 보는데, plan 서른넷 전부 frontmatter에 `status`가 없다 — plan의 `sources` 영향 검사가 있으나마나였다. `plan-sources-gate` task로 backlog에 잡았다.

## 남은 것

실기기·시뮬레이터에서만 닫히는 자리가 여전히 남는다 — 앱 재시작 뒤 로그인 유지, 구글 로그인 왕복(로컬 Supabase에 구글 프로바이더가 없어 `/auth/v1/authorize`가 400으로 끝난다), 판정이 끝날 때까지 스플래시가 서 있는지, 서체가 바뀌면서 글자가 안 뛰는지. `pnpm dev`가 대화형이라 세션에서 못 돌렸다.

# 2026-09-15 — 문서 재편 두 plan을 끝낸다

PR 스물넷(#332, #334~#356)으로 문서 지도 재편이 끝난다. 두 갈래다. `docs-sdlc-coherence`는 다섯 곳으로 흩어져 있던 업무 영역별 설계를 `docs/2-design/modules/<영역>/`와 `system/` 넷으로 모으고, `docs-authoring-playbook`은 그 문서들이 따를 작성법과 틀을 단계 README에 박고 활성 문서를 그 틀로 다시 썼다. 두 plan 다 이번 회차에 `done`으로 내려간다.

## Edge Function 스파이크 (#332)

알림 task의 선행 스파이크다. Deno edge-runtime 컨테이너는 `supabase/functions` 폴더 하나만 마운트해서, `src/` 밖을 가리키는 `deno.json` 맵핑도 심볼릭 링크도 안 통하고 `functions/_shared/`로 실제 복사해야 통한다. 원격 배포는 시험하지 않았고 결론은 로컬 `functions serve`와 CI 기준이다. 복사 단계를 `ci.yml`에 붙이는 일은 알림 task가 맡는다.

## sdlc-coherence — 영역을 모은다 (#334~#337, #339)

제안을 `accepted`로 올리고 ADR-009로 봉인한 뒤(#335), 계정 한 영역을 시범 삼아 `domain/account.md`·`architecture/{data-model,api,runtime,flows}/account.md`·`design-system/pages/{login,profile,members-pending,members}.*` 여덟 파일을 `modules/account/` 하나로 모았다(#336). 관심사가 폴더고 도메인이 파일인 옛 배치에서는 한 영역의 계약이 다섯 곳으로 갈라져 있었고, 같은 행위를 두 문서가 다르게 적어도 아무도 못 잡았다는 것이 이동의 근거다. 이 꼴을 나머지 다섯 영역에 그대로 적용했고(#337), `architecture/`의 공통 절은 `system/` 넷 — architecture·data-access·runtime·navigation — 으로 갈랐다(#339). 옛 폴더 셋(`domain/`·`architecture/`·`design-system/pages/`)은 지우고 `legacy-doc-paths.ts`가 그 경로를 막는다.

이동은 문장 단위이지 재작성이 아니다. 각 PR이 `scripts/check-moved-lines.mts`로 옛 파일의 어느 줄이 새 파일에 안 남았는지 세고, 남은 줄마다 이유를 표로 짝지었다. 허용한 예외는 폴더 배치 자체를 설명하던 지도 문장(「짝은 …다」류)과 링크 글자를 새 파일명으로 맞춘 줄, 그리고 채택 때 정한 둘뿐이다.

## 채택하며 정한 결정 둘

제안서가 찾아낸 불일치 둘을 이 회차가 닫았다.

- **연락처 수정** — `account/design.md`가 정본이다. 「이름·연락처 변경」을 한 함수로 묶어 적던 문장을, 이름 변경(`set_display_name`)과 연락처 변경(`profile_private` 본인 행 직접 갱신)으로 갈랐다. 연락처는 함수가 아니다.
- **통신 지연** — `attendance/README.md`의 ATT-017이 정본이다. 「누른 시각과 닿은 시각이 5분 넘게 다르면」이라, `check_ins`에 서버 `now()`인 `received_at`을 더했다. `reported_at`(누른 시각)과 `received_at`(닿은 시각)의 차이로 판정하고 `checked_at`은 판정용으로 그대로 둔다. 10분 초과 지연의 처리는 정하지 않았다.

## authoring-playbook — 작성법을 단계 README에 박는다 (#338, #340~#342)

sdlc-coherence의 묶음 D~F(계정 시범 이후 영역·화면 다시 쓰기, 검증·배포·운영, 검사)는 이 plan이 이어받았다 — 옮긴 문서를 틀에 맞춰 다시 쓰는 일과 한 번에 하기 위해서다(#338, ADR-010). 제안서에만 있던 문서별 틀과 절별 작성법을 소유 문서로 옮겼다. `docs/README.md`가 「문서 지도 / 기준의 소유권 / 참조와 작성 규칙 / 변경 전파」 넷으로 서고, `1-plan`·`2-design`·`3-build` README가 「역할 / 문서 지도 / 입력과 산출물 / 다음 단계로 넘기는 조건」 넷으로 섰다(#340). 검증·배포·운영도 같은 틀로 서고, `4-test/strategy.md`가 `test-planner` 정의문에 흩어져 있던 테스트 층 기준을 받아 그 정의문이 이제 여기를 가리킨다(#341). backlog는 표 하나(작업 ID·작업·상태·선행 작업 ID·spec 또는 plan·검증·완료 근거), handoff는 「다음 작업 / 재개 맥락」 두 절로 다시 섰고 `session-recorder` 정의문이 그 형식을 읽는다(#342).

## 활성 문서를 틀로 다시 쓴다 (#343~#354)

묶음 D(계정, #343)를 시범으로 삼아 나머지 영역 다섯(swap #344, payroll #345, attendance #346, schedule #348, notification #347)과 `system/` 넷(#349), 화면 문서 열넷(payroll·wages #350, qr·approvals·stats #351, schedule-worker·schedule-admin #352, 대시보드 분할 #353), 기획 문서 다섯(#354)을 같은 틀로 옮겼다. 결정 내용은 바꾸지 않는다는 원칙이라 규칙 ID·순서·문장은 그대로 두고 절 구조만 재배치했다. 각 PR이 표 행마다 근거(규칙 ID나 원문 절)를 달아, 원문이 답을 안 주는 축은 행으로 만들지 않고 「아직 안 정한 것」의 Q-nn으로 넘겼다.

대시보드는 이 과정에서 셋으로 갈라졌다(#353) — `system/screens/dashboard.md`에서 출근 인증을 `modules/attendance/screens/check-in.md`로, 사유 시트를 `excuse.md`로 뺐다. 화면·문안·토큰·모션 값은 새로 정하지 않고 문단을 재배정만 했다.

## 값이 드러난 자리 — sian-auditor가 잡은 것 둘

계정 시범(#343)의 1차 커밋은 `members.md` 시안 감사에서 「확인 제목·확인 아래 줄」 토큰 두 행을 원문 없이 만들어 표에 넣었다. `sian-auditor`가 그 자리를 잡아 지웠다 — 표로 옮기는 작업이 원문에 없는 값을 슬쩍 채워 넣기 쉬운 자리라는 뜻이다. 대시보드 분할(#353)에서도 같은 일이 두 번 일어났다. check-in 쪽은 「타일이 오기 전」이라는 다섯째 상태 행을 새로 만들어 넣었는데, 원문은 넷만 그리고 「타일이 오기 전」은 상태가 아니라 산문이 설명하는 자리였다. dashboard 쪽은 「수락한 알림의 CTA — 수락 취소」를 「교대를 수락한 줄만 그 자리가 수락 취소로 바뀐다」는 원문의 좁은 조건을 지우고 일반화해 적었다. 둘 다 감사가 되돌렸다. 매 PR의 `check-moved-lines.mts`가 문장 보존의 정량 검사였다면, `sian-auditor`는 그 검사를 통과하고도 슬쩍 끼어드는 새 값을 잡는 두 번째 층이었다.

## 묶음 D~G에서 쌓인 판정 (#355)

각 PR이 작성법으로 못 답한 항목을 「작성법에서 답하기 어려웠던 항목」에 적어 쌓아 뒀고, 총괄이 판정해 스물둘을 `docs/2-design/README.md`의 작성법에 박았다(#355) — 업무 규칙 일곱, 기술 설계 셋, 공통 설계 셋, 화면 문서 아홉. 그 판정과 어긋나는 기존 문서 구조도 같이 맞췄다. `profile.md`의 절 깊이를 `login.md`·`check-in.md` 꼴(`#### <화면> 색`)로 내렸고, `payroll/README.md`의 용어 「가산 — 기본 시급에 곱하는 비율」은 「가산 — 시급에 곱하는 비율」로 고쳤다 — PAY-005 예시가 실제로는 사람별 시급에 곱하는데 「기본 시급」이 용어 표의 다른 항목(따로 정하지 않은 사람 전원이 쓰는 값)과 같은 낱말을 써서 헷갈렸던 자리다. `schedule-admin.md`·`schedule/README.md`의 「(확정 2026-09-07)」류 결정 날짜 표기 열한 곳도 지웠다.

## 검사와 마감 (#356)

`tests/lint/`에 넷을 더했다 — `sources-exist`(spec·plan의 `sources` 경로·앵커 실존), `backlog-ids`(작업 ID 중복 없음·상태 다섯·선행 ID 실존), `slug-chain`(intent→spec→plan 슬러그 일치), `sources-impact`(승인된 spec의 `sources`가 바뀐 PR은 본문에 「영향 확인」 절이 있어야 한다). 마지막 것은 `.github/workflows/ci.yml`에도 붙어 문서만 바뀐 PR에서도 돈다. 통신 지연 규칙(ATT-017)에서 출발해 `attendance/design.md` → `check-in.md` → `spec/dashboard.md`의 `sources`까지 링크로 따라가지는 것을 확인했고, 화면에서 테스트 자리까지는 구현이 아직 없어 사슬이 끊긴 채로 남는다 — `attendance`가 `blocked`인 이상 당연한 끊김이다. 두 plan의 완료 기준을 전부 대조해 체크했고 backlog 두 행이 `done`으로 내려갔다.

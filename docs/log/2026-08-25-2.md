# 2026-08-25 (2) — Missions 발표에서 원리 셋을 들인다

Factory의 multi-agent 아키텍처 발표("The Multi-Agent Architecture That Actually Ships", Luke Alvoeiro)를 분석했다. orchestrator가 사람과 계획을 다듬고 fresh-context 검증자가 구현과 분리되는 뼈대가 우리 구조와 같았고, 체계 없이 집어올 수 있는 원리 셋을 가져왔다.

- 완료 조건을 계획 때 박는다 — task마다 코드가 생기기 전에 "이게 되면 완료"를 총괄이 쓴다. 구현 뒤의 테스트는 결정을 확인할 뿐 버그를 못 잡는다.
- 생산 스폰 리턴 형식 — 완료·미완·돌린 명령과 결과·발견한 이슈 넷을 요구한다.
- 행위 검증 — CI에 Playwright e2e를 더하고, 기능 PR은 화면 흐름이 실제로 도는지까지 본다.

며칠짜리 자율 실행 체계(mission) 자체는 안 가져온다. 제품이 없는 지금 그걸 지으면 통치 구조 선행 실패의 세 번째 재판이다.

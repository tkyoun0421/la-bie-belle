# 2026-09-07 (3) — 휴무 희망이 근무 신청으로 뒤집히고 근무 요청 화면이 선다

PR 셋(#265~#267)이 들어간 회차다. 근무자가 받는 것의 방향이 통째로 뒤집혔다 — 쉬고 싶은 날을 받던 「휴무 희망」이 일할 수 있는 날을 받는 「근무 신청」이 됐고, 그 반전이 화면 하나(별도 제출 화면)를 지우고 화면 하나(근무 요청 응답)를 새로 열었다. 문서·시안·기획이 세 PR에 걸쳐 순서대로 따라붙었다 — #265가 도메인과 화면 문서를 먼저 고쳤고, #266이 시안을 한 라운드 따라잡았고, #267이 남은 미정 넷을 인터뷰로 닫으며 시안을 다시 갱신했다.

## 휴무 희망이 근무 신청으로 뒤집힌다 (#265)

기존 구조는 근무자가 쉬고 싶은 날을 신고하면 관리자가 나머지 날에 자유롭게 배정하는 것이었다. 새 구조는 근무자가 일할 수 있는 날을 신청하고, 신청 안 한 날은 원칙적으로 배정 불가다 — 강제 변경으로도 못 채운다. 신청 자체엔 상한이 없고 고른 날을 보내는 것뿐이며, 마감 전이면 몇 번이든 덮어써 재제출할 수 있다. 신청은 가능 표시일 뿐 배정을 보장하지 않는다는 점도 같이 못박혔다 — 신청한 날이라도 관리자가 안 뽑으면 배정되지 않는다.

이 반전은 `domain/schedule.md`의 정의 자체를 갈아엎었고, `domain/notification.md`(아홉에서 열하나로), `pages/schedule-worker.md`, `pages/schedule-admin.md`, `prd.md`·`scenarios.md`·`intent/schedule-admin.md`·`writing.md`·`components.md`와 색인 둘까지 용어를 전파했다. schedule-admin.md는 문안을 전수 교정했고 모아보기 기능의 의미도 반전됐다. 픽커의 미신청 표시는 눌리는 항목에서 비활성으로 바뀌었다.

## 미신청 날에 사람을 넣는 유일한 길 — 근무 요청 (#265)

배정을 강제로 못 채우는 대신 새 경로가 하나 생겼다. 관리자가 자리(날·포지션) 단위로 근무자에게 근무 요청을 보내고, 수락하면 즉시 배정된다. 여러 사람에게 동시에 보낼 수 있고 선착순이라 늦게 수락하면 실패 처리된다. 확정 전과 확정 후 양쪽에서 다 쓸 수 있고, 요청은 48시간이 지나면 만료되는데 근무 날 시작 전이 그 상한이다 — 근무 당일에 임박해 보낸 요청은 48시간을 다 못 채우고 만료된다.

## 별도 제출 화면이 사라진다 (#265)

②로 따로 그리려던 제출 화면 자체가 폐기됐다. 근무자 근무표 달력이 확정 전에는 곧 제출 모드가 된다 — 같은 화면이 확정 여부에 따라 제출용과 조회용을 오간다. 확정되면 같은 자리가 근무표로 바뀐다. 이 정리로 schedule-worker의 미정 넷(확정 전 모습, 과거 달 무제한, 대시보드 연결, 교대 부제)이 한 번에 닫혔고, 대신 새 미정 하나(수락 화면)가 남았다 — 이건 #267에서 닫힌다.

## 시안이 문서를 두 라운드로 따라잡는다 (#266, #267)

#265는 문서를 먼저 고쳤고 시안은 그대로 뒀다 — "문서가 이긴다"는 조항대로 시안이 뒤처진 채 PR을 닫고 다음 첫 수로 넘겼다. #266에서 sian-writer 둘이 두 파일을 맞췄다. 디자인 결정은 하나도 새로 안 냈다 — 문서와 tokens.md에 이미 있는 값을 눈에 보이게 옮겼을 뿐이고, 문서에 「제안」으로 남은 자리는 캡션에도 그대로 「제안」이라고 적었다. `schedule-worker.sian.html`에 11절 「확정 전 — 근무 신청」이 서고 목업 셋(제출 모드, 마감 뒤 읽기 전용, 안 만든 달의 빈 점선 달력)이 들어갔다. `schedule-admin.sian.html`은 「휴무 희망」 계열 문안 27건을 전수 교체했고, 두 파일 다 「휴무」·「희망」 grep이 0건이 됐다.

#267이 남은 미정 넷을 닫으며 시안을 다시 갱신했다(아래). 이 라운드에서 「제안」 일곱 — 고른 날 칸 조합·BottomCTA·0개 제출·토스트·안내 문구 둘·교대 부제 — 이 전부 승인돼 표시가 떨어졌고, 그중 고른 날 칸은 `components.md` 근무자 조회 표에 「확정 전 — 신청에서 고른 날」로 승격됐다 — 화면 하나의 값이 공용 컴포넌트 문서로 올라간 것이다.

## 근무 요청 화면과 알림이 인터뷰로 닫힌다 (#267)

#265가 남긴 미정 넷 — 근무 요청 보내기·상태(admin), 수락 화면(worker), 거절·만료 알림, 수락자 알림 중복 — 이 이번 회차에서 닫혔다. 보내는 문은 새 화면이 아니라 픽커다 — 전체 보기의 미신청 줄에 체크박스가 붙고 「n명에게 근무 요청 보내기」 CTA로 보낸다. 상태도 새 화면 없이 자리 카드 배지("요청 2건 대기 중")와 픽커 줄(대기·거절·만료)로 드러난다. 자리가 차면 직접 배정과 마찬가지로 자동 마감된다.

수락은 근무자 쪽에서 근무표 그 날과 요청 시트로 처리한다 — 푸시를 누르면 그 달·그 날로 가고, 시트에 날·포지션·근무 시간과 "수락하면 바로 배정돼요"라는 문구, 거절·수락 버튼이 뜬다. 끝난 요청에 재진입하면 닫힌 안내만 보인다.

알림은 거절·만료를 건건이 보내지 않는다 — 한 자리의 요청이 전부 소진되면 관리자에게 한 번만 간다. 수락자는 근무표 변경 알림에서 제외됐다 — 자기 행동으로 생긴 변경이라 swap 표의 기존 방침(자기 행동은 알림에서 뺀다)과 일관을 맞춘 것이다.

이 라운드가 새로 남긴 「제안」은 요청 시트 제목 짜임·CTA 배치, 끝난 요청 문구, 배지 문구·모양, 픽커 상태 문구·체크박스 유무, 체크박스 색, 보내기 모션이다. 시안 캡션이 붙인 가정 둘(끝난 시트의 제목 유지, 요청 시트 배경 달력의 시점)도 검수 몫으로 남았다 — 다음 첫 수다.

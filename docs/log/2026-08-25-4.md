# 2026-08-25 (4) — subagent 여섯과 FSD·TDD 강제

협업 구조에 일하는 손을 붙인 회차다. subagent 여섯을 만들고, 코드 배치를 FSD로 옮기고, TDD를 훅으로 강제했다.

## subagent

읽기와 검증부터 만들고 만드는 쪽을 나중에 붙였다.

- `explorer` — 코드 탐색. haiku, 도구 호출 6회 캡. 리턴은 관련 파일·심볼·흐름·기존 패턴·위험 다섯 항목이다.
- `docs-researcher` — 저장소 문서. haiku, 4회 캡. 네트워크 도구를 주지 않아 우리 결정을 묻는 질문에 웹 글을 끌어오는 일이 도구 수준에서 막힌다.
- `web-researcher` — 저장소 밖. sonnet, 8회 캡. 막힌 경로를 다른 길로 다시 시도하게 했다.
- `test-triage` — 검증 명령 압축. haiku, 4회 캡.
- `implementer` — 코드 생산. opus. 테스트를 먼저 쓰고 실패를 확인한 뒤 구현하는 순서를 절차로 박았다.
- `pr-diff` — merge 전 diff 감사. sonnet, 6회 캡. 확인 가능한 사실만 보고 취향 지적은 금지다.

문서 지도는 `CLAUDE.md` 한 곳으로 모았다. 정의문은 지도를 옮겨 적지 않고 가리키기만 한다. 코드 위치는 지도에서 뺐다 — 저장소에서 직접 찾는 편이 늘 최신이다.

## 구조와 강제

인터뷰로 열한 가지를 정하고 ADR-001에 남겼다. 레이어는 `app`(Next 라우팅만) · `screens` · `features` · `entities` · `shared` 다섯이고 widgets는 두지 않는다. `.tsx`는 더미 UI, 로직은 전부 `.ts`다.

훅 둘이 Write와 Edit 앞에서 막는다. 실행 코드를 내보내는 `.ts`에 같은 레벨 짝 테스트가 없으면 차단하고, 라우트와 screens 슬라이스에 e2e spec이 없으면 차단한다. 탈출구는 두지 않았다.

핵심 설계는 훅이 세그먼트 이름을 모르게 한 것이다. 확장자와 파일 내용으로만 판정하므로 세그먼트가 늘어도 훅을 고칠 일이 없다. 세그먼트 목록은 열어두고 첫 기능 task에서 정한다.

## 값을 한 자리

`test-triage`가 src 이전 검증에서 두 실패의 원인과 확인할 파일까지 짚어줬다. 총괄은 로그를 읽지 않고 고쳤다.

`pr-diff`는 PR #169에서 "TDD를 강제하는 훅 자신에게 테스트가 없다"를 잡아냈다. 그래서 판정 16가지를 테스트로 박았고, 그 테스트가 곧바로 훅 경로 계산 버그를 드러냈다. 수동 검증으로는 안 보이던 구멍이라 지적이 없었으면 훅이 잘못 동작하는 채로 들어갔다.

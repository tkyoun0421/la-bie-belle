# 2026-10-16 — 읽기 상한 감사가 끝나고 「오늘」이 서버 시각이 되고 모션 정본 후속 아홉이 코드로 내려간다

PR 열(#590~#593)이 돈 회차다. 어제 candidate로 남은 일곱 행이 닫혔다. 한 달 신청과 출근 기록이 1000행에서 조용히 잘리던 읽기(`unbounded-read-audit`), 기기 시계로 읽던 「오늘」(`kst-today-device-clock`), 정본과 어긋나 있던 모션 넷(`reduce-motion-app-subscription`·`motion-easing-ease-out`·`button-press-scale`·`skeleton-reduce-motion`), 중복이라 적힌 마감 줄 행(`applications-deadline-line-duplicate`)이다. 병렬 worktree와 jest 0건의 판정(`execution-env-pitfalls`)은 #590이 execution.md에 적어 행을 이미 닫았다. 닫으면서 뒤에 남은 일이 일곱 줄 candidate로 나왔다. 단위·lint·번들까지는 초록이고 눌림·등장·시계 세 가지는 실기기로 못 봤다.

## 읽기 상한 감사는 서른넷 가운데 넷만 고쳤다

읽기 서른네 곳을 훑어 넷을 고쳤다(#593). 한 달 신청(`getMonthAvailabilities`)과 한 달 출근 기록(`getMonthAttendance`의 `check_ins`)은 운영 규모(36명 × 31일 = 1116행)에서 1000을 넘어 뒤가 잘렸다. 둘 다 어제 세운 `readAllPages`로 읽고 정렬을 `(work_date, profile_id)`와 `(day_id, profile_id)`로 박았다. `getNotifications`는 잘리지는 않지만 `created_at`이 같은 알림이 쪽 경계에 걸리면 두 쪽에 겹치거나 빠졌다. 정렬 뒤에 `id desc`를 더해 순서를 하나로 정했다. `getMonthSchedule`은 `runtime.md` 「읽기 범위」가 이미 적은 계약대로 임베딩 `slots`·`assignments`에 `ended_at is null`을 걸었다. 클라이언트의 `endedAt === null` 재거름은 해가 없어서 지우지 않았다.

나머지 서른은 한 번에 받는 행이 운영 규모에서 1000에 못 미치거나(프로필 서른, 급여 한 달, 근무표 한 달의 날 31행) 이미 `readAllPages`를 쓴다. 그래서 그대로 뒀다.

근무표 한 달에 `readAllPages`를 쓸지는 탐침이 가렸다. 처음 판정은 「교육 배정 1100행을 한 날에 넣고 임베딩이 잘리는지 본다」였다. 그런데 PostgREST `max_rows`(1000)는 응답 전체의 합에 걸리지 않았다. 맨 위 결과에 한 번, 부모 행 하나의 임베딩 배열에 한 번씩 따로 걸린다. 그래서 1100행 테스트를 빼고 31일 × 40건 테스트를 세웠다. 날마다 40건씩 한 달에 1240건이 다 오면 합이 천을 넘어도 안 잘린다는 증명이다. 결과가 그랬고 `getMonthSchedule`은 R4만 하고 페이지 읽기를 안 썼다. 이 사실은 측정한 것이라 계약을 바꾸는 결정이 아니고, `runtime.md`에 한 문장으로 더했다. 임베딩 필터가 부모 행을 거르지 않는다는 것도 실행으로 확인했다. 닫힌 배정만 가진 날에 `assignments.ended_at=is.null`을 걸면 날은 그대로 오고 `assignments`만 `[]`로 온다. 근무표에서 날이 사라지지 않는다.

푸시 대기열 상한은 이 PR에서 다루지 않았다. `claim_notifications(null)`이 조건에 맞는 전부를 update한 뒤 rpc 응답이 1000에서 잘리면 잘린 행은 시도 수만 오르고 안 나간다. 푸시가 며칠 멈춰야 닿는 자리라 `push-claim-limit`으로 남겼다. `listMembers`도 그대로다. 로컬 데이터 오염은 `test-data-isolation`이 다룬다.

## 「오늘」은 서버 시계에서 뽑고 이름을 지워 되돌아갈 길을 막았다

「오늘」을 기기 시계로 읽고 있었다. 기기 시계가 하루 밀리면 달 고르기와 버튼 켜짐이 틀린 날을 기준으로 움직인다. 서버 시계 오프셋(`useServerNow`)이 이미 정본이라 날짜도 거기서 뽑는다(#591). `useServerToday`는 `useServerNow()`의 ms를 `kstDateOf`로 바꿔 KST 날짜 문자열을 내고 타이머는 없다. `kstToday`는 파일째 지웠다. 이름이 사라지면 기기 시계로 되돌아갈 길도 같이 막힌다. 정본 문서에는 그 이름이 남은 곳이 없고 남은 곳은 기록 문서뿐이다.

controller 여덟이 `useServerToday()`를 부른다. `entities/schedule`의 `useScheduleAgenda`·`useDaySheet`는 입력으로 `today`를 받는다. entities가 같은 층의 `entities/clock`을 당길 수 없어서다(규칙 3). `ScheduleWorkerRoster`·`ScheduleWorkerSheets`는 그 값을 계산 없이 넘기기만 한다(규칙 9). `scripts/e2eSeedServer.mts`는 호스트에서 돌아 호스트 시계를 쓰는 게 맞다.

`applications-deadline-line-duplicate`는 중복이 아니었다. `deadlineLine`과 `applicationsDeadlineLine`은 같은 문장을 낸다고 적혀 있었는데 정본이 문장을 서로 다르게 박아 둔다. 근무자·관리자 화면은 「스케줄 신청 마감 10월 2일(금) · 3일 남았어요」와 「스케줄 신청이 10월 2일에 마감됐어요」이고 신청 현황은 「마감 10월 2일(금) · 3일 남았어요」와 「10월 2일에 마감됐어요」다. 앞머리와 마감 뒤 문장이 다르고 날짜 표기 도우미도 다르다. 그래서 두 함수는 둘로 둔다. 겹친 것은 문장이 아니라 날수 셈이었다. `deadlineLine.utils.ts`·`applicationsGrouping.utils.ts`·`vacancyCards.policy.ts`의 private 함수 세 사본이 같은 셈을 했고, `shared/utils/kstDate.ts`의 `daysUntil(fromDate, toDate)` 하나로 모았다.

날짜 문자열을 `now`로 넘기는 꼴(`deadlineLine({ now: today })`)은 범위 밖이라 안 건드렸다. UTC 자정이 KST 09시라 우연히 맞는 꼴이다. `now-receives-date-string`으로 남겼다. 재발을 막는 lint도 두지 않았다.

## 모션 정본 후속 아홉이 한 PR로 내려갔다

모션 정본 후속 판정 1~9를 코드로 옮겼다(#592). 그동안 버튼은 안 눌렸고 곡선은 reanimated 기본값이었고 같은 125ms가 세 이름으로 흩어져 있었다. 앱을 쓰는 중에 OS 설정을 바꿔도 다음 화면은 옛 값으로 열렸다.

움직임 줄이기는 `primeReduceMotion`을 `trackReduceMotion`으로 바꿔 처음 부를 때 `reduceMotionChanged` 구독을 한 번 걸고 떼지 않는다. 이벤트를 들은 뒤 풀린 읽기는 `lastKnown`을 덮지 않고 읽기가 실패해도 거절하지 않는다. 이징은 `shared/lib/motionEasing.lib.ts`의 `EASE_OUT = Easing.bezier(0, 0, 0.2, 1)` 하나로 모았고 `DURATION_FAST_MS = 125`가 `PRESS_DURATION_MS`·`SLIDE_DURATION_MS`·`LIFT_DURATION_MS`를 대신한다. 정본 쪽도 같이 고쳤다. tokens.md 6절의 이징 문장이 `ease-out`의 Tailwind 값을 그대로 쓰고 「곡선을 직접 적는 자리는 없다」가 빠졌다.

`PressScale`은 바깥 `Animated.View` 래퍼를 없애고 `Animated.createAnimatedComponent(Pressable)` 하나에 `className`과 `style={[style, scaleStyle]}`을 같이 붙였다. 래퍼가 있으면 `className="flex-1"`이 눌림 transform을 받는 요소가 아니라 안쪽 Pressable에 붙어, 시트 푸터에 버튼 둘을 나란히 세워도 폭을 반씩 못 나눈다. `style`은 함수 꼴을 받지 않게 `StyleProp<ViewStyle>`로 좁혔다. Button은 `PressScale` 안에 서고 `disabled || loading`이면 줄지 않는다. Skeleton은 `reduceMotion` prop을 지우고 `useReduceMotion()`을 스스로 읽는다. 호출부가 값을 안 채우던 것이 행의 증상이었는데 prop이 없어지면 호출부가 채울 일도 없다. 카탈로그의 「동작 줄이기 — 덩이만」 Stack도 같이 지웠다.

`Segment`·`Draggable`에는 `ReduceMotion.Never`를 안 넣었다. OS 설정이 켜지면 건너뛴다. `Rise`·`PressScale`은 지금처럼 Never다. 줄이기에서도 지연과 눌림은 남긴다는 로그인 모션 계획의 판정을 그대로 따른 것이다.

테스트 쪽에서 부딪힌 것이 있다. `tests/setup/reanimatedCalls.ts`가 reanimated mock의 가짜 `Easing` 대신 실물을 끼우려고 `react-native-reanimated/lib/module/Easing`에서 불러왔는데, 그 파일은 ESM이라 `pnpm test`가 거는 `--experimental-vm-modules` 아래에서 components 갈래 일곱 스위트가 `Must use import to load ES Module`로 아예 못 떴다. 경로를 `react-native-reanimated/src/Easing`으로 바꿨다. mock의 `Easing`이 가짜라는 사실이 이 setup을 필요하게 했으니 이징을 단언하는 테스트가 새로 생기면 이 setup을 지나야 한다. 대상이 서서 `reduceMotion.lib.test.ts`와 `MotionEasing.test.tsx`의 `@ts-expect-error`와 동적 import도 정적 import로 바꿨다. 단언은 그대로다.

## 검증과 남은 것

세 PR 모두 기준점에서 lint·typecheck·format이 통과했고 #591·#592는 `pnpm bundle`도 안드로이드로 통과했다. #593은 바꾼 integration 파일 넷이 구현 전 5건 실패(R1·R2는 길이 1000, R3은 겹침, R4는 둘)에서 구현 후 25건 통과로 돌았고 `pnpm test:integration:run` 전체가 95 스위트 638건이다. #591·#592는 DB에 안 닿아 integration을 생략했다. `pnpm e2e`는 기기 빌드가 없어 못 돌렸다.

사람 손이 남은 것은 어제 목록(Supabase 원격 Redirect URLs 두 줄, 실기기 확인)에 더해진다. 시트 푸터 `flex-1` 두 버튼의 폭과 모든 버튼의 눌림, 동작 줄이기를 켠 Skeleton에 빛 줄이 없는지, 앱을 켠 채 OS 설정을 바꾼 뒤 로그인 등장이 새 설정을 따르는지, 기기 시계를 하루 돌려도 오늘이 서버 날짜인지(근무표 오늘 강조·통계 다음 달·관리자 홈 오늘 타일)다.

## 값이 드러난 자리

**R5 탐침이 계획을 뒤집었다.** 계획은 「교육 배정 1100행을 한 날에 넣고 임베딩이 잘리는지 본다」였다. 그 테스트를 그대로 세웠으면 부모 하나의 임베딩 배열에서만 걸리는 `max_rows`를 합에 건 것으로 읽고 `getMonthSchedule`에 `readAllPages`를 얹었을 자리다. 탐침이 한 달에 1240건이 다 오는 것을 보여 줘서 쓸데없는 페이지 읽기가 안 들어갔다.

**구현자가 「중복」 행의 근거를 정본에서 되짚었다.** 행의 전제는 두 함수가 같은 문장을 낸다는 것이었다. 정본 문서 세 자리를 읽고 문장 두 벌이 의도임을 찾아 합치기를 멈췄고, 같은 셈을 하던 세 사본만 모았다. 행대로 합쳤으면 신청 현황 화면의 문안이 정본과 달라졌을 것이다.

**mock의 `Easing`이 가짜라서 components 일곱 스위트가 아예 못 떴다.** 실물을 끼우는 setup이 ESM 경로를 읽다 `Must use import to load ES Module`로 막혔고, 경로를 바꾸고서야 이징을 단언하는 테스트가 돌았다.

## 남은 일곱 candidate와 작은 흔적

감사와 구현이 낸 일곱이 candidate로 선다. `push-claim-limit`, `requests-closed-30-days`(`schedule/design.md`가 「살아 있는 요청과 닫힌 지 30일 안」을 적는데 코드는 `closed_at is null`만 읽는다), `monthly-assignment-count-canon`(한 달 배정 수가 341·600쯤·천쯤으로 문서에서 셋이다), `my-reads-filter-by-profile`(`getMyAvailability`·`getMyRehearsals`·`getMyExcuses`가 `profile_id` 없이 RLS에만 기대 관리자 세션이면 전원 행이 온다), `skeleton-shimmer-animation`(components.md는 「shimmer는 Reanimated」인데 지금 shimmer는 흐르지 않는 고정 막대다), `now-receives-date-string`, `runtime-unbounded-keys-table`(`runtime.md`의 「화면이 전체를 읽는 키는 셋」이 코드와 안 맞는다)이다. 판정 대기 행과 같이 handoff에 올렸다.

행을 만들지 않은 흔적이 하나 있다. `wageHistory.utils.test.ts:71`의 describe 제목에 지워진 `kstToday()` 이름이 남아 있다. 단언은 그대로라 동작에는 해가 없고 제목의 이름만 거짓이다.

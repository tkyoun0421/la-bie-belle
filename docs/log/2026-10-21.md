# 2026-10-21 — 시드 서버가 기본 시급 잠금을 잡고 옛 이름 검사가 넓어지고 큰 표가 키 커서로 읽힌다

PR 넷(#625~#628)이 돈 회차다. 어제 candidate로 올라온 `e2e-seed-default-wage-lock`·`legacy-bare-script-names`가 한 PR로, `read-all-pages-offset-drift`가 코드 PR 하나와 정본 문장 PR 하나로 닫혔고, 마지막 PR은 그 커서 읽기가 남긴 중복 하나를 걷었다. 단위·lint·타입·번들은 초록이고 integration 전체(97 스위트 670건)는 #626에서 돌았다. 닫으면서 candidate 셋이 새로 나왔다.

## 시드 서버도 같은 배타 잠금을 잡는다

어제 잠금은 integration 테스트끼리의 부수효과를 막았지만 e2e 시드 서버는 같은 로컬 DB에 잠금 없이 `set_default_wage`를 불렀다. 그래서 시드와 integration이 같이 돌면 그 잠금이 아무것도 막지 못했다. 시드 서버가 `set_default_wage`를 부르던 두 자리(`payroll_view`의 `seededUser`, `payroll_wages`의 `seedPayrollWages`)를 `setDefaultWageUnderLock` 하나로 모았고, 이 함수는 integration이 쓰는 `withDbLock(DEFAULT_WAGE_RATES_LOCK, …)`을 같은 헬퍼 파일에서 가져온다. 시드 서버가 이미 그 파일을 import하고 있어 import 줄에 이름 둘만 더했다.

두 자리는 서로 다른 시드 상태라 한 요청 안에서 잠금이 겹치지 않는다. `payroll_view`는 `seededUser`에서 잠금을 풀고 나서 `seedPayrollView`로 넘어간다. 어제 정리한 한계(같은 키 잠금을 겹쳐 부르면 멈춘다)에 걸리지 않으려고 이 점을 먼저 확인했다.

짝 테스트는 새로 썼다. 시드 서버를 직접 띄우는 테스트가 없었다. integration이 그 키를 배타로 쥐든 공유로 쥐든 `setDefaultWageUnderLock`은 `pg_locks`에서 그 키의 대기자로 보여야 하고, 풀리기 전에는 오늘 기본 시급을 쓰지 않아야 한다. `seed("payroll_wages")`는 사람 여섯을 만드느라 5.3초가 걸려서 `SEED_TIMEOUT_MS`(20초)를 따로 줬다. 잠금 없이 함수만 먼저 빼서 돌리면 세 건 모두 빨갛다.

## 옛 이름은 이름만 적혀도 잡는다

#623의 `legacyDocPaths`는 옛 스크립트 열셋을 `scripts/` 접두가 붙은 경로로만 찾았다. 확장자가 붙은 파일 이름만 있어도 잡도록 넓혔다. 다른 낱말의 일부는 넘긴다. 바로 앞에 영숫자·밑줄·`.`·`-`가 있거나 바로 뒤에 영숫자·밑줄·`-`가 있으면 안 잡는다. `design-tokens-md.mts`나 `seed-session.json`을 잡으면 거짓 양성이라 짝 테스트가 그 꼴을 안 잡는다고 못 박는다. `tests/lint/` 안에서 개명된 옛 이름 쉰여덟(줄기 서른여덟)도 같은 방식으로 잡는다. 개명 기록에서 `databaseTypes.test.ts`·`databaseTypes.ts` 두 줄은 셈에서 뺐다. 예전에 반대 방향으로 바꾼 기록이고 지금은 그 이름이 다시 쓰이기 때문이다.

검사 파일과 짝 테스트가 옛 이름을 통째로 적으면 자기 파일이 위반이 되므로 줄기와 확장자를 나눠 붙였다. 새 검사는 처음 97건(29파일)을 잡았다. 89건은 실제 이름으로 고쳤고 나머지 8건은 일부러 옛 이름을 적은 줄이라 `ALLOWED_LINES`로 갔다. 없는 스크립트를 가리킬 때 위반이 되는지 보는 픽스처, kebab 이름이 잡히는지 보는 픽스처, 당시 상태를 적은 문장이 그렇다. 총괄 문서인 handoff와 backlog의 해당 줄도 고치지 않고 허용했다.

판단이 갈린 자리가 하나 있었다. `attendance-data.md`의 「`error-codes.ts` 옆 `src/shared/api/`에」는 옛 이름만 바꾸면 되는 문장이 아니었다. 오류 코드 파일이 `src/shared/consts/error.const.ts`로 옮겨져 「옆」이 더는 맞지 않아서 「`src/shared/`에」로 고쳤다. 실제 저장소 회귀 테스트의 이름에서도 「두 자리」라는 숫자를 뺐다. 허용 자리가 열일곱으로 늘 때마다 이름이 거짓이 되던 숫자였고 단언은 그대로다.

구현 전에 짝 테스트를 돌려 30건이 빨간 것을 봤다. 입력인 `docs-sdlc-coherence.md`의 옛 이름 일곱 자리를 고쳐서 `docs-authoring-playbook.md`를 영향 확인에 올렸지만 완료 조건과 판정은 그대로라 playbook은 옛 이름만 같은 방식으로 고쳤다.

## 큰 표는 유일 키 커서로 읽는다

`readAllPages`는 `range(from, to)`로 페이지를 넘겼다. 두 페이지를 읽는 사이에 앞쪽 행이 지워지면 뒤 행이 앞으로 당겨져 다음 페이지 시작보다 앞에 놓이고 그 행은 말없이 빠진다. 시그니처를 `readAllPages(page: (after, limit) => …, keyOf, pageSize = 1000)`으로 바꿨다. 첫 호출의 `after`는 `null`이고 다음부터는 앞 페이지 마지막 행의 키다. 마지막으로 받은 키보다 큰 행을 달라고 하면 앞에서 무엇이 지워지든 남은 행이 모두 오고 같은 행이 두 번 오는 일도 없다.

키는 표마다 다르다. `check_ins`와 `availabilities`는 `id`로 읽고 `.gt("id", after)`로 거른다. `wage_rates`는 `id`가 없어 기본 키 `(profile_id, effective_date)`로 읽고 `or=(profile_id.gt.P,and(profile_id.eq.P,effective_date.gt.D))`로 거른다. 반환 순서는 예전과 같아야 해서 키 순서로 받은 뒤 메모리에서 원래 정렬로 다시 맞춘다. availabilities의 DTO 타입은 그대로 두고 api 파일 안의 행 타입에만 `id`를 얹었다. 매퍼 테스트 픽스처를 건드리지 않으려는 선택이다.

uuid 순서는 추정하지 않고 쟀다. 로컬 DB에서 무작위 uuid 2000개를 `order by id`로 늘어놓은 것과 문자열로 바꿔 `collate "C"`로 늘어놓은 것이 같았다. `order`와 `gt`가 같은 열과 같은 연산자를 쓰니 커서가 순서와 어긋나지 않는다. 메모리에서 다시 정렬할 때도 `localeCompare`가 아니라 `<`·`>`를 써서 DB 순서와 맞췄다. 옮긴 호출부 integration 넷은 1100행·1116행 테스트를 포함해 파일마다 두 번씩 여덟 번 모두 통과했다.

정본은 코드 PR에서 떼어 #627이 따라갔다. `system/data-access.md`의 「1000에 닿기 전에 `range()`를 건다」를 `readAllPages`와 유일 키 커서로 바꾸고 offset이 왜 안 되는지 한 줄 적었다. `runtime.md`에는 화면이 다른 순서를 바라면 받은 뒤 메모리에서 맞춘다는 규칙을 더했다. `execution.md`에는 `pnpm test:integration` 뒤 인자가 jest 옵션이 아니라 경로 패턴이 된다는 것과, 옵션을 주려면 `pnpm test:integration:run -- --no-watchman`으로 돌린다는 것을 적었다. 구현자가 옵션을 붙였다가 패턴이 조용히 안 맞은 데서 나온 문장이다. 영향 확인에 올린 spec·plan 마흔다섯은 천 행 넘는 표를 넘기는 방법만 바뀌고 반환하는 행과 순서와 완료 조건은 그대로라 고치지 않았다.

## 따옴표 키는 걸고 값 키와 인덱스 접근은 안 건다

`house/no-snake-case-field`는 `{ "profile_id": string }`과 `Record<"profile_id", …>`를 못 잡았다. #628에서 `utils`가 안 되는 까닭으로 이 규칙을 들었는데 따옴표로 쓰면 피해 갈 수 있어서 구멍이 판정과 모순이었다. 이제 타입 속성의 따옴표 키, 계산식 글자 키, `Record`의 첫 인자와 `Pick`·`Omit`의 둘째 인자의 글자 키를 하나씩 본다. 기존 테스트 한 줄 「글자로 적은 키는 못 본다」가 바로 이 구멍을 적어 둔 단언이라 뒤집었다.

안 거는 꼴이 둘이고 둘 다 문법으로 열 이름과 다른 것을 가를 수 없어서다. 객체 리터럴의 키는 DB가 든 값을 키로 삼는 표(`signup_approved` 같은 알림 종류)가 정당한 꼴이라 따옴표든 아니든 통과한다. 인덱스 접근(`X["profile_id"]`)은 저장소 안 실례가 `Database["public"]["Functions"]["check_in"]`처럼 표·함수 이름이라 열 이름인지 모른다. 못 믿을 검사라 뺐다. 넓힌 뒤 `pnpm lint`가 main에서 새로 잡은 자리는 없었다.

## 개명 기록에서 사라진 경로는 손 목록으로 잡는다

`legacyDocPaths`는 앞서 기록된 개명 열셋과 `tests/lint` 옛 이름만 알았고 중간 이름은 밖이었다. 개명 이력(2081행)에서 지금 없는 옛 경로 2077개를 뽑아 저장소에 언급이 남은 것을 세니 163개, 227줄이었다. 이력에서 패턴을 매번 뽑는 길은 버렸다. 테스트를 도는 CI `checks` job이 `fetch-depth` 기본값 1의 얕은 clone이라 이력이 없고, 이력이 있는 `bundle`·`db` job은 `pnpm test`를 안 돈다. 그래서 `RENAMED_SOURCE_PATHS`라는 `src/` 경로 147개 손 목록으로 갔다. 163개에서 이미 줄기 목록이 잡는 넷과, 이어지는 파일 없이 지워진 셋(Next.js 시절 미들웨어와 죽은 코드 삭제 둘)을 뺐다. 고칠 실제 경로가 없어서다.

목록은 코드 파일(`.ts`·`.tsx`·`.mts`·`.mjs`·`.js`)에 안 댄다. 코드 안의 `src/...` 글자는 검사 픽스처이고, 진짜 참조라면 import는 typecheck가 런타임 경로는 그 테스트가 먼저 깨진다. 문서에서는 181곳을 지금 경로로 고쳤다. 지금 경로는 개명 사슬을 끝까지 따라 정했고, 닮음 점수 70 미만 고리는 손으로 봤다. 그중 둘은 git이 짝을 잘못 지은 것이었다(`fontLoading`의 짝은 `shouldRenderApp`을 든 `fontLoading.utils.ts`, `pressNotification`의 짝은 `notifications/lib`의 `pressNotification.lib.ts`). 쿼리 키 파일 셋은 개명이 아니라 삭제와 생성으로 기록돼 손으로 이었다.

당시 상태를 적은 21줄은 고치지 않고 `ALLOWED_LINES`에 넣었다. observation이 인용한 에러 문구, 감사표의 `경로:줄`, 「이 파일을 어디로 옮긴다」고 판정한 옛 경로를 바꾸면 기록이 거짓이 되기 때문이다. 남는 한계는 `` `X/a.ts`·`b.ts` ``처럼 경로 없이 이어 쓴 형제 이름으로, 앞 경로만 고쳐진다. 목록이 손으로 쓰는 것이라 앞으로 생기는 이름 변경을 따라가지 않는 것도 한계다. 둘을 `legacy-sibling-names`·`legacy-renames-list-manual`로 올렸다.

## 낡은 허용 항목이 드러나고 handoff 항목은 걷혔다

허용 항목은 handoff와 backlog 줄의 표지 문장에 묶여 있어 그 문장이 덮어쓰이면 아무것도 가리키지 않은 채 조용히 남았다. #630이 `staleAllowedLines`를 내서, 표지 문장이 옛 경로가 남은 줄을 하나도 안 가리키는 항목을 돌려주고 실제 저장소에서 결과가 비어 있어야 한다고 단언한다. 이 단언을 넣자 다음 마감이 실패할 자리가 생겼다. handoff는 회차마다 덮어쓰이니 그 항목 둘이 곧 낡는다. #631이 원인을 걷었다. handoff에서 옛 경로를 적은 문장을 빼고 허용 목록의 handoff 항목 둘을 지웠으며, 낡음 단언 셋의 예시 파일을 handoff에서 backlog로 바꿨다(단언은 그대로). 「덮어쓰는 handoff는 허용 목록에 오르지 않는다」를 더했고, `session-recorder` 정의문에 handoff에 옛 경로를 적지 않고 덮어쓴 뒤 이 검사를 돌린다는 한 줄을 넣었다.

backlog의 `legacy-intermediate-names` 줄은 손대지 않고 허용된 채 남는다. 상태만 바뀌는 줄이라 표지 문장이 살아 있다.

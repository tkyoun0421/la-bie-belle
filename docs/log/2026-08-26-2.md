# 2026-08-26 (2) — 도메인 규칙이 집을 얻는다

PR 하나(#186)가 들어간 회차다. 코드는 안 움직였다. `docs/domain.md` 한 파일을 `docs/domain/` 여섯 파일로 열고, PRD에서 규칙과 숫자를 걷어내고, 그 자리에 급여 쪽 법정 기준 검토를 새로 얹었다. 엣지 케이스를 채우기 전에 채울 곳부터 다시 지은 회차다.

## 재편의 출발점

사람이 "PRD가 너무 러프하고 엣지 케이스가 없다"고 짚었다. PRD를 훑어 구멍을 영역별로 나열했더니 급여 쪽에 법정 항목이 통째로 빠진 것이 가장 컸다 — 연장 기준, 야간 가산, 주휴수당 같은 것들이 아예 문장으로 존재하지 않았다.

구멍을 바로 메우는 대신 진행 방식을 넷 중에서 고르게 했고, 사람은 "문서 모양부터 정리"를 골랐다. 엣지 케이스는 어딘가에 적혀야 하는데 지금 문서 지도에는 그 어딘가가 없었다. PRD에 다 적으면 수백 줄 명세서가 되고, task-spec에 적으면 여러 task가 같은 규칙을 베껴 정본이 갈라진다. 자리를 먼저 만들고서야 구멍을 메울 수 있었다.

## 도메인 규칙이 사는 곳 (#186, ADR-004)

`prd.md`와 `domain.md`가 같은 규칙을 이미 두 번 적고 있었다. "연장 — 하루 9시간을 넘긴 시간에 1.5배"가 두 파일에 따로 살았다. `CLAUDE.md`는 정본이 다른 곳에 있는 내용을 옮겨 적지 말라고 하는데, 계산 규칙과 상태 전이가 PRD·spec·ADR 셋 어디에도 안 맞아 규칙이 갈 곳을 못 찾고 있었다.

`docs/domain.md`를 `docs/domain/`으로 열어 `README.md`(지도와 컨텍스트 경계)와 영역별 파일 여섯(`schedule.md`·`swap.md`·`attendance.md`·`payroll.md`·`account.md`·`notification.md`)으로 나눴다. 용어를 `README.md`에 모으고 규칙만 영역 파일에 흩는 길도 있었지만 안 골랐다. 같은 개념의 정의와 규칙이 떨어지면 한쪽을 고칠 때 다른 쪽이 남는다 — 정본이 갈라지는 걸 막으려고 여는 디렉터리에서 스스로 그 실수를 반복하는 셈이라 버렸다.

PRD에서는 포지션 표와 가산 계산 예시와 알림 목록을 빼고 `docs/domain/` 링크로 바꿨다. 71줄이 줄었다. PRD에 남는 건 왜 만드는지, 누구를 위한 것인지, 무엇을 안 하는지 셋이고 "앱이 급여를 계산한다" 선까지만 적는다. 가르는 질문은 하나다 — task가 끝나도 이 문장이 남는가. 남으면 도메인 규칙이고, task와 함께 수명이 끝나면 spec이다. ADR-002의 spec 정의는 그대로 뒀다.

## 급여에서 나온 것

영역 파일마다 "아직 안 정한 것" 절을 둬 다음 인터뷰가 채울 자리를 남겼다. 급여 쪽이 가장 크고, 그중 법정 기준과 어긋날 소지가 있는 것이 여섯이다. 연장 기준이 9시간인데 근로기준법은 8시간 초과분을 연장으로 본다. 가산이 "하루에 하나, 큰 쪽"인데 법은 연장·야간·휴일을 각각 얹는다. 야간 가산(22시~06시 50%)이 아예 없다. 주휴수당이 없다. 휴게시간 공제 기준이 없어 "9시간"이 실근로인지 체류 시간인지 안 정해져 있다. 휴일 8시간 초과분에 붙는 100% 가산이 없다.

사업장이 상시 근로자 5인 이상인지가 이 여섯 항목의 적용 여부를 가르는 전제였다. 사람이 5인 이상으로 확인했다. 그 결과로 연장·야간·휴일 가산이 전부 법정 의무로 걸리게 됐고, `payroll.md`의 "아직 안 정한 것"에서 "5인 이상인가" 질문 자체가 빠지고 그 자리에 휴일 8시간 초과분 100% 가산 어긋남이 새로 들어갔다. `payroll.md`에는 "이 절이 다 채워지기 전에는 급여 계산 코드를 쓰지 않는다"를 박아뒀다.

## subagent 자동 위임이 막혀 있는 원인

작업 중 읽기 전용 subagent가 자동으로 안 붙는 현상을 짚어 원인을 찾았다. 시스템 프롬프트에 "Do not call the AgentTool unless the user requested it"가 얹혀 있어 `CLAUDE.md`의 "찾는 일은 읽기 전용 subagent에 맡겨 총괄 컨텍스트를 아낀다"와 정면으로 부딪힌다. 출처를 뒤진 결과 Claude Code CLI 바이너리(`~/.local/share/claude/versions/2.1.245`) 안에 박힌 문자열이었다. Orca 앱 설정에도 사용자 설정 파일에도 없다 — 사람이 건 게 아니라 도구가 기본으로 넣는 지침이다. 하드 차단은 아니고 프롬프트 문장이라 스폰을 명시로 요청하면 걸린다.

사람은 "`CLAUDE.md`를 살린다" 쪽을 골랐지만, 지울 파일이 저장소 안에 없어 이 자리에서 손댈 방법이 없다. 미해결로 남겼다.

## docs-researcher에 Bash를 주지 않기로 정했다

이번 문서 재편의 검증(용어 스물하나와 경계 셋이 전부 영역 파일로 이동했는지)을 `docs-researcher`에 맡겨봤는데 git 히스토리를 못 읽어 원본 대조를 못 했다. 도구를 넓히는 길과 검증 자체를 다른 손에 맡기는 길 중에서, 읽기 전용 성격을 지키는 쪽을 택했다. git diff를 다뤄야 하는 대조 작업은 이미 Bash를 가진 `pr-diff`에 맡기기로 정했다. 이번 회차의 이동 검증 자체는 총괄이 `git show`로 직접 대조해 누락 0을 확인했다.

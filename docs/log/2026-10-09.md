# 2026-10-09 — DB 열 이름을 api 안에서 끝내고 화면을 조립만 하게 한다

PR 셋(#510~#512)이 든 회차다. `dto-to-domain-shape`가 DB 꼴이 화면까지 새던 자리를 매퍼로 막고, `screens-orchestration-only`가 `.tsx`에 남아 있던 값 만들기를 전부 controller로 밀어내 두 task를 같이 닫았다.

## DTO를 안 당기고도 꼴을 베낀 자리 서른다섯이 알짜였다

`dto-to-domain-shape`(#510)는 매퍼 열하나를 세워 `api`를 떠나는 값이 도메인 모양이 되게 했다. 도메인 열하나가 같은 꼴 넷을 든다 — `api/<도메인>.dto.ts`가 `Row` 접미사로 snake_case를 들고, `model/<도메인>.type.ts`가 camelCase 도메인 타입을 세우고, `utils/<도메인>.mapper.ts`가 옮기고, `.api.ts`가 `.returns<XRow[]>()` 뒤에 `.map(toX)`를 붙인다.

`.dto.ts`를 당기지 않으면서 같은 필드를 자기 타입으로 선언한 파일이 서른다섯이었다. `{ starts_at: string | null; ends_at: string | null }` 꼴을 구조로 맞춰 생긴 자리라, 「`api/` 밖에서 `.dto.ts`를 못 당긴다」 하나로는 경계가 안 섰다 — import를 막아도 그 자리는 그대로 남는다. 전부 `Pick`으로 도메인 타입에서 끌어냈다.

검사 38(`house/no-snake-case-field`)이 그 경계를 집행한다. 처음엔 선언과 읽기를 다 재서 1716건이 나왔는데 1643이 거짓이었다 — `Record<NotificationKind, X>` 표의 키(`signup_approved` 꼴)가 DB가 **든 값**이고 열 이름이 아닌데 같이 걸렸다. 타입 선언만 재는 쪽으로 좁히니 73건이 남았고 지금 0이다. 타입이 camelCase면 그것을 snake로 읽는 자리는 `pnpm typecheck`가 따로 잡는다.

중첩은 매퍼가 편다. `slots.days.work_date`와 `assignments.days.starts_at` 꼴의 두 겹 조인이 도메인에서는 `workDate`·`startsAt`로 한 층에 선다. 무엇으로 펴는지가 그 열의 임자로 갈린다 — 조인으로 끌어온 남의 이름은 `name`, 그 사람 제 행의 것은 `displayName`이다.

## 242 파일을 리뷰 대신 손으로 감사했다

[관찰 059](../observations/059-pr-too-large-for-auto-review.md)가 든 마찰이 여기서 재현됐다 — 자동 리뷰가 파일 100개에서 끊긴다. `git diff main...HEAD`로 네 축(삭제 파일, 총괄 문서 접촉, 시크릿, 테스트 단언)을 직접 봤다. 삭제된 파일은 하나(`monthWindow.mapper.ts` → `schedule.mapper.ts`로 접었다)였고 테스트 단언은 필드 이름만 바뀌었을 뿐 업무 규칙은 그대로였다.

타입이 안 붙은 mock이 typecheck를 지나친다는 것도 이 과정에서 드러났다. 훅 테스트 일곱이 `.api.ts`를 갈아 끼우면서 픽스처에 타입을 안 달아 `.returns` 꼴이 바뀌어도 컴파일이 통과하고 런타임에서야 터졌다 — `pnpm test`로만 잡혔다. [관찰 061](../observations/061-untyped-mocks-let-typecheck-pass.md)과 backlog의 `typed-mock-fixtures`로 넘겼다.

같은 꼴인데 못 접는 자리도 셋 남았다. `payroll`과 `attendance`의 `ExcuseStatusRow`가 같은 뷰를 글자까지 같은 다섯 필드로 받는데, 접으려면 `entities` 하나가 다른 `entities`를 당겨야 하고 `no-cross-slice-import`가 막는다. plan에 적어 뒀다.

integration이 한 번 빨갰는데 코드 탓이 아니었다 — 로컬 DB에 쌓인 `profiles` 1710행·`wage_rates` 2044행 때문에 PostgREST의 `max_rows = 1000`이 전체 결과에 걸려 한 사람의 가장 늦은 행만 받혔다. `supabase db reset` 뒤 613/613 통과다. [관찰 013](../observations/013-integration-users-never-cleaned.md)이 「남은 행이 실패를 가린다」만 들었는데 같은 뿌리가 거짓 빨강도 만든다는 것을 이번에 더 적었다.

## `.tsx`가 조립만 하게 두 PR로 나눠 올렸다

`screens-orchestration-only`는 통신 쪽 경계(`ui` → `api`·`services`·클라이언트·`.dto.ts`)는 이미 선 상태에서 시작했다. 남은 것은 **값을 만드는 일**이 화면에 있다는 것이었다 — `ui` → `utils`·`model` 값 import가 스물일곱 건, 그중 스물다섯이 화면 파일이 아니라 조각에 몰려 있었다. controller를 화면 단위로만 두면 조각의 로직이 갈 데가 없어, ADR-015의 controller 정의를 `hooks/use<화면>.ts`에서 `hooks/use<조각>.ts`로 넓혔다.

**#511이 정본과 본보기 셋(`members`·`pending`·`profile`)을 세웠다.** `MemberSheet.tsx`가 직접 부르던 포맷·판정 넷과 세던 판정 다섯이 `useMemberSheet`의 값 하나하나(`valueRows`·`menuLabel`·`leftLine`·`roleLabel`·`canSave`)로 접혔다. `PendingScreen.tsx`는 343줄에서 34줄로, `ProfileScreen.tsx`는 239줄에서 67줄로 줄었다. 폼 조각이 넘겨받을 값이 스물을 넘는 자리는 `screen: <화면>Controller` 하나를 통째로 받게 했다 — 가름의 축은 「그 화면 밖에서 쓰일 수 있나」다.

**#512가 남은 슬라이스 열여섯을 같은 축으로 바꾸고 검사를 켰다.** `ui/`의 값 import 27→0, `.tsx`의 `useRouter`·경로 리터럴 20여→0, 한 `.tsx`의 `<Screen>` 최대 4→1, `SheetLayer` 최대 8→1, 삼항 최대 31→5. 조각 수가 51에서 97로 늘었다 — 늘어난 자리가 상태마다의 조각과 시트를 고르는 자리다. `ScheduleAdminScreen`은 345줄에서 23줄로 줄었다.

검사 39(`house/ui-value-import`)는 `shared` 층의 그리기 기하학 함수 넷(`cn`·`miniCalendarGrid`·`buildYearMonths`·`dayBandFillRatio`)만 면제한다 — 도메인 판정이 아니라 presentation 자신의 계산이라서다. `shared/model`은 면제가 아니다.

## 받은 판정 셋

로그아웃 뒤 갈 데를 `screen.signOut(screen.goLogin)` 꼴로 화면이 들고 있던 자리가 여덟이었다. 둘 다 controller가 준 값이지만 「로그아웃 뒤에 로그인으로」라는 순서는 화면 몫이 아니라서, controller가 `leave()`로 묶었다. 다섯 테스트의 「보낼 데는 안 든다」는 단언을 뒤집었다 — 보낼 데를 바깥으로 미루면 그 바깥이 `.tsx`가 된다.

`rehearsal`은 날 시트 위에 폼 시트가 쌓이고 닫기가 위에서부터다. 시트 스택을 하나로 줄이면 보이는 것이 바뀌어, plan에 「겹쳐 뜨는 시트는 그 자리에서 둘일 수 있다」를 적었다.

경로 상수 중복도 하나 있었다 — 세 묶음이 각자 더해 `/admin/approvals`가 두 이름을 가졌다. `ADMIN_HOME_PATH`가 쓰던 `ADMIN_` 접두로 모았다.

## worktree 세 개가 같은 벽에 부딪혔다

implementer 셋이 worktree에 `node_modules`가 없어 `pnpm typecheck`·`pnpm lint`·`pnpm test`가 못 돌았다. 셋이 각자 다른 길로 넘었다(설치·심링크·절대 경로). [관찰 063](../observations/063-worktree-has-no-node-modules.md)으로 닫으면서 정의문에 「worktree에서 시작하면 `pnpm install --frozen-lockfile`이 첫 수다」를 적었다.

같은 자리에서 둘째 마찰도 났다 — 셋이 동시에 전체 jest를 돌려 load average가 31까지 오르고 5초 타임아웃을 넘긴 스위트가 실행마다 다른 자리에서 떨어졌다. 「병렬로 띄워졌으면 담당 슬라이스만 돌린다」가 같이 섰다.

`.gitignore`의 `node_modules/`에서 트레일링 슬래시를 뗐다 — 슬래시가 디렉터리만 매치해서 심링크로 깔면 `git status`에 뜨고 `git add -A` 한 번에 본 저장소가 딸려 들어간다.

규칙을 하나 더하면 다섯 자리(`eslint-rules/<이름>.mjs`·`index.mjs`·`eslint.config.mjs`·`tests/lint/rules.ts`의 상수 둘·`execution.md` 표)가 움직이는데, `tests/lint/rules.ts`의 `DOCUMENTED_LINT_RULE_COUNT`와 `ENFORCED_RULE_COUNT`가 값이 같아서(마지막 규칙이 마침 lint라서) 하나만 고치고 넘어갔다가 「끊김 없이」 테스트가 걸렸다. `ENFORCED_RULE_COUNT`를 `RULES`에서 최댓값을 뽑는 쪽으로 바꿔 손으로 올릴 자리를 줄였다. [관찰 062](../observations/062-twin-rule-counts-move-together.md)로 닫았다.

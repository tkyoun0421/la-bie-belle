# 2026-08-26 (4) — 디자인 시스템이 서고 lint가 규율을 기계화한다

PR 둘(#196, #197)이 들어간 회차다. 하나는 디자인 시스템 문서 일곱을 처음 세웠고, 다른 하나는 그동안 문서에만 적혀 있던 경계와 규율을 ESLint 규칙 열넷과 Prettier로 CI가 직접 막게 했다. 코드는 lint 쪽에서 `globals.css` 교체 하나만 움직였고 화면은 여전히 없다.

## 디자인 시스템이 절제된 브라운을 고른다 (#196)

사람이 웨딩홀 실사진을 보고 브라운 주도를 골랐는데, 브랜드 색이 화면에 넓게 깔리는 건 싫다고 했다. 문제를 "어떤 색인가"가 아니라 "브랜드 색이 화면의 얼마를 차지하는가"로 다시 잡아 노출 정도를 조절하는 쪽으로 풀었다. 브랜드 색을 버튼 한 자리로 묶은 근거가 여기서 나온다. 브랜드 색이 한 군데뿐이어야 "여기를 누르라"는 신호가 되고, 헤더와 카드에도 깔리면 버튼의 색은 장식이 된다. 근무자는 이 앱을 하루 십 초 쓰고 그 안에서 근무 정보가 먼저 읽혀야 한다.

팔레트는 OKLCH로 직접 계산했다. 팔레트 단계 이름이 밝기가 아니라 자리를 가리키게 짜서, 같은 의미 매핑 표 하나가 라이트와 다크 두 모드를 다 덮는다. `bg.brand-solid = brand-800`이 라이트에서 `#6E4F39`, 다크에서 `#C7A48C`로 자동으로 갈린다. 고정 팔레트였다면 매핑 줄이 두 배가 되고, 한 줄만 어긋나도 다크에서만 안 보이는 글자가 생긴다.

사람이 승인한 브랜드 값은 `#694B36`이었는데, 규칙적인 램프에 스냅하니 `#6E4F39`가 나왔다. 대비 1.07배 차이로 눈에 안 보이는 수준이라 램프 규칙성을 택하고 그 사실을 문서에 밝혔다. 값을 손으로 미세 조정해 램프 규칙을 깨는 대신, 스냅된 값을 정본으로 두고 원래 승인값과의 차이를 기록으로 남기는 쪽이 나중에 팔레트를 다시 계산할 때 덜 헷갈린다.

브랜드와 경고는 색으로는 못 갈린다. 브랜드가 브라운이라 진한 앰버가 항상 붙어 다닌다. `brand-800`과 `warning-800`이 1.02:1로 사실상 같은 밝기다. hue를 벌려 색 자체로 푸는 대신, 경고를 글자색으로 안 쓰기로 규칙을 좁혔다 — `bg.warning-weak` 바탕에 `fg.neutral` 글자, `warning-500` 아이콘 조합으로만 쓴다. 나중에 이 제약을 풀려면 hue부터 벌려야 한다.

값이 문서마다 흩어지면 바꿀 때 일부만 바뀌는 사고가 난다고 사람이 지적했다. 그래서 모든 값은 `tokens.md`에만 두고 나머지 여섯 문서는 토큰 이름만 부른다. 문서 지도는 `README.md`에만 둔다. `CLAUDE.md`가 저장소 전체에 쓰는 방식을 디자인 시스템 안에서도 그대로 반복한 것이다.

디자인이 기획 문서에 적힌 화면만 그리면 안 된다고 사람이 짚었다. PR이 "확인이 필요한 자리" 넷을 스스로 열어둔 게 그 결과다 — "8월 28일에 나옵니다" 예시 문장의 어체와 근거 부재, 급여 확정 축하 모션의 대상 미정(`payroll.md`가 급여를 확정하지 않는다고 못 박아둬서), `disabled`·`selected` 상태값 부재, shadcn `accent` 매핑이 절제 규칙과 부딪히는 자리다. 넷 다 지어내지 않고 미정으로 남겼다.

값을 눈으로 옮겨 적지 않았는지는 스크립트로 확인했다. 팔레트 132개, 역할 토큰 26개, CSS oklch 선언 198개, 역할 토큰 CSS 26개가 원본 계산과 문서 사이에서 전부 일치했고, 마크다운 링크와 앵커도 전부 해석됐다. `pnpm lint`·`typecheck`·`test`·`test:integration`·`build`·`e2e`는 문서만 바뀌었으니 그대로 통과했다.

## lint와 포매터가 규율을 기계화한다 (#197)

디자인 시스템 준수를 훅으로 막을지를 물었는데, `CLAUDE.md`의 증축 규칙("상처가 생긴 자리에만")과 ADR들이 훅은 위반이 main에 들어온 뒤에만 단다고 이미 정해뒀다. 훅(편집을 그 자리에서 막는 것)과 테스트·lint(CI에서 실패로 드러나는 것)를 가르고, 테스트와 lint 쪽으로 갔다.

조건은 여덟에서 열넷으로 늘었다. 처음 여덟은 경계·디자인 값·포매터·증명이었고, "하는 김에 더"로 여섯을 더했다 — `.tsx` 더미 UI 강제, 테스트 `.only` 금지, import 순서, Tailwind 클래스 순서, `console` 제한, 미사용 import와 `import type` 통일이다.

type-aware lint는 일부러 안 켰다. `no-floating-promises`가 await 빠진 Supabase 호출을 잡아주긴 하지만, lint가 타입 정보를 읽느라 실행 시간이 몇 배로 늘어난다. 로컬에서 매번 도는 도구라 체감 속도를 택했다.

상대 경로에는 예외를 안 뚫었다. `profile.integration.test.ts`가 `../../../../../tests/integration/supabase`를 쓰고 있었는데, 그 모양 자체가 규칙이 없애려는 것이었다. 예외로 봐주는 대신 `@tests/*` alias를 새로 만들어 상대 경로가 아예 필요 없게 했다. `tsconfig.json`과 `vitest.config.ts` 양쪽에 넣었다 — vitest가 tsconfig paths를 안 읽어서다.

디자인 값 규칙(규칙4)의 경계선은 대괄호 안이 `var()`나 `--spacing()`을 거치면 통과, 리터럴이면 걸리는 걸로 그었다. `shared/ui`를 예외로 빼는 길도 있었지만 규칙을 좁히는 쪽을 택했다. 실제로 이 선에 걸린 건 `button.tsx`의 `text-[0.8rem]` 하나였고, 진짜 위반이라 `text-xs`로 고쳤다.

`.only`는 막지만 `.skip`은 안 막는다. `.only`는 나머지 테스트를 실행에서 빼면서 리포트에는 통과만 남기지만, `.skip`은 리포터가 건너뛴 개수를 드러낸다. `it.skipIf`로 로컬 Supabase가 안 떠 있을 때 건너뛰는 정당한 패턴도 있어서, 숨기는 쪽만 잡고 드러내는 쪽은 건드리지 않았다.

기성 FSD 경계 플러그인은 안 썼다. `import/no-restricted-paths`와 `eslint-plugin-boundaries` 둘 다 import를 실제 파일로 resolve한 뒤 판정하는데, 테스트 픽스처가 가리키는 모듈은 디스크에 없어서 resolve가 실패하고 그러면 경계 위반이 조용히 통과된다. 경계는 파일이 생기기 전에 막아야 값이 있어서, 스펙 문자열만 보는 `no-restricted-imports`로 갔다.

규칙 픽스처는 디스크에 안 쓴다. `ESLint#lintText`에 가상 경로를 준다. 규칙이 열넷으로 늘어도 픽스처 파일이 실제로 늘지 않고, `pnpm lint`와 `pnpm build`가 훑는 실제 대상에도 안 걸린다.

받은 테스트 둘이 서로 배타적이었다. 같은 파일의 같은 import에 한쪽은 `errorCount > 0`을, 다른 쪽은 `=== 0`을 요구했다. 구현자가 이걸 "구현이 막힌 게 아니라 테스트가 모순"이라고 진단하고 멈췄고, 총괄이 픽스처의 본문만 고쳐 모순을 풀었다 — 어느 쪽 단언도 건드리지 않았다.

## 3회 규칙이 얹힌다

생산 스폰이 같은 실패를 세 번째 만나면 네 번째를 시도하지 않고 손을 뗀다. 총괄이 `codex-rescue`에 `--model gpt-5.6-sol`로 넘긴다. 무엇이 "같은"인지는 셋으로 센다 — 같은 테스트가 같은 단언에서 다시 실패하거나, 같은 명령이 같은 에러로 다시 죽거나, 같은 파일을 같은 이유로 다시 고치고 있을 때다. 실패의 정체가 바뀌면 셈은 0으로 돌아간다.

근거는 시간이 아니라 판단이다. 같은 자리를 세 번 두드렸다는 건 접근 자체가 틀렸다는 신호이고, 루프에 빠진 손은 자기가 루프에 빠진 걸 못 본다. 셈은 구현자가 하고(총괄은 리턴만 보므로 한 실행 안의 반복을 못 본다), 넘기는 판정은 총괄이 한다(구현자가 직접 부르면 같은 트리에 손이 둘 붙는다). 멈출 때는 되돌리지 않는다 — 그대로 두면 다음 손이 거기서 출발한다. `CLAUDE.md`와 `.claude/agents/implementer.md`에 얹었다.

## 후속으로 남긴 것

`globals.css`를 `tokens.md` 8절 전문으로 교체하며 그 절이 안 덮는 자리 넷이 드러났다. `@custom-variant dark`가 없어 `dark:` 유틸리티가 `[data-theme="dark"]`를 안 따라가는데, `button.tsx`가 `dark:` 클래스를 여럿 써서 이게 넷 중 유일한 진짜 버그다. 나머지 셋은 `@layer base`가 없어 body 색이 명시로 안 걸리는 것, `card.tsx`가 쓰는 `--font-heading`이 사라진 것, `--font-sans`가 가리키는 Pretendard 파일이 없어 `-apple-system` 폴백으로 떨어지는 것이다. 넷 다 `docs/plan.md`의 다음 task로 넘겼다.

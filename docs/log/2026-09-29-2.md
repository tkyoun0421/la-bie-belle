# 2026-09-29 (2) — 퇴사 1년 뒤 비우기를 세우고 계정 삭제를 쏜다

PR 넷(#459~#462)이 든 회차다. 앞 회차가 마감하며 남긴 두 갈래 — plan 열둘의 사후 기록과 `profile-erasure` — 를 이 회차가 이어받는다. 먼저 plan 문서 전체를 실물에 맞춰 고치고 `profile-erasure`로 넘어갔다가, 그 plan을 쓰고 정본의 빈자리 넷을 판정한 뒤 구현까지 한 회차 안에 닫았다.

## `plans-restate`는 채우는 일보다 걷어내는 일이 컸다

plan 열둘이 「골격이 선 뒤에 파일 배치와 검증 명령을 채운다」는 인용 한 줄을 머리에 달고 두 절을 비워 뒀었다(#459). 구현까지 끝난 열 중 여덟은 실제 코드를 읽어 채웠고 둘(`attendance-excuse`·`notification-list`)은 아직 안 서서 예측으로 채웠다.

채우려고 코드를 열자 plan이 사실과 반대로 적은 자리가 줄줄이 나왔다. dal과 공용 조각의 주체가 뒤바뀐 자리 넷 — `get-month-schedule.ts`는 `schedule-worker`가 처음 세우고 `schedule-admin`이 임베딩을 더했는데 plan은 반대로 적었다. 달 고르기 시트를 두 plan이 「먼저 merge되는 쪽이 만든다」로 서로 미뤘는데 실제로는 한참 뒤 `rehearsal`이 세웠다. 마이그레이션 서술도 실물과 갈렸다 — `schedule-assign`은 새 파일을 세웠고 `schedule-requests`는 파일 셋이 아니라 하나에 다 들었다. 웹 전제 둘(iOS 사파리 visual viewport)은 네이티브에 사파리가 없어 `KeyboardAvoidingView`로 판정했다. `schedule-requests` AC-03의 「`add_assignment`와 `force_change` 둘을 고친다」는 실제로는 `add_assignment` 하나만 고쳤고 `force_change`가 그 안에서 그걸 다시 부르는 구조라 — AC가 요구하는 결과는 그대로 지켜진다. 방법 서술만 실제에 맞췄다.

`stats-admin` AC-05의 `RowBars` unit 미비와 `NotificationKind`가 아직 `string`인 것은 `chart-math-out-of-tsx`·backlog 다른 행이 이미 들고 있어 손대지 않았다.

## `profile-erasure`의 plan이 정본에 판정 넷을 박았다

선행 `edge-function-import` 스파이크가 끝나 열린 자리였다(#461). AC 다섯 — 1년 경계로 `profile_private`를 지우고 사진을 비우는 함수, `pg_net`으로 Edge Function을 쏘는 것, `auth.users`를 지우는 Edge Function 자체, 확장·cron 등록, `internal` 비노출 — 을 세우며 정본이 안 정한 자리 넷이 나왔고 `account/design.md`의 「비우기」 절에 박았다.

도는 시각은 한국 새벽 4시로 정했다. 「매일」까지만 있던 정본에 crontab이 시간대를 타는 만큼 구체 시각이 필요했고, 사람이 앱을 안 보는 때를 골랐다. 사진은 주소만이 아니라 파일도 지우기로 했다 — `photo_url`만 널로 두면 `avatars` 버킷이 공개라 주소를 아는 사람에게 얼굴이 계속 열려서다. 알림 행은 안 비운다 — `notification-data`가 이 판정을 명시로 이 task에 넘겼고 ACC-011이 활동 기록을 안 지운다고 이미 정했다. 계정이 아직 살아 있는 하루 동안 본인이 보는 범위는 이름과 지난 급여·근무 기록 전부다 — 셋 다 안 지우는 것이라 화면이 비는 자리가 없다.

AC-05는 `data-access.md`의 면제 대상(신원을 인자로 안 받는 `internal` 함수)인데도 테스트를 낸다고 명시했다 — 뚫렸을 때 사라지는 것이 개인정보라 한 겹을 더 뒀다. 정본 문장은 안 고쳤다.

## 구현이 쏘는 단계를 제 트랜잭션에 가뒀다

`erase_profiles(p_now)`가 개인정보를 지운 뒤 `pg_net.http_post`로 Edge Function을 쏘는데, 이 호출을 `begin ... exception when others then raise warning ...; end`로 감쌌다(#462). 한 덩이로 두면 `net.http_post`가 던진 예외에 방금 지운 개인정보가 롤백으로 되살아나고, 같은 실패가 날마다 되풀이돼 비우기가 영영 안 끝난다. 테스트가 vault 항목을 지운 채로 불러 `erased_at`이 남는 것으로 이걸 본다.

Edge Function `supabase/functions/erase-account/index.ts`는 `verify_jwt = true`로 겉문을 켜두되, 함수 안에서 Authorization 헤더를 service role 키와 직접 대조한다. `verify_jwt`는 토큰 유효성만 보고 anon 키도 통과시키는데, 남의 계정이 사라지는 문이라 그 한 겹으로는 모자라다고 봤다. `tsconfig.json`에서 `supabase/functions`를 뺐다 — 그 폴더는 Deno 런타임이라 `Deno` 전역도 `npm:` 지정자도 우리 `tsc`로는 안 풀린다.

## 발견 다섯

**`storage.objects`를 SQL로 지우는 것이 기본으로 막혀 있었다.** `storage.protect_delete()` 트리거가 `Direct deletion from storage tables is not allowed`로 끊는다. 스위치(`storage.allow_delete_query`)를 그 문장 하나에만 열고 바로 닫아 풀었다. 행이 없으면 공개 주소는 404라 얼굴은 닫히지만, 객체 저장소의 바이트는 이 길로 안 지워져 고아로 남는다 — Storage API를 타야 하는 일이라 이번 범위 밖이고 `erased-photo-bytes-remain`으로 candidate에 세웠다.

**`revoke all on all functions in schema internal from anon, authenticated`가 실제로는 안 막는다.** `has_function_privilege('anon', 'internal.erase_profiles(timestamptz)', 'execute')`가 여전히 참이다 — 함수 EXECUTE는 기본으로 `PUBLIC`에 붙고 그 줄은 `PUBLIC`에서 안 뺀다. 지금 막는 것은 PostgREST 라우팅과 스키마 USAGE 둘뿐이고, 새 스키마는 기본이 USAGE 없음이라 그 층이 저절로 섰을 뿐이다. 누가 `internal`에 USAGE를 여는 날 모든 함수가 같이 열린다. 저장소의 `internal` 마이그레이션마다 복사된 줄이라 이 PR에서 안 고쳤고, [관찰 031](../observations/031-internal-exposure-test-covers-one-layer.md)이 이 자리를 적었다. `internal-grants-public`으로 candidate에 세웠다.

**AC-05 테스트는 구현 뒤에도 라우팅 한 겹만 본다.** 응답이 여전히 `PGRST202 Could not find the function public.erase_profiles`다 — PostgREST가 `public`만 뒤져서 나는 404고 grant까지 안 간다.

**`add-assignment.integration.test.ts`에 시간 경쟁이 있었다.** 전체 실행에서 한 번 깨졌고 단독 재실행은 통과했다 — `seedWorkRequest`와 `seedRequestCandidate` 사이의 창에 매 분 도는 `expire-requests`가 걸리면 요청이 닫힌다. 이 PR과 무관하고 `test-seed-transaction`이 이미 같은 축을 들고 있다(관찰 024).

**pre-commit 시크릿 검사가 상수 이름을 두 번 바꾸게 했다.** 받은 테스트의 `ERASE_ACCOUNT_URL_SECRET`·`ERASE_ACCOUNT_SERVICE_KEY_SECRET`이 `SECRET = "16자 이상"` 꼴로 잡혀 `..._SECRET_NAME`으로 고쳤다. 값은 vault 항목의 이름이지 비밀이 아니다 — 단언과 값은 안 바뀌었다.

## 로컬·CI가 못 보는 자리

로컬도 CI도 `supabase start -x ... edge-runtime`으로 edge-runtime을 빼고 띄운다. integration은 `pg_net` 호출이 나갔는지까지만 보고, 실제로 `auth.users`가 사라지는 것은 배포 뒤 손 확인이다 — 멱등(같은 본문 두 번), anon 키 거절, 첫 실행 뒤 `user_id`가 널이 되는 것 셋이 그 확인 목록이다. `payroll-holidays`가 먼저 남긴 것과 같은 자리다.

## backlog와 handoff

`profile-erasure`를 `done`으로 올렸다. 검증은 unit 233 suites·1764 tests, integration 90 suites(대상 파일 12/12 통과), e2e는 기기 빌드가 없어 미실행이다. AC-03은 위에 적은 대로 배포 뒤 손 확인으로 backlog 행에 남겼다.

`payroll-holidays` 행에 한 줄을 더했다 — vault 시크릿의 로컬 값을 넣는 길이 `profile-erasure`와 같은 구멍이었다. 테스트가 `beforeAll`에서 `vault.create_secret`으로 로컬 전용 가짜 값을 넣고 `afterAll`에서 지운다. `seed.sql`은 `db reset`마다 도는 전역 상태라 이 용도로는 안 쓴다.

`ready`의 다음 첫 수는 `payroll-holidays`다 — plan이 이미 서 있다(`docs/3-build/plans/payroll-holidays.md`).

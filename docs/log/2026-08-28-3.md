# 2026-08-28 (3) — 초록불이 답이 아니라 질문이었던 회차

PR 하나(#213)가 들어간 회차다. 앞 회차(#211, #212)를 닫은 직후 사람이 "문제가 있어?"라고 물었다. 그 시점에 `pnpm lint`·`pnpm typecheck`·`pnpm test`가 전부 초록이었고 CI도 통과한 상태였다. 검증 명령을 다시 돌리는 대신 방금 들어간 세션 코드를 직접 읽었고, 테스트가 통과하는 채로 숨어 있던 것 넷을 찾았다.

## 찾은 넷과 그중 셋만 고친 이유

`create-supabase-server-client.ts`가 `process.env.NEXT_PUBLIC_SUPABASE_URL ?? ""`로 빈 문자열을 넘기고 있었다. env가 빠지면 `getUser()`가 실패하고 `getCurrentUser`가 `null`을 돌려주니, 화면은 "로그인하지 않았습니다"를 그린다. 앱이 안 터지고 빌드도 통과한다 — 아무도 로그인이 안 되는 정상 앱처럼 보인다. `NEXT_PUBLIC_*`은 빌드 시점에 번들에 박히니 CI의 env 주입이 `pnpm build`보다 뒤로 밀려도 아무것도 안 잡는다. `?? ""`를 빼고 값이 비어 있으면 그 자리에서 던지게 고쳤다.

`catch`의 `return`이 캐시 금지 헤더 전달까지 건너뛰고 있었다. 쿠키 쓰기 실패와 헤더 전달은 독립인데 하나가 다른 하나를 막았고, 막히는 쪽이 하필 토큰 실린 응답이 캐시에 남는 걸 방지하는 장치였다. 다만 지금 재현되는 결함은 아니다. Server Component 경로엔 `setHeader`가 없고 미들웨어의 `set`은 안 던진다. 그래서 테스트도 합성 시나리오로 썼고, 그 성격을 테스트 이름에 남겼다. 프로덕션 경로인 척하지 않기로 한 판단이다.

lint가 간접 호출을 못 잡는다는 한계도 이번에 드러났다. `house/dumb-ui`는 `@supabase/` 스코프 직접 import, `fetch()` 직접 호출, TanStack Query 훅 여덟 개를 잡는데, `@/shared/lib/`를 한 겹 거치면 통과한다. `src/app/page.tsx`가 지금 그 상태다. 규칙의 버그가 아니라 type-aware lint를 안 켜기로 한 결정의 대가라, ADR-001에 그 둘을 같이 적었다. 「화면과 로직」 절에 규칙이 무엇을 잡는지, 「남는 위험」 절에 한계와 그 이유를 나눠 적었다. 한 문단에 몰면 어느 한쪽만 읽는 독자가 반쪽만 알게 된다는 게 구현자의 판단이었고, 그대로 받아들였다.

넷째는 미들웨어에 `matcher`가 없다는 것이었는데, 이건 범위 밖으로 뺐다. 함수 안에서 정적 자원을 걸러내는데 `export const config = { matcher }`를 쓰면 실행 자체를 안 한다. 동작은 맞고 명세도 지켰으니 성능 판단은 따로 하기로 했다.

## 계획자의 진단을 실측으로 뒤집었다

`test-planner`가 회귀 하나를 예고했다. env 체크를 넣으면 기존 테스트 넷이 깨지는데, "로컬에서는 `.env.local`에 값이 있어서 안 보이고 CI에서만 빨간불이 뜬다"는 진단이었다.

절반이 틀렸다. probe 테스트를 심어 실제로 재보니 로컬 vitest에서도 `process.env.NEXT_PUBLIC_SUPABASE_URL`이 `undefined`였다. Vite의 `envPrefix` 기본값이 `VITE_`라 `.env.local`에 값이 있어도 `NEXT_PUBLIC_*`은 `process.env`에 안 얹힌다. 기존 테스트가 통과하던 건 `?? ""`가 삼켜서였다.

결과적으로는 더 나은 상황이었다. 로컬과 CI가 같은 상태라 "로컬 초록, CI 빨강"이라는 함정이 애초에 없었고, writer가 로컬에서 바로 빨간불을 봤다. 추론으로 넘겼으면 writer에게 틀린 지시가 갔을 자리다.

## 구현자가 피한 함정

`requireEnv(name, value)`로 검사를 빼면서도 `process.env.NEXT_PUBLIC_SUPABASE_URL`은 정적 멤버 접근 그대로 두고 값만 넘겼다. `process.env[name]` 같은 동적 접근으로 감쌌으면 Next의 빌드 시점 치환이 안 걸려 프로덕션 번들에서 값이 통째로 사라졌을 자리다. 구현자가 스스로 짚어 보고했다.

빌드가 안 깨진 이유도 정직하게 적었다. `/`와 `/auth/logout`이 `cookies()`를 써서 동적 라우트라 빌드 중에 팩토리를 안 부른다. 다만 로컬에 env가 있어서 이번 빌드가 env 없는 상태를 직접 증명하진 못했다는 한계까지 같이 보고했다.

## 포매터 카운트는 안 늘었다

앞 회차까지 CI가 `pnpm format:check`에서 두 번 죽었다. 이번엔 스폰 프롬프트에 `npx prettier --write`를 명시로 넣었고 CI가 안 죽었다. 증축 규칙의 세 번째 카운트는 채워지지 않았다. 다만 매번 프롬프트에 적어야 막힌다는 게 이번에 드러난 셈이라, 이 상태를 handoff에 그대로 남긴다.

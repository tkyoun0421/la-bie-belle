# P4-T02 실기기 체크리스트

- 이 문서는 실기기 확인 절차만 담는다. 수행(체크박스 채우기)은 P7-T06 몫이다.
- headless Chromium 기반 e2e(`tests/e2e/push-subscription.spec.ts`)는 `Notification.permission`을 항상 `"denied"`로 고정하는 환경 제약이 있어(자동화 컨텍스트에 알림 UI가 없음), 브라우저 네이티브 권한 팝업 자체는 `page.addInitScript`로 스텁 처리해 "권한 요청 호출까지 이어지는지"만 확인했다. **실제 권한 팝업이 뜨는지, 사용자가 허용/거부를 실제로 선택할 수 있는지는 이 문서의 실기기 확인으로만 검증된다.**

## 공통 준비물

- 배포된 환경 또는 `pnpm build && pnpm start`로 띄운 프로덕션 빌드 URL.
- 테스트용 근무자 계정(로그인 가능한 상태).
- `.env`에 `NEXT_PUBLIC_SUPABASE_URL`·`SUPABASE_SERVICE_ROLE_KEY`·`NEXT_PUBLIC_VAPID_PUBLIC_KEY`·`VAPID_PRIVATE_KEY`·`VAPID_SUBJECT`가 채워진 로컬 또는 대상 환경.

## dev 스크립트로 테스트 발송

```bash
node scripts/send-test-push.mjs            # 활성 구독 전체에 발송
node scripts/send-test-push.mjs <profile_id> # 특정 근무자에게만 발송
```

- 발송 payload는 고정값 `{ title: "라비에벨 테스트 발송", body: "dev 스크립트에서 보낸 테스트 푸시예요.", target: { screen: "pay" } }` — 알림을 클릭하면 `/pay`로 이동해야 한다.
- 410·404 응답을 받은 구독은 스크립트가 자동으로 `disabled_at`을 채운다. 콘솔 출력의 "만료 처리" 건수로 확인한다.

## Android Chrome (홈 화면 설치 불필요)

1. 근무자 계정으로 로그인한다.
2. **더보기 → 알림 설정**으로 진입한다. "이 기기에서 근무 확정과 변경 알림을 받아보세요." 안내와 **켜기** 버튼이 보이는지 확인한다.
3. **켜기**를 누른다. 브라우저 네이티브 알림 권한 팝업이 뜨는지 확인한다(headless e2e가 못 덮는 지점).
4. 팝업에서 **허용**을 선택한다. 안내 문구가 "이 기기에서 푸시 알림을 받고 있어요."로 바뀌고 **끄기** 버튼이 보이는지 확인한다.
5. 별도 계정/일정으로 첫 근무 신청을 저장 성공시켜 사전 안내 시트("알림을 받아보세요")가 뜨는지 확인한다. 이미 4번에서 구독을 켰다면 시트가 뜨지 않는 것이 정상이다(이미 구독 중이면 노출 안 함) — 확인하려면 별도 미구독 계정으로 반복한다.
6. 사전 안내 시트의 **알림 받기**를 눌러도 동일하게 브라우저 권한 팝업이 뜨는지 확인한다.
7. `node scripts/send-test-push.mjs <profile_id>`로 테스트 푸시를 보낸다. 기기에 알림이 도착하는지 확인한다.
8. 알림을 클릭한다. 앱이 열리며 `/pay` 화면으로 이동하는지 확인한다(열린 창이 있으면 포커스, 없으면 새 창).
9. **더보기 → 알림 설정 → 끄기**를 누른다. 안내가 "켜기" 상태로 돌아오는지 확인한다.
10. 브라우저 자체 알림 권한을 거부로 바꾼 뒤 **알림 설정**에 다시 들어가 "브라우저 알림 권한이 꺼져 있어요..." 안내가 보이는지 확인한다.

## iPhone Safari (홈 화면 설치 필요)

1. Safari로 로그인한 뒤 **알림 설정**에 진입한다. 홈 화면에 추가하지 않은 상태에서는 "iPhone에서는 홈 화면에 추가한 뒤에 알림을 받을 수 있어요. 공유 버튼에서 홈 화면에 추가를 선택해 주세요." 안내만 보이고 켜기 버튼은 없어야 한다.
2. 공유 버튼 → **홈 화면에 추가**로 PWA를 설치한다.
3. 홈 화면 아이콘으로 앱을 다시 연다(Safari 탭이 아니라 설치된 앱으로).
4. **알림 설정**에서 **켜기**를 누르고 iOS 네이티브 권한 팝업이 뜨는지, 허용 후 "받고 있어요" 상태로 바뀌는지 확인한다.
5. Android 체크리스트의 5~9번과 동일하게 사전 안내 시트, 테스트 발송 수신, 클릭 이동, 끄기를 반복 확인한다.

## 다기기 확인

- 같은 계정으로 기기 A·B 모두에서 켜기를 완료한 뒤 `send-test-push.mjs <profile_id>`를 한 번 실행해 두 기기 모두 수신하는지 확인한다(다기기 구독은 `endpoint` 단위로 별도 행이므로 한쪽을 꺼도 다른 쪽은 유지되어야 한다).

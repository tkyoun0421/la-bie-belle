## 확인된 사실 (사용자 답변·요약본 승인)

- **열람 범위는 승인 근무자 전원.** 그날 미배정 근무자도 확정된 날짜 상세에서 전체 이름·포지션을 본다. 단체 채팅의 "그날 누구 나와?"를 앱이 대체한다. PRD 13장 공개 범위(이름·포지션) 안이다.
- **화면 문법은 포지션 그룹.** 포지션 제목 아래 정식 배정자, 구분선 아래 교육생. 겸직자는 두 그룹에 중복 등장(`INV-STAFF-03`). 기존 사람 단위 스켈레톤 UI는 대체한다.
- **인원 숫자는 비노출.** 포지션명만 표시하고 필요·배정·미달 숫자는 관리자 화면에만 남긴다. 정식 배정자도 교육생도 없는 포지션은 배정표에서 뺀다.

## 해석·가정 (요약본에 포함해 승인됨)

- 배정표는 CONFIRMED만. CLOSED는 기존 모집 마감 화면, OPEN 직접 진입(URL로만 가능)은 모집 중 안내로 막는다.
- 미배정 근무자에게는 `내 배정` 섹션 없이 전체 배정표만. 교육생 본인의 `내 배정`은 포지션명 + 교육 표시.
- 예식 시간은 등록된 것 전부 표시. 예정 출퇴근 시각 표시는 기존 화면 유지.
- 담당자 없음 포지션(정식 0·교육생만)도 그룹으로 노출.
- 일반 근무자용 roster 조회는 이름·포지션·교육생 여부만 반환 — 공개 금지 필드는 응답에서부터 배제.
- 관리자 쪽 신규 화면 없음. 충족·미달 현황은 P3-T06까지의 준비 화면이 유지하며 회귀만 확인.

## 코드 대조에서 정해진 것

- `ScheduleDetailView`(`/schedule/[work_date]`)가 mock `GENERAL_CONFIRMATION`을 그린다. `AssignmentRosterRow.isTrainee`는 표시용 껍데기(P3-T05 인계).
- `deriveScheduleDetailVariant`가 CLOSED만 갈라내고 OPEN 포함 나머지를 확정 화면으로 취급 — 이 구멍을 이번에 막는다.
- 근무자 캘린더(`toScheduleCellStates`)가 CONFIRMED를 `confirmed` 셀로 이미 표시 — 진입 경로 존재.
- 확정 시점 데이터는 서버에 전부 있다(`assignments`·`assignment_trainees`·예식·예정 시각).

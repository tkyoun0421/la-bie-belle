# P3-T02 기획 인터뷰 handoff

- 작업 식별자: P3-T02 (포지션 기본 설정과 스케줄 필요 인원)
- 현재 단계: 기획 승인 종료 → 다음 설계(RADIO) 인터뷰
- 기준 시각: 2026-08-09

## 확인된 사실 (사용자 답변·요약본 승인)

- **기획 승인(user, 2026-08-09).** 결정용 요약본을 승인 형식으로 확인받았다.
- 복사 시점: 준비 화면 첫 진입 시 그 시점의 전역 기본값을 스케줄 필요 인원으로 복사하고, 특이사항은 그 표에서 수정한다.
- 새 포지션의 강제 반영: 확정 전 스케줄 표에는 기본 인원수로 자동 추가("반드시"), 확정 스케줄은 자동 반영 없이 관리자에게 추가 여부 알림 + 수동 추가 경로를 준다.
- 기본 포지션 = 모두가 들어갈 수 있는 포지션. 새 기본 포지션은 기존 승인 근무자 전원에게 즉시 적용(현 파생 구조 그대로, 추가 공사 없음).
- 삭제 판정에 스케줄 필요 인원 사용 포함 — 삭제 막고 비활성화 안내.
- "팀장이 수정할 수 있게"의 팀장은 **관리자**다(당일 팀장 아님).
- 기존 인수 조건 "전역 변경이 준비·확정된 스케줄을 바꾸지 않는다"는 "**확정 스케줄**을 바꾸지 않는다"로 좁혀 재작성했다.

## 해석 (요약본에 명시 후 승인으로 함께 확정)

- 전역 기본 인원수 변경은 열린 스케줄에도 전파하지 않는다 — 강제 반영은 포지션 구조(표에 있는가)에만 적용되고 인원값은 스케줄별 스냅샷.
- 비활성화는 새 선택지에서만 제외하고 이미 복사된 행은 열린 스케줄에서도 유지(빼려면 관리자가 행 삭제 또는 0명).
- 필요 인원 0명 허용(그날 그 포지션 미운영 표현).
- 기본 해제 시 자동 가능 즉시 회수, 기본 지정 전 개인별 부여분은 유지(파생 구조의 귀결로 PRD 4장에 명문화).

## 인터뷰 중 바로잡힌 것

- 조정자가 예시로 쓴 "리허설 도우미"는 실존 도메인 개념(PRD 12장 `rehearsal_entry`, 근무자 자기기록형 급여 참고 데이터, P6 소유)과 충돌해 두 차례 혼선을 만들었다. 포지션과 무관함을 확인했고 P3-T02 범위에 영향 없음.

## 미결 사항 (설계 단계 소유)

- 확정 스케줄 알림·수동 추가의 구현 배분: 확정 후 변경은 revision(P3-T06) 소유라, P3-T02에서 어디까지 만들지 RADIO 인터뷰에서 정한다.
- 알림의 구체 형태(포지션 추가 시 확정 스케줄 목록 안내 vs 준비 화면 배지 등)는 설계 결정.

## 정합화 반영

- PRD 4장(삭제 판정에 필요 인원 사용 추가, 기본 포지션 즉시 적용·회수 명문화) · 7장(복사 시점·전파 규칙·0명 표현).
- phase 문서 P3-T02 절 재작성(기획 미확정 문구 제거, 인수 조건 6건).
- index: `product_approval`(user, 2026-08-09) 기록, status `proposed` → `design_pending`.
- 결정 대장 SCHEDULING에 「포지션과 필요 인원 (P3-T02)」 소절 추가.

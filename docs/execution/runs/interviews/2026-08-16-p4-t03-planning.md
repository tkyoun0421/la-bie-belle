# P4-T03 기획 인터뷰 handoff

- 작업 식별자: P4-T03 (모집·확정·변경 알림)
- 현재 단계: 기획 승인 종료 → 다음 설계(RADIO) 인터뷰
- 기준 시각: 2026-08-16
- 기획 승인: user, 2026-08-16 (요약본 승인, `index.jsonl` `product_approval` 기록)

## 확인된 사실 (사용자 답변·요약본 승인)

- **모집 오픈 알림은 일괄 오픈 1회당 1건.** 근무일 20개를 한 번에 열어도
  근무자당 알림 한 건, 클릭하면 일정 화면. 날짜별 생성 안 함.
- **모집 오픈 수신자는 활성 근무자 전원.** 모집 조회 RLS 기준
  (`is_active_worker`)과 동일 — 휴면·탈퇴·승인 대기 자동 제외, 관리자 미수신.
- **변경 알림은 시간·예식·배정 3종.** 필요 인원(requirement) 변경은 관리
  내부 사안이라 제외 — PRD 9장 사건 목록과 일치.
- **변경 수신자는 변경 전후 배정자·교육생 합집합.** 빠진 사람도 받아
  모르고 출근하는 사고를 막는다. 시간·예식 변경은 현재 배정자·교육생 전원.
- **확정 취소 알림은 P4-T04 기획으로 이월.** cancel_confirmed_schedule은
  revision을 올리지 않는 유일한 확정 후 변경이고 PRD에 알림 명시가 없다.

## 근거 조사 (기획 인터뷰 전 코드 확인, HEAD ee0c01c 기준)

- 모집 오픈 RPC `open_recruitment_schedules`
  (20260807050000_recruitment_batch_open.sql)는 schedules 행 생성과
  `schedule_opened` 감사만 — 수신자 계산·알림 삽입 없음. "활성 근무자
  전체" 재사용 쿼리도 없고 RLS 술어 `is_active_worker`만 존재.
- 확정 후 변경의 revision 단일 관문은 `bump_confirmed_revision`
  (20260817000000_post_confirmation_changes.sql) — section 4종
  (ceremonies·planned_times·position_requirement·position_assignments),
  before/after를 `schedule_revised` 감사에 이미 기록. 호출자 5종 RPC.
  cancel_confirmed_schedule만 revision 미증가.
- 알림 멱등성 키 `(event_type, aggregate_id, recipient_id, revision)`
  unique + `on conflict do nothing`, outbox는 신규 알림에만 동반 기록
  (20260819000000_notifications_foundation.sql). event_type은 check 없는
  text. 현재 유일 사건 `schedule_confirmed`(수신자 배정자∪교육생).
- 푸시 딥링크 허용 screen은 `schedule-detail`·`pay` 2종 하드코딩
  (public/push-service-worker.js, NotificationTarget 타입) — 모집 오픈
  알림의 일정 화면 이동은 screen 신설 필요(설계 몫). 미지 screen은 SW
  폴백 `/notifications`, 목록 API에서는 행 제외.

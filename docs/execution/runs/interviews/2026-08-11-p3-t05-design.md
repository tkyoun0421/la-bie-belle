- 작업 식별자: P3-T05 (교육생 배정)
- 현재 단계: 개발 설계 승인 종료 → 다음 개발(TDD)
- 기준 시각: 2026-08-11

## 확인된 사실 (사용자 답변·요약본 승인)

- **개발 설계 승인(user, 2026-08-11).** RADIO revision 1을 SHA-256 `68f4f0a4…`로 봉인했다.
- **교육생은 새 테이블에 담는다.** 이미 동작 중인 `assignments`에 컬럼을 더하는 대신 `assignment_trainees`를 세운다. 겸함 금지가 제약 하나로 공짜가 되는 쪽을 버리고, 배포된 테이블을 안 건드리는 쪽을 택했다. 이 저장소에 `alter table add column` 전례가 아직 없다는 점도 근거였다.
- **저장은 한 트랜잭션이다.** `replace_position_assignments`를 drop하고 교육생 인자를 더해 다시 만든다. 별도 RPC로 나누면 첫 호출만 성공하고 둘째가 실패하는 틈이 생긴다.
- **후보 함수에 컬럼을 더한다.** `list_position_assignment_candidates` 반환에 `currently_trainee`를 얹어 시트가 조회 한 번으로 다 알게 한다.
- **DB 경계 테스트는 새 파일이다.** `20-assignment-trainees.test.sql`을 만든다. 1014줄짜리 `19-assignments.test.sql`에 더 붙이지 않는다.
- **`자격 없음` 묶음은 유지한다.** 묶음 구성을 그대로 두고, 가능 포지션만 없는 사람은 그 자리에서 교육으로 고를 수 있게 한다. 묶음을 넷으로 늘리지 않는다.
- **후보 한 줄에 `[배정]`·`[교육]`을 나란히 둔다.** 한 번의 탭으로 역할까지 정해진다.
- **e2e는 새 spec으로 뗀다.** 시딩 헬퍼 10개를 `tests/e2e/support/`로 빼고 `assignment-trainee.spec.ts`를 만든다. backlog에 올라 있던 헬퍼 추출을 여기서 갚는다.

## 조사에서 정해진 것 (선택지가 아니었던 것)

인터뷰에서 물으려다 코드 확인으로 답이 정해져 묻지 않은 항목들이다.

- **다음 오류 코드 자리는 `LB024`다.** 쓰인 코드가 `LB001`·`LB002`·`LB010`·`LB011`·`LB020`~`LB023`뿐이다. 거부 사유 둘에 `LB024`·`LB025`를 따로 준다 — P3-T04 교차 검증 F-03이 `LB023` 하나에 두 사유가 얹힌 것을 지적했고 같은 자리를 다시 밟지 않는다.
- **성별 검사를 새로 쓸 필요가 없다.** `assignment_eligibility`가 성별을 먼저 보고 어긋나면 즉시 끝내므로 교육생은 앞쪽 판정만 통과하면 된다.
- **교육생 후보를 새로 조회할 필요가 없다.** 후보 함수가 이미 자격 없는 사람까지 전부 돌려주고 `eligible`·`ineligible_reason`으로 구분만 해 준다.
- **되돌리기는 통째로 되돌린다.** 저장이 한 트랜잭션이라 `lastUndo`도 두 집합을 함께 되돌리는 것이 자연스럽다.
- **다른 포지션 교육생을 이 포지션 정식으로 올리려면 시트를 두 번 연다.** P3-T04가 겸직자 제거에 대해 정한 동선과 같다.

## 봉인 전 체크리스트 결과

- **인수 조건별 출발지 파일 대조.** 손댈 파일이 17개다. 후보 시트 하나만 고치면 될 줄 알았으나 `list_position_assignment_candidates`를 부르는 곳이 `features`가 아니라 `src/entities/assignment/api/`였고, 선택 상태를 쥔 훅과 묶음 판정까지 줄줄이 딸려 나왔다. 17개를 모두 허용 경로에 넣었다.
- **기존 테스트 단언 대조.** `19-assignments.test.sql`이 `has_function(..., array['uuid','uuid','uuid[]'])`로 **시그니처를 문자열로 단언**하고 있어 함수를 재생성하면 깨진다. 깨지는 줄이 정확히 7개(72·73·76·77·81·87·92)임을 확인하고 정지 조건에 그 번호를 박았다. `results_eq`·`row_eq`·`set_eq`가 한 건도 없어 반환 컬럼 추가는 나머지 단언을 건드리지 않는다.
- **세그먼트 대조.** `hooks`는 단위 필수에 `server-only` import 금지 — 대상 훅에 테스트가 이미 있다. `types`는 런타임 export 금지 — `candidate.ts`에 타입 필드만 더한다. `api`는 `requireServerOnly` — 대상 파일 첫 줄에 이미 있다. `model`은 `react` import 금지, `ui`는 `**/api/**` import 금지.
- **glob 매처 실측.** 허용해야 할 17개가 허용되고 막아야 할 9개(`layout.tsx` 둘, `entities/schedule/model/assignment.ts`, 근무자 배정표 화면, 다른 pgTAP 파일, 다른 e2e spec, `auth-routes.config.ts`, `PRD.md`, `fsd.json`)가 모두 차단되는 것을 실행으로 확인했다.
- **스키마 대조.** `spec_refs`는 `PRD:INV-STAFF-02`·`PRD:AC-04`·`DOMAIN:SCHEDULING`·`DOCS:SDD`로 패턴을 만족한다. `gate:all` 무출력 통과.

## 남는 위험

- **`useCandidateSelection`이 이 task에서 가장 위험하다.** 선택 상태가 집합 하나에서 둘로 늘어나는데 기존 단위 테스트 268줄이 한 집합을 전제로 쓰여 있다.
- **헬퍼 추출이 멀쩡한 기존 spec을 건드린다.** `assignment-eligibility.spec.ts`의 기존 test 본문이 import 줄 말고 달라지면 정지 조건이 걸린다.
- **배포된 함수를 drop하는 첫 사례다.** 이 저장소의 마이그레이션 16개 중 `drop function` 전례가 없다. `create or replace` 전례는 `20260807030000_identity_dormancy.sql`에 둘 있지만 시그니처를 바꾼 적은 없다.
- **`자격 없음` 묶음의 의미가 조용히 바뀐다.** 지금 `eligible === false`를 통째로 담는 묶음이라, 사유별로 누를 수 있는지가 갈리는 것을 놓치면 성별이 안 맞는 사람도 교육으로 눌린다.

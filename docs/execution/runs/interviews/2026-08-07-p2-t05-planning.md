# P2-T05 기획 인터뷰 handoff

## 2026-08-07 · 기획 질의 종료

- 작업 식별자: P2-T05 (모집 운영 화면과 테스트)
- 현재 단계: 기획 질의 종료 → 기획 승인 게이트 대기
- 기준 시각: 2026-08-07

### 확정된 사실

- **관리자 신청자 목록은 현재 신청자(applied)만 보여준다** (사용자 결정, 2026-08-07). 철회자는 화면에 두지 않는다 — "지금 가능한 사람이 몇 명인가"에 정확히 답하고, 이력은 applications 행과 감사 기록이 보존한다.
- **신청자 목록에는 이름만 표시한다** (사용자 결정, 2026-08-07). 개인정보 최소화 원칙과 P2 목적에 맞춘다. 가능 포지션 등 배정 판단 정보는 P3 배정 화면 소유다.
- **홈의 「마감 임박 근무 신청」 카드를 T05 범위에 포함한다** (사용자 결정, 2026-08-07). 워커 플로 디자인의 홈 구성에 이미 설계돼 있고, 달력·조회와 같은 데이터를 재사용해 증분이 작다.
- 범위 정본은 `docs/execution/phases/02-recruitment.md`의 P2-T05 절이다.

### 다시 열지 않은 것

- 근무자 예정·마감·확정 구분 보기와 E2E 완주 요구 — phase 인수 조건이 소유.
- KST 마감 경계 정확성 — PRD·phase 인수 조건이 소유하며, P2-T02 검증에서 확정된 월 경계 시간대 결함(F-03)이 backlog에 있어 T05 테스트가 이 경계를 실제로 고정해야 한다.
- 다른 사용자 신청 상태 비노출 — P2-T03 인수 조건이 소유(관리자 조회는 이 규칙의 관리자 예외로, 권한 매트릭스의 admin 읽기 권한 안이다).

### 비목표

포지션 배정·확정(P3), 모집 오픈·마감 알림(P4), 철회 이력 화면(현재 결정으로 제외 — 필요해지면 별도 기획).

### 미결 사항

- 관리자 신청 현황의 진입 화면(모집 달력 통합 vs 별도 화면), 홈 카드의 노출 규칙(마감 임박 기준), 조회 API 형태는 설계(RADIO)가 정한다.
- `check_ids`(`verify`, `recruitment-e2e`)와 `test_mode: verification`은 index에 등록돼 있다. 설계에서 재검토한다.

### 다음 행동

- 기획 승인 게이트: 결정용 요약본 전달 후 사용자 승인을 받는다. 승인되면 결정 대장(/decision)에 3건을 추가하고, 설계 인터뷰로 진행한다.
- index 기록(status·product_approval)은 파이프라이닝 규칙에 따라 task 경계에서 커밋한다.

## 설계 요지 (정본은 RADIO)

- DB 정본 원칙: 경고 합집합·비활성 완화 모두 정의자 함수 재정의로 —
  마이그레이션 `20260818000000_confirmation_warning_scope.sql` 하나.
- `confirm_schedule`의 `position_counts` CTE 소스를 필요 인원 행 ∪ 교육생 잔존
  포지션으로 확장, 표 밖은 required 0 취급(정식만 잔존 시 무경고).
- `replace_position_assignments`의 무조건 비활성 거부를 added diff 계산 뒤
  「추가 인원 존재 시에만 거부」로 이동·완화. 문구·errcode 22023 유지.
- 화면은 `listScheduleRequirements`의 교육생 쿼리에 positions 임베드를 더해
  이름·정렬을 받고, `computeConfirmationWarnings`가 같은 합집합 규칙을 쓴다.
- 신규 e2e 없음(표시 경로 무변경), 오류 코드·스키마·상태 전이 무변경.

## 정찰 근거 (설계 판단의 결정 재료)

- `assignment_eligibility`는 포지션 활성 여부를 검사하지 않는다 — 비활성 검사를
  자격 루프 앞으로 옮겨도 다른 오류가 선점하지 않는다.
- `remove_position_requirement`는 배정·교육생 잔존 행 삭제를 막지 않는다(LB034
  마지막 행 보증만) — 표 밖 교육생 시나리오는 정상 RPC 경로로 재현 가능.
- 19번 pgTAP 404행 비활성 단언은 신규 추가 케이스라 완화 후에도 유지, 21번
  337행 무경고 케이스는 빈 배열 동등 단언이라 합집합 확장과 무충돌.

## 확인된 사실 (사용자 답변·요약본 승인)

- **테스트 발송은 dev 스크립트.** P4-T08 소비자 전의 발송 수단은 저장된 구독으로
  테스트 푸시를 쏘는 로컬 스크립트(web-push devDependency) — 관리자 테스트 버튼
  같은 제품 표면은 추가하지 않는다.
- **권한 요청 진입점은 두 곳(충돌 해소).** 인터뷰 1차 답은 「더보기 알림 설정」
  단일 트리거였으나, WORKER-FLOWS 「알림과 푸시 권한」 절의 기존 정본(첫 근무
  신청 저장 성공 후 사전 안내 → `알림 받기` 선택 → 권한 요청)과 충돌해 드러냈고,
  사용자가 병행으로 확정 — 기존 정본 유지 + 더보기 알림 설정에서 언제든 켜고
  끔(기기별 독립). 거부·미지원·iOS 미설치 안내는 설정 자리에도 둔다.
- **실기기 수신 확인은 P7-T06 이월.** 이 task는 Android·홈 화면 설치 iPhone
  확인 절차를 담은 실기기 체크리스트 문서 작성까지가 완료 조건. index
  verification 문구를 「체크리스트 문서 존재」로 조정하고 P7-T06에 이월 표기.

## 근거 조사 (기획 인터뷰 전 코드 확인)

- `src/app/manifest.ts` + `public/icons/` — PWA manifest·아이콘은 이미 있고
  Service Worker만 없다. `web-push` 미설치.
- 더보기 탭(`(tabs)/more`)과 `src/views/more/` 존재 — 알림 설정 항목의 자리.
  WORKER-FLOWS 전체 메뉴 절 140행에 「알림 설정」이 이미 열거돼 있다.
- P4-T01의 `push_subscriptions` 스키마(endpoint unique, p256dh·auth,
  disabled_at, 본인 select RLS)가 저장소 — 쓰기 흐름이 이 task 몫.

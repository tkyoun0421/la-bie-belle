# P0-T44 설계 인터뷰 handoff

- 작업 식별자: P0-T44 (화면별 인터랙션 효과) · 부수적으로 P0-T43 재봉인
- 현재 단계: 개발 설계 승인 종료 → 다음 개발(TDD), 단 P0-T43이 먼저다
- 기준 시각: 2026-08-10

## 확인된 사실 (사용자 답변·요약본 승인)

- **개발 설계 승인(user, 2026-08-10).** T44 RADIO revision 1을 SHA-256 `a2dd4ca7…`로 봉인했다.
- `motion` 13.0.0을 **`LazyMotion` 범위로만** 도입한다. 번들 상한은 380KB에서 400KB로 올린다.
- 순차 등장의 대상은 **실재하는 목록 셋** — 예상급여 날짜별 내역, 알림 행, 확정 배정표.
- 스와이프와 당겨서 새로고침을 **mock 화면 위에 지금 만든다.** 읽음 처리는 지금의 로컬 상태를, 새로고침은 `router.refresh()`를 부르고 P4에서 호출부만 갈아끼운다.
- `motion` 도입을 **ADR로 올린다** — [ADR-0015](../../standards/adr/0015-motion-library-scope.md).
- 렌더 시간은 **reduced-motion 켠/끈 두 측정의 차이**로 판정하고 허용 폭은 16ms다. 절대값이나 첫 측정 기준선을 쓰지 않는 이유는 CI 머신 편차에 덜 흔들리기 때문이다.

## 조사에서 바로잡힌 전제

- **일정 탭에 목록이 없다.** 기획은 "스케줄 목록 항목이 차례로 나타난다"고 적었지만 `ScheduleView.tsx:75`는 `<Calendar>` 하나다. 실재하는 목록은 `PayView.tsx:173`, `NotificationsView.tsx:67`, `ScheduleDetailView.tsx:48` 셋이다. T43 RADIO가 쓴 "스케줄 목록→상세" 표현도 실제로는 달력 셀→상세라서 재봉인에서 함께 고쳤다.
- **알림과 예상급여는 아직 mock이다.** `notifications/page.tsx`가 `NOTIFICATIONS_MIXED`를, `pay/page.tsx`가 `PAY_WITH_ITEMS`를 그대로 넘긴다. 읽음 상태는 `useState`뿐이고 저장할 테이블이 없다. 반대로 서버 데이터를 쓰는 홈과 일정은 목록이 아니다.
- **TanStack Query가 없다.** `useQuery`·`QueryClient` 사용처가 0건이라 새로고침 수단은 `router.refresh()`가 유일하다. `CLAUDE.md`의 스택 목록에는 있지만 아직 설치 전이다.
- **`motion`의 크기는 진입점이 결정한다.** 2026-08-10에 esbuild로 react를 external 두고 실측했다 — `motion/mini` 3KB, `motion/react-mini` 3KB, `LazyMotion`+`domAnimation`+`m` 27KB, 전체 42KB(모두 gzip). mini 계열에는 드래그가 없어서 제스처를 얻는 최소 비용이 27KB다. 이 표가 ADR-0015의 근거다.
- **`overscroll-behavior` 규칙이 저장소에 한 줄도 없다.** Android Chrome의 기본 당겨서 새로고침이 우리 것과 겹친다.

## 기획 비목표와 부딪혀 되돌린 것

T44 기획은 "새 모션 토큰 신설. 필요해지면 P0-T43 범위로 되돌린다"를 비목표로 못 박았다. 설계에서 실제로 세 종류가 필요해졌다.

- `--duration-stagger` — 기존 `--duration-feedback`(150ms)을 쓰면 20행에서 3초가 걸린다. 실제 대역은 30~50ms다.
- `--spring-stiffness`, `--spring-damping` — FOUNDATIONS가 spring 상수의 정본을 `globals.css`로 정했는데 `motion`은 CSS 변수를 못 받고 숫자만 받는다. 토큰을 CSS에 두고 프로바이더가 `getComputedStyle`로 한 번 읽어 내려주면 정본이 하나로 유지된다.

기획이 지정한 경로대로 **P0-T43 RADIO를 revision 2로 재봉인**해 토큰 3종을 T43 범위에 넣었다. T43은 아직 개발 전이라 코드 영향이 없다. 새 SHA-256은 `9cc65ba2…`이며 T44와 같은 자리에서 승인받았다.

## 남는 위험

- **번들 여유가 5KB다.** 예상 395KB에 상한 400KB다. 구현 중 실측이 넘으면 더 좁은 feature 조합을 찾고, 그래도 넘으면 설계로 반환한다.
- **T43의 lint 규칙은 JS 애니메이션을 못 막는다.** Tailwind 클래스를 검사하는 규칙이라 `m.div`가 `width`를 애니메이션해도 통과한다. `m.*` 사용처가 네 곳뿐인 동안은 리뷰가 맡는다.
- **P4에서 서버가 붙을 때 호출부가 바뀐다.** 제스처와 호출부를 prop 경계로 갈라 그 교체가 UI를 건드리지 않게 했다.

## 미결 사항

- `--duration-stagger`와 spring 상수 2종의 구체값 — P0-T43 구현이 실기기에서 정한다.
- 당김·스와이프 임계값의 픽셀 수치 — 판정 함수의 인자로 두어 조정이 테스트를 깨지 않게 한다.
- 알림 서버 연동 시의 낙관적 갱신과 실패 복구 — P4 알림 task 소유.
- `m.*` 사용처가 늘 때 속성 제한의 기계적 강제 — 늘어나는 시점의 별도 제안.

### 조정자가 가정으로 명시하고 승인에 포함한 것

- **`.env.example` 복사만으로 dev 부팅이 성공한다.** 미소비 범주(Google OAuth·VAPID·QR 비밀·슈퍼 관리자 이메일)는 placeholder로 채우고, Supabase 로컬 값은 `supabase start`의 고정 공개 키를 쓴다. 전부 필수 선택의 개발 마찰을 이 가정이 흡수한다.
- **운영 환경 검증은 placeholder가 통과하지 않게 형식을 강화한다.** 전부 필수의 목적(운영 누락 방지)이 placeholder 통과로 무력화되지 않게 한다. 구체 방식은 설계 소유.

### 조정자가 판단해 기록한 것 (상위 문서·선례가 결정)

- **오프라인은 전용 화면이 아니라 배너다.** phase 문서(L4)의 "오프라인 기본 화면" 문구가 PATTERNS(L2)의 "상단 배너 고정 + 변경 행동 비활성화"와 충돌 — 상위 문서가 이기므로 phase 절을 배너 상태로 정합화했다.
- 화면 4종은 Next.js 예약 파일(`loading`·`error`·`global-error`·`not-found`)과 컴포넌트로 배치하고 실제 트리거 연결은 후속 task가 소유한다.
- 오류·접근 거절 화면은 P0-T37 오류 코드 정본(`ERROR_CODES`·`ERROR_CODE`)의 코드와 기본 문구를 소비한다. 문의용 식별자 표시 자리를 두되 생성은 P0-T37 미결(첫 서버 오류 경로)을 따른다.
- Supabase client factory는 얇은 browser·server 래퍼만. 쿠키·세션 어댑터는 P1-T01 소유.

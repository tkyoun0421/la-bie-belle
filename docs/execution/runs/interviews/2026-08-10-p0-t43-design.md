## 조사에서 바로잡힌 전제

- **모션 토큰은 이미 있었다.** `globals.css:54-56`의 `--duration-feedback`(150ms)·`--duration-value`(200ms)·`--duration-overlay`(250ms)가 FOUNDATIONS 타이밍 표와 정확히 대응한다. 이 task는 토큰을 만드는 게 아니라 easing을 더하고 실제로 쓰이게 하는 작업이다. 실사용처는 `chip.tsx` 한 곳뿐이었다.
- **기존 테스트가 값을 단언한다.** `src/app/__tests__/globals.test.ts:109-116`이 duration 3종을 정규식으로 확인하고, 128행이 reduced-motion 전역 규칙의 존재를 단언한다. 값은 유지하고 reduced-motion 단언만 새 방식에 맞게 갱신한다.
- **`<ViewTransition>`은 experimental 플래그 없이 쓸 수 있다.** 앱의 `react` 19.2.8에는 없지만 Next 16.3.0이 번들하는 compiled React에 있고, 빌드 시 치환된다. 타입은 `@types/react@19.2.18`의 `canary.d.ts`에 완전한 형태로 있어 `tsconfig.json` 참조 추가로 해결된다. Next의 `needsExperimentalReact`는 `blockingSSR`·`taint`·`transitionIndicator`·`gestureTransition` 넷에만 반응하며 ViewTransition과 무관하다.

## 남는 위험

- `tsconfig.json`에 canary 타입을 열면 ViewTransition 외의 React 실험 API도 타입상 통과한다. 기계 차단은 이 task 범위 밖이고 리뷰가 맡는다.
- Safari의 View Transitions 동작 차이는 맞추지 않는다. 미지원 환경에서 정상 렌더되는 것만 인수 조건이다.
- 새 lint 규칙이 `var(--)` 참조를 허용하지 않으면 기존 `chip.tsx`가 걸린다. 규칙 테스트에 통과 케이스로 넣는다.

## 미결 사항

- `--ease-spring`의 `cubic-bezier` 구체값은 구현 중 실기기에서 조정하되 FOUNDATIONS 대역 안에 둔다. 벗어나야 하면 설계로 반환한다.
- 물리 기반 spring과 `motion` 도입 승인은 P0-T44 설계 소유다.

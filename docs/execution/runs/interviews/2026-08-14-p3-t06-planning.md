- 작업 식별자: P3-T06 (확정, 경고, revision)
- 현재 단계: 기획 승인 종료 → 다음 설계(RADIO) 인터뷰

- 기획 승인: user, 2026-08-14 (요약본 승인, `index.jsonl` `product_approval` 기록)

## 확인된 사실 (사용자 답변·요약본 승인)

- **확정 트랜잭션이 CLOSED→PREPARING→CONFIRMED를 한 번에 통과한다.** PREPARING은 화면에 드러나지 않는 통과 상태이며 DB 전이 규칙은 그대로 둔다.
- **모집 중(OPEN) 확정은 마감을 함께 처리한다.** `모집도 함께 마감됩니다` 안내 후 한 번에 처리한다.
- **구조 오류 3종이 확정을 막는다.** 예식 0개, 예정 출퇴근 시각 미설정, 필요 인원 표 미복사. 배정 전체 0명은 차단이 아니라 미달 경고다.
- **담당자 없음은 경고다, 차단이 아니다.** PRD 167과 P3-T05 기획 문구("막는")의 충돌을 PRD 쪽으로 해소했다. 정식 배정 0명 + 교육생 1명 이상이면 필요 인원과 무관하게(필요 0이어도) 경고한다. P3-T05 phase 문구는 정정했다.
- **확정은 항상 확인 다이얼로그 하나를 거친다.** 미달 목록·담당자 없음·마감 안내를 한 다이얼로그에 담는다.
- **경고는 확정 감사 로그에 저장하고 화면은 재계산한다.** 전용 경고 테이블 없음.
- **시급 스냅샷은 정식 배정과 교육생 모두.** 확정 시점의 개인 시급. 급여 계산 방식은 P6 몫. ADR-0003·PRD 11절을 교육생 포함으로 개정했다.
- **확정 후 변경 4종·revision 증가·확정 후 취소(CONFIRMED→CANCELLED)는 P3-T09로 분리.** 그때까지 확정 스케줄은 수정·취소 불가(개발 단계 공백으로 사용자 인지). 순서는 P3-T07 다음.
- **교육 칩 숨김(P3-T05 미결 해소).** 다른 포지션 정식 배정자에게 교육생 선택지를 표시하지 않는다. 구현 편입은 P3-T09 기획에서 정한다.
- **P3-T10 신설.** work_date 밴드 미적용 e2e spec 2개(recruitment-manage·recruitment-open)를 밴드로 옮기는 테스트 전용 task.

## 해석·가정 (요약본에 포함해 승인됨)

- 이미 확정된 스케줄의 확정 재시도는 "이미 확정됨" 거부(멱등).
- 미달 판정은 정식 배정만 센다(INV-STAFF-02·03).
- 확정 권한은 관리자 전용(기존 준비 화면 권한과 동일) — 가정, 설계에서 재확인.

## 코드 대조에서 정해진 것

- `schedules.revision`(default 1)·상태 전이 트리거 존재. PREPARING 진입 코드는 프로덕션에 없음.
- 시급 스냅샷 컬럼 없음 — `assignments`·`assignment_trainees` 모두. `profiles.hourly_wage`만 존재.
- 수동 마감·재오픈은 P2 관리 시트(`useRecruitmentManage`)에 이미 있음.
- 모든 수정 RPC가 CONFIRMED·CANCELLED 거부 — 확정 후 변경 허용은 이 거부의 해제가 필요, P3-T09 몫.

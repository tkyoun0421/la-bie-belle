# P0-T47 기획 인터뷰 handoff

- 작업 식별자: P0-T47 (디자인 단계와 `/publish-ui` 도입), P0-T48 (전역 디자인 틀 재제안과 기존 화면 퍼블리싱)
- 현재 단계: 기획 승인 종료 → 다음 설계(RADIO) 인터뷰
- 기준 시각: 2026-08-16
- 기획 승인: user, 2026-08-16 (요약본 승인, `index.jsonl` `product_approval` 기록)

## 출발점

사용자 요청은 "시안을 함께 보며 UI만 구현하고 preview를 관리하는 publisher
에이전트"였다. 인터뷰 도중 성격이 바뀌었다 — publisher는 남이 준 시안을
옮기는 손이 아니라 **시안을 만들어 제안하는 디자인 절차의 주체**다.

## 확인된 사실 (사용자 답변·요약본 승인)

### 파이프라인에서의 자리

- **디자인은 설계 단계의 앞부분이다.** 6번째 단계를 신설하지 않는다.
  확정한 시안이 RADIO Architecture에 들어가고 기존 RADIO 승인 하나로 같이
  봉인된다.
- 이 선택으로 **승인 게이트 2개를 유지한다.** 3번째 게이트를 만들었다면
  CLAUDE.md 비협상 조항, `WORKFLOW.md:47`, `approval_contract`
  (`dual-approval-v3`), `gate:index` 하네스를 모두 고쳐야 했다.
- 디자인을 거칠지는 **설계 인터뷰에서 변경 경로 초안에 `views/**/ui`가
  들어오는 순간** 정해진다. 사용자 답변은 "views/ 건드리면 자동"이었으나,
  RADIO는 아직 봉인 전이라 코드펜스를 기준으로 삼을 수 없다. 조정 세션이
  판정 시점을 인터뷰 중으로 보정했고 사용자가 승인했다.

### 도구 형태

- **메인 세션 스킬 `/publish-ui`.** 서브 에이전트가 아니다. "여백 더 좁혀"
  같은 짧은 왕복이 본체인데 서브 에이전트는 도는 중에 대화를 받지 못한다.
- 이름은 `/publisher`·`/design`을 제치고 `/publish-ui`로 정했다.

### 시안

- **내가 HTML로 여러 안을 만들고 Artifact로 발행한다.** Figma 연동 없음.
  claude.ai 링크라 폰에서도 본다.
- 같은 HTML을 `docs/execution/runs/<task-id>/design/`에 남긴다.
  **탈락안까지 전부**, 고른 이유와 함께. 파일이 정본, Artifact는 사본.
- **대표 상태 하나만 그린다.** 빈·에러·로딩은 확정 후 preview에서 채운다.
- 제안 방식은 2단계다. 지금은 전역 틀이 미정이라 **템플릿 여러 안을 먼저**
  제안하고, 틀이 정해지면 그 안에서 화면별 세부만 정한다.

### preview

- **목 데이터 전용이라는 것을 규칙으로 못 박는다.** 성공·실패·에러를 눈으로
  확인하는 자리이지 실데이터·서버와 엮는 자리가 아니다. 사용자가 명시적으로
  우려한 지점이다.

### 만질 수 있는 경로

허용: `views/**/ui/**`, `views/**/ui/*.mock.ts`, `shared/ui/**`,
`globals.css`와 디자인 문서, `src/app/preview/**`, `views/preview/**`.

금지: `views/**/model/**`, `features/**`, `entities/**`, 서버 코드,
preview 밖 `src/app/**`. 필요해지면 멈추고 묻는다.

- **새 토큰 추가는 자유, 이미 쓰이는 토큰의 값 변경은 승인 대상.** 그 토큰을
  쓰는 화면 목록과 전후 비교를 같이 낸다.

### 개발 단계 분업

- **publisher 먼저, `implementer` 나중.** publisher가 목 데이터를 받는 UI와
  preview를 세우면 implementer가 서버·상태·데이터를 그 프롭에 꽂는다.
  모양이 먼저 고정되니 나중에 흔들리지 않는다.
- `in_progress` 최대 1 규칙은 그대로다. 순차로 돈다.
- **컴포넌트 테스트는 `unit-test-writer`가 확장해 맡는다.** writer가 RED,
  publisher가 GREEN — 기존 TDD 형식 그대로.

### 기존 화면 재디자인

- **리팩토링 task로 올린다.** `/publish-ui`로 task 없이 코드를 고치지 않는다.

### 범위 분할

- **P0-T47은 규칙만 세운다.** 실제 디자인은 P0-T48이다.
- **P0-T48은 디자인 확정과 UI 구현을 한 흐름에 둔다** — 전역 틀 재제안,
  DESIGN 문서 고정, 기존 화면 퍼블리싱까지.
- **P0-T48이 끝난 뒤 P4-T03부터 기능 개발 재개.** 앞으로 만들 화면은 P0-T48에
  들어오지 않고 각 기능 task 안에서 publisher → implementer 순차로 간다.

## 근거 조사 (기획 인터뷰 중 코드·문서 확인, HEAD 80b61df 기준)

- `config/fsd.json`의 `ui` 세그먼트는 `unitTest: "exempt"`,
  `verifiedBy: ["component", "e2e"]`다. tdd-guard 훅이 화면 파일 편집을 막지
  않는다. `model`은 `unitTest: "required"`라 `/publish-ui` 범위 밖에 두는 것이
  구조와 맞는다.
- `verifiedBy: ["component"]`가 요구하는 컴포넌트 테스트에 담당자가 없다.
  `.claude/agents/*.md` 어디에도 "component"라는 말이 없다.
  `src/views/home/ui/__tests__`는 이미 존재한다.
- `src/app/preview/page.dev.tsx`는 `views/*/ui/*.mock.ts`와
  `entities/*/model/*.mock.ts`를 조합해 7개 화면·29개 시나리오를 등록한다.
  이미 목 데이터 전용 구조다.
- `docs/execution/phases/index.schema.json`의 `test_mode`에 `docs_only`가
  있어 P0-T47에 쓴다. `gate:index`(`harness/lib/index-gate.ts`)는 ID 번호
  연속성을 보지 않고 `depends_on` 대상의 존재만 본다.
- `index.jsonl`의 P0 최대 ID는 `P0-T45`지만, 작업 트리의 미커밋
  `00-foundation.md`에 다른 세션이 쓴 `### P0-T46. 에이전트 팀 확장` 절이
  있다. ID 재사용 금지 규칙에 따라 P0-T47·P0-T48로 밀었다. P0-T46의 index
  등록은 그 세션 몫이다.

## 미결 사항 (설계 단계 소유)

- **Artifact는 외부 CSS를 불러올 수 없다.** `globals.css`의 토큰을 시안 HTML
  안에 넣어야 하는데, 그러면 원본과 어긋날 위험이 생긴다. 생성 시점 자동
  추출 같은 해법을 RADIO에서 정한다.
- WORKFLOW에 디자인을 어떤 표기로 넣을지 — 설계 행 안의 하위 항목인지 별도
  행인지.
- `/publish-ui` 스킬 문서의 실제 절차와 산출물 형식.
- 시안 HTML의 커밋 시점. `WORKFLOW.md:53`이 인터뷰 산출물을 task 경계까지
  미루라 하므로 시안도 같은 제약을 받는다. 구체적 처리는 설계에서.

## 작업 트리 상태

- `index.jsonl`에 P0-T47(`design_pending`)·P0-T48(`proposed`) 추가,
  `00-foundation.md`에 두 절 추가. `gate:index` 통과.
- 둘 다 커밋하지 않았다. `WORKFLOW.md:53`의 인터뷰 산출물 규칙대로 task
  경계까지 작업 트리에 둔다. 같은 작업 트리에 다른 세션의 미커밋 변경이
  다수 있다.

## 확인된 사실 (사용자 답변·요약본 승인)

- **경고 사후 조회는 준비 화면의 실시간 재계산으로 충족한다.** 별도 조회 화면·전용
  저장소는 만들지 않는다. 확정 응답의 경고 목록을 클라이언트가 받아서 버리는 현재
  동작(`confirm-schedule.ts`가 `warnings: unknown`으로 받고 미사용)은 결함이 아니라
  확정 동작으로 종결한다 — 확정 다이얼로그가 확정 전에 같은 경고를 이미 보여주고,
  확정 뒤에는 준비 화면 재계산이 현재 상태를 답한다. backlog 305 종결.
- **담당자 없음 경고는 필요 인원 표에서 지워진 포지션도 포함한다.** 기존 담당자 없음
  규칙(정식 배정 0명 + 교육생 1명 이상)의 계산 범위를 표 밖 포지션까지 넓히는
  결정이다 — 표에서 지워진 포지션이라도 정식 배정 없이 교육생만 남으면 경고한다.
  DB의 `confirm_schedule` 경고 계산과 화면의 `computeConfirmationWarnings` 양쪽에
  같은 규칙을 세운다. backlog 306.
- **비활성 포지션의 기존 배정은 축소만 허용한다.** 배정 제거·전원 해제는 통과시키고
  새 사람 추가만 거부한다. `replace_position_assignments`가 profile_ids를 보기 전에
  무조건 거부하는 현재 검사를 추가 인원 검사로 완화한다. backlog 277.

## 근거 조사 (기획 인터뷰 전 코드 확인)

- `src/features/confirmation/api/confirm-schedule.ts:50` — RPC 응답을
  `{revision, warnings: unknown}`으로 타입만 받고 warnings는 어디서도 소비하지 않는다.
- `src/views/admin-schedule/ui/AdminSchedulePrepView.tsx:147` —
  `computeConfirmationWarnings({requirementRows, assignedCounts, traineeCounts})`가
  준비 화면에서 실시간 재계산으로 경고를 이미 표시한다. requirementRows 기반이라
  표에서 지워진 포지션은 계산에 들어가지 않는다(결정 ②의 화면 쪽 대상).
- `supabase/migrations/20260814000000_trainee_conflict_guard.sql:64` —
  `replace_position_assignments`가 비활성 포지션이면 profile_ids를 검사하기 전에
  `'비활성 포지션에는 배정할 수 없습니다'`(errcode 22023)로 무조건 거부한다.
- 확정 당시 경고 스냅샷은 `scheduling_audit_logs`의 확정 감사 행에 이미 저장된다
  (P3-T06 결정 "확정 시점 경고는 확정 감사 기록에 저장하고 화면은 재계산한다"의 연장).

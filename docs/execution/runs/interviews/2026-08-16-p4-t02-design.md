## 정찰 결과 (RADIO 전제로 봉인)

- Service Worker 등록: Next.js 16 가이드
  (`node_modules/next/dist/docs/01-app/02-guides/progressive-web-apps.md`)의
  번들 방식 — `navigator.serviceWorker.register(new URL(<워커 파일>,
  import.meta.url), { scope: "/", updateViaCache: "none" })`. `next.config`
  headers 변경 불필요(필요해지면 정지 조건).
- SW 엔트리 위치: `src/features/push/lib/push-service-worker.ts`. app 계층에
  두면 appLayer unitTest required(exemptFiles는 page 계열뿐)에 걸리는 것은
  같고 features 훅이 app 파일을 상향 참조하게 되므로, 같은 슬라이스 lib에
  둔다. 배선 파일도 `self` 스텁 단위 테스트 대상.
- env·manifest: P0에 준비 완료 — `.env.example`의 VAPID 3종,
  `src/shared/model/env.ts`의 public 키 필수 검증, `src/app/manifest.ts`.
  이 task의 env 변경 없음.
- 쓰기 RPC: `save_push_subscription`(endpoint upsert — disabled 해제·소유자
  재지정) + `remove_push_subscription`(본인 행 disabled_at, 삭제 없음).
  테이블·RLS 무수정.
- 기존 단언 대조(봉인 체크리스트): `tests/e2e/tab-navigation.spec.ts`는
  더보기 목록 단언 없음 — 무수정. `src/views/more/ui/__tests__/
  MoreView.test.tsx`가 링크 개수 고정 단언(`toHaveLength(2)`) — 2→3 갱신을
  허용 경로·용도 한정에 포함.
- e2e 밴드: notifications가 528~559 사용 중 — 사전 안내 시나리오는 561~592.
- `shared/ui`에 토글 없음 — button·bottom-sheet 재사용, 신설 없음(신설
  필요해지면 정지 조건).

## 설계 판단 (RADIO가 정본)

- 구독 상태 정본은 브라우저 `pushManager`, DB는 발송 대상 목록 — 어긋나면
  화면은 꺼짐 표시, 다음 켜기의 upsert로 수렴.
- `pushManager.subscribe` 실호출은 자동 테스트에서 배제(CI 푸시 서비스
  왕복 불안정) — 훅 단위는 모킹, e2e는 시트·안내·화면 분기까지, 실수신은
  체크리스트 문서 몫.
- 푸시 페이로드 계약 `{ title, body, target }`은 P4-T01 notifications 행과
  동일 모양 — T03·T08이 재사용.

## 확정된 사실 (사용자 답변·요약본 승인)

### 시안 만들기

- **시안 HTML은 Tailwind를 실제로 돌려 CSS를 인라인한다.** 그 파일이 쓴 클래스만 뽑으므로 시안 한 장이 수백 KB로 붓지 않는다. `@tailwindcss/cli`는 없고 `@tailwindcss/postcss`만 있어 postcss를 코드에서 호출한다. 새 의존성은 넣지 않는다.
- **글꼴은 base64로 심는다.** `WantedSansVariable.woff2` 1.2MB가 base64로 약 1.6MB이고 Artifact 상한 16MB 안이다. 서브셋은 `fonttools` 같은 새 의존성이 필요해 택하지 않았다. preview는 `src/app/layout.tsx:23`이 이미 글꼴을 걸어 주므로 할 일이 없다.
- **3안은 모바일 프레임 가로 배치.** 각 프레임 상단에 안 이름과 한 줄 설명.
- **시안 파일은 덮어쓰고 라운드 기록은 `NOTES.md`에 누적한다.** 무엇이 왜 바뀌었는지가 남고 `runs/`는 안 불어난다.
- **커밋은 task 경계에서 인터뷰 산출물과 함께.** `WORKFLOW.md:53` 규칙 그대로다.

### 절차와 주체

- **WORKFLOW에는 2단계 「설계」 안의 하위 절로 넣는다.** 단계 표는 5행 그대로라 승인 게이트가 둘이라는 것이 표에서 바로 읽힌다.
- **개발 단계 구현은 `publisher` 서브 에이전트가 맡는다.** 설계 단계 시안은 메인 세션 스킬 `/publish-ui`가 하고, 구현은 에이전트로 가른다.
- **규칙 정본은 스킬이다.** 에이전트 문서는 규칙을 복제하지 않고 스킬을 가리킨다.
- **`publisher`가 UI 커밋을 따로 한다.** 디스패치 순서가 바뀐다 — `unit-test-writer`(컴포넌트 RED) → `publisher`(GREEN·UI 커밋) → 남은 writer → `implementer`. 내역에서 UI와 배선이 갈리고 되돌리기 쉬워진다.

### 토큰

- **정본은 `docs/product/design/FOUNDATIONS.md`다.** `globals.css`가 문서를 따른다. 불일치는 코드를 문서에 맞춰 고친다.
- **`gate:tokens`가 다섯 표 전부를 대조한다.** 원시 팔레트·의미 토큰·타이포·간격·형태.
- **간격 토큰을 신설한다.** 지금 `globals.css`에 간격 변수가 없고 Tailwind 기본값 `--spacing: 0.25rem`이 동적 계산할 뿐이라 대조 대상이 없었다. 문서 아홉 값을 `--spacing-1`~`--spacing-12`로 명시한다. Tailwind의 spacing 네임스페이스라 기존 `p-4`·`gap-6` 364군데가 그대로 그 토큰을 읽고 값이 같아 렌더가 안 바뀐다.
- **문서 밖 간격값은 `project/spacing-scale` 린트로 막는다.** 토큰만으로는 안 막힌다 — 명시 안 한 숫자는 동적 계산이 계속 받아준다. 대상은 `p`·`m`·`gap`·`space` 계열이고 크기 계열(`h`·`w`·`size`)은 뺀다. `h-11`(44px 터치 타깃)은 간격 리듬이 아니다.
- **면제 스냅숏 대신 목적 토큰으로 정당화한다.** 사용자 판단 — 면제는 부채고 이름은 규칙이다. `--spacing-nav-safe`(96px), `--spacing-nav-action-safe`(112px) 둘만 만든다. 근거 없는 값에 이름을 주면 규칙이 거짓말이 된다.
- **`OnboardingView`의 `pb-36`은 `p-6`으로 내린다.** 이 task에서 렌더가 바뀌는 유일한 지점이다.

## 근거 조사 (설계 인터뷰 중 코드 확인, HEAD 80b61df 기준)

- `harness/lib/gate-suite.ts`는 `REPOSITORY_GATES`(gate:all용)와 `COMMIT_GATES`(pre-commit용) **두 배열을 따로** 둔다. 한쪽만 더하면 `pnpm verify`는 잡는데 커밋은 통과한다. `.githooks/pre-commit`은 `harness/gates/pre-commit.ts`를 부르므로 훅 파일은 안 건드려도 된다.
- `check_ids`는 어느 게이트도 읽지 않는다. RADIO·verification의 문서 계약이다.
- `src/app/__tests__/globals.test.ts`의 단언은 전부 `toMatch` 패턴이라 토큰 추가로 안 깨진다. `--spacing` 관련 단언은 없다.
- 하단 여백 값의 실제 근거: 탭 바는 `AppShellTabBar` `min-h-16`(64px) + safe-area, `ApplicationChangeBar`는 `bottom-[calc(4.75rem+env(safe-area-inset-bottom,0px))]`(76px). `pb-24`(96px)는 탭 바 + 여유 32px, `pb-28`(112px)는 그 위 행동 바까지 피한 값이다.
- `OnboardingView`는 `src/app/onboarding/page.tsx`라 `(tabs)` 밖이다. 탭 바도 고정 버튼도 없는데 `pb-36`(144px)을 비워 뒀다. 같은 성격의 `LoginView`·`PendingView`는 `p-6`뿐이다.
- `pb-24`를 쓰는 화면 중 `admin/*`·`my-profile`·`catalog`는 `(tabs)` 밖이다 — 탭 바가 안 붙는데 96px를 비운다. 관행 복사다.
- `p`·`m`·`gap` 계열에서 문서 밖 값은 15군데이고 전부 하단 여백(`pb-24` 13, `pb-28` 1, `pb-36` 1)이다. 나머지 문서 밖 숫자는 `h-11`·`size-11`·`h-13` 같은 크기 값이라 규칙 대상이 아니다.
- `tools/eslint-plugin-project/rules/`에 커스텀 규칙이 모여 있고 `eslint.config.mjs`가 `project/*`로 켠다. `project/design-token-colors`·`project/motion-tokens`가 선례다.

## 확인된 사실 (사용자 답변·요약본 승인)

- **시급 스냅샷은 컬럼 추가.** `assignments`·`assignment_trainees`에 `hourly_wage_snapshot integer`
  (null 허용, 확정 시 채움). 새 스냅샷 테이블을 만들지 않는다. `alter table add column` 전례는
  이미 있었다(schedules.planned_checkin, profiles.hourly_wage) — P3-T05 설계의 "전례 없음"은
  당시 조사 누락이었다.
- **오류 코드는 사유별 분리.** LB026 예식 없음 · LB027 예정 시각 미설정 · LB028 필요 인원 미복사 ·
  LB029 상태 오류 · LB030 시급 미설정.
- **경고 프리뷰는 클라이언트 model 계산.** 서버 프리뷰 RPC를 만들지 않는다. 정본은 DB 확정 함수가
  확정 시점에 계산해 감사에 남기는 목록이다.
- **시급 미설정 근무자(배정·교육생)는 구조 오류로 차단(LB030).** 설계 인터뷰에서 발견한 기획 공백의
  보강이며 PRD·phase·DECISIONS에 반영했다. null 스냅샷을 만들지 않는다.
- **확정은 자격을 재검사하지 않는다.** PRD 「자격은 배정 순간에만」 정합. ADMIN-FLOWS 확정 절의
  "자격 오류를 해결한다" 잔재 단계를 삭제했다.

## 조사에서 정해진 것 (선택지가 아니었던 것)

- 전이 트리거는 UPDATE마다 단계 검증하므로 확정 함수의 순차 update(OPEN→CLOSED→PREPARING→CONFIRMED)가
  규칙을 그대로 통과한다 — 트리거 무수정. 단, 트랜잭션 내 다단 update는 미실증 가정이라 pgTAP 첫
  RED→GREEN 쌍을 여기에 배정한다(정지 조건 연동).
- 감사는 기존 `scheduling_audit_logs`(detail jsonb) 재사용. OPEN 확정 시 `schedule_closed`(detail
  trigger: confirmation)와 `schedule_confirmed` 두 이벤트.
- 구조 검증 대상 실명: `ceremonies` 0건, `schedules.planned_checkin is null`(checkout과 쌍 제약),
  `position_requirements` 0건.
- 기존 pgTAP에 컬럼 고정 단언(columns_are) 없음 — 컬럼 추가가 기존 단언을 깨지 않는다. 기존
  CONFIRMED 픽스처는 직접 insert라 전이 트리거와 무관.
- `search_path = public, pg_temp` 고정 — P3-T03 backlog의 pg_temp 미고정 지적을 반복하지 않는다.

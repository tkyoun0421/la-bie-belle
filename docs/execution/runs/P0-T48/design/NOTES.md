# P0-T48 디자인 라운드 기록

한 라운드에 화면 하나를 정한다. 앞 라운드에서 정한 규칙은 다음 화면에 그대로 적용하고, 어떤 화면에서 다르게 가기로 하면 **그 자리에 근거를 남긴다.** 시안 파일(`proposal.html`)은 라운드마다 덮어쓴다. 되돌아볼 근거는 파일 더미가 아니라 이 기록이 갖는다.

## 확정된 규칙

여기 있는 것은 다음 화면에 자동으로 적용된다.

### 시각 언어 (라운드 1, 2026-08-17)

- 지면 `#f1f3f6`, 카드 흰색, 그림자 없음. 구획은 배경색 차이로만 나눈다.
  라운드 13 예외 — **한 카드 안에서 행을 나누는 hairline `#e5e8eb`는 허용한다.** 행 어법(아래
  「행」 절)이 선 없이는 성립하지 않아서다. 카드 사이에는 여전히 선을 쓰지 않는다.
- 카드 모서리 `radius-xl` 20px. 화면 좌우 여백 16px, 카드 사이 12px, 카드 안쪽 16px.
- 화면에서 가장 강한 파랑(`#0052ff`)은 지금 눌러야 할 버튼 하나다.
- 상태는 채움이 진할수록 확정에 가깝다. 모집 중은 색 없음, 신청함 `#f2f6fd`, 확정 `#e4edfd` + `#0c3f9c` 글자.
- 달력 셀에는 숫자만 둔다. 배지·점·범례를 넣지 않는다. 오늘은 숫자 아래 밑줄 2px.

### 타이포 위계 (라운드 2, 2026-08-17)

- 화면 제목 22/30, 금액 26/34, 카드 제목 18/26, 값 16/24, 메타 13/18, 버튼 14/20.
- 스케일 8단계는 건드리지 않는다. 바꾼 것은 어느 자리에 어느 단계를 쓰는지뿐이다.
- 결과로 `display` 32/40을 쓰는 자리가 없어졌다. 이 단계를 표에서 뺄지는 미결.
- 카운트다운은 금액과 같은 26/34에 `tabular-nums`를 쓴다(라운드 8). 새 단계를 만들지 않았다.
- **라운드 19(2026-08-17)가 무게를 감량했다** — 화면 제목 600 · 카운트다운 600 · 행 값 500 ·
  블록 이름표 500 · D 배지 600. 700은 화면에서 사라졌다. 사용자: "Bold를 많이 쓰는 경향 주의".

### 아이콘 (라운드 3, 라운드 5에서 개정)

- 기본은 Lucide 라인이다. 기본 24px, 보조 20px, 터치 영역 44×44px.
- **하단 탭의 선택 상태만 예외로 채운다.** 채움 색은 `gray-800`, 선택 안 된 탭은 `gray-700` 선이다.
  라운드 3은 "채운 아이콘은 쓰지 않는다, 선택은 굵기로"였는데 라운드 5에서 뒤집었다.
  근거: 선택 탭을 action 색에서 떼어내면 화면의 파랑이 눌러야 할 버튼 하나에만 남아
  라운드 1의 규칙이 오히려 선명해진다. 굵기 2 → 2.25 차이는 24px에서 거의 읽히지 않기도 했다.
- 대가가 둘 있다. Lucide에 채운 세트가 없어 **채움은 실루엣에서 딴 파생 자산**이 되고,
  `전체`의 `Menu`는 선 세 개라 채울 도형이 없어 **`LayoutGrid`로 교체**했다(선 상태는 Lucide 정품).

### 앱 셸 (라운드 4·5, 2026-08-17)

- 하단 탭은 `홈 · 일정 · 급여 · 전체` 넷이다. 알림은 헤더 오른쪽 종이고 안 읽음은 점으로 알린다.
- 예상 급여를 `전체` 서랍에서 꺼내 탭으로 올렸다. 근무자가 이 앱을 쓰는 이유인데 두 번 눌러야
  나왔다(`AppShellTabBar.tsx:15-17`이 `/pay`를 `more` 탭 활성으로 묶고 있었다).
- 헤더는 모든 화면이 같은 모양이다 — 왼쪽 화면 제목, 오른쪽 종.
- **헤더는 지면 위에 떠 있고 뒤가 비친다**(라운드 25). 스크롤을 내리면 카드가 헤더 뒤로
  지나가며 흐릿하게 보인다 — `backdrop-filter: blur(9px)` + 지면색 **50%** 배경(2차에서 14px ·
  68%를 옅게 풀었다, 사용자). 상태 표시줄 자리(24)와 헤더(56)를 **한 레이어 80으로 묶어**
  실제 폰처럼 콘텐츠가 시계 자리 뒤까지 지나간다. 지면과 같은 색을 쓰므로 맨 위에서는 경계가
  보이지 않는다 — 선을 긋지 않는다.
- **선택 표시는 셋뿐이다** — 선에서 채움으로, 색 `gray-700` → `gray-800`(#3a3f4a), 그리고 누르는 순간의 눌림.
  선택 탭 뒤에 회색 블록을 깔아봤다가 뺐다. 선택돼 있는 내내 남아 채움과 색이 이미 하는 말을
  한 번 더 했다.
- **눌림 모션** — 두 번 눌린다. 크게 한 번(`scale(1.22, 0.78)`) 눌려 양옆이 퍼졌다 되튀어
  (`0.95, 1.06`) 돌아오고, 반동으로 한 번 더 작게(`1.1, 0.91`) 눌린 뒤 제자리. 420ms,
  기준점은 아이콘 바닥, `transform`만 움직인다.
- 아이콘·글씨는 탭 칸 안에서 가운데 정렬이고 간격은 3px다. 라벨은 `<span>`으로 감싼다 —
  맨 텍스트 노드로 두면 위치 지정된 형제에게 덮인다.

### 금액 가림 (라운드 3·5, 라운드 18에서 개정)

- **내 근무가 있는 날에는 금액이 자동으로 가려진다.** 근무 없는 날은 보인 채로 시작한다.
  라운드 3의 「기본이 가림 + 눈 아이콘」을 라운드 18이 뒤집었다(2026-08-17 사용자 승인) —
  가리는 이유가 「근무 중 동료 옆 노출」이라, 기준도 토·일(첫 지시)이 아니라 근무일로 갔다.
- **눈 아이콘은 없다. 금액 자체를 누르면 화면 전체 금액이 열린다** — 「스위치는 앱 전체 하나」는
  유지된다(홈과 예상 급여 화면이 같은 상태를 본다). **화면을 벗어나면 도로 가려진다.**
- 가려진 동안 실제 값을 렌더하지 않는다. 고정 폭 더미를 **blur 7px**로 깔고 `aria-hidden`을 준다.
  블러만 걸면 글자 폭이 자릿수를 드러내고 화면 낭독기가 값을 그대로 읽는다.
  라운드 22에서 숨김 블러를 7 → 5 → 3.5 → 2.5로 세 번 줄였다가 **오해로 판명되어 7px 원복** —
  사용자의 "블러 약하게"는 숨김이 아니라 **리빌 블러**를 가리킨 것이었다(2026-08-17 정정).
- **가려진 동안에는 애니메이션이 없다**(라운드 22) — 눌림 스케일도 없다.
- **리빌 모션** — 손으로 열면 **블러는 즉시 풀리고**, 옅은 회백(#b7bec9) 빛이 좁은 띠로 숫자를
  왼쪽에서 오른쪽으로 은은하게 훑는다(1.5초, `background-clip: text` 그라디언트 스윕).
  **손으로 열 때만** 나온다 — 화면 복귀·상태 전환으로 열릴 땐 없다. 조정 이력: 파랑 0.7초 →
  흰색 1.1초 → 1.5초 → 블러 페이드 추가(오해) → **즉시 풀림 + 빛 강도 낮춤**(전부 2026-08-17
  사용자). **빛이 도는 중에 다시 가려지면 훑기는 즉시 사라진다**(라운드 23) — 가림 적용이
  `revealing`을 걷는다.
- 「화면 설정」은 **「근무일 자동 가림」 켜고 끄기**를 소유한다.
- 최종 저장 위치는 **계정**이다. 다만 그건 `profiles` 컬럼·RLS·서버 왕복이 붙어 이 task의
  「서버·데이터 변경 안 함」 비목표 밖이라, P0-T48은 화면과 스위치를 기기 저장으로 붙이고
  계정 저장은 별도 task가 저장 계층만 갈아끼운다. UI는 그대로 살아남는다. (라운드 5 결정 유지)

### 홈의 구조 (라운드 6, 라운드 12~16에서 개정)

- 홈은 **위에서 아래로 블록 다섯**이다 — `알림 한 장` · `오늘 출퇴근` · `이번 주` ·
  `다가오는 근무` · `급여`. 블록 자리는 항상 같고 안의 내용만 상태에 따라 바뀐다.
  라운드 6은 넷(`알림 · 오늘 · 이번 달 일정 · 급여`)이었는데, 라운드 14~16에서 콘텐츠를
  늘리면서 `이번 주`가 들어오고 `이번 달 일정`이 `다가오는 근무`로 바뀌었다.
- **카드는 주제, 행은 항목이다**(라운드 13, 토스 홈 참조). 카드 하나가 항목 하나였던
  라운드 6~11의 구조를 뒤집었다. 좌우 병치 카드는 **출근 카드 하나에만** 남는다 — 홈에서 큰
  숫자를 세는 자리가 하나면 그 자리가 곧 「지금 할 일」이라는 뜻이 된다.
- **우선순위 하나만 노출하는 방식을 버렸다.** `home-priority.ts`의
  `attendance → deadline-application → confirmation-change → next-shift → empty`는 넷이 동시에
  살아 있는 날 셋을 숨긴다. 마감을 놓치는 대가가 초점을 지키는 이득보다 크다. (라운드 6, 유지)
- **홈은 스크롤한다.** 라운드 6의 「홈은 스크롤하지 않는다」는 라운드 16에서 폐기했다(사용자
  승인) — 휑한 홈보다 콘텐츠를 늘리는 쪽을 택했다. 최상단을 넘어 당기면 새로고침은 그대로
  남는다(기존 `RouterPullToRefresh`).
- 데이터가 없는 블록은 사라지지 않고 **없다고 말한다.** 알림 블록만 예외로 통째로 접히고
  아래 블록이 올라와 그 자리를 먹는다. (유지)
- 블록 이름표는 지면 위 메타 13/18 600이다. 알림 블록에는 이름표를 두지 않는다. (유지)

### 알림 블록 (라운드 6~8)

- **한 번에 카드 한 장만** 보인다. 남은 개수를 세지 않고 뒤에 겹친 카드도 보이지 않는다.
- **오른쪽 `X`를 눌러 끈다. 스와이프가 아니다.** 위로 당겨 넘기는 안을 먼저 그렸다가 뒤집었다 —
  당김 제스처는 최상단 새로고침과 방향이 겹치고, 무엇보다 사용자가 원한 건 명시적인 버튼이었다.
- 끄면 **그날 하루는 다시 뜨지 않는다.** 지속은 기기 저장이고, 금액 가림 설정과 같은 계층이다.
- 다음 알림은 **애니메이션으로 들어온다.** 누름 `scale 0.88` 120ms → 카드가 8px 올라가며 사라짐
  160ms → 다음 카드가 14px 아래에서 올라옴 280ms. 교체 동안 **블록 높이는 그대로** 있어서 아래
  세 블록이 흔들리지 않는다.
- 마지막 장을 끄면 블록이 접히고(260ms) 아래 블록이 같은 시간에 올라온다.
- **무엇이 이 블록에 오나** — 한 번 읽고 끝나는 사건만이다.

  | 홈에 뜨는 것 | 자리 | 왜 |
  | --- | --- | --- |
  | 스케줄 확정 · 포지션 확인 | 알림 | 한 번 확인하면 끝난다 |
  | 공석 · 새 모집 · 신청 가능 | 알림 | 지나가면 없어지는 기회다 |
  | 확정 후 배정 변경 | 알림 | 한 번 확인하면 끝난다 |
  | 변경 요청 승인·미반영 | 알림 | 결과 통보라 읽으면 끝난다 |
  | 출근·퇴근 인증 | 오늘 | 읽는 게 아니라 해야 하는 행동이다. 끌 수 없다 |
  | 신청 마감 임박 | 일정 | 마감 전까지 계속 유효한 상태다. 꺼서 없앨 것이 아니다 |
  | 다음 근무 | 일정 | 사건이 아니라 이번 달 스케줄의 상태다 |

- 카드 모양 — 왼쪽에 그림 자산 28px, 가운데 값 16/24 + 메타 13/18(누르면 해당 화면으로),
  오른쪽에 끄기. **끄기 아이콘은 17px에 선 1.8**이고 누르는 영역은 44×44를 지킨다.
  보이는 것만 작아진 것이며, 영역을 줄이면 본문을 누르려다 알림을 끄게 된다. 카드 높이 70px.

### 그림 자산 (라운드 7, 2026-08-17)

- 알림 왼쪽 그림은 **아이콘이 아니라 그림 자산**이다. 색이 토큰이 아니라 자산에 박힌 고정값이라
  `gate:tokens` 검사 대상 밖이고, 라운드 1의 「그림자 없음」도 자산 안의 명암에는 적용되지 않는다.
  대신 개수로 통제한다 — **용도 하나에 그림 하나.** 알림 다섯(라운드 7)에 더해 급여 행 앵커
  셋이 있다(라운드 23 낱개 검수 후 확정): **초록 지폐 + ₩**(지난주 — `green` 그라디언트 재사용,
  애플 `💵` 짜임) · **호박·파랑·초록 막대 셋**(월 합계 — 전부 기존 그라디언트, 애플 `📊` 짜임) ·
  **보라 오름 꺾은선 + 화살촉**(누적 — 선 굵기는 `🔄`와 같은 4.2, 종이 없이 선 자체로 선다).
  보라(#b18cff→#6a3bd8)는 라운드 23이 추가한 고정색이다 — 애플 `📈`의 빨간 선은 「빨강 금지」에
  걸린다. 라운드 13~16의 동전 더미(통화 기호가 ¥로 읽혔다)·사각 배경 차트·추이는 폐기됐고,
  파랑 밴드 달력 앵커는 라운드 22의 D 배지 전환으로 자리가 없어졌다.
- **왼쪽 앵커 자리는 32×32 고정**이다 — 그림도 D 배지도 같은 칸을 쓴다. 알림 카드의 그림만
  28px(라운드 8 결정 유지).
- 어법은 **애플 이모지**다 — 다색 그라디언트, 위가 밝고 아래가 어두운 입체, 배경 블록 없이 그림
  자체로 선다. 2톤 실루엣으로 먼저 그렸다가 버렸다. 색을 넣어도 아이콘으로 읽혔다.
- 연한 바탕 원을 깔지 않는다. 그림이 이미 색을 갖고 있어 두 번 말하는 셈이 된다.
- 기본 28px. **24px 미만으로 쓰지 않는다** — 손 든 사람의 눈코입이 20px에서 뭉친다.
  더 작은 자리에는 그림을 아예 쓰지 않는다.
- 흰 종이가 들어가는 그림(달력·공고)은 흰 카드 위에서 실루엣이 녹아 **0.8px 옅은 테두리**를 넣는다.
- 다섯 그림과 색

  | 알림 | 무엇을 그렸나 | 색 |
  | --- | --- | --- |
  | 스케줄 확정 | 파란 밴드 달력 + 체크. 애플 `📅`의 빨간 밴드를 파랑으로 | 흰 종이 · 파랑 · 링 회색 |
  | 공석 · 새 모집 | 손 든 사람. 애플 `🙋`와 같은 자세, 셔츠만 초록 | 얼굴 노랑 · 머리 갈색 · 초록 |
  | 확정 후 변경 | 순환 화살표 둘. 애플 `🔄`와 같은 형태, 색만 호박 | 호박 |
  | 변경 요청 승인 | 애플 `✅`와 같은 초록 사각 + 흰 체크 | 초록 |
  | 변경 요청 미반영 | 같은 사각의 회색 판 + 흰 가로줄 | 회색 |

- **얼굴은 애플 기본과 같은 노란색이다.** 특정 피부색을 고르지 않기 위한 선택이고 애플이 노랑을
  쓰는 이유와 같다.
- **빨강을 쓰지 않는다.** 미반영도 실패가 아니라 처리가 끝난 결과다. 홈에서 빨강은 위치 권한 실패
  같은 진짜 오류에만 남긴다.
- 진짜 이모지(폰트)는 쓰지 않는다. `📅`는 코드포인트일 뿐이고 그림은 기기의 이모지 폰트가 그려서
  애플·삼성·구글이 서로 다른 것을 보여준다. 컬러 이모지 웹폰트를 싣는 길도 재봤는데 Noto Color
  Emoji 전체가 약 10MB이고 서브셋해도 COLRv1·CBDT 포맷 편차가 커서
  `harness/lib/bundle-budget.ts:8`의 예산(`500 * 1024`)에 안 들어간다.
- 남의 세트(Fluent Emoji Flat MIT / Twemoji CC-BY / Noto OFL)에서 SVG만 골라 싣는 길도 열려 있다.
  화면 쪽 구조가 같아서 — 알림 종류 하나에 그림 하나를 대응시키는 표 — 나중에 파일만 갈아끼울 수 있다.

### 이번 주 블록 (라운드 16 신설, 라운드 20·21에서 개정)

라운드 3의 시안이 하단 탭을 `홈 · 일정 · 전체` 셋으로 그렸는데 계층이 맞지 않는다는 지적. 예상 급여가 `전체` 아래 2단계에 있고 알림이 헤더로 빠져 탭 자리가 하나 비었다. 세 안(A 급여를 탭으로, B 현행 유지, C 전체를 헤더로)을 비교해 **A**를 골랐다.

### 라운드 5 — 선택 탭의 모양과 움직임 (2026-08-17)

선택 표현을 "라인에 색"에서 "어두운 채움"으로 바꿨다. 움직임은 세 가지(통통 scale, 좌우 wobble, 솟구침)를 먼저 냈다가 전부 버리고 **눌림**으로 갔다 — 위아래로 눌리며 양옆이 퍼지는 형태다. 이후 세 번 더 고쳤다.

1. 채움을 `ink-950`에서 `gray-800`(#3a3f4a)로 낮췄다. 팔레트에 `ink-950` #0a0b0d와 `gray-700`
   #5b616e 사이가 비어 있어 새로 만든 단계다. 선택 안 된 탭이 이미 `gray-700`이라 그걸 쓰면
   채움 말고는 구별이 사라진다. 2026-08-17 이름 확정.
2. 선택 탭 뒤 회색 블록을 뺐다. 처음엔 셀 전체를 덮었다가 좌우 8px·위 6px 들여 줄였는데, 결국
   "선택돼 있는 내내 유지되는 것이면 채움과 색이 이미 하는 말"이라 없앴다.
3. 눌림을 두 번으로 늘렸다. 크게 한 번, 반동으로 작게 한 번.

그 과정에서 버그 하나를 잡았다. 블록이 `position: absolute`인데 라벨이 `<span>` 없는 맨 텍스트 노드라 덮여 사라졌다. 아이콘은 `<span class="glyph">`에 싸여 있어 살아남아서 글씨만 없어 보였다.

### 라운드 6 — 홈의 구조 (2026-08-17)

세 안(하나만 / 하나 + 놓칠 것만 줄로 / 우선순위 스택)을 냈는데 셋 다 아니었다. 사용자가 **고정 4블록**을 제시했고 그 구조로 다시 그렸다. 그 뒤로 다섯 번 고쳤다.

1. 첫 블록을 **가로 슬라이드**로 그렸다 → 슬라이드가 아니라 **끌 수 있는 카드**였다.
2. 넘김을 **위로 당기기 + 천장 닿음 이펙트**로 만들었다 → 스와이프가 아니라 **`X` 버튼**이었다.
3. 남은 개수 `1 / 3`을 붙였다 → **개수는 표시하지 않는다.**
4. 블록 안에 스크롤이 생기게 뒀다 → 블록 안에도 화면에도 **스크롤은 없다.** 스크롤은 최상단을
   넘어 당길 때 새로고침으로만 쓴다.
5. 출퇴근 인증을 첫 블록 슬라이드에 넣었다 → **알림에서 빼서 두 번째 자리에 고정**했다.
   알림은 읽고 끝나는 사건이고 인증은 해야 하는 행동이라는 구분이 여기서 나왔다.

프레임 높이도 340×640에서 340×736으로 고쳤다. 640은 실제 폰 비율보다 짧아서 없는 잘림을 만들고 있었다(Playwright 기준 기기는 Pixel 5, 393×851).

카드 바깥 배치를 가로 타일·하단 고정 바로 바꿔보는 라운드를 한 번 더 냈다가 되돌렸다 — "배치가 아니라 카드 안 내용이 문제"라는 지적이었다. 하단 고정 바는 `PATTERNS.md:15`가 하단 고정 버튼을 「깊은 작업」에만 허용하는 것과도 부딪혔다.

### 라운드 7 — 알림 그림 (2026-08-17)

이모지를 쓰고 싶은데 기기마다 다르게 보이는 게 문제였다. 원인은 이모지가 그림이 아니라 글자여서다. 세 길(웹폰트 / 남의 세트에서 SVG만 / 직접 그리기)을 재고 **직접 그리기**로 갔다.

첫 시안은 2톤 실루엣이었고 "너무 이상하다, 애플처럼"이라는 지적을 받았다. 어법을 바꿨다 — 다색 그라디언트 + 입체 + 배경 없음. 그다음 두 번 더 고쳤다.

1. 크기 36 → 32 → **28px**.
2. 공석을 「공고 종이 + 초록 더하기 배지」로 그렸다가 애플 `🙋`처럼 **손 든 사람**으로 다시 그렸다.

### 라운드 8 — 출근 카드 안 (2026-08-17)

### 라운드 12~13 — 행 어법 전환 (2026-08-17)

나열감의 원인은 좌우 병치를 일정 카드에도 쓴 것이었다. 무게 차이 세 안(흰 카드는 행동에만 / 아래 둘 합침 / 어법 분리)을 낸 뒤, 사용자가 토스 홈 캡처를 참조로 제시해 **행 어법**으로 다시 짰다 — 그림 앵커 32 + 라벨 위·값 아래 + 알약 + 한 카드에 행 여러 개 + 더보기 행. 세 안 중 **나(출근만 카드, 나머지 행)** 채택. 라운드 9~11의 좌우 병치 일정 카드는 폐기되고 왼쪽 큰 자리 규칙은 D 배지가 이어받았다. 이 전환이 라운드 1 「선 없음」(hairline 예외), 라운드 2 값·메타 순서, 라운드 6 네 블록, 라운드 7 그림 개수를 건드린다는 것을 명시하고 진행했다.

### 라운드 14~16 — 콘텐츠 확충과 주급 (2026-08-17)

"휑하다"는 지적에 세 축(오늘 깊게 / 이번 달 깊게 / 주제별 카드)을 냈고, "급여도 이번·저번·총, 우린 주급이라 주급이 중요" 지시로 주급 중심 재편. 라운드 15는 행마다 셋째 줄을 붙였다가 "텍스트가 아니라 컨텐츠"라는 지적으로 뒤집고, 라운드 16에서 **항목을 늘리고 글을 줄였다** — 7일 스트립, 다가오는 근무 세 건, 급여 세 줄, 더보기 둘. 사용자 승인("응 이거 좋은데"). 이 승인으로 무스크롤 규칙이 폐기됐다. 오늘 카드에 발치(아바타 + 예식 시각)가 들어와 라운드 8의 「예식은 상세로」가 뒤집혔다. 라운드 15부터 proposal.html은 **인터랙티브 프로토타입**이다 — 카운트다운·금액 가림·알림 끄기·탭 모션·당겨 새로고침이 실제로 동작하고 상태 조작판이 붙어 있다(`design:build`가 `<script>`를 보존한다).

### 라운드 18 — 금액 가림 방식 (2026-08-17, 확정)

라운드 17 확정을 미루고 가림 방식부터 고쳤다(사용자 지시). 눈 아이콘을 빼고 **자동 블러 + 금액 탭으로 해제**로 바꿨다 — 주급 발치의 눈이 사라지고 금액 자체가 누르는 자리가 됐다. 더미 렌더 + `aria-hidden` 규칙은 유지. 파생 물음 넷을 물어 같은 날 답을 받았다 — ① 기준은 토·일 고정(처음 지시)이 아니라 **근무 있는 날** ② 해제는 **화면 전체** ③ 지속은 **화면 이탈까지** ④ 설정 스위치는 **자동 가림 on/off**로 남김. 기준이 근무일로 정해지면서 조작판의 「요일」 그룹을 뺐다 — 「오늘」(근무일/근무 없는 날)이 이미 그 축이다. 2026-08-17 사용자 승인("응 좋아")으로 확정, 위 「금액 가림」 절에 반영.

### 라운드 19~21 — 굵기 · 이번 주 스트립 · 발치 (2026-08-17, 확정)

한 판에 두 축을 조작판으로 걸었다. **라운드 19 굵기** — "Bold가 너무 많다"는 지적. 세 안: 현행(700 중심) · 감량(제목·큰 숫자·행 값·D 배지 전부 600, 이름표 500) · 최소(값 500, 제목만 600, 이름표 400). 기본 선택은 감량. **라운드 20 이번 주** — "기존 일정 화면 구조와 너무 다르다"는 지적. 실물 일정 화면(`ScheduleView.tsx` + `shared/ui/calendar.tsx`)은 달력/목록 토글에 셀 상태 여섯(모집 없음·신청 가능·선택됨·신청·마감·확정), 셀 전체 틴트 + 셀 안 상태 글자, 오늘은 파란 링이다. 어법 세 안: 가(숫자만+틴트, 현행 — 신청 가능·마감을 구분 못 함) · 나(일정 셀 어법 그대로 이식: 42×44 셀, 상태 글자, 오늘 링) · 다(틴트만 이식, 상태 글자 없이, 오늘 밑줄 유지). 케이스 넷(확정 3회 · 확정·모집 섞임 · 신청만 · 빈 주)을 조작판으로 오간다. 신청만·빈 주는 확정 근무가 없어 주급이 「—」다(INV-PAY-01 — 신청분을 금액으로 계산하지 않는다). **어법 나를 고르면 라운드 1의 「달력 셀에는 숫자만, 배지 없음, 오늘 밑줄」 규칙 개정이 딸려온다.**

**5차(같은 날, 확정)** — 발치를 **나(한 줄 좌우 병치)**로 확정("나가 좋은 것 같고"). 리빌을 1.1초 → **1.5초**로, 블러를 7 → **5px**로 풀었다(사용자 "더 느리게 · 블러 약하게"). 굵기·스트립·발치 전부 확정 규칙 절에 반영했다. 주급이 26에서 18로 내려오면서 라운드 17 계층 표의 「큰 숫자 최대 두 곳(카운트다운·주급)」이 낡았다 — 재확정 때 「카운트다운 하나」로 고쳐 받는다. 다음은 라운드 22(다가오는 근무 배치).

**4차(같은 날)** — 사용자가 스트립 선택·리빌 방향을 승인("응 좋은데"). 리빌 빛을 파랑에서 **흰색**으로, 700ms에서 **1100ms**로 늦추고 띠를 넓혔다(35/50/65). 그리고 3차 네 안이 과녁을 잘못 짚은 것을 정정 — 고쳐달라던 곳은 급여 블록이 아니라 **이번 주 카드의 발치(주급 자리)**였다. 급여 벤치를 걷고 발치 네 안으로 교체: **가**(현행 — 라벨 위·금액 26 아래) · **나**(행처럼 한 줄 좌우, 금액 18 — 홈의 큰 숫자가 카운트다운 하나로 준다) · **다**(근무·시간·주급 스탯 세 칸) · **라**(금액 위·캡션 아래 — 두 줄 순서 규칙을 뒤집는 안). 각각 주 요약/날 선택 두 상태로 그렸다. 라운드 21은 이 발치 선택이다.

**3차(같은 날)** — ① 스트립 선택을 테두리에서 **파랑 배경 깔림**으로 바꾸고, 애니메이션은 하단 탭의 눌림-되튐(420ms, 같은 키프레임)을 그대로 이어받았다("아래 라우팅 섹션처럼"). 선택 안 된 근무일은 틴트 없이 **검은 숫자만**, 근무 없는 날은 흐린 숫자. ② **금액 리빌** — 블러가 벗겨질 때 빛이 숫자를 왼쪽→오른쪽으로 훑는다(700ms, `background-clip: text` 그라디언트 스윕, 끝나면 클래스 제거). ③ 급여 블록이 아쉽다는 지적에 **네 안**을 기기 아래 벤치로 냈다 — 가(현행 정리, 행 상하 12→14) · 나(그림 앵커 제거) · 다(8월을 26으로 크게 + 발치 두 줄) · 라(그림 대신 글자 배지 주·8월·연). 급여 안 선택은 라운드 21로 잡는다.

**2차(같은 날)** — 세 안 비교를 보고 사용자가 방향을 새로 줬고 비교판은 걷었다. ① 굵기 확정 방향: **카운트다운·주급 600, 덜 중요한 것 500** — 제목 600 · 행 값 500 · 이름표 500 · D 배지 600, "Bold를 많이 쓰는 경향 주의". ② **오늘 밑줄(검은 그림자) 삭제** — 스트립에서 오늘 표시가 없어졌다. ③ 어법 문제 자체를 재정의: 홈 스트립은 **신청·모집을 다루지 않고 확정 근무만 보여준다.** 근무 있는 날만 누를 수 있고, 누르면 **파란 테두리가 애니메이션(240ms 눌림-되튐)으로 잡히며** 발치가 그날 정보(포지션·시간·금액)로 바뀐다. 해제하거나 아무것도 안 고르면 주 요약(주급·근무 횟수·시간). 케이스는 근무 3회 · 근무 1회 · 빈 주 셋으로 줄었다 — 신청·마감 케이스는 이 블록의 소관이 아니게 됐다. 일정 셀 어법(상태 여섯)은 일정 화면 라운드의 몫으로 돌아간다.

### 라운드 22 — 다가오는 근무 배치 (2026-08-17, 확정)

"다가오는 근무도 배치를 좀 수정하자"는 지적. 같은 내용(확정 둘 · 열린 모집 하나 · 더보기)을 네 배치로 벤치에 냈다 — **가**(현행: D 배지 앵커, 날짜가 값) · **나**(포지션이 주인공: 날짜·시간이 라벨, 값이 포지션) · **다**(날짜 상자 앵커: D 배지 대신 「8월/21」 상자, 며칠 남았는지 표시가 사라진다) · **라**(한 줄 압축: 앵커·두 줄 없이 — 행 골격 「라벨 위·값 아래」를 벗어나는 안이라 고르면 행 규칙 개정이 딸려온다).

# P7. 탈퇴 복구, 운영 검증, 출시

## 목표

계정 생명주기와 운영 도구를 마무리하고 실제 다음 달 스케줄을 앱만으로 운영할 수 있게 한다.

## 진입 조건

- P4, P5, P6 완료.
- 관련 spec: [PRD](../../product/PRD.md) `AC-01`~`13`, [Domain](../../product/DOMAIN.md) `DOMAIN:IDENTITY`, [ADR-0007](../../standards/adr/0007-offboarding-and-history-recovery.md), [ADR-0010](../../standards/adr/0010-dormancy-and-automatic-account-lifecycle.md).

## 작업

### P7-T01. 휴면·자동 계정 정리와 탈퇴 연쇄 처리

목표:

- 3개월 휴면, 1년 자동 탈퇴, 미승인 계정 3개월 삭제와 자진 탈퇴의 개인정보·신청·배정 연쇄 처리를 하나의 계정 생명주기 계약으로 구현한다.

범위:

- 정상 저장된 출근 신청, 최초 활성 승인과 재활성화로 인정 활동 시각을 갱신한다. 나중에 취소된 정상 신청은 인정하고 실패·중복 신청, 로그인과 관리자 수동 휴면은 인정하지 않는다.
- Asia/Seoul 달력 기준 3개월·1년과 월말·윤년 경계를 계산한다.
- 활성 신청 또는 진행 중·미래 활성 배정이 있으면 자동·수동 휴면과 자동 탈퇴를 차단한다. 완료·취소된 과거 배정은 차단하지 않는다.
- 한국 시간 기준 매일 새벽 멱등 작업으로 휴면·탈퇴를 처리하고, 최초 적용 계정에는 정책 적용일부터 최소 3개월의 유예를 준다.
- 승인 대기 계정은 가입 후, 승인 거절 계정은 거절 후 3개월에 vault 없이 삭제하고 승인 감사 기록만 익명화한다. 로그인은 기한을 연장하지 않는다.
- 자진 탈퇴 시 활성 신청을 `계정 탈퇴`로 철회하고 대기 변경 요청을 무효화한다.
- 자진 탈퇴자의 진행 중·미래 확정 배정은 `변경 필요`로 표시하고 필요 인원에서 제외하되 스케줄 확정 상태는 유지한다.
- 대체 근무자 지정 시 같은 배정의 근무자를 바꾸고 `변경 필요`를 해제하며 이전·이후 근무자, 관리자와 시각을 감사한다.
- 탈퇴 시 OAuth 연결, 이메일, 휴대폰, push subscription을 삭제하고 이름, 생년월일, 성별, 시급, 내부 ID를 별도 vault에 저장한다.
- 과거 스케줄·배정·출퇴근 참조를 유지한다.
- 근무자에게는 일반 탈퇴만 제공하고, 완전 삭제는 관리자에게 직접 문의하도록 안내한다.
- 관리자는 앱 밖에서 직접 받은 요청에 한해 관리 화면에서 완전 삭제를 실행한다.
- 완전 삭제 command는 대상 이름 재입력을 확인한 뒤 복구 정보를 파기하고 과거 기록을 익명화한다.
- 완전 삭제의 실행 관리자, 대상, 시각을 감사 로그에 남긴다.
- 탈퇴 후 외부 연결 정리 실패는 계정을 복구하지 않고 멱등 재시도하며 장기 실패를 운영 오류로 노출한다.
- 관리자는 마지막 인정 활동 시각, 휴면·탈퇴 예정일과 전환 차단 신청·배정을 조회한다.

비목표:

- 자동 탈퇴 사전 앱 내·푸시 알림을 만들지 않는다.
- 별도 `탈퇴로 대체됨` 배정 상태를 만들지 않는다.
- 진행 중 근무에서 탈퇴한 사용자의 체크아웃 예외를 이 task에서 결정하거나 구현하지 않는다.

인수 조건:

- 탈퇴 사용자는 로그인과 업무 mutation을 수행할 수 없다.
- 휴면·탈퇴 기한이 KST 달력, 월말과 윤년 경계에서 일관되게 계산된다.
- 활성 신청·배정은 자동·수동 휴면과 자동 탈퇴를 차단하고 원본 신청·배정을 임의로 지우지 않는다.
- 신청·재활성화·승인과 자동 상태 전환의 동시 요청에서 먼저 커밋된 작업만 남고 성공처럼 표시된 데이터가 사라지지 않는다.
- 자진 탈퇴는 신청 철회, 변경 요청 무효화, 배정 `변경 필요`, 인원 제외와 감사 이력을 원자적으로 남긴다.
- 대체 배정 후 별도 상태 없이 같은 배정의 근무자와 인원 계산이 갱신된다.
- 승인 대기·거절 계정은 3개월 후 vault 없이 삭제되고 로그인으로 기한이 연장되지 않는다.
- 자동 탈퇴 외부 정리 실패는 탈퇴 상태를 유지한 채 재시도되고 관리자에게 장기 오류가 보인다.
- 일반 사용자와 불필요한 관리자 화면에서 vault가 노출되지 않는다.
- 일반 근무자와 권한 없는 관리자의 완전 삭제 command를 차단한다.
- 대상 이름이 일치하지 않으면 완전 삭제를 차단하고, 성공한 실행은 감사 로그로 추적할 수 있다.

### P7-T02. 재가입 이력 복구

- 재가입 프로필 정보로 탈퇴 이력 후보를 찾는다.
- 관리자가 과거 근무일·포지션을 확인하고 연결한다.
- 자동 연결하지 않고 동명이인 경고를 표시한다.
- 연결 행위와 전후 ID를 감사 로그에 남긴다.

인수 조건:

- 잘못된 동시 연결과 하나의 이력을 여러 계정에 연결하는 것을 차단한다.
- 복구 후 과거 근무·예상 급여 이력이 새 계정에서 조회된다.

### P7-T03. 보관 만료와 감사 조회

- 탈퇴 후 3년 만료된 vault를 익명화하는 멱등 Cron을 구현한다.
- 역할, 시급, 배정, 시간, 교대, 복구 변경의 감사 조회를 제공한다.
- 감사 로그는 관리자도 수정·삭제할 수 없게 한다.

인수 조건:

- 만료 작업 재실행이 안전하다.
- 민감한 변경의 행위자·시각·대상을 추적할 수 있다.

### P7-T04. 프로덕션 설정과 운영자 준비

- 프로덕션 Supabase Seoul 프로젝트와 Vercel 환경을 구성한다.
- Google OAuth redirect, VAPID, QR secret, 슈퍼 관리자 이메일을 설정한다.
- 기본 장소 좌표, 시급, 출근 규칙, 포지션을 관리자가 확인한다.
- 비밀키 회전과 환경 복구 절차를 문서화한다.

인수 조건:

- preview와 production 비밀·데이터가 분리되어 있다.
- 슈퍼 관리자 최초 로그인과 관리자 3명 임명이 성공한다.

### P7-T05. 운영 런북과 모니터링

- 모집 마감, outbox, 푸시 실패, Cron 실패, DB 용량을 확인하는 운영 절차를 작성한다.
- 휴면·자동 탈퇴 처리 수, 차단 계정, 외부 정리 재시도와 장기 실패를 확인하는 운영 절차를 작성한다.
- 장애 시 수동 재실행 가능한 멱등 command를 제공한다.
- 백업과 복구 확인 절차를 작성한다.
- 개인정보 요청과 탈퇴 처리 담당 흐름을 기록한다.

인수 조건:

- 운영자가 코드 수정 없이 실패 작업을 식별하고 재실행할 수 있다.

### P7-T06. 전체 사용자 여정 리허설

- 실제 역할과 유사한 테스트 계정으로 한 달 모집을 일괄 생성한다.
- 신청, 예식, 배정, 미달 확정, 교대, GPS 실패 QR, 결근, 급여, 리허설, 휴면·재활성화와 탈퇴 연쇄 처리를 수행한다.
- Android와 iPhone에서 PWA 설치·푸시를 확인한다.
- 발견한 문제를 새 task ID로 추가하고 해결한다.

인수 조건:

- PRD 15절 제품 인수 조건 13개가 모두 증거와 함께 통과한다.

### P7-T07. 다음 달 스케줄 파일럿

- 실제 관리자와 제한된 근무자로 첫 모집을 오픈한다.
- 단체 채팅은 장애 공지 외의 정상 업무에 사용하지 않는다.
- 신청·배정·변경·출퇴근 누락을 기록하고 차단 이슈를 수정한다.
- 파일럿 종료 후 go/no-go를 기록한다.

인수 조건:

- 관리자들이 수기 배정표 없이 스케줄을 확정한다.
- 출시를 막는 심각도 높은 미해결 이슈가 없다.

### P7-T08. 정식 전환

- 다음 달 전체 근무일 모집을 앱에서 오픈한다.
- 기존 채팅과 수기 배정표의 신규 입력을 중단한다.
- 운영 책임자, 장애 연락 경로, 첫 주 모니터링 일정을 공지한다.
- MVP 범위와 알려진 제한을 사용자에게 안내한다.

인수 조건:

- 성공 기준인 단체 채팅·수기 배정표 대체가 달성된다.
- Phase index와 운영 문서가 실제 배포 상태와 일치한다.

## 종료 조건

- 실제 다음 달 근무 모집과 배정이 라비에벨 앱에서만 운영된다.

## 제외

- 자동 배정, 사고 이력, 실제 급여 정산.
- `DESIGN.md` 이후의 브랜드 리디자인.

# P2. 모집 일괄 생성과 다중 신청

## 목표

관리자가 여러 근무일의 모집을 한 번에 열고 근무자가 여러 날짜를 신청·취소할 수 있게 한다.

## 진입 조건

- P1 완료.
- 관련 spec: [PRD](../../product/PRD.md) `AC-01`, `AC-02`, [Domain](../../product/DOMAIN.md) `DOMAIN:SCHEDULING`, [ADR-0003](../../standards/adr/0003-schedule-lifecycle-and-snapshots.md).

## 작업

### P2-T01. 스케줄과 신청 스키마

- 스케줄 상태(ADR-0003의 5종 전부), 근무일, 마감일, revision을 정의한다.
- 날짜·상태 전이와 중복 근무일 제약을 구현한다. 활성 모집은 CANCELLED를 제외한 전 상태이며, 같은 근무일의 활성 모집은 하나다(2026-08-07 기획 — 추가 인원은 재오픈으로 해결).
- 마감일은 근무일과 같거나 이전이어야 하고, 생성 시점의 KST 오늘 이전 근무일·마감일은 생성할 수 없다(당일 허용, 2026-08-07 기획).
- CANCELLED 전이와 취소 기능의 구현은 P3로 이월한다(상태 값만 이번 스키마에 포함, 2026-08-07 기획).
- 신청의 applied·withdrawn 이력과 고유 제약을 구현한다. 재오픈 시 기존 applied 신청은 유지된다.
- 모든 마감 계산은 Asia/Seoul 기준으로 한다.

인수 조건:

- 같은 근무일에 활성 모집이 중복 생성되지 않는다.
- 신청 이력이 삭제 없이 상태 전이로 남는다.
- 날짜 제약(마감일 ≤ 근무일, 과거 날짜 생성 금지)이 DB 제약으로 강제되고 위반이 테스트된다.

### P2-T02. 관리자 모집 일괄 오픈

- 달력에서 여러 근무일과 공통 마감일을 선택한다. 한 번의 일괄 생성에 월 경계 제약을 두지 않는다(2026-08-07 기획).
- 한 명령으로 여러 `OPEN` 스케줄을 생성한다.
- 일부 날짜가 충돌하면 전체 롤백하고 충돌 날짜를 알려준다. 날짜 규칙(과거 금지·마감≤근무일)은 P2-T01 DB 제약이 최종 거부한다.

인수 조건:

- 월 8개 이상의 날짜를 한 번에 생성할 수 있다.
- 생성 시 예식·출퇴근 상세 입력을 요구하지 않는다.

### P2-T03. 근무자 달력과 다중 신청

- 월 달력에 모집 상태와 본인 신청 상태를 표시한다.
- 여러 날짜를 선택해 한 번에 신청한다.
- 마감 전에는 선택 날짜를 자유롭게 철회한다.
- 관리자 역할 사용자도 같은 신청 흐름을 사용한다.
- 마지막 batch 되돌리기(Undo)를 범위에 포함한다 — 직전 batch의 반대 방향 batch 한 번으로 복원하며 서버에 별도 상태를 두지 않는다(2026-08-07 기획).
- 신청·철회 저장은 스케줄 상태와 마감 시각(마감일 23:59:59 KST)을 모두 검증한다 — 자동 마감 실행 지연과 무관하게 마감 후 신청·철회는 거부된다(2026-08-07 기획).

인수 조건:

- 다중 신청이 부분 성공 없이 원자적으로 처리된다.
- 다른 사용자의 신청 상태는 노출되지 않는다.
- 마감 시각이 지난 스케줄에는 상태가 OPEN이어도 신청·철회가 거부된다.
- 마지막 batch를 되돌리기 한 번으로 복원할 수 있다.

### P2-T04. 자동 마감, 연장, 재오픈

- 마감 날짜 23:59:59 KST 이후 `CLOSED`로 전환한다.
- 관리자가 마감일을 연장하거나 모집을 재오픈한다.
- 연장·재오픈의 새 마감일은 KST 오늘 이상·근무일 이하만 허용하고, 근무일이 지난 스케줄은 연장·재오픈할 수 없다(2026-08-07 기획 — 생성 규칙과 대칭).
- 재실행 가능한 Cron 작업과 수동 복구 명령을 제공한다. 수동 복구 명령은 운영자용이며 관리자 화면에 두지 않는다(2026-08-07 기획).
- 마감 후 신청 변경 요청은 P2에서는 재오픈으로 해결한다. 요청 기반 취소·교대 흐름은 P4 소유이며, 마감 후~확정 전 구간까지 확장할지는 P4 기획이 검토한다(2026-08-07 기획).

인수 조건:

- 마감 후 일반 근무자는 직접 신청·철회할 수 없다.
- 동일 마감 작업을 반복 실행해도 상태와 로그가 중복되지 않는다.
- 과거 마감일로의 연장과 지난 근무일의 재오픈이 거부된다.

### P2-T05. 모집 운영 화면과 테스트

- 관리자는 날짜별 신청자와 신청 수를 조회한다.
- 근무자는 예정·마감·확정 스케줄을 구분해 본다.
- 상태 전이, 시간대 경계, 다중 신청의 단위·통합·E2E 테스트를 작성한다.

인수 조건:

- KST 자정 경계와 브라우저 시간대가 다른 경우에도 마감이 정확하다.
- 모집 생성부터 다중 신청까지 모바일 E2E가 통과한다.

## 종료 조건

- 단체 채팅 없이 한 달 모집 오픈과 신청 수집을 완료할 수 있다.

## 제외

- 예식, 포지션 배정, 확정은 P3.
- 모집 오픈 푸시는 P4.

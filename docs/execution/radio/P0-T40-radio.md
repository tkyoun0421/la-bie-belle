## Requirements

### 범위와 비목표

- 범위: `gate:tdd`의 증거 검사에 미래 시각 거부를 추가한다 — tdd.json 기록의 `at`이 검사 시점보다 허용 오차 이상 미래면 위반으로 보고한다. 판정은 주입된 현재 시각을 받는 순수 함수로 작성하고 self-test로 단언한다.
- 비목표(기획 승인 그대로): 정각·등간격 패턴 진단(오탐이 정상 커밋을 막을 수 있는 휴리스틱), 기록 간 순서 역행 탐지(RED→GREEN 순서 검사가 이미 소유), 커밋 이력의 소급 검사(게이트는 현재 in_progress task만 본다), tdd.json 스키마 변경.

### 불변 규칙

- 기존 검사(스키마 검증·RED exit 0 금지·GREEN 선행 RED 요구)는 의미 불변이다. 미래 시각 거부는 추가 검사이지 대체가 아니다.
- 허용 오차는 시계 오차를 위한 소폭 상수(120초)로 하고 `harness/lib` 안에 이름 붙은 상수로 둔다. 오차 이내의 미래는 통과한다 — fail-closed가 아니라 정확한 거부가 목적이다.
- 통과하는 게이트는 아무것도 출력하지 않는다(기존 규약). 위반 메시지는 파일 경로와 항목 위치 단서를 담는다.
- 판정 함수는 현재 시각을 인자로 받는다 — 게이트 실행부만 실제 시각을 주입하고 self-test는 고정 시각으로 단언한다.

### 기술 인수 조건

1. 검사 시점 + 120초보다 미래인 `at`을 가진 기록이 있으면 `gate:tdd`가 해당 항목 위치와 함께 위반을 보고한다.
2. 과거·현재·오차 이내 시각의 기록은 통과하고, 기존 검사(스키마·RED→GREEN)의 판정은 모든 기존 self-test 케이스에서 불변이다.
3. 판정 로직이 주입 시각 기반 self-test로 단언된다: 미래 거부, 경계(오차 ±1초) 판정, 기존 유효 증거 회귀.

## Architecture

- `harness/lib/tdd-gate.ts`: `checkTddEvidence(evidence, now)`로 시그니처 확장(또는 동등한 주입 구조) — 미래 시각 검사 추가. `runTddGate`가 실제 시각을 주입한다.
- `harness/self-test/tdd-gate.test.ts`: 미래 거부·경계·회귀 케이스 추가.
- 다른 게이트·훅·문서는 무수정.

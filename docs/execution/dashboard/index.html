RADIO는 DEV-SEC-04·DEV-OBS-02를 no-console로 부분 강제한다고 적었지만 실제 강제력은 0이다. 같은 블록의 process.env 차단은 error라 정상 동작하므로 두 규칙의 등급 차이가 의도된 것인지 문서로 구분되지 않는다. 중요도가 갈려(codex medium, opus low) 높은 쪽을 택했다.

    RADIO Data model의 스키마 블록은 config 세그먼트를 runtimeExports: false로 적는데 같은 문서 'runtimeExports 세 단계(revision 4)' 표는 config를 constants로 적고 구현도 constants다. Interface 표도 pnpm lint를 eslint ., pnpm format을 prettier --write .로 적어 같은 문서의 '포맷·린트 적용 범위(revision 4)' 절 및 실제 package.json(eslint src / prettier --write src)과 어긋난다. 기획 문서 00-foundation.md 표도 config 런타임 코드를 금지로 남겨 뒀다. RADIO는 SHA-256으로 봉인된 설계 정본이라 자기 모순 상태로 승인되면 '승인된 RADIO와 실제 구현의 일치'를 판정할 기준 자체가 흔들린다(DEV-SSOT-01).

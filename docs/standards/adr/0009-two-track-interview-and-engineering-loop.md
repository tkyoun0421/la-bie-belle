# ADR-0009: 딥인터뷰 설계와 자율 개발 루프 분리

- 상태: Accepted
- 날짜: 2026-07-24
- 세 단계 승인으로 부분 대체: [ADR-0011](0011-planning-radio-development-contract.md)
- 5단계 파이프라인과 연속 루프로 부분 대체: [ADR-0013](0013-project-layer-structure.md)
- 아래 Decision의 트랙 명칭, `--task <ID>` 단일 실행과 "한 task 완료 후 정지" 항목은 ADR-0013이 대체했다. 본문은 당시 결정의 역사 기록으로 보존한다.

## Context

기존 하네스는 task 선택, 격리 worktree, TDD, 검증과 commit을 자동화했다. 그러나 제품·프로젝트·개발 설계 문서와 전체 task 계획까지 이미 확정된 입력처럼 보이면서, 사용자가 AI와 깊게 인터뷰해 방향을 결정하려던 협업 방식과 실행 자동화의 경계가 불분명해졌다.

설계 결정에는 사용자의 현장 맥락과 가치 판단이 필요하지만, 승인된 작은 작업의 구현·검증 반복은 AI가 자율적으로 수행하는 편이 효율적이다.

## Decision

- 운영을 `딥인터뷰 설계 트랙`과 `자율 개발 트랙`으로 분리한다. ADR-0011은 설계 트랙을 기획 인터뷰와 RADIO 개발 인터뷰로 세분화한다.
- 설계 트랙에서 AI는 질문, 이해 반영, 경계 사례, 선택지와 트레이드오프를 제공하고 사용자가 제품·프로젝트·개발 설계를 승인한다.
- 승인 전 문서와 task는 제안이며 구현 근거가 아니다.
- 개발 인계 task는 `planned`, `approved_by: "user"`, `approved_at`, 상세 인수 조건, `spec_refs`, `test_mode`, `check_ids`를 가져야 한다.
- 개발 runner는 자동으로 다음 task를 고르지 않고 명시된 `--task <ID>`만 실행한다.
- ADR-0011 이전에는 승인된 task가 시작되면 RADIO를 작성했다. 이후에는 task 시작 전에 승인된 RADIO 정본을 사용하고 run에는 적용 결과와 차이를 기록한다.
- 개발 중 새 제품·프로젝트·설계 결정이 필요하면 task 범위를 임의로 확장하지 않고 설계 트랙으로 반환한다.
- 한 task 완료 후 다음 task를 자동 실행하지 않고 사용자 결과 검토를 기다린다.

## Consequences

- 기존 미구현 계획은 삭제하지 않고 `proposed` 상태의 인터뷰 자료로 보존한다.
- 자동화의 범위는 줄어드는 것이 아니라 승인된 실행 구간에서 더 명확하고 깊어진다.
- 설계 진행 속도는 사용자 응답에 좌우되지만, 승인되지 않은 가정이 대량 구현되는 위험을 줄인다.
- 각 task 승인에 최소 메타데이터가 추가되고 runner 호출에는 task ID가 필수다.
- ADR-0008의 개발 가드는 유지되며 이 ADR의 인계 이후에만 실행된다.

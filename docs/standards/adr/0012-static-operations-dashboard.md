## Context

프로젝트 상태 판단이 여러 파일에 흩어져 있다. `index.jsonl`은 승인과 상태의 정본이고, 실행 증거는 `docs/execution/runs/`, 교차 검증 결과는 `docs/execution/reviews/`, 계약 위반 판정은 하네스 게이트에 있다. 사람이 이 네 곳을 매번 읽고 조합해야 "지금 무엇을 할 수 있는가"를 알 수 있다.

동시에 이 판단을 자동 실행으로 연결하면 승인 게이트가 무력해진다. 필요한 것은 실행 권한이 없는 하나의 읽기 전용 진입점이다.

revision 1은 구 하네스의 readiness 보고서·dashboard 산출물을 전제했다. [ADR-0013](0013-project-layer-structure.md) 재편으로 그 전제가 사라져 보류했고, P0-T31 게이트 하네스가 자리를 잡은 뒤 새 구조에 맞춰 다시 확정한다.

## Decision

### 위치와 생성

- 생성기는 `harness/dashboard/`에 두고 `pnpm dashboard` 명령 하나로 실행한다. 산출물은 `docs/execution/dashboard/` 아래 세 파일이며 저장소에 커밋한다.

| 파일 | 담는 것 | 정본 |
| --- | --- | --- |
| `index.html` | 진행도·준비도·검증·다음 행동. 판단용 첫 화면 | `index.jsonl`, `runs/`, `reviews/`, 게이트 결과 |
| `retrospective.html` | 성공·실패 집계, task별 회고, 미결 제안 | `docs/execution/retrospective/cases.md`·`proposals.md` |
| `coaching.html` | 최신 `/coach` 결과의 중요도별 제안, 실행 이력 | `docs/execution/coaching/<날짜>-coach.md` |

`index.html`이 나머지 둘을 링크한다. 세 파일 모두 원본이 없으면 **누락**을 표시하고 생성은 계속한다 — 대시보드가 없어서 작업이 멈추는 일은 없어야 한다.
- 산출물은 인라인 CSS만 사용하는 자체 포함 HTML이다. 외부 리소스를 로드하지 않고 네트워크 없이 열린다. 모바일 우선으로 핵심 판단 정보를 먼저 보여주고 상세는 접어 둔다.
- 계약 준수 판정은 하네스 게이트 실행 결과를 재사용한다. 대시보드는 게이트 규칙을 다시 구현하지 않는다.

### 섹션 4종

1. **진행도**: 전체·phase별 완료율, 상태별 집계, 현재 `in_progress`, 다음 후보.
2. **준비도 루브릭**: 100점 기계 판정과 근거 수치.
3. **검증**: [교차 검증 계약](../../workflow/REVIEW.md)의 결과 파일과 backlog에서 읽은 최신 영역 점수·종합, 중요도별 확정 발견, 미완료 backlog.
4. **다음 행동·차단**: 단일 다음 행동, 추천 근거, 직접 선행 조건, 차단 사유, 대안 후보. 추천은 상태·승인·의존성의 실행 경로를 따른다.

상단에는 기준 시각과 기준 커밋을 표시한다.

### 준비도 루브릭

| 영역 | 배점 | 판정 |
| --- | ---: | --- |
| 계약 준수 | 40 | 저장소 게이트 4종(index·radio·handoff·tdd) 통과율. 커밋 문맥 게이트(scope·commit-msg)는 생성 시점에 실패할 수 없는 값이므로 점수에서 빼고 참고로만 표시한다 |
| 증거 완결성 | 25 | 재편 이후 완료 task의 handoff·(tdd task면) tdd.json 보유율. `legacy-v2` 계약 task는 제외한다 |
| 실행 준비도 | 20 | 실행 가능한 `planned` 존재 10 + `blocked` 0건 10 |
| 문서 신선도 | 15 | 재생성 준수 7 + 보류 ADR 0건 4 + 미결 부채 0건 4 |

- 등급 경계는 90 이상 우수, 70~89 양호, 70 미만 주의다.
- 모든 점수는 기계 판정이며 점수마다 산출 근거 수치를 함께 표시한다. 사람이 매기는 주관 점수를 넣지 않는다.
- 재생성 준수 7점은 생성 시점의 HEAD가 아니라 **커밋된 기존 산출물**로 실측한다. 산출물이 심어 둔 `base-commit` marker의 커밋 이후, 대시보드 재생성 없이 `docs/execution/phases/`를 바꾼 커밋이 있으면 0점이다. 기존 산출물이 없으면(첫 생성) 위반 없음으로 만점을 주고 그 사실을 근거에 명시한다.

### advisory 원칙

- 대시보드는 읽기 전용 파생물이다. 정본(`index.jsonl`, `runs/`, `reviews/`)을 수정하지 않고 승인, 상태 전환, 구현 실행을 수행하거나 유도하는 제어 기능을 두지 않는다. 실행 큐의 진행은 개발 루프가 소유한다.
- 원본이 없거나 형식이 깨졌으면 값을 추정하지 않고 "누락", "결과 없음", "형식 오류"로 표시하며 생성은 계속한다.
- 생성 실패는 advisory다. task 결과를 막지 않고 한국어 오류와 종료 코드로만 알린다.
- task가 `done`·`blocked`·`skipped` 최종 상태로 전환되거나 phase 경계 상태가 바뀌면 AI 세션이 대시보드를 재생성한다. 훅이나 게이트로 강제하지 않는다.

## Consequences

- 사용자는 `index.html` 한 파일에서 현재 상태, 준비도 점수와 근거, 검증 결과, 다음 행동과 직접 차단 조건을 판단할 수 있다. 회고와 코칭은 판단이 아니라 되돌아보기용이라 별도 페이지로 뺀다.
- 점수가 전부 기계 판정이므로 등급이 흔들리면 원인이 되는 수치를 바로 지목할 수 있다. 반대로 루브릭에 없는 품질은 이 점수로 드러나지 않는다.
- 게이트 실행 결과를 재사용하므로 게이트 규칙이 바뀌면 대시보드 점수도 자동으로 따라간다. 게이트가 느려지면 생성도 같이 느려진다.
- 산출물이 커밋되므로 어느 시점의 판단이었는지 이력이 남는다. 대신 재생성을 잊으면 기준 커밋이 뒤처지며, 그 사실은 문서 신선도 점수와 상단 표시로 드러난다.
- 대시보드가 상태를 조작할 수 없으므로 이중 승인과 실행의 안전 경계는 그대로 유지된다.

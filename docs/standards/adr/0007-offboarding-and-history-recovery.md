# ADR-0007: 탈퇴 정보 분리 보관과 관리자 복구 연결

- 상태: Accepted
- 날짜: 2026-07-23

## Context

탈퇴 시 개인정보는 최소화해야 하지만 과거 근무 이력과 재가입 복구가 필요하다. 개인정보를 모두 지우면 기존 익명 기록과 재가입자를 안전하게 연결할 수 없다.

## Decision

- 탈퇴 즉시 OAuth 연결, 이메일, 휴대폰, 푸시 구독을 삭제한다.
- 이름, 생년월일, 성별, 개인 시급, 내부 근무자 ID는 활성 프로필과 분리된 vault에 3년간 보관한다.
- 과거 스케줄·배정·출퇴근은 내부 근무자 ID로 유지한다.
- 재가입 시 이름·생년월일·성별로 후보를 찾고 관리자가 과거 기록을 확인한 뒤 연결한다.
- 연결 행위자와 대상, 시각을 감사 로그에 남긴다.
- 근무자는 앱에서 일반 탈퇴만 직접 실행하며, 완전 삭제 요청 workflow는 앱에 만들지 않는다.
- 완전 삭제를 원하는 근무자는 앱 밖에서 관리자에게 직접 요청한다.
- 관리자만 관리 화면의 서버 command로 완전 삭제를 실행할 수 있다.
- command는 복구할 수 없다는 안내와 대상 근무자 이름 재입력을 요구하고, 권한 없는 실행을 차단한다.
- 3년 만료 또는 관리자 완전 삭제 실행 시 복구 정보를 파기하고 과거 기록을 익명화한다.
- 완전 삭제의 실행 관리자, 대상, 시각을 수정할 수 없는 감사 로그에 남긴다.

## Consequences

- 재가입 복구가 가능하지만 자동 연결은 하지 않는다.
- 복구용 개인정보의 접근과 보관 만료 작업을 별도로 관리해야 한다.
- 동명이인 연결 위험을 관리자 확인과 감사 기록으로 낮춘다.
- 앱 안에 개인정보 삭제 요청 접수·처리 상태 workflow를 만들지 않아 운영자가 직접 받은 요청의 근거를 별도로 관리해야 한다.
- 완전 삭제는 되돌릴 수 없으므로 관리자 권한, 대상 이름 재입력, 감사 로그를 서버 경계에서 강제해야 한다.
- 실제 운영 전 개인정보 처리방침과 보관 근거를 검토해야 한다.

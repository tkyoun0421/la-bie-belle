# Loop 무인 계약

loop-mode supervisor가 자동 재개(respawn)했거나 야간 큐에서 기동한 세션에 적용된다. 사용자가 자리에 없다는 전제로 동작한다. [loop.md](loop.md)의 공통 계약을 보완한다.

## 진행 원칙

- 질문으로 멈추지 않는다. 구현 수준 선택지는 추천안을 채택해 진행하고, 아래 보고서에 결정·근거·기각한 대안을 기록한다.
- 승인 게이트를 넘는 결정은 추천안 대상이 아니다. 기획·설계 승인, 스코프 추가, RADIO 개정, 결정 대장(DECISIONS.md) 항목이 필요한 도메인 결정이 나오면 **그 task만 blocked로 기록하고**(보고서·handoff에 사유 명시) 다음 planned task로 넘어간다. 루프 전체를 멈추지 않는다.
- 검증·CI에서 critical·high 결함이 나오면 **먼저 고치고**, 보고서의 "사후 확인 필요" 절에 기록한다. 유인 규칙("critical·high는 수정 없이 보고")의 무인 한정 예외다(2026-08-08 사용자 지시). 고칠 수 없는 critical은 해당 task만 blocked 처리하고 다음 task로 진행한다.
- 인증·결제 오류, 되돌리기 어려운 파괴적 작업이 필요한 상황만 루프 전체를 `needs_user`로 즉시 멈춘다.

## 결과 보고서

세션을 마치기 전, 체크포인트 기록과 함께 `docs/execution/runs/loop-reports/YYYY-MM-DD-<세션 ID 앞 8자>.md`를 남긴다. 같은 세션이 하루에 여러 번 재개되면 같은 파일에 절을 추가한다.

1. **한 일** — task ID와 커밋 기준 요약
2. **자동 채택한 추천안** — 결정, 근거, 기각한 대안 (없으면 "없음")
3. **사후 확인 필요** — critical·high 수정 내역과 영향 범위, 되돌리는 방법
4. **미결** — `needs_user`로 멈췄다면 그 이유, 사용자에게 넘기는 질문

# e2e 테스트 작성자

배정받은 사용자 여정을 실패하는 플로우로 옮긴다. 구현하지 않는다.

## 시작할 때

`test-planner`가 e2e로 배정한 리스크와 그것이 지키는 완료 조건을 받는다. 배정받은 것만 쓴다. 계획이 unit으로 보낸 것을 여기서 다시 훑지 않는다.

공통 검증 기준과 대역의 한계는 [strategy](../../docs/4-test/strategy.md), 러너 준비와 실행은 [execution](../../docs/4-test/execution.md#pnpm-e2e)을 따른다. 러너를 Maestro로 고른 근거와 받아들인 비용은 [ADR-013](../../docs/2-design/adr/ADR-013-e2e-runner-maestro.md)이다. 배정이 기준과 어긋나면 임의로 층을 바꾸지 말고 이슈로 돌려준다.

`tests/e2e/`의 기존 플로우를 먼저 읽는다. 화면 이름과 셀렉터 방식이 이미 서 있으면 따른다.

## 어디에 쓰나

`tests/e2e/<화면이름>.yaml`에 둔다. 훅이 이 경로를 그대로 본다 — `src/screens/cart/` 아래 화면이면 `tests/e2e/cart.yaml`이고, `src/app/` 라우트면 그 파일 이름이 화면 이름이다. 디렉터리를 대표하는 `index.tsx`·`_layout.tsx`는 그 디렉터리 이름, 최상위는 `home`이다.

한 화면에 플로우 하나다. 화면마다 파일을 새로 만들지 말고 기존 파일에 커맨드를 이어 붙인다. 여러 화면이 나눠 쓰는 준비 절차는 별도 파일로 빼고 `runFlow`로 끼운다.

플로우 머리는 이 모양이다. `appId`는 워크스페이스 설정이 안 받으니 파일마다 적는다.

```yaml
appId: com.labiebelle.app
---
- launchApp:
    clearState: true
    clearKeychain: true
- assertVisible: "보이는 글자"
```

## 실패를 확인한다

**지금은 못 돌린다.** Maestro는 기기나 시뮬레이터에 올라간 앱을 `appId`로 찾아 띄우는데 그 빌드가 아직 없다. 그러니 실패 확인을 했다고 적지 말고, 돌리지 못한 사실과 이유를 리턴 2번에 적는다.

빌드가 서면 쓴 파일만 돌린다.

```
pnpm exec maestro test tests/e2e/<이름>.yaml
```

기대와 다른 이유로 실패하면(앱이 안 뜸, 앱 ID가 안 맞음) 그건 아직 확인이 아니다. 원인을 적고 다시 돌린다.

## 무엇을 단언하나

사용자가 보는 것만 단언한다. 화면이 어떻게 만들어졌는지는 보지 않는다.

- 화면에 보이는 글자로 잡는다. **텍스트 셀렉터는 정규식이다** — 일부만 맞히려면 `.*`를 앞뒤에 붙이고 `$`·`[`·`(` 같은 글자는 이스케이프한다.
- 같은 글자가 여러 자리에 나와 애매할 때만 `testID`를 붙여 그것으로 잡는다. 그 속성을 요구하는 것은 `src/`를 고치는 일이라 리턴에 적어 넘긴다.
- 좌표(`tapOn: point`)와 화면 구조 순서에 기대지 않는다. 퍼블리싱이 스타일을 갈아끼워도 플로우는 그대로 통과해야 한다.
- 고정 대기를 쓰지 않는다. Maestro의 커맨드가 스스로 기다린다.
- 한 플로우가 한 여정을 끝까지 간다. 여정을 쪼개 파일 사이에 상태를 넘기지 않는다.
- 여정 이름과 주석은 사용자가 겪는 일을 한국어로 적는다.

업무 규칙의 경우의 수는 [층 배정 기준](../../docs/4-test/strategy.md#리스크와-층-배정)에 맡기고, 여기는 층이 맞물려 도는지를 본다.

## 지키는 것

- 구현하지 않는다. `tests/e2e/` 밖의 파일을 만들거나 고치지 않는다.
- 화면을 통과시키려고 `src/`를 손대지 않는다.
- 세션이 필요한 여정을 우회로로 덮지 않는다. **세션을 심는 방법은 아직 안 정했다** — 로그인 뒤 화면에 닿아야 하면 그 사실을 리턴 3번에 적고 멈춘다.
- 플로우가 불안정하다고 재시도로 덮지 않는다. 불안정하면 그 사실을 리턴에 적는다.
- 커밋하지 않는다. 파일만 남긴다.

## 리턴

1. 쓴 플로우 — 파일 경로와 각 플로우가 지키는 리스크
2. 실패 확인 — 돌린 명령과 실패를 가리키는 줄. 못 돌렸으면 그 이유
3. 못 쓴 것 — 배정받았지만 이 층에서 검증이 안 되는 리스크와 그 이유
4. 발견한 이슈 — 불안정한 지점, 계획이 어긋난다고 보이는 곳, `src/`에 요구할 `testID`

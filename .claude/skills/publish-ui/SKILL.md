# publish-ui — 모양을 먼저 정하고 옮기기

화면을 만들 때 제일 비싼 실수는 코드를 다 짠 뒤에 "이 모양이 아닌데"를 발견하는 것이다. 이 스킬은 그 순서를 뒤집는다. **모양을 시안으로 먼저 확정하고, 확정된 모양만 코드로 옮긴다.**

이 문서가 규칙의 정본이다. `publisher` 서브 에이전트는 여기를 읽고 따르며 규칙을 자기 문서에 복제하지 않는다.

## 두 국면

같은 규칙이 두 순간에 쓰인다.

**설계 단계 — 시안 확정.** 조정 세션이 직접 한다. 시안을 여러 안 만들어 사용자와 함께 고른다. 확정된 모양은 그 task의 RADIO Architecture에 들어가고 RADIO 승인과 함께 봉인된다. 디자인만 따로 승인받는 게이트는 없다.

**개발 단계 — UI 구현.** `publisher` 서브 에이전트가 한다. 봉인된 시안을 React로 옮기고, `unit-test-writer`가 남긴 컴포넌트 테스트를 GREEN으로 만든 뒤 UI 커밋 하나를 남긴다. 그다음 `implementer`가 서버·상태·데이터를 그 프롭에 꽂는다.

## 언제 이 절차를 거치나

설계 인터뷰에서 변경 경로 초안에 `views/**/ui`가 들어오는 순간이다. RADIO는 아직 봉인 전이라 코드펜스를 기준으로 삼을 수 없어서, 인터뷰 중에 판정한다.

이미 살아 있는 화면을 다시 디자인하고 싶으면 리팩토링 task로 올린다. 이 스킬로 task 없이 코드를 고치지 않는다.

## 만질 수 있는 곳

| 허용 | 금지 |
| --- | --- |
| `src/views/**/ui/**` | `src/views/**/model/**` |
| `src/views/**/ui/*.mock.ts` | `src/features/**`, `src/entities/**` |
| `src/shared/ui/**` | 서버 코드 전부 |
| `src/app/globals.css`, `docs/product/design/**` | `src/app/**` (preview 제외) |
| `src/app/preview/**`, `src/views/preview/**` | |

`config/fsd.json`이 `ui` 세그먼트를 `unitTest: "exempt"`로 두어 tdd-guard 훅이 화면 파일 편집을 막지 않는다. 같은 파일의 `model`은 `unitTest: "required"`다 — 화면 계산 로직이 UI 밖에 있어야 한다는 뜻이고, 그래서 `model`은 이 스킬의 범위 밖이다.

금지 경로가 필요해지면 **우회하지 말고 멈춘다.** "이 값을 계산하려면 model이 필요하다"는 설계로 돌려보낼 신호이지 UI 안에서 해결할 문제가 아니다.

## preview는 목 데이터 전용이다

`src/app/preview/page.dev.tsx`는 화면의 여러 상태를 눈으로 확인하는 자리다. **실데이터·서버 호출·인증을 붙이지 않는다.** 성공만이 아니라 빈 상태, 에러, 로딩, 긴 이름, 값이 0인 경우까지 목 데이터로 만들어 등록한다. 빈 상태의 **모양과 문구는 시안에서 이미 정해져 있다** — preview는 그것을 확인하는 자리이지 새로 정하는 자리가 아니다.

목 데이터는 화면 옆에 둔다 — `src/views/pay/ui/pay.mock.ts` 같은 자리다. 도메인 수준의 목은 `src/entities/*/model/*.mock.ts`에 있다.

새 화면을 만들면 preview 등록까지가 한 벌이다. 등록 안 된 화면은 아무도 그 빈 상태를 본 적이 없다는 뜻이다.

## 토큰을 바꿔야 할 때

**토큰의 정본은 `docs/product/design/FOUNDATIONS.md`다.** `src/app/globals.css`가 문서를 따른다. 둘이 어긋나면 문서를 코드에 맞추는 게 아니라 코드를 문서에 맞춘다. `gate:tokens`가 이 일치를 강제한다.

- **새 토큰 추가는 자유다.** 문서와 코드 양쪽에 함께 넣는다.
- **이미 쓰이는 토큰의 값 변경은 멈추고 묻는다.** 그 토큰을 쓰는 화면 목록과 전후 비교를 함께 낸다. `--color-text-muted` 하나를 바꾸면 화면 수십 개가 조용히 따라 움직인다.

간격은 문서에 적힌 값만 쓴다. 문서 밖 숫자가 필요하면 값을 먼저 쓰지 말고 **이름과 근거를 문서에 만든다.** 근거 없는 값에 이름을 주면 규칙이 거짓말이 된다. `project/spacing-scale` 린트가 이걸 강제한다.

## 시안 만들기

### 몇 안을, 무엇이 다르게

전역 틀이 아직 안 정해진 동안은 **템플릿 여러 안**을 먼저 낸다. 앱 셸, 카드 구조, 여백 리듬, 타이포 위계처럼 화면 전체가 공유할 뼈대다.

틀이 정해진 뒤에는 그 틀 **안에서** 화면별 세부만 제안한다. 매번 뼈대를 다시 흔들지 않는다.

한 라운드는 보통 세 안이고, 무엇을 다르게 할지는 그 화면에서 실제로 갈리는 것을 고른다. 예를 들어 예상 급여 화면이면 "총액을 먼저" / "날짜별 나열" / "근무 카드 중심"처럼. 각 안 위에 **무엇을 앞에 놓았는지** 한 줄로 적는다. 설명 없는 안은 고를 수가 없다.

### 어떻게 그리나

- **빈 상태까지 시안에서 정한다.** 대표 상태만 그리고 나머지를 preview로 미루지 않는다 —
  「데이터가 없을 때 무엇이 남고 무슨 말을 하나」는 개발이 알아서 채울 여백이 아니라
  **설계가 정할 것**이다. 시안에 조작판을 두어 빈 상태로 바로 넘겨볼 수 있게 만든다.
  화면마다 최소한 이 셋을 정하고 NOTES에 적는다 — **아무 데이터도 없을 때** · **일부만 있을
  때**(목록은 있는데 지금 할 일이 없는 경우) · **값이 0이거나 이름이 아주 길 때**.
- 로딩·에러·오프라인은 화면마다 다르지 않으면 전역 규칙 하나로 정하고 화면 라운드에서
  다시 묻지 않는다.
- 모바일 프레임 3개를 **가로로 나란히** 놓는다.
- 외부 CSS·CDN·폰트·이미지를 참조하지 않는다. Artifact가 그것들을 차단한다.

### 시안은 디자인 시스템을 거스를 수 없다

시안은 토큰을 **쓰는** 문서지 토큰을 **정하는** 문서가 아니다.

- **토큰 블록을 손으로 베끼지 마라.** `src/app/globals.css`의 것을 그대로 받는다. 베낀 사본은 반드시 반쪽이 되고 반드시 드리프트한다.
- **색·간격·radius·모션 넷 다 토큰만 쓴다.** 생 px도 생 hex도 시안에 안 적는다. 손에 없는 토큰 자리에 값을 찍는 순간 그 값은 퍼블리싱 때 「흡수냐 확장이냐」 판정을 부르고, 그 판정을 worker가 조용히 내리게 된다.
- **토큰에 없는 값이 필요하면 찍지 말고 멈추고 묻는다.** 이건 「막힌다」가 아니라 「설계가 아직 안 끝났다」는 신호다.
- **거스르는 값은 사용자가 직접 제안한 것만 들어온다. 그리고 그 값은 그 자리에서 디자인 시스템에 추가된다** — `FOUNDATIONS.md`와 `globals.css` 양쪽에 넣고 `gate:tokens`가 둘의 일치를 잡는다. 시안에만 사는 값은 없다.

기준은 **의도인가 사고인가**다. 사용자가 고른 값은 의도라 시스템이 늘어난다. worker가 토큰이 없어서 찍은 값은 사고라 애초에 못 생기게 막는다.

P0-T48이 이 규칙 없이 그려진 마지막 시안이다. 그 대가는 NOTES 라운드 36에 적혀 있다 — 모션 여섯·간격 둘·색 둘이 어긋났고 전부 퍼블리싱 중에 사람이 하나씩 판정했다.

### 빌드와 발행

```bash
pnpm design:build docs/execution/runs/<task-id>/design/proposal.html
```

이 명령이 그 파일이 쓴 Tailwind 클래스만 뽑아 CSS를 `<style>`에 인라인하고, 글꼴을 base64 `data:` URI로 `@font-face`에 심는다. 산출물에 외부 참조가 남지 않는다.

산출물을 Artifact로 발행해 링크를 건넨다. 폰에서 바로 열어볼 수 있다.

### 어디에 남기나

```
docs/execution/runs/<task-id>/design/
  proposal.html      진행 중인 라운드의 시안 (덮어쓴다)
  confirmed/<화면>.html   확정된 화면 (화면당 하나, 안 덮어쓴다)
  NOTES.md           라운드마다 무엇이 왜 바뀌었는지 누적
```

`proposal.html`은 **덮어쓴다.** 라운드마다 파일을 쌓지 않는다. 되돌아볼 근거는 파일 더미가 아니라 `NOTES.md`가 갖는다.

**화면 하나가 확정되면 그 시점의 `proposal.html`을 `confirmed/<화면>.html`로 옮겨 세운다.** 여러 화면을 도는 task는 다음 화면 라운드가 곧바로 `proposal.html`을 덮어쓰므로, 확정본을 옮겨두지 않으면 나중에 **코드로 옮길 계약이 git 이력 안에만 남는다.** 개발 단계의 `publisher`는 이 파일을 계약으로 읽는다.

- 화면당 파일 **하나**다. 같은 화면이 재확정되면 그 파일을 덮어쓰고 근거는 `NOTES.md`가 갖는다.
- `<title>`을 「<화면> 화면 (확정본)」으로 고쳐 진행 중 시안과 구별한다.
- 라운드 중간본은 여기 넣지 않는다. **확정된 것만** 들어온다.

시안은 설계 단계 산출물이라 **task 경계에서** 인터뷰 산출물과 함께 커밋한다. 진행 중 task가 있으면 `gate:scope`가 스테이징을 그 task의 허용 경로로 제한하므로 작업 트리에 두었다가 나중에 커밋한다.

## 확정된 시안을 코드로 옮길 때

- 시안이 계약이다. 옮기면서 모양을 바꾸지 않는다. 시안대로는 만들 수 없는 지점을 만나면 임의로 다르게 만들지 말고 멈추고 묻는다.
- 화면 계산은 UI에 심지 않는다. "30자 넘으면 말줄임" 같은 파생값이 필요하면 그건 `model`이고, 이 스킬 범위 밖이라 설계로 돌려보낸다.
- 컴포넌트 테스트는 `unit-test-writer`가 먼저 RED로 남긴다. 그 테스트를 고치지 않는다 — 어떤 구현으로도 만족될 수 없는 단언은 봉인된 설계의 결함 신호다.
- 설명 주석을 쓰지 않는다(`DEV-CODE-07`). 의도는 이름과 구조에 담고 근거는 RADIO와 handoff에 남긴다.

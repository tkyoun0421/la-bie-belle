# hotfix — 결정이 없는 수정은 바로 고친다

5단계 파이프라인은 **결정을 지키는 장치**다. 오타에는 지킬 결정이 없다. 그런데도 오타 하나가 RADIO 재봉인·허용 경로·승인을 거치면 장치가 일을 막는 쪽으로 뒤집힌다. 이 스킬은 그 경우만 골라 빠른 길을 낸다.

**게이트를 끄지 않는다.** 끄는 대신, 게이트가 원래 안 거는 자리를 정확히 쓴다.

## 진짜 제약은 하나다

`harness/lib/scope-gate.ts:24-26`:

```ts
const current = loaded.task;
if (current === null) {
  return [];
}
```

`in_progress` task가 없으면 `gate:scope`는 staged 파일을 하나도 안 막는다. 그러니 이 저장소에서 작은 수정을 가로막는 것은 규칙의 개수가 아니라 **「task 하나가 도는 동안 그 task의 허용 경로 밖 파일이 staged에 못 들어간다」** 한 줄이다.

`commit-msg`는 `P[0-9]+-T[0-9]{2}` 패턴만 본다(`harness/lib/commit-msg-gate.ts:6`) — 그 ID가 실재하는지는 안 본다. 그래도 **없는 ID를 지어내지 않는다.** 아래 「커밋 ID」를 따른다.

## 이 스킬이 맡는 것

- 오타, 맞춤법, 깨진 마크다운, 끊긴 상대 경로 링크
- 이미 내려진 결정을 **그대로 옮겨 적는** 문구 다듬기
- 코드 현실과 어긋난 문서의 사실 정정 — 파일 경로·줄 번호·명령 이름·표에서 빠진 행
- 죽은 참조 제거(지워진 파일·스크립트를 가리키는 줄)
- 로컬 도구 설정 — `.claude/**`, 에디터 설정, `.gitignore`

## 이 스킬이 절대 안 맡는 것

하나라도 걸리면 **멈추고 파이프라인으로 돌린다.** 「작아 보인다」는 근거가 아니다.

- **`src/**` 아래 무엇이든.** 한 글자여도 아니다 — 테스트가 지키는 자리다.
- **봉인된 RADIO 본문**과 `index.jsonl`의 승인 필드. 재봉인은 승인이 필요하다.
- `docs/product/PRD.md` · `DOMAIN.md` · `DECISIONS.md` · `docs/standards/adr/**` — 불변식과 결정의 정본이다.
- **결정이 하나라도 섞인 것.** 「이렇게 하는 게 나을 것 같은데」가 떠오르면 그건 결정이다.
- `config/fsd.json` — ESLint와 `.claude/hooks/tdd-guard.sh`가 같이 읽어서 한 줄이 훅을 움직인다.
- `harness/**` — 게이트 자신이다. 게이트를 우회하는 길을 게이트 자신에게 내지 않는다.
- 사용자에게 물어야 답이 갈리는 것.

애매하면 안 맡는다. 이 목록은 좁게 유지한다 — 넓어지는 순간 이 스킬이 파이프라인의 우회로가 된다.

## 절차

### 1. 판정

위 두 목록으로 가른다. 안 맡는 쪽이면 **그 자리에서 말하고 멈춘다** — 「hotfix가 아니라 〈이유〉라서 파이프라인으로 간다」.

### 2. 고친다

바로 고친다. RADIO도, 승인도, 인터뷰도 없다.

### 3. 값싼 게이트만 돌린다

건드린 것에 해당하는 것만이다. 전체 `pnpm verify`를 돌리지 않는다 — 그게 이 스킬이 아끼려는 시간이다.

| 건드린 것 | 돌릴 것 |
| --- | --- |
| `docs/**` | `pnpm gate:docs` |
| `docs/product/design/FOUNDATIONS.md` | `pnpm gate:docs` · `pnpm gate:tokens` |
| `.claude/**` · 설정 | 없음 |

### 4. 커밋

**`in_progress` task가 있는지 본다.** `docs/execution/phases/index.jsonl`에서 `"status": "in_progress"`를 찾는다.

**없으면 — 바로 커밋한다.** `gate:scope`가 통과시킨다.

**있으면 — 고친 파일이 그 task의 허용 경로 안인지 본다**(RADIO의 `## 변경 허용 경로` 코드블록).

- **안이면** 그 task의 다음 커밋에 함께 실린다. 따로 커밋하지 않는다.
- **밖이면 커밋하지 않는다.** 수정은 작업 트리에 그대로 두고 `docs/execution/hotfix-queue.md`에 한 줄 적는다. **이때도 사용자는 이미 고쳐진 파일을 본다** — 기다리는 것은 커밋이지 수정이 아니다.

`--no-verify`를 쓰지 않는다. index.jsonl의 상태를 잠깐 바꿔 게이트를 피하지 않는다. 둘 다 기록을 거짓으로 만든다.

### 커밋 ID

hotfix 커밋도 메시지에 task ID가 필요하다. 순서대로 고른다.

1. 고친 문서를 **소유한 task가 살아 있으면** 그 ID를 쓴다(예: `runs/P0-T48/**` → `P0-T48`).
2. 아니면 **상시 정비 task의 ID**를 쓴다. 없으면 만들지 말고 사용자에게 묻는다 — 없는 ID를 지어내면 `index.jsonl`과 커밋 이력이 어긋난다.

메시지 형식은 저장소 규약 그대로다. `chore(P0-T48): fix the broken link in the workflow map`

## 큐 파일

`docs/execution/hotfix-queue.md`. Git이 무시한다(`.gitignore`) — 이 파일 자신이 허용 경로에 걸리면 안 되기 때문이다.

한 건에 한 줄이다.

```
- 2026-08-18 · docs/workflow/WORKFLOW.md · 퍼블리싱 순서에 대조 단계 한 줄 추가 · P0-T48 진행 중이라 대기
```

**task 경계마다 이 파일을 비운다.** `in_progress`가 비는 순간이 큐를 흘려보낼 자리다 — 쌓인 수정을 한 커밋으로 묶고 줄을 지운다. 큐가 길어지면 그건 이 스킬이 안 맡을 것을 맡고 있다는 신호다.

## 왜 이 모양인가

빠른 길을 「게이트를 끄는 스위치」로 만들면 반드시 큰일에도 쓰인다. 그래서 이 스킬은 **끄지 않고 비켜간다** — 게이트가 원래 안 막는 자리(`in_progress` 없음, 허용 경로 안)를 쓰고, 못 비켜가는 한 자리에서는 **수정을 즉시 반영하되 커밋만 미룬다.**

느려지는 것은 커밋 하나뿐이고, 사람이 느끼는 「고쳐졌다」는 즉시다.

# decision — 결정 대장 기록

이 스킬은 **기록 절차의 정본**이다. 기록 의무와 대장의 지위(대장은 읽기용이며 정본과 어긋나면 정본이 이긴다)는 [WORKFLOW 공통 인터뷰 계약](../../../docs/workflow/WORKFLOW.md)이 소유하고, 항목 양식은 [templates/decision-entry.md](templates/decision-entry.md)가 소유한다. 이 문서와 그쪽이 어긋나면 그쪽이 이긴다.

## 1. 입력 수집

한 항목에 필요한 슬롯은 넷이다. 대화·승인 기록에서 채울 수 없는 슬롯은 지어내지 말고 사용자에게 묻는다.

| 슬롯 | 내용 |
| --- | --- |
| 요지 | 결정의 결론 한 문장(단정문) |
| 세부 | 조건·예외·경계. 이월·미결이면 어느 단계 소유인지 |
| 정본 | 결정을 소유하는 문서 1개 이상, 절 이름까지 |
| 날짜·단계 | 승인일 YYYY-MM-DD + 게이트 종류(기획·설계·정합화·검증에서 확인) |

## 2. 정본 확인

- 링크 대상 파일이 실재하는지 확인한다. 경로는 `docs/product/` 기준 상대 경로다.
- 그 문서의 해당 절을 열어 결정 내용을 실제로 담고 있는지 확인한다. 담고 있지 않으면 추가를 멈추고 보고한다 — 대장이 정본을 앞지르지 않는다.

## 3. 배치

- 도메인 경계(IDENTITY · SCHEDULING · ATTENDANCE · NOTIFICATIONS · PAY) 중 맞는 섹션의 끝에 붙인다.
- 같은 주제의 `### 주제 (task ID)` 소절이 이미 있으면 그 소절 끝에 붙이고, 같은 주제 항목이 3개 이상 모이면 소절을 신설한다.
- "아직 인터뷰 결정 없음" 자리에 첫 결정이 들어가면 그 문구는 지운다.

## 4. 추가

[templates/decision-entry.md](templates/decision-entry.md)의 양식과 작성 규칙대로 **새 항목 하나를 추가**한다.

- 같은 결정이 이미 있으면 추가하지 않는다.
- 기존 항목을 고치는 유일한 이유는 정본이 먼저 바뀌었거나 오탈자·깨진 링크다. 대장 단독으로 결정 내용을 수정하지 않는다.
- 커밋할 때는 해당 승인이 속한 task ID를 커밋 메시지에 넣는다(저장소 공통 규칙).

## 5. 자가 점검

추가 직후 확인하고, 어긋나면 고친 뒤 끝낸다.

- 볼드 문장만 읽어도 무엇이 결정됐는지 이해되는가.
- 항목의 첫 볼드가 요지 한 문장이고 문두에 있는가.
- 링크가 전부 실재 파일을 가리키는가.
- 날짜·단계가 있는가(새 항목은 필수).
- 기존 항목이 의도치 않게 바뀌지 않았는가.
